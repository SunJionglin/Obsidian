# 03 数据链路层（上）

> 物理层只管把比特送到对面，**不管这些比特拼起来是什么意思**。链路层接着干三件事：**把比特切成帧**、**发现传错了**、**传丢了要能补**。
> 这一篇是 408 计算题重灾区：CRC、海明码、滑动窗口、信道利用率。

## 3.0 先讲清楚：链路层在解决什么问题

物理层会把 `0101110…` 一长串比特送过去。但对面收到这么一串，会问：

1. 从哪一位开始算一个「包」？（→ **组帧**）
2. 这一路有干扰，某几位翻转了怎么办？（→ **差错控制**）
3. 我收得慢，你发太快我存不下怎么办？（→ **流量控制**）
4. 帧丢了要不要重发？（→ **可靠传输**）

链路层是**相邻两个节点之间**的协议（点到点），不是端到端——这是它和传输层最本质的区别。

## 3.1 五大功能

| 功能 | 干什么 | 常见实现 |
| --- | --- | --- |
| 组帧 | 把比特流切成一个个帧，让接收方能分清边界 | 字符计数、字符填充、零比特填充、违规编码 |
| 差错控制 | 发现/纠正比特错误 | 奇偶校验、CRC、海明码 |
| 流量控制 | 别让发送方发太快 | 停止等待、滑动窗口 |
| 可靠传输 | 出错或丢失后重传 | 停等、GBN、SR |
| 介质访问控制 | 共享信道上谁先发 | CSMA/CD、CSMA/CA、令牌（见下一篇） |

## 3.2 组帧：怎么知道帧从哪开始

### 3.2.1 字符计数法

帧头用一个字段写明「本帧有多少个字符」。

- 缺点：**计数一旦出错，后面全部错位**，整个流都废了，所以实际不用。

### 3.2.2 字符填充法（字节填充）

用特殊字符定界：帧开始 `SOH`、帧结束 `EOT`。如果数据里正好出现 `EOT` 怎么办？在它前面插一个转义字符 `ESC`。

```
原始数据：  A  EOT  B
发送：     SOH  A  ESC EOT  B  EOT
接收方看到 ESC EOT → 还原成数据里的 EOT
```

- 缺点：依赖 8 位字符集，二进制数据里 ESC 出现频繁时开销大（PPP 用这个思路）。

### 3.2.3 零比特填充法（HDLC 用）

用 `01111110` 作帧界。规则：**发送方每遇到 5 个连续的 1，就插一个 0**；接收方每看到 5 个 1 后跟一个 0，就把这个 0 删掉。

```
原始：  01111111 0
发送：  01111101 10      ← 5 个 1 后面插了 0
接收：  遇到 11111 0 → 删 0 → 还原 01111111
```

- 好处：数据可以是任意比特，不依赖字符集。

### 3.2.4 违规编码法

用编码里**不会出现的电平组合**做帧界（比如曼彻斯特编码中不会出现的持续高电平）。常用于局域网。

## 3.3 差错控制

### 3.3.1 奇偶校验

| 类型 | 做法 | 能力 |
| --- | --- | --- |
| 一维奇校验 | 加 1 位，使 1 的个数为奇数 | 只能发现**奇数个**错误，不能纠错 |
| 一维奇校验 | 使 1 的个数为偶数 | 同上 |
| 二维奇偶校验 | 排成矩阵，每行每列都加校验位 | 能发现并**定位**一位错，纠正一位；两位错能发现但不能纠 |

**为什么一维只能查奇数个错**：两个比特同时翻转，1 的个数奇偶性不变，校验位照样对得上。

### 3.3.2 CRC 循环冗余校验（重点）

思路：把数据看成多项式，用一个**生成多项式 G(x)** 去除，余数作为校验码附在数据后面。

**手算步骤（模 2 除法，不借位不进位，等价于异或）**：

1. 数据后面补 `r` 个 0（r = 生成多项式位数 − 1）
2. 用 G(x) 对补零后的数做模 2 除法
3. 余数就是 FCS（校验码），替换掉补的 0
4. 接收方用同样的 G(x) 去除「数据+FCS」，余数为 0 则认为无错

**例题**：数据 `1101`，生成多项式 `x³ + x + 1`（即 `1011`，r=3）

```
被除数： 1101 000        （补 3 个 0）

1101000 ÷ 1011：
  1101000
⊕ 1011
  ------
  0110000
⊕  1011
   ------
   011110
⊕   1011
    ------
    01010
⊕    1011
     ------
     0001        ← 余数 001

发送：1101 001
```

**CRC 能发现什么**：所有单个错、所有双错、所有奇数个错、所有长度小于 r+1 的突发错；但**不能纠错**（要纠错得重传或上纠错码）。

### 3.3.3 海明码（能纠一位错）

**核心公式**：`2^r ≥ k + r + 1`，其中 k 是数据位数，r 是校验位数。

| 数据位 k | 最少校验位 r | 总位数 |
| --- | --- | --- |
| 1 | 2 | 3 |
| 4 | 3 | 7 |
| 8 | 4 | 12 |
| 16 | 5 | 21 |
| 32 | 6 | 38 |

**校验位放哪**：放在 2 的幂次位置（第 1、2、4、8、16…位），数据位填空位。

以 k=4（数据 `D1D2D3D4`）、r=3 为例：

```
位号:   1    2    3    4    5    6    7
内容:  P1   P2   D1   P4   D2   D3   D4
```

**每组校验位管哪些位**（看位号二进制里哪一位为 1）：

| 校验位 | 负责的位（二进制含对应位） | 举例 |
| --- | --- | --- |
| P1 | 1,3,5,7…（最低位为 1） | P1 校验 D1、D2、D4 |
| P2 | 2,3,6,7…（次低位为 1） | P2 校验 D1、D3、D4 |
| P4 | 4,5,6,7…（第 3 位为 1） | P4 校验 D2、D3、D4 |

**纠错**：接收方重算三个校验位，谁不匹配就把它的位号相加，得到的数就是出错位号。例如 P1 和 P4 出错 → 1+4=5 → 第 5 位错了，取反即可。

## 3.4 流量控制与可靠传输

### 3.4.1 三种协议对比

![[图/三种可靠传输.png]]

> 左边是三种协议的窗口规则，右边是它们的时序：停等是一问一答，GBN 连发但一错全重发，SR 只补出错的那一帧。

| 协议 | 发送窗口 | 接收窗口 | 确认方式 | 重传方式 |
| --- | --- | --- | --- | --- |
| 停止等待 | 1 | 1 | 逐帧确认 | 超时重发该帧 |
| 后退 N 帧（GBN） | `≤ 2^n - 1` | 1 | 累计确认 | 从出错帧起全部重发 |
| 选择重传（SR） | `≤ 2^(n-1)` | 与发送窗口相同 | 逐帧确认 | 只重发出错帧 |

n 是序号位数（序号空间 2^n）。

**为什么 GBN 的窗口是 2^n − 1**：如果窗口等于 2^n，接收方无法区分「新帧」和「重传的旧帧」，会把重复帧当新帧收下。

**为什么 SR 只能 2^(n-1)**：发送窗口和接收窗口都要一半序号空间，加起来不超过 2^n。

### 3.4.2 停止等待的效率

```
一个帧的发送时延 Td = L / C        （L 帧长，C 数据率）
信道利用率 U = Td / (Td + RTT + Ta)   （Ta 是确认帧发送时延）
```

**例题**：帧长 1000 bit，数据率 10 Mbit/s，单程传播时延 20 ms，确认帧忽略。
- `Td = 1000 / 10⁷ = 0.1 ms`
- `RTT = 2 × 20 = 40 ms`
- `U = 0.1 / (0.1 + 40) ≈ 0.25%`

效率极低，这就是为什么要用滑动窗口——让信道别空等。

### 3.4.3 滑动窗口的信道利用率

```
U = min(1, W·Td / (Td + RTT + Ta))
```

W 为窗口大小。要让信道跑满，需要 `W·Td ≥ Td + RTT`，即 `W ≥ 1 + RTT/Td`。

## 3.5 常见易错点

1. **CRC 只能检错不能纠错**；能纠一位错的是海明码。
2. CRC 的「除法」是模 2 除法，不是普通除法，**不借位**。
3. 海明码校验位在 2 的幂次位，**数据位不是连续排的**。
4. GBN 收到失序帧会**丢弃**，SR 会**缓存**，这是两者最大的行为差异。
5. 窗口公式：GBN 是 `2^n − 1`，SR 是 `2^(n-1)`，别混。
6. 链路层是**点到点**（相邻节点），传输层才是**端到端**。

## 3.6 自测

<details>
<summary>Q1：一维奇偶校验为什么发现不了两位错？</summary>

两位同时翻转，1 的总个数奇偶性不变，校验位仍然匹配，所以查不出来。
</details>

<details>
<summary>Q2：CRC 的生成多项式 1011，数据 1101，FCS 是多少？</summary>

补 3 个 0 得 1101000，模 2 除以 1011，余数 001。所以发送 1101001。
</details>

<details>
<summary>Q3：k=8 的数据需要几位海明校验位？</summary>

`2^r ≥ 8 + r + 1`：r=4 时 16 ≥ 13 成立，所以 r=4，总长 12 位。
</details>

<details>
<summary>Q4：序号 3 位，GBN 和 SR 的最大窗口各是多少？</summary>

GBN：`2^3 − 1 = 7`；SR：`2^(3-1) = 4`。
</details>

<details>
<summary>Q5：为什么停等协议利用率低？</summary>

发送一帧后必须等 RTT 才能发下一帧，大部分时间信道是空的。RTT 远大于发送时延时，利用率接近 0。
</details>
