# 01 计算机网络概述

> 这一篇是整门课的地基。零基础就看两件事：**两台电脑之间到底怎么把数据送过去**，以及**为什么要把这件事分成一层一层**。公式先不用背，先把画面想出来。

## 1.0 先建立一个画面：两台电脑怎么说话

假设你在宿舍，要给隔壁楼的同学传一个 1 MB 的文件。中间会发生什么：

1. 你的电脑把文件切成很多小块（**分组**），每块加上「从哪来、到哪去」的标签（**首部**）。
2. 这些小块先经过宿舍的**交换机**，再到校园网的**路由器**，一跳一跳往前走。
3. 每一跳都要决定「下一步往哪送」，这叫**路由**。
4. 到了对方电脑，小块按顺序拼回去，还原成文件。

这里面出现了三样东西：**信号**（线上跑的电流/光）、**交换设备**（交换机、路由器）、**规则**（先发什么、收到怎么办，也就是协议）。网络这门课，就是把这幅画拆开逐层讲清楚。

## 1.1 计算机网络的准确定义

教材定义：把**分布在不同地点**、具有**独立功能**的多台计算机，通过**通信设备与线路**连接起来，在**协议**控制下实现**资源共享与信息传递**的系统。

逐个词拆开看：

| 词 | 意思 | 反例 |
| --- | --- | --- |
| 分布在不同地点 | 有距离，需要传输 | 一台机器里的两个进程不算网络 |
| 独立功能 | 每台机器自己能干活 | 显示器、键盘这种外设不算「计算机」 |
| 通信设备与线路 | 网卡、交换机、路由器、光纤 | 光有两台电脑没线路也不成网 |
| 协议 | 双方约定好的通信规则 | 没有规则，收到的数据不知道怎么解释 |
| 资源共享 | 文件、打印机、算力 | 只能聊天不算完整网络 |

**三个视角理解组成**：

| 视角 | 分法 | 各是什么 |
| --- | --- | --- |
| 按组成 | 硬件 + 软件 + 协议 | 硬件是网卡网线，软件是操作系统里的协议栈，协议是规则本身 |
| 按工作方式 | 边缘部分 + 核心部分 | 边缘是我们用的主机；核心是路由器这些只负责转发的东西 |
| 按功能 | 资源子网 + 通信子网 | 资源子网提供内容和算力；通信子网负责把数据搬过去 |

**五大功能**：数据通信（最基本，没有它别的都谈不上）、资源共享、分布式处理（一台算不完分给多台）、提高可靠性（一条路断了换一条）、负载均衡（别让一台忙死）。

## 1.2 三种交换方式：为什么需要「交换」

先想一个问题：全班 50 个人，如果两两直接拉一根线，需要 1225 根线，根本不可能。**交换**就是引入一个中间设备，让所有线都接到它身上，通过它转发。

![[图/交换方式.png]]

> 三条时间轴：电路交换是「先占道、再传、再放」；报文交换每站都要等整份收完；分组交换斜着排开，就是流水线。

### 1.2.1 电路交换（像打电话）

过程三步：**建立连接 → 通话 → 释放连接**。

打电话时，从拨号到挂断，这条线路是你独占的，别人打不进来。这就是电路交换的核心特点：**独占资源**。

- 好处：时延小且稳定，数据按序到达，适合实时语音。
- 坏处：建立连接慢（要一段段接通），通信期间别人用不了，线路利用率低。

### 1.2.2 报文交换（像寄一整箱书）

不建连接，把整个报文交给第一个节点，它**全部收下来、存起来，再转发**给下一个节点，一站一站传。

- 好处：不用建连接，线路共享，利用率高。
- 坏处：每个节点都要等整箱收完才能转，**时延大**；报文多大就要多大缓存。

### 1.2.3 分组交换（像把书拆成很多小包裹）

把报文切成固定大小的小块（分组），每个分组自己带首部，独立转发。中间节点**收完一个分组就能马上往下发**，不用等全部到齐。

- 好处：时延小（流水线）、利用率高、灵活（某条路断了可以绕）。
- 坏处：每个分组都要加首部（额外开销），到达可能乱序，需要重组。

### 1.2.4 三种方式的时延公式

符号先说清楚：

| 符号 | 含义 | 单位 |
| --- | --- | --- |
| `x` | 报文总长度 | bit |
| `b` | 链路带宽（每秒能发多少 bit） | bit/s |
| `p` | 一个分组的长度 | bit |
| `k` | 经过的链路段数 | 段 |
| `d` | 每段链路的传播时延 | s |
| `s` | 电路交换建立连接的时间 | s |

```
电路交换： t = s + x/b + k·d
报文交换： t = k·(x/b) + k·d
分组交换： t = (x/b) + (k−1)·(p/b) + k·d
```

**为什么要这样写**，逐项解释：

- `x/b`：把整个报文「推上线路」的时间，叫**发送时延**（也叫传输时延）。
- `k·d`：信号在 k 段线路上「飞」的时间，叫**传播时延**，与带宽无关。
- 报文交换里每个节点都要完整收一次再发，所以发送时延乘了 k。
- 分组交换里第一个分组推上线要 `p/b`，之后可以流水线，所以额外只多了 `(k−1)·(p/b)`。

**例题（王道常考）**：报文 1000 bit，分成 10 个 100 bit 分组，经过 3 段链路，每段带宽 10 bit/s，每段传播时延 0.1 s。

```
分组交换： x/b = 1000/10 = 100 s
          (k−1)·(p/b) = 2 × (100/10) = 20 s
          k·d = 3 × 0.1 = 0.3 s
          t = 100 + 20 + 0.3 = 120.3 s

报文交换： k·(x/b) = 3 × 100 = 300 s
          t = 300 + 0.3 = 300.3 s
```

差的那 180 s，就是分组交换「流水线」省下来的。

## 1.3 分类

| 分类依据 | 类别 | 判断要点 |
| --- | --- | --- |
| 分布范围 | 广域网 WAN / 城域网 MAN / 局域网 LAN / 个人区域网 PAN | 看覆盖范围与归属：校园网是 LAN，跨城市是 WAN |
| 拓扑结构 | 总线、星形、环形、网状 | 看设备怎么连：交换机为中心是星形 |
| 交换技术 | 电路、报文、分组 | 看有没有建连接、是不是整份转发 |
| 传输技术 | 广播式、点对点 | 广播式一条线上所有人收到；点对点只发给一个人 |

## 1.4 性能指标：用「水管」理解

把网络想成水管：**带宽是管子的粗细，时延是水从这头到那头要多久，吞吐量是实际流过去的水量。**

| 指标 | 通俗解释 | 公式 / 注意 |
| --- | --- | --- |
| 速率（数据率） | 每秒能传多少 bit | 单位 bit/s，注意 `1 B = 8 bit` |
| 带宽 | 链路理论最高速率 | 物理层里指频带宽度 Hz，网络里指 bit/s，看语境 |
| 吞吐量 | 实际通过的数据量 | 受最慢的一段（瓶颈链路）限制 |
| 发送时延 | 把数据推上线的时间 | `数据量 / 带宽` |
| 传播时延 | 信号在线路上飞的时间 | `距离 / 传播速度`（光纤约 2×10⁸ m/s） |
| 处理时延 | 节点检查首部、查表 | 通常题目忽略 |
| 排队时延 | 排队等发送 | 负载高时急剧增大 |
| 时延带宽积 | 链路里「正在飞」的比特数 | `传播时延 × 带宽`，单位 bit |
| 往返时延 RTT | 一来一回 | 含中间处理，不只是两倍传播时延 |
| 利用率 | 有多少时间在有效传输 | 利用率接近 1 时时延会暴涨 |

**两个必须分清的时延**：

- 把 1000 bit 用 1 Mbit/s 发出去 = 1 ms（发送时延）
- 信号在 1000 km 光纤上飞：1000 km ÷ 2×10⁸ m/s = 5 ms（传播时延）

**加大带宽只减发送时延，一点都不影响传播时延**——这是最常见的判断题陷阱。

**单位换算例子**：一个 10 MB 的文件，带宽 100 Mbit/s，忽略其他时延，最短要多久？
`10 MB = 80 Mbit`，`80 / 100 = 0.8 s`。注意 MB 是字节、Mbit/s 是比特，差 8 倍。

## 1.5 分层结构：拆快递的比喻

假设你要给外地朋友寄东西：你只管把东西交给快递点（应用层），快递点负责打包贴单（传输层），中转站决定走哪条线路（网络层），货车司机负责一站站运（链路层），公路本身负责让车能跑（物理层）。

好处：**每一层只做一件事，换掉某一层不影响其他层**（换货车不影响你怎么打包）。

| 概念 | 通俗说法 | 关键点 |
| --- | --- | --- |
| 协议 | 两人通信的语法（说什么、按什么顺序） | 只在对等层之间，三要素：语法、语义、时序 |
| 接口 | 上下层之间的「窗口」 | 上层通过接口调用下层的服务 |
| 服务 | 下层给上层提供的能力 | 垂直方向；分面向连接 / 无连接 |

一句话记住：**协议是水平（同层）的，服务是垂直（上下层）的。**

## 1.6 OSI 七层与 TCP/IP 四层

### 1.6.1 每一层到底干什么（配场景）

| 层 | 一句话职责 | 生活中的类比 |
| --- | --- | --- |
| 物理层 | 把 0/1 变成电信号/光信号送出去 | 公路本身 |
| 数据链路层 | 相邻两台设备之间可靠地传一帧 | 一段路的货车司机 |
| 网络层 | 从源主机到目的主机选路和寻址 | 快递中转站决定走哪条线 |
| 传输层 | 进程到进程，端到端 | 收件人是谁（不是哪个小区） |
| 会话层 | 建立、管理、结束会话 | 打电话时「喂，在吗」 |
| 表示层 | 编码、压缩、加密 | 把中文翻译成对方能看懂的写法 |
| 应用层 | 直接给用户用的服务 | 你填的快递单 |

### 1.6.2 对照表

| OSI 七层 | TCP/IP 四层 | 典型协议 | 设备 | 数据单元 |
| --- | --- | --- | --- | --- |
| 应用层 | 应用层 | HTTP、FTP、DNS、SMTP | 主机 | 报文 |
| 表示层 | 应用层 | — | — | 报文 |
| 会话层 | 应用层 | — | — | 报文 |
| 传输层 | 传输层 | TCP、UDP | 主机 | 报文段 / 用户数据报 |
| 网络层 | 网际层 | IP、ICMP、ARP、RIP、OSPF | 路由器、三层交换机 | 分组 |
| 数据链路层 | 网络接口层 | 以太网、PPP、802.11 | 交换机、网桥 | 帧 |
| 物理层 | 网络接口层 | — | 中继器、集线器 | 比特 |

![[图/分层对照.png]]

**五层模型**（教学默认）：应用 → 传输 → 网络 → 链路 → 物理。

记忆：OSI 自上而下 **应表会传网数物**。

### 1.6.3 封装与解封装（一定要有画面）

发送方从上往下走，每层加自己的首部：

```
应用层数据           [数据]
传输层加端口号       [TCP首部][数据]                    → 报文段
网络层加 IP 地址     [IP首部][TCP首部][数据]            → 分组
链路层加 MAC 和校验  [帧头][IP首部][TCP首部][数据][帧尾] → 帧
物理层               …变成 0101 的比特流…
```

接收方反过来一层层拆掉首部，直到拿到原始数据。**每层只解析属于自己的首部**，这就是分层的实际体现。

接收方反过来一层层拆掉首部，直到拿到原始数据。**每层只解析属于自己的首部**，这就是分层的实际体现。

## 1.7 常见易错点

1. **端到端 vs 点到点**：传输层是端到端（进程到进程）；链路层是相邻节点之间（点到点）。
2. **协议 ≠ 服务**：协议是同层之间怎么通信；服务是下层给上层的能力。
3. **带宽两个含义**：物理层指频率范围（Hz），网络性能里指速率（bit/s）。
4. **时延带宽积是容量**，单位 bit，不是时间。
5. **OSI 只是理论模型**，互联网实际用 TCP/IP。
6. **报文交换的时延是 k 倍发送时延**，别和分组交换混。
7. **MB 与 Mbit 差 8 倍**，换算题最爱在这挖坑。

## 1.8 自测

<details>
<summary>Q1：为什么分组交换比报文交换快？</summary>

报文交换要「完整收到再转发」，每个节点都得等整份报文接收完；分组交换可以流水线，收到一个分组就往下转，只有第一个分组需要完整发送时间。
</details>

<details>
<summary>Q2：为什么带宽变大，传播时延不变？</summary>

传播时延 = 距离 ÷ 信号速度，只与介质和距离有关。带宽只影响「把数据推上线」的速度，即发送时延。
</details>

<details>
<summary>Q3：协议三要素是什么？各举一例。</summary>

语法（报文格式，例如 HTTP 请求行的结构）、语义（每个字段什么意思，例如 200 表示成功）、时序（发送顺序与时机，例如三次握手的顺序）。
</details>

<details>
<summary>Q4：ARP 到底属于哪一层？它干什么？</summary>

功能上归网络层：把 IP 地址解析成 MAC 地址，为网络层提供下一跳的硬件地址。它的报文虽然封装在链路层帧里传，但服务对象是网络层。
</details>

<details>
<summary>Q5：一个 500 MB 的文件，带宽 1 Gbit/s，最短传输时间约多少？</summary>

500 MB = 500 × 8 = 4000 Mbit = 4 Gbit；4 / 1 = 4 s（忽略其他时延）。
</details>
