# 09 应用层

> 下面四层都在「搬数据」，应用层才决定「**搬什么、按什么规矩搬**」。这一章的考点集中在：DNS 的解析过程、HTTP 的方法与状态码、FTP 的双连接、邮件的三个协议。

## 9.0 先讲清楚：应用层在解决什么

两台机器的程序要通信，得先约定：

- 我用什么格式发（报文长什么样）
- 我说「这个」你理解成什么（语义）
- 谁先说、什么时候结束（时序）

这些约定就叫**应用层协议**。它不负责传输（那是 TCP/UDP 的事），只负责「内容怎么组织」。

## 9.1 两种体系结构

| 模型 | 说明 | 例子 | 优缺点 |
| --- | --- | --- | --- |
| C/S（客户/服务器） | 有一个固定服务器，客户主动请求 | 网页、微信 | 好管理、可集中控制；服务器压力大、成本高 |
| P2P（对等） | 每个节点既是客户又是服务器 | BitTorrent、区块链 | 扩展性好、越多人越快；难管理、版权问题 |

## 9.2 DNS：把域名翻译成 IP

人记不住 `142.250.72.14`，但记得住 `www.google.com`。DNS 就是那本电话簿。

**域名结构**：从右往左级别降低。

```
www.example.com.
 │    │      └── 根（.）
 │    └───────── 顶级域 com
 └────────────── 主机名 www（三级域名 example.com）
```

**域名服务器分四级**：

| 类型 | 管什么 |
| --- | --- |
| 根域名服务器 | 知道所有顶级域的地址（13 组） |
| 顶级域名服务器 | 管 .com / .cn / .org 等 |
| 权限域名服务器 | 管某个具体域名（example.com） |
| 本地域名服务器 | 离用户最近，负责代问并缓存 |

![[图/DNS解析.png]]

> 客户端只问本地 DNS 一次（递归）；本地 DNS 则一级级去问根、.com、权威（迭代）。

**递归 vs 迭代**：

| 方式 | 谁干活 | 特点 |
| --- | --- | --- |
| 递归查询 | 被问的一方负责拿到最终答案 | 客户端省事，服务器压力大 |
| 迭代查询 | 每次只告诉你「下一台问谁」 | 服务器省事，需要多轮 |

**缓存**：本地 DNS 拿到结果后会按 TTL 缓存，TTL 内再问同一个域名直接返回，不再走一遍。

**DNS 用 UDP 53 端口**（查询报文小、要快）；区域传送等大报文时才用 TCP。

## 9.3 FTP：两个连接

FTP 特殊在**用两条 TCP 连接**：

| 连接 | 端口 | 作用 |
| --- | --- | --- |
| 控制连接 | 21 | 传命令（登录、切换目录、请求文件） |
| 数据连接 | 20（主动模式） | 传文件内容 |

- **主动模式**：服务器主动连客户端的某个端口（客户端在防火墙后常失败）。
- **被动模式**：客户端连服务器开的临时端口（现在常用）。

**带外传送**：控制信息走控制连接，数据走数据连接——所以 FTP 的控制连接在整个会话期间一直保持。

## 9.4 电子邮件

三个协议分工：

| 协议 | 方向 | 作用 |
| --- | --- | --- |
| SMTP | 发送（推送） | 把邮件从客户端推到服务器，或服务器之间转发 |
| POP3 | 接收（拉取） | 把邮件下载到本地（通常下载后删除） |
| IMAP | 接收（拉取） | 在服务器上管理邮件（多设备同步） |

**MIME**：SMTP 原本只能传 ASCII 文本，MIME 扩展后可以传图片、附件、非英文字符（用 Base64 编码）。

一条邮件路径：

```
发件人客户端 --SMTP--> 发件服务器 --SMTP--> 收件服务器 --POP3/IMAP--> 收件人客户端
```

## 9.5 WWW 与 HTTP

**URL 结构**：

```
https://www.example.com:443/path/to/page?q=1#section
└─┬──┘   └──────┬───────┘└┬┘└─────┬─────┘└─┬─┘└──┬──┘
 协议         主机        端口    路径      查询   片段
```

**HTTP 方法**：

| 方法 | 作用 | 幂等？ |
| --- | --- | --- |
| GET | 获取资源 | 是 |
| POST | 提交数据（可能改变状态） | 否 |
| HEAD | 只要响应头 | 是 |
| PUT | 上传/替换资源 | 是 |
| DELETE | 删除资源 | 是 |

**状态码**：

| 类别 | 含义 | 常见 |
| --- | --- | --- |
| 1xx | 信息 | 100 Continue |
| 2xx | 成功 | 200 OK、206 部分内容 |
| 3xx | 重定向 | 301 永久、302 临时、304 未修改 |
| 4xx | 客户端错误 | 400 请求错误、401 未授权、403 禁止、404 找不到 |
| 5xx | 服务器错误 | 500 内部错误、502 网关错误、504 超时 |

**HTTP 版本演进**：

| 版本 | 特点 |
| --- | --- |
| HTTP/1.0 | 非持久连接：一次请求一个 TCP 连接 |
| HTTP/1.1 | 持久连接（keep-alive）、管线化、Host 头 |
| HTTP/2 | 二进制分帧、多路复用（一个连接并行多请求）、头部压缩 |
| HTTPS | HTTP + TLS，加密传输，默认 443 |

**Cookie**：服务器通过 `Set-Cookie` 让浏览器保存一小段数据，之后每次请求自动带上，用来维持登录状态。

**代理服务器 / 缓存**：`Cache-Control`、`ETag`、`Last-Modified` 控制缓存，命中就不必回源。

## 9.6 常见易错点

1. **DNS 默认用 UDP**，不是 TCP（除区域传送、响应过大）。
2. FTP 有两个连接、两个端口（21 控制、20 数据），别写成一条连接。
3. SMTP 只负责**发送**；接收用 POP3/IMAP。
4. 301 是**永久**重定向，302 是**临时**，304 表示缓存可用、没有修改。
5. HTTP/1.1 的持久连接减少了 TCP 建连开销，但仍有**队头阻塞**；HTTP/2 用多路复用解决。
6. Cookie 存在**客户端**，session 数据存在**服务端**。

## 9.7 自测

<details>
<summary>Q1：客户端问本地 DNS 是递归还是迭代？</summary>

递归。客户端只提一次请求，本地 DNS 负责拿到最终结果；本地 DNS 向根/顶级域/权威服务器查询时用迭代。
</details>

<details>
<summary>Q2：为什么 FTP 需要两条连接？</summary>

一条传控制命令（21），一条传数据（20 或临时端口）。分开是为了能在传大文件的同时继续发控制命令（如中止传输）。
</details>

<details>
<summary>Q3：301、302、304 分别是什么？</summary>

301 永久重定向（搜索引擎会更新链接）；302 临时重定向；304 资源未修改，客户端可用本地缓存。
</details>

<details>
<summary>Q4：SMTP、POP3、IMAP 各管什么？</summary>

SMTP 负责发送/转发；POP3 负责下载到本地（常见下载后删除）；IMAP 在服务器上管理邮件，多设备同步。
</details>

<details>
<summary>Q5：HTTP/1.1 的队头阻塞是什么？HTTP/2 怎么解决？</summary>

HTTP/1.1 在一个 TCP 连接上串行处理请求，前一个慢会堵住后面；HTTP/2 用二进制分帧和多路复用，多个请求并行传输。
</details>
