# 06 网络层（下）

> 上一篇给机器编了号，这一篇解决「**怎么知道往哪走**」。路由分两层：一个自治系统（AS）内部自己算路（RIP / OSPF），AS 之间互相告知「我这边能到哪些网段」（BGP）。

## 6.0 先讲清楚：路由在算什么

路由器里有一张**路由表**，每条长得像：

```
目的网段 / 掩码      下一跳          出接口     度量
192.168.2.0/24      10.0.0.2        eth1       2
0.0.0.0/0           202.1.2.1       eth0       —
```

收到包就查表：匹配哪条、从哪个口扔出去。问题是——**这张表怎么来的**？

- **静态路由**：人手工写。简单、可控，但网络一变就要改。
- **动态路由**：路由器之间互相通告、自动算出来。这就是路由协议干的事。

### 6.0.1 为什么分「内部」和「外部」

整个互联网太大，不可能让所有路由器都跑同一个协议、共享同一张表（表会爆炸、收敛会崩）。所以分成许多**自治系统 AS**（一个机构/运营商管的一片网络）：

![[图/路由协议分层.png]]

> AS 内部用自己的协议算细路（RIP/OSPF），AS 边界用 BGP 只交换「我这边能到哪些网段」，不关心对方内部怎么走。

| 类别 | 协议 | 作用范围 |
| --- | --- | --- |
| 内部网关协议 IGP | RIP、OSPF | 一个 AS 内部 |
| 外部网关协议 EGP | BGP | AS 之间 |

## 6.1 两类路由算法

| | 距离向量（RIP 用） | 链路状态（OSPF 用） |
| --- | --- | --- |
| 知道什么 | 只知道「到每个目的地的距离和下一跳」 | 知道**整个网络的拓扑** |
| 怎么交换 | 把整张路由表发给邻居 | 只把「我和邻居的链路状态」洪泛给所有人 |
| 算法 | Bellman-Ford | Dijkstra |
| 收敛速度 | 慢（坏消息传得慢） | 快 |
| 开销 | 小（只发邻居） | 大（洪泛），但只在拓扑变化时 |
| 典型问题 | 计数到无穷 | 大规模时 LSA 太多（用区域解决） |

一句话：**距离向量是「问路」，链路状态是「大家都拿到地图自己算」。**

## 6.2 RIP（距离向量）

- 度量是**跳数**（经过的路由器数），**最大 15 跳，16 表示不可达**。
- 每 **30 秒**向邻居发一次完整路由表（RIP 报文用 UDP，端口 520）。
- 只和**相邻**路由器交换，不跨路由器直接对话。

**坏消息传得慢（计数到无穷）**：一条链路断了，路由器 A 从邻居 B 那里听说「我这儿还能到」，于是以为还有别的路，慢慢把跳数加上去，直到加到 16 才发现不通。收敛很慢。

| 缓解手段 | 做法 |
| --- | --- |
| 水平分割 | 从哪个口学来的路由，不再从这个口通告回去 |
| 毒性逆转 | 从某口学来的路由，往该口通告时把距离设为 16（不可达） |
| 触发更新 | 拓扑一变立刻发，不等 30 秒 |
| 抑制计时 | 一段时间内不信任可疑路由 |

## 6.3 OSPF（链路状态）

工作流程：

1. 每台路由器发现直连邻居（**Hello 报文**）
2. 把自己和邻居的链路状态封装成 **LSA**，洪泛给整个区域
3. 每台路由器收集所有 LSA，拼出**全网拓扑图**
4. 各自跑 **Dijkstra** 算最短路径树，生成路由表

**五种分组**（记名字就够）：

| 报文 | 作用 |
| --- | --- |
| Hello | 发现与维持邻居 |
| DD（数据库描述） | 我先告诉你我有哪些 LSA |
| LSR（链路状态请求） | 我要你那条 LSA |
| LSU（链路状态更新） | 给你 LSA（洪泛就靠它） |
| LSAck | 收到确认 |

**区域（Area）**：大网络划成多个区域，骨干区是 `Area 0`，所有非骨干区必须连到骨干区。这样 LSA 洪泛只在本区域内，减小开销。

**DR/BDR**：广播型网络上选一个指定路由器（DR），其他路由器只和 DR 交换，避免 n² 条邻接关系。

**特点**：OSPF 直接封装在 IP 里（协议号 89），不用 TCP/UDP；收敛快；支持等价多路径。

## 6.4 BGP（路径向量）

AS 之间用 BGP，它关心的是「**到某个网段要经过哪些 AS**」（AS-PATH），不是跳数。

为什么不用跳数：不同 AS 之间的链路带宽、政策差别巨大，最短跳数不代表最优；而且运营商有商业策略（谁能走谁不能走）。

| 报文 | 作用 |
| --- | --- |
| OPEN | 建立邻居关系 |
| UPDATE | 通告/撤销路由 |
| KEEPALIVE | 保活 |
| NOTIFICATION | 报错并关闭连接 |

BGP 用 **TCP 179** 端口，保证可靠传输——因为路由信息错一条可能影响半个互联网。

## 6.5 三者对比（必背）

| 项 | RIP | OSPF | BGP |
| --- | --- | --- | --- |
| 类型 | 内部 IGP | 内部 IGP | 外部 EGP |
| 算法/思路 | 距离向量 | 链路状态 | 路径向量 |
| 度量 | 跳数（≤15） | 带宽/开销 | AS-PATH 等策略 |
| 交换对象 | 邻居 | 区域内所有路由器（洪泛） | AS 边界路由器 |
| 传输层 | UDP 520 | 直接封装在 IP（89） | TCP 179 |
| 收敛 | 慢 | 快 | 慢（但稳定） |
| 规模 | 小网络 | 中大型 AS | 全球互联网 |

## 6.6 IP 多播

- **多播地址**：D 类 `224.0.0.0 ~ 239.255.255.255`，代表「一组主机」。
- **IGMP**：主机用它告诉本地路由器「我要加入/退出某个多播组」。
- **多播路由**：路由器用协议（如 PIM）建立一棵分发树，避免重复发送。

对比：单播（一对一）、广播（一对全网段）、多播（一对一组）。

## 6.7 移动 IP（了解）

手机换网络时 IP 变了，TCP 连接就断了。移动 IP 的思路：

```
归属代理（家里） ← 隧道 ← 外地代理（当前所在地） ← 移动主机
```

- 移动主机到了外地，向外地代理注册，外地代理告知归属代理。
- 别人发给它「归属地址」的包，先到归属代理，再由归属代理**隧道**转发到外地代理。
- 对外部来说，它的 IP 一直没变。

## 6.8 网络层设备：路由器

路由器内部三部分：

| 部件 | 干什么 |
| --- | --- |
| 输入端口 | 收帧、拆帧、查转发表、排队 |
| 交换结构 | 把包从输入端口搬到输出端口 |
| 输出端口 | 排队、重新封装成帧、发出去 |

**路由表 vs 转发表**：路由表是路由协议算出来的（带下一跳）；转发表是路由表经过优化后给硬件用的（带出接口、更快）。考试常问两者关系，答「转发表由路由表生成」。

## 6.9 常见易错点

1. RIP 的跳数**最大 15**，16 就是不可达，别写 16 跳可用。
2. OSPF **不跑 TCP/UDP**，直接封装在 IP 里；BGP 才跑 TCP。
3. 距离向量交换的是**整张表**，链路状态交换的是**链路状态**。
4. BGP 交换的是 **AS-PATH**，不是跳数。
5. 多播地址是 D 类，不是 C 类。
6. 路由器隔离广播域，交换机不隔离。

## 6.10 自测

<details>
<summary>Q1：RIP 为什么收敛慢？</summary>

距离向量只看邻居通告，链路断开后邻居可能还保留着旧路由，导致跳数逐步累加到 16 才知道不可达（计数到无穷）。
</details>

<details>
<summary>Q2：OSPF 怎么知道全网拓扑？</summary>

每台路由器把自己的链路状态封装成 LSA 洪泛到整个区域，人人收齐后各自构建拓扑图并跑 Dijkstra。
</details>

<details>
<summary>Q3：BGP 为什么用 TCP 而不是 UDP？</summary>

路由信息必须可靠传递，丢一条可能造成大规模路由错误；TCP 提供重传与保活。
</details>

<details>
<summary>Q4：为什么 OSPF 要划分区域？</summary>

缩小 LSA 洪泛范围，降低每台路由器的拓扑计算量；所有非骨干区必须连到骨干区 Area 0。
</details>

<details>
<summary>Q5：三者的传输层封装分别是什么？</summary>

RIP 用 UDP 520；OSPF 直接封装在 IP（协议号 89）；BGP 用 TCP 179。
</details>
