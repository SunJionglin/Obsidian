# 08 传输层（下）

> 上一篇把连接建起来，这一篇解决「**传的过程中怎么保证不丢、不重、不乱序，还不把网络挤爆**」。
> 408 最爱在这里出计算题：给初始窗口和 ssthresh，让你画 cwnd 的变化过程。

## 8.0 先讲清楚：可靠传输靠什么

TCP 保证可靠，靠四件事配合：

| 机制 | 作用 |
| --- | --- |
| 校验和 | 发现数据是否被损坏 |
| 序号 | 排好顺序、发现丢包和重复 |
| 确认（ACK） | 告诉对方「我收到哪了」 |
| 重传 | 超时没收到确认，或者收到重复 ACK 就重发 |

再加两个「调速」：

- **流量控制**：别把接收方撑爆（看接收窗口 rwnd）
- **拥塞控制**：别把网络撑爆（看拥塞窗口 cwnd）

**发送窗口 = min(rwnd, cwnd)**——两个限制取小的那个。

## 8.1 超时重传与 RTT 估计

超时时间不能乱定：太短会误判重传（本来没丢），太长则丢包后等太久。

TCP 用**加权平均**估计 RTT：

```
新 RTT 样本 RTTs
平均 RTT：RTT_avg = (1−α)·RTT_avg + α·RTTs     （α 通常 1/8）
偏差：    Dev = (1−β)·Dev + β·|RTTs − RTT_avg|  （β 通常 1/4）
超时时间：RTO = RTT_avg + 4·Dev
```

**Karn 算法**：重传过的报文段**不用于 RTT 采样**——因为你分不清收到的是第一次还是第二次的确认，采样会算错。

**超时时间加倍**：连续超时时 RTO 翻倍（指数退避），避免网络更堵。

## 8.2 快速重传

不用等到超时：如果发送方连续收到 **3 个重复 ACK**（都在要同一个序号），说明中间那个包丢了，立刻重传，不必等 RTO。

```
发送 1 2 3 4 5
2 丢了：收到 ACK1、ACK1、ACK1、ACK1（4 个 ACK1）
第 3 个重复 ACK 一到就重传 2，不等超时
```

## 8.3 流量控制

接收方在每个 ACK 里带上**接收窗口 rwnd**，告诉发送方「我还能收多少」。

- `rwnd=0`：发送方停止发送，启动**坚持定时器**，定期发探测报文，问「现在能收了吗」，避免死锁（万一窗口更新的 ACK 丢了）。
- 窗口太大→接收方缓存溢出；窗口太小→效率低（**糊涂窗口综合征**，解决：接收方等窗口够大再通告，或发送方攒够一个 MSS 再发）。

## 8.4 拥塞控制：四个算法

![[图/拥塞控制曲线.png]]

> 蓝线翻倍是慢开始，绿线线性是拥塞避免，红线垂直掉下去是超时，橙线是快恢复。

两个变量：

- **cwnd**：拥塞窗口，发送方自己维护，表示「我认为网络还能承受多少」
- **ssthresh**：慢开始门限，初始通常设为一个较大值（如 16 个 MSS）

### 8.4.1 慢开始

- cwnd 从 **1 个 MSS** 开始
- 每收到一个 ACK，cwnd +1 MSS → 每个 RTT **翻倍**（指数增长）
- 直到 `cwnd ≥ ssthresh`，转拥塞避免

### 8.4.2 拥塞避免

- 每经过一个 RTT，cwnd **只 +1 MSS**（线性增长）
- 网络逐渐被填满，直到丢包

### 8.4.3 超时（严重拥塞）

```
ssthresh = cwnd / 2
cwnd = 1
重新慢开始
```

### 8.4.4 快重传 + 快恢复（轻度拥塞）

收到 3 个重复 ACK 说明只是个别包丢了，网络还没瘫：

```
ssthresh = cwnd / 2
cwnd = ssthresh          （快恢复，不回到 1）
直接进入拥塞避免（线性增长）
```

### 8.4.5 例题：画 cwnd 的变化

**题目**：初始 cwnd=1，ssthresh=8（单位 MSS）。传输顺利，第 6 轮时发生超时。求前 8 轮 cwnd。

| 轮次 | cwnd | 阶段 | 说明 |
| --- | --- | --- | --- |
| 1 | 1 | 慢开始 | 起点 |
| 2 | 2 | 慢开始 | 翻倍 |
| 3 | 4 | 慢开始 | 翻倍 |
| 4 | 8 | 慢开始→避免 | 达到 ssthresh |
| 5 | 9 | 拥塞避免 | +1 |
| 6 | 10 | 拥塞避免 | +1 |
| 7（超时后） | 1 | 慢开始 | ssthresh = 10/2 = 5 |
| 8 | 2 | 慢开始 | 翻倍，仍未到 5 |

如果第 7 轮是**收到 3 个重复 ACK**（不是超时），则 `ssthresh=5, cwnd=5`，第 8 轮 cwnd=6（拥塞避免线性）。

## 8.5 易错点

1. **超时**和**三个重复 ACK** 的反应不同：超时 cwnd=1；快重传 cwnd=ssthresh（不归 1）。
2. 慢开始不是「增长慢」，是「起点低」；它其实是指数增长。
3. `ssthresh` 减半是相对**当时的 cwnd** 减半，不是相对上一次的 ssthresh。
4. 发送窗口取 `min(rwnd, cwnd)`，两个都要看。
5. 拥塞控制是**发送方**自己判断的，网络不告诉它。
6. RTT 采样只对**未重传**的报文段做（Karn 算法）。

## 8.6 自测

<details>
<summary>Q1：cwnd=16，ssthresh=8，下一个 RTT 后 cwnd 是多少？</summary>

`cwnd ≥ ssthresh`，走拥塞避免，每 RTT +1 → 17。
</details>

<details>
<summary>Q2：cwnd=12 时超时，ssthresh 和 cwnd 各变成多少？</summary>

`ssthresh = 12/2 = 6`，`cwnd = 1`，重新慢开始。
</details>

<details>
<summary>Q3：cwnd=12 时收到 3 个重复 ACK，怎么处理？</summary>

快重传 + 快恢复：`ssthresh = 6`，`cwnd = 6`，然后进入拥塞避免（线性增长），不回 1。
</details>

<details>
<summary>Q4：为什么发送窗口不能只看 cwnd？</summary>

cwnd 只代表网络承受能力；还要看接收方剩余缓存 rwnd，取两者较小值才不会把接收方撑爆。
</details>

<details>
<summary>Q5：Karn 算法解决什么问题？</summary>

重传的报文段无法区分 ACK 对应哪一次发送，若拿它采样会把 RTT 算错，所以重传段不采样。
</details>
