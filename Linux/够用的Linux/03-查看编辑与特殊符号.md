# 03 查看、编辑与特殊符号

## 1. 本篇知识点清单

- **分页看文件**：`more` 与 `less` 的区别与按键
- **看头看尾**：`head`、`tail -f` 跟日志
- **改文件**：`vim` 的三种模式与五个救命命令
- **改文件（简单版）**：`nano` 的保存退出
- **通配符**：`*` `?` `[]` 怎么匹配
- **重定向**：`>` `>>` `<` `2>` `2>&1`
- **管道**：`|` 把前一个命令的输出当后一个的输入
- **命令连接**：`;` `&&` `||` 的差别
- **引号与转义**：单引号、双引号、反斜杠、`$变量`、`$()`

## 2. 正文·知识块

### 2.1 分页查看：more 与 less

```bash
less /var/log/syslog      # 推荐：可上下翻、可搜索
more /var/log/syslog      # 只能往下翻
```

| 按键（在 less 里） | 作用 |
| --- | --- |
| `空格` / `b` | 下一页 / 上一页 |
| `↑` `↓` | 逐行滚动 |
| `/关键词` | 向下搜索，`n` 下一个，`N` 上一个 |
| `g` / `G` | 跳到文件头 / 文件尾 |
| `q` | 退出 |

**为什么推荐 less**：它不会一次性把文件读进内存（大文件也秒开），而且能往回翻。

### 2.2 看头看尾

```bash
head -n 20 access.log     # 前 20 行
tail -n 20 access.log     # 后 20 行
tail -f access.log        # 持续跟新内容（看日志必备），Ctrl+C 退出
```

`tail -f` 是排查线上问题的第一招：开着它，然后复现问题。

### 2.3 vim：三种模式与五个命令

vim 的坑在于「模式」：默认进的是**普通模式**，此时敲字母是命令，不是输入。

| 模式 | 怎么进 | 能干什么 |
| --- | --- | --- |
| 普通模式 | 启动即在；按 `Esc` 随时回来 | 移动、删除、复制、粘贴、保存 |
| 插入模式 | `i`（光标前插入）/ `a`（后）/ `o`（下一行新起） | 打字 |
| 命令模式 | 普通模式按 `:` | 保存、退出、替换 |

五个救命命令（普通模式下）：

```
:q        退出（没改过）
:q!       不保存强行退出
:w        保存
:wq       保存并退出（等价 ZZ）
dd        删掉整行
```

**坑**：进 vim 后乱敲会改坏文件；不确定就按 `Esc` 再 `:q!`。

### 2.4 nano：最省事的编辑器

```bash
nano note.txt
# 改完：Ctrl+O 回车 保存，Ctrl+X 退出
```

屏幕底部常驻快捷键提示，零学习成本；服务器上快速改个配置够用。

### 2.5 通配符

| 符号 | 匹配 | 例子 | 匹配结果 |
| --- | --- | --- | --- |
| `*` | 任意长度任意字符 | `ls *.txt` | 所有 txt 文件 |
| `?` | 恰好一个字符 | `ls file?.log` | `file1.log`、`fileA.log` |
| `[]` | 括号里任一字符 | `ls file[123].log` | file1/2/3.log |
| `{a,b}` | 展开成多个（bash 特有） | `mkdir {src,doc,test}` | 一次建三个目录 |

**坑**：通配符是 **shell** 展开的，不是命令自己处理的。所以 `find . -name *.txt` 会出错，要加引号让它别展开。

### 2.6 重定向

| 写法 | 作用 | 真实例子 → 效果 |
| --- | --- | --- |
| `>` | 覆盖输出到文件 | `ls -l > list.txt` → 写进文件，原有内容被清空 |
| `>>` | 追加到文件末尾 | `echo new >> list.txt` → 加一行，不清空 |
| `<` | 从文件读输入 | `wc -l < list.txt` → 统计行数，不需要文件名参数 |
| `2>` | 把错误信息写文件 | `ls /nope 2> err.txt` → 错误进 err.txt |
| `2>&1` | 错误合并进标准输出 | `cmd > all.log 2>&1` → 正确和错误都进同一个文件 |

**坑**：`>` 会先把文件清空再写。想看结果又想留日志，用 `>>` 或者 `tee`（第 08 篇）。

### 2.7 管道

```bash
ls -l | wc -l                 # 数当前目录有多少项
cat access.log | grep 404     # 从日志里筛 404
ps aux | grep python          # 找 python 进程
```

`|` 把左边命令的**标准输出**接到右边命令的**标准输入**。命令可以串很多级，这是 Linux 最实用的设计。

### 2.8 命令连接：; && ||

| 写法 | 含义 | 例子 |
| --- | --- | --- |
| `;` | 依次执行，不管成败 | `cd /tmp; ls` |
| `&&` | 前一个**成功**才执行后一个 | `cd /tmp && ls` |
| `\|\|` | 前一个**失败**才执行后一个 | `cd /nope \|\| echo 目录不存在` |

实战里最常用 `&&`：`mkdir build && cd build`，建失败就别进去。

### 2.9 引号、变量与转义

```bash
name=chris                 # 赋值，等号两边不能有空格
echo $name                 # chris
echo "hello $name"         # hello chris     双引号：变量会展开
echo 'hello $name'         # hello $name     单引号：原样输出
echo "files: $(ls | wc -l)"  # 命令替换，先执行 $() 里的命令
echo \$name                # $name           反斜杠转义
```

| 写法 | 变量展不展开 | 什么时候用 |
| --- | --- | --- |
| `"双引号"` | 展开 | 需要变量、需要保留空格 |
| `'单引号'` | 不展开 | 写正则、写含 `$` 的字面量 |
| `` `反引号` `` | 展开（旧写法） | 用 `$()` 代替，别用 |

**坑**：`name = chris`（等号两边有空格）会被当成「执行名叫 name 的命令」并报错。

## 3. 命令速查表

| 命令 / 符号 | 作用 | 真实例子 → 干什么 |
| --- | --- | --- |
| `less` | 分页看 | `less app.log` → 可搜索可回翻 |
| `head` | 看头 | `head -n 20 app.log` → 前 20 行 |
| `tail -f` | 跟日志 | `tail -f app.log` → 有新内容就刷 |
| `vim` | 编辑 | `vim conf.ini` → `i` 改、`Esc`、`:wq` 存退 |
| `nano` | 编辑（简单） | `nano note.txt` → `Ctrl+O` 存、`Ctrl+X` 退 |
| `>` / `>>` | 重定向 | `ls > a.txt` 覆盖、`ls >> a.txt` 追加 |
| `2>` | 重定向错误 | `ls /nope 2> err.txt` |
| `\|` | 管道 | `ps aux \| grep python` |
| `&&` | 成功才执行 | `mkdir build && cd build` |
| `$()` | 命令替换 | `echo $(date)` |

## 4. 动手练

**① 造一个日志并用三种方式看**
```bash
seq 1 100 > ~/lab/num.txt
head -n 5 ~/lab/num.txt      # 1~5
tail -n 3 ~/lab/num.txt      # 98 99 100
less ~/lab/num.txt           # 用 /50 搜一下，q 退出
```

**② 重定向的覆盖与追加**
```bash
echo first > ~/lab/t.txt     # 文件里是 first
echo second > ~/lab/t.txt    # 变成 second（覆盖）
echo third >> ~/lab/t.txt    # second 下面多一行 third
```

**③ 管道组合**
```bash
ls -l /etc | wc -l           # /etc 下有多少项
ls /etc | grep conf | head   # 名字里带 conf 的
```

**④ 通配符**
```bash
touch ~/lab/{a1.log,a2.log,b1.txt}
ls ~/lab/a*.log              # a1.log a2.log
ls ~/lab/a?.log              # 同上
```

**⑤ 用 vim 改一行并保存**
```bash
vim ~/lab/t.txt
# i 进入插入，改内容，Esc，:wq 回车退出；再用 cat 验证
```

## 5. 常见报错

**① `-bash: name: command not found`（赋值时）**
`name = chris` 等号两边有空格。写成 `name=chris`。

**② 重定向把文件清空了**
`>` 会先截断文件。要保留请用 `>>`。

**③ 进了 vim 出不来**
先按 `Esc`，再敲 `:q!`（不保存）或 `:wq`（保存）。

**④ `find . -name *.txt` 结果比预期少**
通配符被 shell 展开。加引号。

## 6. 平台差异

| 项 | Linux | macOS |
| --- | --- | --- |
| `sed -i` 原地改 | `sed -i 's/a/b/' f` | 必须写 `sed -i '' 's/a/b/' f` |
| `ls` 颜色 | `--color=auto` | `-G` |
| `grep -P`（Perl 正则） | 通常支持 | 默认不支持 |
| `tail -f` | 支持 | 支持（`-F` 也可） |

## 7. 自测

<details>
<summary>Q1：`less` 和 `cat` 的本质差别是什么？</summary>

`cat` 一次把整个文件输出到终端，`less` 只按屏幕需要读，所以大文件也能秒开，还能搜索、回翻。
</details>

<details>
<summary>Q2：`>` 和 `>>` 的区别？</summary>

`>` 先清空文件再写（覆盖），`>>` 追加到末尾。误用 `>` 会丢数据。
</details>

<details>
<summary>Q3：`cmd1 && cmd2` 和 `cmd1 ; cmd2` 差在哪？</summary>

`;` 不管前一个成不成功都执行后一个；`&&` 只有前一个成功（退出码 0）才执行后一个。
</details>

<details>
<summary>Q4：为什么 `echo 'hello $USER'` 不展开变量？</summary>

单引号里一切都是字面量，shell 不做变量替换；双引号才会展开。
</details>

<details>
<summary>Q5：`2>&1` 是什么意思？</summary>

把标准错误（fd 2）重定向到标准输出（fd 1）指向的地方，于是正确输出和错误输出会进同一个文件。
</details>
