# 07 链接、后台任务与终端复用

## 1. 本篇知识点清单

- **硬链接与软链接**：一个指向 inode，一个指向路径
- **能不能链目录**：硬链接不能，软链接可以
- **前台后台**：`&`、`jobs`、`fg`、`bg`、`Ctrl+Z`
- **关掉终端还在跑**：`nohup`、`setsid`
- **杀进程**：`kill`、`pkill`、信号 TERM / 9
- **终端复用**：`tmux` 的会话、分离、重连

## 2. 正文·知识块

### 2.1 硬链接 vs 软链接

```bash
ln  target.txt hard.txt        # 硬链接
ln -s target.txt soft.txt      # 软链接（符号链接）
ls -li                         # -i 看 inode
```

| | 硬链接 | 软链接 |
| --- | --- | --- |
| 本质 | 指向同一个 inode（同一份数据） | 一个小文件，内容是目标路径 |
| 删掉原文件 | 数据还在（链接数减一），仍能访问 | 断链，访问报 `No such file or directory` |
| 能链目录 | 不能 | 能 |
| 跨分区 | 不能 | 能 |
| `ls -l` 显示 | 和普通文件一样 | `soft.txt -> target.txt` |

```bash
echo hello > t.txt
ln t.txt h.txt && ln -s t.txt s.txt
rm t.txt
cat h.txt      # hello（数据还在）
cat s.txt      # No such file or directory（断链）
```

**典型用途**：软链接把配置文件挂到别处（`/etc/nginx/sites-enabled/x -> ../sites-available/x`），或者给长路径起个短名。

### 2.2 前台与后台

```bash
sleep 300 &        # & 丢后台，输出 [1] 12345（作业号 + PID）
jobs               # 看当前终端的作业列表
fg %1              # 把作业 1 拉回前台
bg %1              # 让挂起的作业 1 在后台继续跑
```

按 `Ctrl+Z` 是**挂起**（暂停）当前前台任务，它会出现在 `jobs` 里但不再消耗 CPU；`fg` 恢复、`bg` 继续后台跑。

**坑**：用 `&` 丢后台的进程，**关掉终端就没了**（收到 SIGHUP）。要跑得久见下一条。

### 2.3 nohup：关掉终端也不死

```bash
nohup python3 job.py > job.log 2>&1 &
# 或者
nohup ./server &
```

`nohup` 让进程忽略挂断信号（SIGHUP），输出默认写到 `nohup.out`。配合 `&` 放后台，就可以退出 ssh 让它继续跑。

```bash
nohup long_task.sh > out.log 2>&1 &
jobs          # 看作业
ps aux | grep long_task      # 确认还活着
```

### 2.4 杀进程

```bash
kill 12345              # 默认发 SIGTERM（15），礼貌地让程序自己收拾
kill -9 12345           # SIGKILL，强杀，程序没机会清理
pkill -f "python3 job"  # 按命令行匹配批量杀
killall nginx           # 按进程名杀
```

**优先级**：先 `kill`（TERM），不行再 `-9`。上来就 `-9` 会留下临时文件、锁、半截数据。

### 2.5 tmux：一个终端变很多个

```bash
sudo apt install tmux
tmux                # 新建会话
tmux ls             # 列出会话
tmux attach -t 0    # 重连会话 0
```

**最关键的三个操作**（前缀键默认 `Ctrl+b`）：

| 操作 | 按键 |
| --- | --- |
| 分离（会话留在后台） | `Ctrl+b` 然后 `d` |
| 新开窗口 | `Ctrl+b` 然后 `c` |
| 切窗口 | `Ctrl+b` 然后数字 `0/1/2` |
| 上下分屏 | `Ctrl+b` 然后 `\` |

比起 `nohup`，tmux 的好处是**能回来接着看**：ssh 断了、网断了，重连 `tmux attach` 就行，之前的输出都在。

## 3. 命令速查表

| 命令 | 作用 | 真实例子 → 干什么 |
| --- | --- | --- |
| `ln` | 硬链接 | `ln t.txt h.txt` → 同数据多一个名字 |
| `ln -s` | 软链接 | `ln -s /opt/app/conf ./conf` → 建快捷方式 |
| `&` | 后台运行 | `sleep 300 &` → 不占终端 |
| `jobs` / `fg` / `bg` | 管理作业 | `fg %1` → 拉回前台 |
| `nohup` | 脱终端运行 | `nohup ./srv > srv.log 2>&1 &` |
| `kill` | 发信号 | `kill 1234` → 请它退出 |
| `kill -9` | 强杀 | `kill -9 1234` → 立刻死 |
| `tmux` | 终端复用 | `tmux attach -t 0` → 接回会话 |

## 4. 动手练

**① 体验软硬链接的差别**
```bash
cd ~/lab && echo hi > t.txt
ln t.txt h.txt && ln -s t.txt s.txt && ls -li t.txt h.txt s.txt
rm t.txt
cat h.txt   # hi
cat s.txt   # 报错：断链
```

**② 后台跑一个任务**
```bash
sleep 120 &
jobs
fg %1        # 拉回前台，Ctrl+C 结束
```

**③ 挂起再恢复**
```bash
sleep 300    # 前台
# Ctrl+Z 挂起
jobs         # 看到 Stopped
bg %1        # 后台继续
kill %1      # 结束它
```

**④ nohup 跑一段脚本**
```bash
nohup bash -c 'for i in 1 2 3; do echo $i; sleep 1; done' > ~/lab/nohup.log 2>&1 &
cat ~/lab/nohup.log
```

**⑤ tmux 走一遍分离与重连**
```bash
tmux new -s demo     # 进去
# 按 Ctrl+b 再按 d 分离
tmux ls              # 看到 demo
tmux attach -t demo  # 回来
exit                 # 退出会话
```

## 5. 常见报错

**① 软链接打开报 `No such file or directory`**
目标被删或路径写错。`ln -sf` 重建，用绝对路径最稳。

**② 关掉 ssh 后程序没了**
没用 `nohup` 或 tmux。下次用 `nohup ... &` 或直接在 tmux 里跑。

**③ `kill` 之后进程还在**
可能忽略了 TERM 信号，或者 `kill` 的是父进程。确认 PID（`ps aux | grep`）再 `kill -9`。

**④ `tmux: command not found`**
精简系统没装，`sudo apt install tmux`。

## 6. 平台差异

| 项 | Linux | macOS |
| --- | --- | --- |
| 硬/软链接 | 标准支持 | 标准支持（软牛ln -s 同） |
| `nohup` | 自带 | 自带 |
| tmux | 需装 | `brew install tmux` |
| `killall` | 有 | 有，但参数语义略有不同 |

## 7. 自测

<details>
<summary>Q1：删掉原文件之后，硬链接和软链接分别怎样？</summary>

硬链接照常可读（它只是同一份数据的另一个名字，数据要等链接数归零才释放）；软链接变成断链，访问报错。
</details>

<details>
<summary>Q2：`Ctrl+Z` 和 `Ctrl+C` 的区别？</summary>

`Ctrl+Z` 挂起（暂停，进程还在，可 `fg` 恢复）；`Ctrl+C` 中断（通常直接终止）。
</details>

<details>
<summary>Q3：`nohup` 和 tmux 都能让任务在断线后继续，怎么选？</summary>

一次性跑完就行的批处理用 `nohup`；要回来继续看输出、继续敲命令的用 tmux。
</details>

<details>
<summary>Q4：为什么建议先 `kill` 再 `kill -9`？</summary>

TERM 让程序自己收尾（关文件、删临时文件、写完缓冲）；KILL 是内核直接干掉，程序的清理逻辑全被跳过。
</details>

<details>
<summary>Q5：硬链接为什么不能跨分区、不能指向目录？</summary>

它共享的是 inode，而 inode 属于具体文件系统，跨分区就没有同一个 inode 可指；目录硬链接会造成环状结构，文件系统遍历会死循环，所以系统禁止。
</details>
