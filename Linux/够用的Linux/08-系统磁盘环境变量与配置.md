# 08 系统、磁盘、环境变量与配置

## 1. 本篇知识点清单

- **看负载**：`top` / `htop` 里 load average、CPU、内存三块怎么读
- **看进程**：`ps aux` 与 `ps -ef` 的用法
- **看磁盘**：`df`（分区）、`du`（目录）、`lsblk`（设备）三者的分工
- **看 IO 与网络**：`iotop`、`iftop`、`nload` 什么时候用
- **挂载**：`mount` / `umount` 与 `/etc/fstab` 持久化
- **环境变量**：`env`、`export`、`PATH`、`LD_LIBRARY_PATH`
- **配置文件**：`.bashrc` / `.profile` / `.zshrc` 的区别与 `source`
- **拾遗与快捷键**：`watch`、`tee`、`diff`、`uname`，以及几个会让人以为「终端死了」的按键

## 2. 正文·知识块

### 2.1 top / htop：先看三块

```bash
top          # 自带
htop         # 更好看，需 apt install htop
```

`top` 顶部四行是关键：

```
top - 14:20:01 up 3 days,  2 users,  load average: 0.52, 0.61, 0.48
Tasks: 187 total,   1 running, 186 sleeping,   0 stopped,   0 zombie
%Cpu(s):  3.2 us,  1.1 sy,  0.0 ni, 95.4 id,  0.3 wa
MiB Mem :   7823.4 total,    512.9 free,   2048.3 used,   5262.2 buff/cache
```

| 看什么 | 含义 | 怎么判断有问题 |
| --- | --- | --- |
| `load average` | 1/5/15 分钟的平均负载 | 长期 ≥ CPU 核数（`nproc`）说明排队严重 |
| `%Cpu` 的 `us` / `sy` / `wa` | 用户态 / 内核态 / 等 IO | `wa` 高说明卡在磁盘 |
| `Mem` 的 `used` / `buff/cache` | 已用 / 缓存 | 缓存高不算坏事，`available` 才是可用 |
| `Tasks` 的 `zombie` | 僵尸进程数 | 持续增长要看父进程 |

常用交互键：`M` 按内存排序、`P` 按 CPU 排序、`1` 展开多核、`q` 退出。

### 2.2 ps：静态快照

```bash
ps aux                 # 所有进程，看 CPU/MEM 两列
ps aux | grep nginx    # 找特定进程
ps -ef                 # 另一种风格，看 PPID（父进程）
ps -eo pid,ppid,cmd --sort=-%cpu | head   # 按 CPU 排序看前几名
```

`top` 是动态刷新，`ps` 是一瞬间的快照——写脚本、抓现场用 `ps`。

### 2.3 磁盘三件套：df / du / lsblk

```bash
df -h              # 各分区用了多少、还剩多少
df -i              # inode 使用率（满了也会写不进文件）
du -sh ~/lab       # 某个目录总占用
du -h --max-depth=1 /var | sort -h   # 逐层看到底谁大
lsblk              # 有哪些块设备、挂在哪
```

| 命令 | 回答的问题 | 真实例子 → 干什么 |
| --- | --- | --- |
| `df -h` | 分区还剩多少空间 | `df -h /` → 根分区用量 |
| `du -sh` | 这个目录占多大 | `du -sh /var/log` → 日志占了多少 |
| `lsblk` | 系统识别到哪些磁盘 | `lsblk` → 看 sda、nvme0n1 及分区 |

**两个经典坑**：
1. `df` 显示满了但 `du` 加起来对不上 → 有进程删了文件却没释放（`lsof | grep deleted`）。
2. `df -i` 满了但 `df -h` 还有空间 → inode 用尽，常见于大量小文件（缓存目录）。

### 2.4 IO 与网络观察

```bash
iotop -o                 # 哪些进程在读写磁盘（需 sudo）
iftop -i eth0            # 实时看连接流量（需装 + sudo）
nload eth0               # 简单看进出带宽
```

排查「服务器卡但不占 CPU」时，先用 `iotop` 看是不是磁盘，再用 `iftop` 看是不是网络。

### 2.5 挂载：mount 与 umount

```bash
lsblk                                  # 先看设备名
sudo mount /dev/sdb1 /mnt/data         # 挂到 /mnt/data
df -h /mnt/data                        # 确认挂上
sudo umount /mnt/data                  # 卸载（注意是 umount，少个 n）
```

持久化写进 `/etc/fstab`：

```
/dev/sdb1  /mnt/data  ext4  defaults  0  2
```

**坑**：`fstab` 写错会让系统起不来；改完先 `sudo mount -a` 验证，别直接重启。

### 2.6 环境变量

```bash
env                     # 看所有环境变量
echo $PATH              # 看可执行文件搜索路径
export MYVAR=hello      # 当前 shell 及子进程可见
MYVAR=hello             # 只当前 shell 可见（不导出）
unset MYVAR             # 删掉
```

| 变量 | 作用 | 典型值 |
| --- | --- | --- |
| `PATH` | 命令搜索路径，冒号分隔，**靠前的优先** | `/usr/local/bin:/usr/bin:/bin` |
| `HOME` | 家目录 | `/home/chriskim` |
| `SHELL` | 登录 shell | `/bin/bash` |
| `LD_LIBRARY_PATH` | 动态库搜索路径 | 自己编译的库常加这里 |
| `LANG` | 语言与编码 | `en_US.UTF-8` |

**临时 vs 永久**：`export` 只在当前会话有效；要永久生效，写进 `~/.bashrc`（或 `~/.zshrc`）再 `source`。

### 2.7 配置文件与 source

```bash
source ~/.bashrc        # 重新加载，等价于 . ~/.bashrc
```

| 文件 | 谁读它 | 什么时候 |
| --- | --- | --- |
| `~/.bashrc` | bash（交互式非登录） | 每次开新终端 |
| `~/.bash_profile` / `~/.profile` | bash（登录 shell） | 登录时（ssh 登录、图形登录） |
| `~/.zshrc` | zsh | macOS 默认 shell 读这个 |

**坑**：改了 `.bashrc` 不生效，多半是当前 shell 是 zsh（macOS），要改 `~/.zshrc`；或者是在登录 shell 里，得改 `.profile` 或手动 `source`。

### 2.8 拾遗四件套

```bash
watch -n 2 'df -h'          # 每 2 秒刷一次命令输出（Ctrl+C 退出）
echo hello | tee out.txt    # 既打印到屏幕又写文件
diff a.txt b.txt            # 比较两个文件的差异
uname -a                    # 内核与系统架构信息
```

`tee` 在「既要看又要留」时最有用；`watch` 适合盯一个会变化的指标。

### 2.9 会让人以为「终端死了」的按键

| 按键 | 现象 | 解法 |
| --- | --- | --- |
| `Ctrl+S` | 终端像卡住，其实只是暂停输出（XOFF） | 按 `Ctrl+Q` 恢复 |
| `Ctrl+Z` | 命令停了，提示符回来 | `fg` 拉回，或 `bg` 后台继续 |
| `Ctrl+D` | 直接退出 shell / 输入结束 | 想退出编辑器或会话时才用 |
| `Ctrl+L` | 清屏（不是清历史） | 无害 |

## 3. 命令速查表

| 命令 | 作用 | 真实例子 → 干什么 |
| --- | --- | --- |
| `top` | 动态看资源 | `top` → `M` 按内存排序 |
| `ps aux` | 进程快照 | `ps aux \| grep nginx` → 找 nginx 进程 |
| `df -h` | 分区用量 | `df -h /` → 根分区还剩多少 |
| `du -sh` | 目录占用 | `du -sh ~/lab` → 这个目录多大 |
| `lsblk` | 块设备 | `lsblk` → 看有几块盘 |
| `mount` | 挂载 | `sudo mount /dev/sdb1 /mnt` |
| `env` | 环境变量 | `env \| grep PATH` |
| `export` | 设变量 | `export PATH=$PATH:~/bin` |
| `source` | 重载配置 | `source ~/.bashrc` |
| `watch` | 定时刷新 | `watch -n 2 'df -h'` |
| `tee` | 屏幕+文件 | `cmd \| tee log.txt` |

## 4. 动手练

**① 读一次自己的负载**
```bash
nproc          # 几核
uptime         # load average
top            # 按 1 展开多核，按 q 退出
```
判断：load average 长期超过 `nproc` 就跑满了。

**② 找出家目录里谁最大**
```bash
du -h --max-depth=1 ~ | sort -h | tail -5
```

**③ 看分区与 inode**
```bash
df -h; df -i
```

**④ 设一个临时变量并验证作用域**
```bash
export MYLAB=hello
bash -c 'echo $MYLAB'    # hello（子进程能看见）
unset MYLAB
```

**⑤ 写进 .bashrc 并立刻生效**
```bash
echo 'export MYLAB=hello' >> ~/.bashrc
source ~/.bashrc
echo $MYLAB              # hello
```

## 5. 常见报错

**① `df` 显示 100%，但 `du` 加起来没那么多**
有被删除但仍被进程占用的文件。`sudo lsof | grep deleted` 找到进程，重启它释放空间。

**② `No space left on device` 但 `df -h` 还有空间**
inode 用尽。`df -i` 确认，清掉大量小文件（缓存、临时目录）。

**③ 改了 `~/.bashrc` 没生效**
当前 shell 不是 bash，或没 `source`。`echo $SHELL` 确认，macOS 改 `~/.zshrc`。

**④ 终端像死了一样没反应**
可能按到了 `Ctrl+S`。按 `Ctrl+Q`。

## 6. 平台差异

| 项 | Linux | macOS |
| --- | --- | --- |
| 资源监控 | `top` 自带，`htop` 需装 | `top` 参数不同（`top -o cpu`） |
| 磁盘 | `df/du/lsblk` | `df/du` 有，**没有 `lsblk`**（用 `diskutil list`） |
| 挂载 | `mount` + `/etc/fstab` | `mount`，持久化用 `/etc/fstab` 也可，但更推荐「系统设置 / `diskutil`」 |
| shell 配置 | `~/.bashrc` | `~/.zshrc` |
| 环境变量 | 同上 | 同上（`launchctl setenv` 可设 GUI 程序的环境） |

## 7. 自测

<details>
<summary>Q1：`df` 和 `du` 分别回答什么问题？</summary>

`df` 看**分区层面**还剩多少（文件系统视角）；`du` 看**具体目录/文件**占了多少（逐个 inode 累加）。两者对不上时，常见原因是有进程占着已删除的文件。
</details>

<details>
<summary>Q2：load average 多高算高？</summary>

看核数。4 核机器上 load 4 表示刚好跑满，长期 >4 说明有排队；1 核机器上 load 1 就已经满了。
</details>


<details>
<summary>Q3：`export` 和不 `export` 有什么区别？</summary>

`export` 让变量进入环境，子进程（新开的 shell、跑的程序）能读到；不 export 只在当前 shell 里有效。
</details>

<details>
<summary>Q4：`PATH` 里靠前的目录会怎样？</summary>

同名命令优先执行靠前的那个。所以把自己写的脚本放进 `~/bin` 并加到 `PATH` 最前面，就能覆盖系统命令（小心用）。
</details>

<details>
<summary>Q5：按了 `Ctrl+S` 终端不动了，怎么办？</summary>

按 `Ctrl+Q` 恢复。`Ctrl+S` 是终端的流控暂停（XOFF），不是系统卡死。
</details>
