# 04 用户、权限与软件包

## 1. 本篇知识点清单

- **谁是我**：`whoami`、`id`、`groups` 看身份与组
- **root 与 sudo**：为什么要提权、`su` 和 `sudo` 的区别
- **三类人三类权限**：属主 / 属组 / 其他人，读 4 写 2 执行 1
- **数字法**：`chmod 755`、`644` 各是什么
- **符号法**：`chmod u+x`、`chmod o-r` 怎么算
- **改属主与属组**：`chown`、`chgrp`、`-R`
- **装软件**：`apt update / install / remove / purge / search`
- **换源**：为什么国内要换镜像

## 2. 正文·知识块

### 2.1 看身份

```bash
whoami          # chriskim
id              # uid=1000(chriskim) gid=1000(chriskim) groups=1000(chriskim),27(sudo)
groups          # chriskim sudo
```

`id` 一行里有三样东西：uid（用户号）、gid（主组号）、groups（附加组）。**在 `sudo` 组里才能用 sudo 提权**。

### 2.2 root 与 sudo

- `root` 是超级用户（uid 0），能改任何东西，也能删掉系统。
- `su` 是「切换用户」，`su -` 切到 root 并加载 root 的环境；要输 root 密码。
- `sudo` 是「以 root 身份执行这一条命令」，输的是**你自己的密码**，而且有日志。

```bash
sudo apt update          # 只让这条命令有 root 权限
sudo -i                  # 进入 root 的交互 shell（等价 su -）
```

**为什么推荐 sudo**：不用知道 root 密码、每条都有记录、权限只在这条命令内有效。Ubuntu 默认禁用 root 密码登录，全靠 sudo。

### 2.3 权限的九位与三类人

`ls -l` 第一列 `-rwxr-xr--` 拆开看：

```
-  rwx  r-x  r--
│  │    │    └─ 其他人（other）：只读
│  │    └─ 属组（group）：读 + 执行
│  └─ 属主（user）：读 + 写 + 执行
└─ 类型：- 普通文件，d 目录，l 符号链接
```

数值换算：**r=4，w=2，x=1**，三位一组求和。

| 数字 | 权限 | 常见用途 |
| --- | --- | --- |
| 644 | rw-r--r-- | 普通文件（自己的配置、代码） |
| 600 | rw------- | 私钥、`.env` 这类机密 |
| 755 | rwxr-xr-x | 目录、可执行脚本 |
| 700 | rwx------ | 只有自己能进的目录（如 `~/.ssh`） |
| 777 | rwxrwxrwx | 谁都能改，**别用** |

```bash
chmod 755 run.sh        # 脚本加上执行权限
chmod 600 id_rsa        # 私钥只给自己读写
chmod 644 conf.ini      # 配置文件普通权限
```

### 2.4 符号法

```bash
chmod u+x run.sh        # 属主加执行
chmod go-w note.txt     # 属组和其他人去掉写
chmod a+r README.md     # 所有人加读
chmod -R 755 public/    # 递归改整个目录
```

`u`=属主，`g`=属组，`o`=其他人，`a`=全部；`+` 加、`-` 去、`=` 设为。

**坑**：目录的 `x` 位不是「执行」，而是「能不能进去 / 能不能穿过它」。目录没有 `x`，里面文件权限再大也访问不到。

### 2.5 改属主与属组

```bash
sudo chown chriskim note.txt          # 改属主
sudo chown chriskim:develop app/      # 同时改属主和属组
sudo chgrp developers note.txt        # 只改属组
sudo chown -R chriskim:chriskim ~/lab # 递归改
```

**坑**：`chown` 一般需要 root 权限（把自己的文件给别人不需要，把别人的文件给自己就需要）。

### 2.6 apt：软件包管理

```bash
sudo apt update                # 刷新软件清单（不进源，只更新索引）
sudo apt upgrade               # 升级已装软件
sudo apt install nginx         # 安装
sudo apt remove nginx          # 卸载（保留配置）
sudo apt purge nginx           # 卸载并删配置
sudo apt search "http server"  # 搜索
sudo apt show nginx            # 看包信息
sudo apt autoremove            # 清理不再需要的依赖
```

| 概念 | 说明 |
| --- | --- |
| 源（repository） | 软件从哪下载，配置在 `/etc/apt/sources.list` 与 `/etc/apt/sources.list.d/` |
| 索引 | `apt update` 拉的是「有哪些包、什么版本」的清单 |
| 依赖 | 装 A 会连带装 A 需要的包，`autoremove` 用来清残留 |

**国内换源**：改 `sources.list` 指向清华/上交/中科大镜像（模板见[清华镜像站](https://mirrors.tuna.tsinghua.edu.cn/)），改完必须 `sudo apt update`。

**坑**：
1. 忘了 `sudo` → `E: Could not open lock file ... Permission denied`
2. 刚装完系统没 `apt update` → `E: Unable to locate package nginx`
3. 用 `pip install` 装系统工具 → 装到 Python 环境里，命令行找不到

## 3. 命令速查表

| 命令 | 作用 | 真实例子 → 干什么 |
| --- | --- | --- |
| `whoami` / `id` | 看身份 | `id` → 看自己在不在 sudo 组 |
| `su -` | 切到 root | `su -` → 输 root 密码进 root shell |
| `sudo` | 单条提权 | `sudo apt install git` → 用 root 装 git |
| `chmod` | 改权限 | `chmod 755 run.sh` → 变成 rwxr-xr-x |
| `chown` | 改属主 | `sudo chown me:me f.txt` → 属主属组都改成 me |
| `chgrp` | 改属组 | `chgrp dev f.txt` → 属组改 dev |
| `apt update` | 刷新索引 | `sudo apt update` → 拉最新包清单 |
| `apt install` | 装 | `sudo apt install nginx` → 装 nginx |
| `apt remove/purge` | 卸 | `sudo apt purge nginx` → 连配置一起删 |

## 4. 动手练

**① 看自己的身份和组**
```bash
whoami; id; groups
```
预期：能看到 `groups=... sudo`，说明你有提权资格。

**② 造一个脚本，先跑失败再给权限**
```bash
echo 'echo hello' > ~/lab/run.sh
~/lab/run.sh                 # Permission denied
chmod 755 ~/lab/run.sh
~/lab/run.sh                 # hello
```

**③ 观察 644 与 600 的区别**
```bash
touch ~/lab/a.txt && chmod 644 ~/lab/a.txt && ls -l ~/lab/a.txt   # -rw-r--r--
chmod 600 ~/lab/a.txt && ls -l ~/lab/a.txt                        # -rw-------
```

**④ 目录的 x 位**
```bash
mkdir -p ~/lab/secret && echo hi > ~/lab/secret/f
chmod 600 ~/lab/secret        # 去掉目录的 x
ls ~/lab/secret               # Permission denied
chmod 755 ~/lab/secret        # 恢复
```

**⑤ 装一个小工具**
```bash
sudo apt update && sudo apt install -y tree
tree ~/lab
```

## 5. 常见报错

**① `Permission denied`（执行脚本）**
没有 `x` 位。`chmod +x run.sh`。

**② `Permission denied`（进目录）**
目录缺 `x` 位。`chmod 755 目录`。

**③ `E: Could not open lock file /var/lib/dpkg/lock-frontend`**
没加 `sudo`，或者另一个 apt 正在跑。等它结束，别硬删锁文件。

**④ `E: Unable to locate package xxx`**
索引没更新（`sudo apt update`），或包名拼错、源里没有。

## 6. 平台差异

| 项 | Linux（Ubuntu） | macOS |
| --- | --- | --- |
| 包管理 | `apt`（Debian 系） / `dnf`（RHEL 系） | Homebrew：`brew install` |
| 权限模型 | 同 POSIX | 同 POSIX，但用户多在 `staff` 组 |
| root | sudo 提权 | sudo 提权（同） |
| 默认 shell 用户组配置 | `/etc/sudoers` | `/etc/sudoers` |

## 7. 自测

<details>
<summary>Q1：`chmod 755` 具体是什么权限？</summary>

属主 rwx（7）、属组 r-x（5）、其他人 r-x（5）。目录常用它，表示「我能改，别人能进能看不能改」。
</details>

<details>
<summary>Q2：`su` 和 `sudo` 的核心区别？</summary>

`su` 换成另一个用户的身份（要对方密码，root 切换要 root 密码）；`sudo` 只用 root 权限执行**一条**命令（要自己密码，有审计日志）。
</details>

<details>
<summary>Q3：为什么私钥要设成 600？</summary>
 
私钥等同于密码，权限过宽会让别人读到；`ssh` 也会主动拒绝使用权限过松的私钥（`Bad permissions`）。
</details>

<details>
<summary>Q4：`apt update` 和 `apt upgrade` 差在哪？</summary>

`update` 只刷新「有哪些包、什么版本」的索引，不装东西；`upgrade` 才真的升级已安装的软件。
</details>

<details>
<summary>Q5：目录的 `x` 位为什么重要？</summary>

`x` 对目录意味着「可以进入 / 穿过」。没有它，即使里面文件权限全开，你连路径都走不进去。
</details>
