# 05 远程操作与目录结构

## 1. 本篇知识点清单

- **登录服务器**：`ssh 用户@主机 -p 端口`
- **免密登录**：`ssh-keygen` + `ssh-copy-id`
- **传文件**：`scp` 的四个方向与 `-P/-r`
- **更稳的同步**：`rsync`
- **目录结构**：`/bin /etc /home /var /tmp /opt /usr /proc` 各放什么
- **排错**：连不上、权限太松、端口写错

## 2. 正文·知识块

### 2.1 ssh：登录远程机器

```bash
ssh chriskim@192.168.1.10          # 默认 22 端口
ssh -p 2222 chriskim@example.com   # 指定端口（小写 p）
ssh example.com                     # 用户名和本地一致时可省略
```

第一次连接会问 `Are you sure you want to continue connecting?`，输入 `yes`，对方公钥会存进 `~/.ssh/known_hosts`。

### 2.2 免密登录：密钥认证

```bash
ssh-keygen -t ed25519 -C "chriskim@laptop"   # 生成密钥对
ssh-copy-id chriskim@192.168.1.10            # 把公钥装到对方 authorized_keys
ssh chriskim@192.168.1.10                    # 这次不再问密码
```

| 文件 | 作用 |
| --- | --- |
| `~/.ssh/id_ed25519` | 私钥，权限必须 600，绝不外传 |
| `~/.ssh/id_ed25519.pub` | 公钥，可以随便发 |
| `~/.ssh/authorized_keys`（服务器上） | 允许登录的公钥清单 |
| `~/.ssh/config` | 给主机起别名、写死端口和密钥 |

`~/.ssh/config` 示例：

```
Host myserver
    HostName 192.168.1.10
    User chriskim
    Port 2222
    IdentityFile ~/.ssh/id_ed25519
```

之后直接 `ssh myserver` 就行。

### 2.3 scp：传文件

```bash
# 本地 → 远程（上传）
scp local.txt chriskim@host:/home/chriskim/

# 远程 → 本地（下载）
scp chriskim@host:/var/log/app.log ./

# 目录要 -r
scp -r ./site chriskim@host:/var/www/

# 指定端口：注意是大写 P
scp -P 2222 local.txt chriskim@host:/tmp/
```

**坑**：`ssh` 用 `-p`（小写），`scp` 用 `-P`（大写），写反了会被当成别的参数。

### 2.4 rsync：断点续传与增量同步

```bash
rsync -avz ./site/ chriskim@host:/var/www/site/     # 本地同步到远程
rsync -avz chriskim@host:/data/logs/ ./logs/        # 远程同步到本地
rsync -avz --delete ./site/ host:/var/www/site/     # 删掉目标端多余文件（危险）
```

比 `scp` 好用的地方：只传变化的文件、断了能续、可以排除目录（`--exclude`）。日常备份首选。

**坑**：源路径结尾有没有 `/` 意思不同——`site/` 表示「把 site 里的内容同步过去」，`site` 表示「把 site 这个目录同步过去」。

### 2.5 Linux 目录结构（FHS 简版）

| 目录 | 放什么 | 常见例子 |
| --- | --- | --- |
| `/` | 根，一切从这里长出来 | — |
| `/bin`、`/usr/bin` | 普通用户能用的命令 | `ls`、`cp`、`grep` |
| `/sbin`、`/usr/sbin` | 管理类命令（多需 root） | `fdisk`、`iptables` |
| `/etc` | 系统与软件的配置文件 | `nginx/`、`passwd`、`fstab` |
| `/home/用户名` | 用户的家目录 | 你的代码、下载 |
| `/root` | root 的家目录 | 只有 root 能进 |
| `/var` | 会变大的数据：日志、数据库、缓存 | `/var/log`、`/var/lib/mysql` |
| `/tmp` | 临时文件，重启可能清空 | 脚本中间产物 |
| `/opt` | 第三方商业/大型软件 | `/opt/google` |
| `/usr/local` | 自己编译安装的软件 | 源码装的东西 |
| `/dev` | 设备文件 | `/dev/sda`、`/dev/null` |
| `/proc`、`/sys` | 内核与进程的虚拟文件系统 | `/proc/cpuinfo` |
| `/srv` | 对外提供的服务数据（约定） | 网站数据 |

**为什么 `/var` 会撑爆磁盘**：日志都往里写，不清理就会满；第 08 篇 `df` / `du` 就是查这个的。

## 3. 命令速查表

| 命令 | 作用 | 真实例子 → 干什么 |
| --- | --- | --- |
| `ssh` | 远程登录 | `ssh -p 2222 me@host` → 用 2222 端口登录 |
| `ssh-keygen` | 生成密钥 | `ssh-keygen -t ed25519` → 生成密钥对 |
| `ssh-copy-id` | 装公钥 | `ssh-copy-id me@host` → 从此免密 |
| `scp` | 传文件 | `scp a.txt me@host:/tmp/` → 上传 |
| `scp -r` | 传目录 | `scp -r site host:/var/www/` |
| `rsync -avz` | 增量同步 | `rsync -avz ./site/ host:/var/www/site/` |
| `ls /var/log` | 看日志目录 | 确认日志长在哪 |

## 4. 动手练

**① 看自己的密钥有没有**
```bash
ls -l ~/.ssh/
```
预期：有 `id_ed25519`（600）和 `id_ed25519.pub`（644）。没有就 `ssh-keygen -t ed25519`。

**② 给本机起个别名**
```bash
cat >> ~/.ssh/config <<'EOF'
Host localtest
    HostName 127.0.0.1
    User $(whoami)
EOF
ssh localtest "echo ok"     # 需要本机开了远程登录
```
macOS 要在「系统设置 → 通用 → 共享 → 远程登录」打开。

**③ 用 scp 复制到本机另一个目录**
```bash
scp ~/lab/num.txt /tmp/     # 本地复制也用它，验证路径写法
ls -l /tmp/num.txt
```

**④ 认目录结构**
```bash
ls /etc | head -20
ls /var/log | head -20
cat /proc/cpuinfo | grep "model name" | head -1
```

**⑤ 观察日志会变大**
```bash
du -sh /var/log        # 第 08 篇细讲 du
```

## 5. 常见报错

**① `Permission denied (publickey)`**
公钥没装上，或私钥权限过松。`chmod 600 ~/.ssh/id_ed25519`，再 `ssh -v` 看用了哪把钥匙。

**② `Connection refused`**
对方 sshd 没开，或端口不对。`ssh -p 端口`，服务端 `sudo systemctl status ssh` 查。

**③ `scp: -P 2222: command not found` 之类**
`scp` 的端口是大写 `-P`；小写 `-p` 在 `scp` 里表示「保留时间戳」。

**④ `rsync` 后目标多了一层目录**
源路径结尾没加 `/`。要同步内容就写 `./site/`。

## 6. 平台差异

| 项 | Linux | macOS |
| --- | --- | --- |
| ssh 客户端 | 自带 | 自带 |
| ssh 服务端 | `sudo apt install openssh-server` | 系统设置里开「远程登录」 |
| 配置目录 | `~/.ssh` | `~/.ssh`（同） |
| 目录结构 | FHS | 不是 FHS：没有 `/etc/nginx` 这类，软件在 `/opt/homebrew` |

## 7. 自测

<details>
<summary>Q1：`ssh` 的 `-p` 和 `scp` 的 `-P` 为什么不一样？</summary>

历史遗留：`ssh` 用 `-p` 指定端口，`scp` 的 `-p` 已被占用（表示保留时间戳），所以端口改用大写 `-P`。
</details>

<details>
<summary>Q2：`authorized_keys` 在服务器上还是客户端？</summary>

服务器上（`~/.ssh/authorized_keys`），里面放的是「允许登录的公钥」；私钥永远只留在客户端。
</details>

<details>
<summary>Q3：日志一般写在哪个目录？为什么容易撑满磁盘？</summary>

`/var/log`。服务运行越久日志越大，加上轮转配置不合理，就会把 `/var` 所在分区写满。
</details>

<details>
<summary>Q4：`rsync ./site` 和 `rsync ./site/` 有什么区别？</summary>

`./site/` 同步的是目录里的内容（目标端直接得到文件），`./site` 同步的是目录本身（目标端多一层 `site`）。
</details>

<details>
<summary>Q5：`/bin` 和 `/usr/local/bin` 有什么区别？</summary>

`/bin`、`/usr/bin` 放包管理器装的系统命令；`/usr/local/bin` 放自己编译或手工安装的命令，通常优先级更靠前。
</details>
