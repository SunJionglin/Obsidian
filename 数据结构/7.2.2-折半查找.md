# 7.2.2 折半查找

## 1. 本节定位

- **对应王道书**：第 7 章「查找」→ 7.2 顺序查找与折半查找 → 7.2.2 折半查找（Binary Search / 二分查找）。
- **408 大纲对应**：查找基本概念 → 顺序查找、折半查找（含查找判定树、平均查找长度 ASL 分析）。
- **先修知识**：顺序表（数组）的随机存取特性、二叉树基本性质（$n$ 个结点的二叉树有 $n+1$ 个空链域）、完全二叉树树高公式、二叉排序树定义。
- **本章位置**：折半查找是「有序静态查找表」的最优查找方法，是后续 B 树/B+ 树「多路折半」思想的源头，也是「查找判定树」这一分析工具的第一个完整范例。

## 2. 一句话结论

折半查找只适用于**有序顺序表**，每轮用 `mid = ⌊(low+high)/2⌋` 把查找区间一分为二，时间复杂度 $O(\log_2 n)$；其判定树必为**平衡二叉排序树**，且任一结点**右子树结点数 = 左子树结点数 或 比左子树多 1**（向下取整时）。

## 3. 知识地图

```
折半查找
├── 适用条件
│   ├── 有序（关键字递增或递减）
│   └── 顺序表（数组，可随机存取 → 能 O(1) 取 mid）
├── 算法思想
│   ├── low、high 圈定当前查找区间
│   ├── mid = ⌊(low+high)/2⌋，与目标 key 比较
│   ├── key == a[mid] → 成功，返回 mid
│   ├── key < a[mid]  → high = mid-1（去左半区）
│   └── key > a[mid]  → low  = mid+1（去右半区）
├── 终止条件
│   ├── 找到 → 成功
│   └── low > high → 失败，返回 -1
├── 查找判定树
│   ├── 构造：以 mid 为根，递归左右子区间
│   ├── 性质1：平衡二叉树（左右子树深度差 ≤ 1）
│   ├── 性质2：只有最下一层不满（类完全二叉树）
│   ├── 性质3：是二叉排序树（左<根<右）
│   ├── 性质4：向下取整时 右子树结点数 − 左子树结点数 ∈ {0, 1}
│   ├── 性质5：成功结点 n 个 → 失败结点 n+1 个（空链域）
│   └── 树高 h = ⌈log₂(n+1)⌉（与完全二叉树同）
├── 效率分析
│   ├── 成功 ASL：按层数加权平均
│   ├── 失败 ASL：按失败结点所在层加权平均
│   └── 时间复杂度 O(log₂ n)
└── 取整方式的影响
    ├── 向下取整 ⌊ ⌋：右子树 ≥ 左子树（多 0 或 1）
    └── 向上取整 ⌈ ⌉：左子树 ≥ 右子树（多 0 或 1）
```

## 4. 核心内容

### 4.1 适用条件（408 必考判断）

1. **必须有序**：表中关键字递增或递减排列。
2. **必须是顺序表**：只有数组能按下标 $O(1)$ 定位中间元素；链表找中点要从头遍历，不具备随机存取特性，**折半查找不能基于链表实现**。

> 位序与下标：本节例子中 `0,1,2,…` 是**数组下标**，从 0 开始；若题目说「第 $i$ 个元素」是位序，从 1 开始，写代码时注意换算。

### 4.2 算法执行过程（以升序表、查 33 为例）

设表 `a[0..10] = {7,10,13,16,19,29,32,33,37,41,43}`。

| 轮次 | low | high | mid=⌊(low+high)/2⌋ | a[mid] | 比较结果 | 动作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 10 | 5 | 29 | 33 > 29 | low = 6 |
| 2 | 6 | 10 | 8 | 37 | 33 < 37 | high = 7 |
| 3 | 6 | 7 | 6 | 32 | 33 > 32 | low = 7 |
| 4 | 7 | 7 | 7 | 33 | 相等 | 成功，返回 7 |

**失败例（查 12）**：mid 依次为 5(29)→2(13)→0(7)→1(10)，比较后 `low = mid+1 = 2 > high = 1`，循环条件 `low ≤ high` 不成立，返回 -1。

**关键观察**：每轮 mid 把「可能含目标的区间」一分为二，故称二分/折半；区间长度按 $\lfloor n/2 \rfloor$ 递减，这是 $O(\log n)$ 的来源。

### 4.3 代码（升序表，C 语言，王道风格）

```c
// 前提：顺序表 a[0..n-1] 中关键字严格递增
int Binary_Search(int a[], int n, int key) {
    int low = 0, high = n - 1;          // 初始查找区间为整个表
    while (low <= high) {               // 区间非空才继续
        int mid = (low + high) / 2;     // 向下取整；等价于 low + (high-low)/2 防溢出
        if (a[mid] == key)
            return mid;                 // 查找成功，返回数组下标
        else if (a[mid] > key)
            high = mid - 1;             // key 只可能在左半区
        else
            low = mid + 1;              // key 只可能在右半区
    }
    return -1;                          // low > high，查找失败
}
```

**降序表的改法（408 常考变式）**：只需把两个分支的判断方向对调——`a[mid] > key` 时去右半区（`low = mid+1`），`a[mid] < key` 时去左半区（`high = mid-1`）。原理不变：**根据 key 与 a[mid] 的大小关系，丢弃不可能的一半**。

### 4.4 查找判定树（本节最重要考点）

**构造方法**：以当前区间的 mid 为根结点，左子区间递归构造左子树，右子区间递归构造右子树；失败结点（外部结点）挂在每个成功结点的空链域上。

**例：11 个元素（下标 0~10）的判定树**

```
                5(29)
              /       \
          2(13)        8(37)
         /    \       /    \
      0(7)  3(16)  6(32)  9(41)
        \   /  \     \    /   \
       1(10)4(19)7(33) 10(43)
```

（图中编号为数组下标，括号内为关键字；第 4 层结点为 1、4、7、10。）

**判定树的五条性质（408 必考）**：

1. **是平衡二叉树**：任一结点左右子树深度差不超过 1。
2. **只有最下一层不满**，形态与完全二叉树一致。
3. **是二叉排序树**：左子树关键字 < 根 < 右子树关键字。
4. **结点数关系（向下取整时）**：对任一结点，`右子树结点数 − 左子树结点数 ∈ {0, 1}`，即右子树结点数 ≥ 左子树结点数，且最多多 1。**绝不可能左子树更多**。
   - 原因：区间有奇数个元素时 mid 正居中，左右等长；有偶数个元素时 $\lfloor (low+high)/2 \rfloor$ 偏左，刨去 mid 后左半区比右半区少 1 个。
5. **失败结点数 = 成功结点数 + 1**：失败结点即 $n$ 个结点的二叉树的空链域数 $n+1$。

**由性质 4 快速画树**：给定 $n$，按「右子树结点数 = 左子树结点数 或 多 1」递归分配即可唯一确定形态。例如 $n=3$ 时根只能是「左 1 右 1」或「左 0 右 2」中的合法者——由于右最多比左多 1，根左 0 右 2 不合法，故 3 个结点的判定树根必为中间元素，左右各 1。

**由大树删结点得小树**：$n=16$ 的判定树删去编号 16、15 两个结点，即得 $n=14$ 的判定树（编号只是位置标号，不是关键字值）。

### 4.5 向上取整的变式（了解即可，但选择题会挖坑）

若 `mid = ⌈(low+high)/2⌉`，则偶数个元素时 mid 偏右，刨去后**左半区比右半区多 1 个**，判定树性质 4 反转为：`左子树结点数 − 右子树结点数 ∈ {0, 1}`。画出的树形态与向下取整时**左右镜像**。做题先看清题目规定的取整方式。

## 5. 复杂度分析

设表长 $n$，各元素查找概率相等（$1/n$），各失败区间概率相等（$1/(n+1)$）。

**树高**：判定树与完全二叉树同形，$h = \lceil \log_2(n+1) \rceil$（补充：完全二叉树高度公式，等价于 $\lfloor \log_2 n \rfloor + 1$）。

**成功 ASL**：设第 $i$ 层有 $n_i$ 个成功结点，查找该层元素需比较 $i$ 次，则

$$ASL_{成功} = \frac{1}{n}\sum_{i=1}^{h} i \cdot n_i$$

以 11 元素为例：第 1 层 1 个、第 2 层 2 个、第 3 层 4 个、第 4 层 4 个，

$$ASL_{成功} = \frac{1\times1 + 2\times2 + 3\times4 + 4\times4}{11} = \frac{35}{11} \approx 3.18$$

**失败 ASL**：失败结点共 $n+1$ 个，落在第 $i$ 层的失败结点需比较 $i-1$ 次（走到该外部结点前经过的内部结点数），

$$ASL_{失败} = \frac{1}{n+1}\sum_{i} (i-1)\cdot m_i$$

11 元素例：第 3 层 4 个失败结点（比较 3 次）、第 4 层 8 个（比较 4 次），

$$ASL_{失败} = \frac{3\times4 + 4\times8}{12} = \frac{44}{12} \approx 3.67$$

**三种情况**：

- **最好**：$O(1)$，第一次 mid 即命中（如查 29）。
- **最坏**：$O(\log_2 n)$，走到判定树最深层。
- **平均**：比较次数不超过树高 $h = \lceil \log_2(n+1)\rceil$，故 $O(\log_2 n)$。推导核心：每轮区间长度至多减半，最多 $\lceil \log_2(n+1)\rceil$ 轮后区间为空。

**空间复杂度**：$O(1)$（迭代版，仅 low/high/mid 三个变量）。

## 6. 易错点与考试写法

1. **「折半查找一定比顺序查找快」是错的**。若目标恰在表头（如查 7），顺序查找 1 次即中，折半查找要 4 次。正确表述：**平均性能**折半更优，最坏情况折半更优，但个别元素顺序查找更快。
2. **链表不能折半**：不是「效率低」，而是**根本不能实现**（无随机存取，取 mid 需 $O(n)$）。
3. **判定树结点数关系方向记反**：向下取整 → **右 ≥ 左**（多 0 或 1）；向上取整 → 左 ≥ 右。选择题常给一棵「左子树明显多于右子树」的树让你判断是否合法。
4. **失败结点数**：是 $n+1$，不是 $n$；失败结点是外部结点，不算在树高 $h$ 的层数里（树高只数内部结点层数）。
5. **mid 计算溢出**：`(low+high)/2` 在 low、high 接近 `INT_MAX` 时溢出，工程写法 `low + (high-low)/2`；408 代码题写前者即可，但知道后者是加分项。
6. **答题深度**：算法题要求写出完整可运行代码 + 循环不变式说明（「每轮开始时，若 key 存在则必在 `a[low..high]` 内」）+ 复杂度；判定树题要求**画出完整树并标出失败结点**，再按层统计 $n_i$ 代入 ASL 公式，只写结果不给分层统计会扣分。

## 7. 408 题型与解题套路

**选择题高频考法**：

- 给 $n$，问判定树高度 / 最多比较次数 → 直接套 $h=\lceil\log_2(n+1)\rceil$。
- 给一棵树，判断是否为合法折半判定树 → 查三条：是否二叉排序树、是否平衡、每个结点是否满足「右−左 ∈ {0,1}」（或按题目取整方式反向）。
- 给 $n$ 个元素的有序表，问某关键字需比较几次 → 现场模拟 low/high/mid，注意**比较次数 = 经过的内部结点数**。
- 问「折半查找与顺序查找比较」的正误判断 → 抓「平均 vs 个别」。
- 给 ASL 值反推 $n$ 或反推取整方式。

**算法题套路**：

- 直接考折半代码：默写 4.3 节代码，注意边界 `low <= high`、`mid±1`。
- 变形考法：在**有序**数组中找第一个 ≥ key 的位置（二分下界）、找插入位置、统计某值出现次数 → 都是折半框架改判定条件，核心不变：**每次丢弃一半**。
- 若题目给的是链表或无序表，先判断能否用折半，不能则说明理由并改用顺序查找。

**常见陷阱**：题目表是**降序**却套用升序代码；把位序当数组下标；把失败结点算进树高层数。

## 8. 自测题

**1.** 对含 100 个元素的有序顺序表做折半查找，查找失败时最多需要比较多少次？

**2.** 某折半查找判定树（mid 向下取整）中，结点 A 的左子树有 5 个结点，则 A 的右子树结点数可能是多少？

**3.** 含 $n$ 个成功结点的折半判定树，失败结点有多少个？依据是什么？

**4.** 判断：对有序单链表也可以采用折半查找，只是效率低于顺序表。（说明理由）

**5.** 有序表 `{7,10,13,16,19,29,32,33,37,41,43}`，查找关键字 12 时，依次与哪些元素比较？共比较几次？

<details>
<summary>答案</summary>

1. $h=\lceil\log_2(100+1)\rceil=\lceil 6.66\rceil=7$ 次。失败时走到最深的外部结点，比较次数等于树高。
2. 只能是 5 或 6（右 − 左 ∈ {0,1}，且右不少于左）。
3. $n+1$ 个。失败结点挂在成功结点的空链域上，$n$ 个结点的二叉树共有 $n+1$ 个空链域。
4. 错误。链表不具备随机存取特性，定位中间元素需从头遍历 $O(n)$，折半查找无法在链表上实现（不是「效率低」而是「不可行」）。
5. 依次比较 29（mid=5）→13（mid=2）→7（mid=0）→10（mid=1），共 4 次，随后 low=2 > high=1，查找失败。

</details>

## 9. 背诵卡

1. 折半查找 = 有序 + 顺序表；链表不行（无随机存取）。
2. `mid = ⌊(low+high)/2⌋`；`a[mid]==key` 返回，`>` 则 `high=mid-1`，`<` 则 `low=mid+1`；`low>high` 失败。
3. 判定树：平衡二叉排序树，只有最下层不满，树高 $h=\lceil\log_2(n+1)\rceil$。
4. 向下取整：任一结点 **右子树结点数 − 左子树结点数 ∈ {0,1}**；向上取整则左右互换。
5. 成功结点 $n$ 个 → 失败结点 $n+1$ 个；成功 ASL 按层加权 $\frac{1}{n}\sum i\cdot n_i$，失败 ASL 按外部结点层加权；时间 $O(\log_2 n)$，空间 $O(1)$。
