# 5.3.2_1 线索二叉树的概念

## 1. 本节定位

- **王道书对应**：第 5 章「树与二叉树」→ 5.3 二叉树的遍历与线索二叉树 → 5.3.2 线索二叉树（概念部分）。
- **408 大纲对应**：二叉树的遍历、线索二叉树（线索链表、线索化、前驱/后继查找）——属于「408 必考」。
- **先修知识**：二叉树的链式存储（二叉链表）、先序/中序/后序遍历的递归过程、$n$ 个结点的二叉树有 $n+1$ 个空链域的结论。
- **本节位置**：紧接三种遍历之后，是「遍历」的延伸——把遍历序列中的前驱/后继关系“固化”到空指针里；后续小节讲线索二叉树的构造、找前驱/后继的具体算法与遍历。

---

## 2. 一句话结论

线索二叉树把二叉链表中的 $n+1$ 个空链域改造成指向前驱/后继的**线索**，用 `ltag`/`rtag` 区分“孩子指针”与“线索”，从而能从一个结点直接找到它在某种遍历序列中的前驱或后继，不必每次从根出发重新遍历。

## 4. 核心内容

### 1. 为什么需要线索二叉树（动机）

以中序遍历为例，遍历序列把非线性的树“拉直”成线性序列，每个结点在序列中有唯一前驱、唯一后继（首结点无前驱，末结点无后继）。

> **概念辨析（易混）**：树形逻辑结构里说的“前驱/后继”是**双亲/孩子**意义下的；本节说的前驱/后继是**基于遍历序列**定义的。两者不是一回事，选择题常在此设陷阱。

普通二叉链表（只有 `lchild`、`rchild`）的三个不便：

1. **遍历必须从根出发**：只给某个结点 $g$ 的指针，无法从 $g$ 往后走完中序序列，因为结点只有指向孩子的指针，不能回找双亲或直接找后继。
2. **找中序前驱困难**：只给结点 $f$ 的指针，找不到它的中序前驱 $a$。可行办法是从根做一次完整中序遍历，用两个指针 `q`（当前访问结点）与 `pre`（`q` 的前驱）同步后移，当 `pre` 追上目标结点时，`q` 即为其后继（找前驱则看 `pre` 追上目标时 `pre` 的前一个位置）。
3. **找中序后继同样困难**：原理同上，`pre` 追上目标结点后，`q` 所指即后继。

结论：若应用中“找前驱/后继/从任意结点遍历”很频繁，普通二叉链表效率低，于是引入线索。

### 2. 线索化的做法（手工画图步骤，408 必考）

以中序线索二叉树为例：

1. 先写出该树的**中序遍历序列**，给每个结点标上访问序号（如 $d,g,b,e,a,f,c$ 对应 1~6）。
2. 对每个结点：若左指针为空，令其指向序列中的**前驱**（首结点指向 `NULL`）；若右指针为空，令其指向序列中的**后继**（末结点指向 `NULL`）。
3. 被改造的指针即为**线索**：左空指针改造的叫**前驱线索**，右空指针改造的叫**后继线索**。

先序、后序线索二叉树做法完全相同，只是第 1 步换成先序/后序序列。**审题时必须看清是哪种线索二叉树**。

### 3. 存储结构（王道风格 C 代码）

```c
typedef struct ThreadNode {
    ElemType data;                 // 数据域
    struct ThreadNode *lchild, *rchild; // 左、右指针
    int ltag, rtag;                // 左、右线索标志
} ThreadNode, *ThreadTree;
```

标志位含义（必须记死）：

| 标志 | 值 | 含义 |
|---|---|---|
| `ltag` | 0 | `lchild` 指向**左孩子** |
| `ltag` | 1 | `lchild` 指向**前驱线索** |
| `rtag` | 0 | `rchild` 指向**右孩子** |
| `rtag` | 1 | `rchild` 指向**后继线索** |

- 普通二叉链表称“二叉链表”，改造后的结构称“**线索链表**”。
- 画图约定：实线=孩子指针，虚线=线索（前驱线索、后继线索用不同颜色区分）。

### 4. 三种线索二叉树对照

| 类型 | 前驱/后继依据 | 首结点 | 末结点 |
|---|---|---|---|
| 中序线索二叉树 | 中序遍历序列 | 最左下结点，前驱线索为 `NULL` | 最右下结点，后继线索为 `NULL` |
| 先序线索二叉树 | 先序遍历序列 | 根结点，前驱线索为 `NULL` | 按先序最后访问者，后继线索为 `NULL` |
| 后序线索二叉树 | 后序遍历序列 | 按后序最先访问者，前驱线索为 `NULL` | 根结点，后继线索为 `NULL` |

> 表中“首/末结点”的具体身份由遍历规则决定，画图时以实际序列为准，不要死背。

### 5. 线索化的收益

- 找**后继线索**指向的结点：$O(1)$ 直接取 `rchild`。
- 若一个结点有后继线索，则“从该结点出发沿后继线索往后遍历”可行——遍历本质就是不断找后继。
- 注意：若某结点的右指针指向的是**右孩子**（`rtag=0`），找它的后继不能直接取指针，需按遍历规则继续走（具体算法在后续小节，本节只要求理解“线索使找前驱/后继更方便”这一作用）。

## 5. 复杂度分析

本节是概念课，核心操作是“手工线索化”与“利用线索找前驱/后继”，复杂度按操作分析：

- **手工线索化一棵 $n$ 个结点的二叉树**：需先求遍历序列 $O(n)$，再对每个结点填线索 $O(n)$，合计 $O(n)$；空间 $O(n)$（存序列或递归栈）。
- **利用线索找前驱/后继（当对应标志位为 1 时）**：直接读指针，最好=最坏=平均 $O(1)$，无概率假设。
- **普通二叉链表找中序前驱/后继**：必须从根做一次完整中序遍历，最好/最坏/平均均为 $O(n)$（与树形无关，都要访问全部结点）。
- **对比结论**：线索化是一次性 $O(n)$ 的预处理，换取此后每次找前驱/后继从 $O(n)$ 降为 $O(1)$——典型的“空间换时间”。

## 6. 易错点与考试写法

1. **前驱/后继的定义域**：必须说“在××遍历序列中的前驱/后继”，不能与树结构中的双亲/孩子混淆。
2. **`ltag`/`rtag` 的 0/1 含义记反**：0=孩子，1=线索。选择题常给反例图让判断。
3. **线索只改造空链域**：非空的孩子指针**不能**被改成线索；$n$ 个结点恰好 $n+1$ 个空链域，所以线索总数最多 $n+1$（首结点前驱、末结点后继可为 `NULL`）。
4. **三种线索二叉树不可混用**：题目说“中序线索二叉树”，前驱/后继就按中序序列定；先序/后序同理。审题错一步全错。
5. **答题写到什么程度算对**：能写出含 `ltag`/`rtag` 的结构体定义、说明 0/1 含义、按指定遍历序列正确画出全部线索（含首末结点的 `NULL`），即算掌握；具体找前驱/后继的算法代码属后续小节要求。

## 7. 408 题型与解题套路

- **选择题（高频）**：
  - 给一棵二叉树，问“其中序线索二叉树中某结点的右指针指向谁”——先写遍历序列，再定位该结点的后继。
  - 判断“某结点的 `ltag`/`rtag` 值”——看它的左/右孩子是否存在。
  - 概念辨析：“树中前驱” vs “遍历序列前驱”。
- **画图题套路**：① 按题目指定遍历写出序列并编号；② 逐个结点检查空指针；③ 左空指前驱、右空指后继；④ 首结点前驱、末结点后继画 `NULL`；⑤ 用虚线标注线索。
- **常见陷阱**：把“有右孩子”的结点的右指针误画成后继线索；把先序线索当成中序线索画；漏画首/末结点的 `NULL` 线索。

## 8. 自测题

**1.** 含 $n$ 个结点的二叉链表中共有多少个空链域？线索二叉树最多能设置多少条线索？

**2.** 某结点 `ltag=1`，说明它的 `lchild` 指向什么？若 `rtag=0` 呢？

**3.** 一棵二叉树先序序列为 $a,b,d,g,e,c,f$，则其先序线索二叉树中结点 $d$ 的前驱线索指向谁？$g$ 的后继线索指向谁？

**4.** 为什么普通二叉链表中给定某结点指针找其中序前驱必须 $O(n)$，而线索二叉树中可以 $O(1)$？

**5.** 判断：中序线索二叉树中，任意结点的右指针都指向它的中序后继。

<details>
<summary>答案</summary>

1. $n+1$ 个空链域；最多 $n+1$ 条线索（每个空链域改造成一条，首结点前驱与末结点后继可为 `NULL`）。
2. `ltag=1` 表示 `lchild` 是**前驱线索**，指向该结点在对应遍历序列中的前驱；`rtag=0` 表示 `rchild` 指向**右孩子**，不是线索。
3. 先序序列 $a,b,d,g,e,c,f$：$d$ 的前驱是 $b$，故 $d$ 的前驱线索指向 $b$；$g$ 的后继是 $e$，故 $g$ 的后继线索指向 $e$。
4. 普通二叉链表只有指向孩子的指针，无法回找，只能从根重新做一次完整中序遍历，最坏/平均 $O(n)$；线索二叉树把前驱/后继预先存入空链域，标志位为 1 时直接读指针，$O(1)$。
5. 错。只有 `rtag=1` 时右指针才是后继线索；`rtag=0` 时右指针指向右孩子，需按遍历规则继续找后继。

</details>

## 9. 背诵卡

1. $n$ 个结点的二叉链表有 $n+1$ 个空链域，全部可改造为线索。
2. `ltag=0` 指左孩子，`ltag=1` 指前驱；`rtag=0` 指右孩子，`rtag=1` 指后继。
3. 线索二叉树分中序、先序、后序三种，区别只在“按哪种遍历序列定前驱/后继”。
4. 线索化 = 先写遍历序列编号 → 左空指前驱、右空指后继 → 首结点前驱、末结点后继为 `NULL`。
5. 线索化的意义：找前驱/后继由 $O(n)$ 降为 $O(1)$，并支持从任意结点出发沿线索遍历。
