# 3.2.3 队列的链式实现

## 1. 本节定位

- **王道书对应**：第 3 章 栈、队列和数组，3.2 队列，3.2.3 队列的链式存储结构（链队列）。
- **408 大纲对应**：队列的基本概念与基本操作（链式存储结构及其实现）。
- **先修知识**：单链表（带头结点/不带头结点的插入删除）、队列的先进先出（FIFO）特性、`malloc`/`free` 的使用。
- **位置**：上一节 3.2.2 是循环队列（顺序存储），本节是队列的链式存储实现；后续 3.2.4 是双端队列。本节是"队列两种存储实现"的收尾，与单链表高度同构，是算法题中"用链表实现队列"的直接模板。

## 2. 一句话结论

链队列 = 单链表 + 只能队尾插入、队头删除；用 `front`、`rear` 两个指针分别标记队头与队尾，入队 $O(1)$、出队 $O(1)$，且**不存在队满问题**（除非内存耗尽）。

## 3. 知识地图

```
链队列
├── 存储结构
│   ├── 结点：data + next
│   └── 队列：front 指针 + rear 指针
├── 两种版本
│   ├── 带头结点：front、rear 初始都指向头结点
│   └── 不带头结点：front、rear 初始都为 NULL
├── 基本操作
│   ├── 初始化 InitQueue
│   ├── 判空 QueueEmpty
│   ├── 入队 EnQueue（队尾插入）
│   └── 出队 DeQueue（队头删除）
└── 特性
    ├── 无队满（动态扩容，内存够就能入队）
    └── 求队长默认 O(n)，可加 length 变量优化为 O(1)
```

## 4. 核心内容

### 1. 结构体定义

```c
typedef struct LinkNode {      // 链队列中的结点
    ElemType data;             // 数据域
    struct LinkNode *next;     // 指针域
} LinkNode;

typedef struct {               // 链队列
    LinkNode *front;           // 队头指针
    LinkNode *rear;            // 队尾指针
} LinkQueue;
```

**为什么要专门设 `rear` 指针？** 若只保存头指针，队尾插入需从头遍历找尾结点，$O(n)$；队列每次都在队尾插入，故用 `rear` 直接指向尾结点，入队降为 $O(1)$。

### 2. 初始化

**带头结点版本**（王道书主推，操作统一）：

```c
void InitQueue(LinkQueue &Q) {
    Q.front = Q.rear = (LinkNode *)malloc(sizeof(LinkNode)); // 申请头结点
    Q.front->next = NULL;                                    // 头结点 next 置空
}
```

判空：`Q.front == Q.rear`（也可写 `Q.front->next == NULL`）。

**不带头结点版本**：

```c
void InitQueue(LinkQueue &Q) {
    Q.front = Q.rear = NULL;   // 两个指针都置空
}
```

判空：`Q.front == NULL`（或 `Q.rear == NULL`）。

### 3. 入队（队尾插入）

**带头结点**（所有元素处理逻辑统一）：

```c
bool EnQueue(LinkQueue &Q, ElemType x) {
    LinkNode *s = (LinkNode *)malloc(sizeof(LinkNode)); // 新结点
    s->data = x;
    s->next = NULL;              // 新结点将成为新的尾结点
    Q.rear->next = s;            // 挂到当前尾结点之后
    Q.rear = s;                  // rear 后移，指向新尾结点
    return true;
}
```

**不带头结点**（第一个元素入队需特判）：

```c
bool EnQueue(LinkQueue &Q, ElemType x) {
    LinkNode *s = (LinkNode *)malloc(sizeof(LinkNode));
    s->data = x;
    s->next = NULL;
    if (Q.front == NULL) {       // 空队列：第一个元素入队
        Q.front = s;             // front、rear 同时指向它
        Q.rear = s;
    } else {                     // 非空：常规尾插
        Q.rear->next = s;
        Q.rear = s;
    }
    return true;
}
```

### 4. 出队（队头删除）

**带头结点**：

```c
bool DeQueue(LinkQueue &Q, ElemType &x) {
    if (Q.front == Q.rear) return false;      // 队空
    LinkNode *p = Q.front->next;              // p 指向队头数据结点
    x = p->data;                              // 保存出队元素
    Q.front->next = p->next;                  // 头结点跳过 p
    if (Q.rear == p)                          // 关键：p 是最后一个结点
        Q.rear = Q.front;                     // 恢复空队状态
    free(p);
    return true;
}
```

**不带头结点**：

```c
bool DeQueue(LinkQueue &Q, ElemType &x) {
    if (Q.front == NULL) return false;        // 队空
    LinkNode *p = Q.front;                    // p 指向队头结点
    x = p->data;
    Q.front = p->next;                        // front 后移
    if (Q.rear == p)                          // 最后一个结点出队
        Q.rear = NULL;                        // 恢复空队状态
    free(p);
    return true;
}
```

### 5. 图解（带头结点，元素 a→b 依次入队后出队 a）

```
初始化：  front→[头]←rear
入队 a：  front→[头]→[a]←rear
入队 b：  front→[头]→[a]→[b]←rear
出队 a：  front→[头]→[b]←rear   （p=[a]，free 后 front->next 指向 b）
出队 b：  front→[头]←rear        （p=[b] 是尾结点，rear 回退到 front，队空）
```

### 6. 求队长（王道书扩展）

默认只能从队头遍历计数，$O(n)$。若频繁访问队长，可在 `LinkQueue` 中加 `int length`，入队 `++`、出队 `--`，降为 $O(1)$。这是"因地制宜改造数据结构"的典型例子。

## 5. 复杂度分析

设队列当前元素个数为 $n$。

| 操作 | 最好 | 最坏 | 平均 |
|---|---|---|---|
| 入队 EnQueue | $O(1)$ | $O(1)$ | $O(1)$ |
| 出队 DeQueue | $O(1)$ | $O(1)$ | $O(1)$ |
| 判空 | $O(1)$ | $O(1)$ | $O(1)$ |
| 求队长（无 length） | $O(1)$（空队） | $O(n)$ | $O(n)$ |
| 求队长（有 length） | $O(1)$ | $O(1)$ | $O(1)$ |

**推导**：
- 入队：`malloc` 一次 + 常数次指针赋值，与 $n$ 无关，故 $O(1)$。不带头结点版本多一次 `if` 判断，仍 $O(1)$。
- 出队：定位队头结点靠 `front` 直接取，常数次指针修改 + `free`，与 $n$ 无关，故 $O(1)$。
- 求队长：从 `front` 沿 `next` 遍历到 `rear`，需访问全部 $n$ 个结点，故 $O(n)$。平均情况：若队长在 $0\sim n$ 间等概率分布，平均遍历 $\frac{n}{2}$ 次，仍为 $O(n)$。

**空间**：每个元素一个结点，空间 $O(n)$；无预分配上限，入队不判满。

## 6. 易错点与考试写法

1. **出队时"删的是最后一个结点"必须特判**：带头结点版本要把 `rear` 回退到 `front`（`Q.rear = Q.front`），不带头结点版本要把 `rear` 置 `NULL`。漏掉这一步，队列变空后 `rear` 成野指针，下次入队崩溃。这是本节最高频考点。
2. **不带头结点时第一个元素入队要同时改 `front` 和 `rear`**：空队时 `front == NULL`，若只改 `rear`，`front` 仍为 `NULL`，出队直接判空失败。
3. **带头结点判空是 `front == rear`，不是 `front->next == NULL` 之外乱写**：两种写法等价，但答题时写一种并说明即可；不带头结点判空是 `front == NULL`。
4. **`free(p)` 前先保存 `p->data` 和 `p->next`**：顺序不能反，先改指针再 `free`，否则访问已释放内存。
5. **链队列没有"队满"**：顺序循环队列要判满（牺牲一个单元或设 `size`/`tag`），链队列只需 `malloc` 成功即可入队。答题时若题目问"链队列是否需要判满"，答"不需要，仅受内存限制"。
6. **考研答题标准**：算法题写链队列操作，必须给出结构体定义 + 初始化 + 入队/出队完整代码，出队中"尾结点特判"要显式写出并加注释；选择题常考"出队后 rear 指向哪里"。

## 7. 408 题型与解题套路

- **选择题**：
  - 给带头结点链队列的初始状态，问连续入队/出队后 `front`、`rear` 的指向（重点考最后一个元素出队后 `rear` 回退）。
  - 问"链队列判空条件"（带头/不带头两种）。
  - 问"链队列与循环队列的区别"（无队满、动态扩容、求队长需遍历）。
- **算法题**：
  - 用链队列实现 BFS（二叉树层序遍历、图的广度优先遍历），直接套本节入队/出队模板。
  - 题目要求"不带头结点"时，务必写第一个元素入队的特判分支。
  - 若题目要求 $O(1)$ 求队长，主动加 `length` 字段——这是加分点。
- **常见陷阱**：
  - 把链队列当单链表，在中间插入/删除（违反 FIFO）。
  - 出队后忘记 `free`，或 `free` 后继续用 `p`。
  - 混淆 `front` 指向头结点（带头）还是队头数据结点（不带头）。

## 8. 自测题

**1.** 带头结点链队列初始为空，`front` 和 `rear` 分别指向哪里？判空条件是什么？

**2.** 带头结点链队列中依次入队 a、b、c，再连续出队三次，第三次出队后 `rear` 指向哪个结点？为什么必须特判？

**3.** 不带头结点链队列，第一个元素入队时为什么要同时修改 `front` 和 `rear`？

**4.** 链队列求队长的时间复杂度是多少？如何优化到 $O(1)$？

**5.** 判断：链队列和循环队列一样，入队前必须判断队满。（对/错，说明理由）

<details>
<summary>答案</summary>

1. `front` 和 `rear` 都指向同一个头结点（`malloc` 申请的空结点），头结点 `next = NULL`。判空条件：`front == rear`（等价于 `front->next == NULL`）。
2. 第三次出队删的是结点 c，它是当前尾结点，故 `rear` 回退指向头结点（`Q.rear = Q.front`），队列恢复空状态。若不特判，`rear` 仍指向已 `free` 的 c，成野指针，下次入队 `Q.rear->next = s` 访问非法内存。
3. 空队时 `front == rear == NULL`，第一个元素入队后它既是队头又是队尾，故 `front` 和 `rear` 都要指向该结点；只改 `rear` 会导致 `front` 仍为 `NULL`，出队判空误判。
4. 默认 $O(n)$，需从 `front` 沿 `next` 遍历到 `rear` 计数。优化：在 `LinkQueue` 结构体中增加 `int length`，入队 `++length`、出队 `--length`，降为 $O(1)$。
5. 错。链队列动态申请结点，只要内存足够就不会满，无需判满；循环队列因静态数组预分配空间有限，才需判满。

</details>

## 9. 背诵卡

1. 链队列结构体：`LinkNode{data,next}` + `LinkQueue{front,rear}`；`rear` 的存在使入队 $O(1)$。
2. 带头结点：初始化 `front=rear=头结点`，判空 `front==rear`；不带头结点：初始化 `front=rear=NULL`，判空 `front==NULL`。
3. 入队 = 尾插：`s->next=NULL; rear->next=s; rear=s;`（不带头结点空队时 `front=rear=s`）。
4. 出队 = 头删：`p=front->next; x=p->data; front->next=p->next;` **若 `p==rear` 则 `rear=front`**；`free(p)`。
5. 链队列无队满；求队长默认 $O(n)$，加 `length` 字段可 $O(1)$。

## 10. 关联与下一节

- **向前关联**：本节是单链表头删/尾插的"受限版"——队列只允许在两端操作，故称"单链表的阉割版"。与 3.2.2 循环队列对比：顺序存储需判满、容量固定；链式存储无队满、可动态扩容，但每个结点多一个指针域开销。
- **向后关联**：下一节 3.2.4 双端队列（deque），允许两端插入删除，是队列的推广；本节入队/出队模板也是后续 BFS 层序遍历、图广度优先遍历的底层工具。
