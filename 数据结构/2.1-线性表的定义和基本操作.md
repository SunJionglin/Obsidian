---

## 2. 一句话结论

**线性表是具有相同数据类型的 $n$（$n \ge 0$）个数据元素的有限序列；对它的基本操作可归为「创建/销毁 + 增删改查」，函数接口是抽象的，参数是否需要引用类型取决于「修改结果要不要带回」。**

---

## 3. 知识地图

```
线性表 linear list
├── 逻辑结构：线性结构（元素排成一条线，有前后次序）
├── 严格定义
│   ├── 相同数据类型（ElemType 一致 → 每个元素占空间相同）
│   ├── 有限（n 有限；"所有整数递增排列"不是线性表）
│   └── 序列（有次序，a_i 有唯一前驱/后继）
├── 术语
│   ├── 表长 n；n = 0 → 空表
│   ├── 位序 i：从 1 开始（≠ 数组下标从 0 开始）
│   ├── 表头元素 a_1、表尾元素 a_n
│   ├── 直接前驱：除 a_1 外每个元素有且仅有一个
│   └── 直接后继：除 a_n 外每个元素有且仅有一个
└── 基本操作（抽象接口，不写具体类型）
    ├── 核心：InitList / DestroyList / ListInsert / ListDelete / LocateElem / GetElem
    └── 常用：Length / PrintList / Empty
```

## 4. 核心内容

### 1. 定义（必背原文）

> 线性表是具有**相同数据类型**的 $n$ 个数据元素的**有限序列**，记作
> $$L = (a_1, a_2, \dots, a_i, \dots, a_n)$$

三个关键词逐个抠：

| 关键词 | 含义 | 反例 / 作用 |
|---|---|---|
| 相同数据类型 | 所有元素类型一致（如全 `int`，或全为自定义 `struct`） | 保证每个元素**占用存储空间相同**，便于计算机快速定位某元素 |
| 有限 | 元素个数 $n$ 有限 | 「所有整数按递增排列」满足同类型、有次序，但个数无限，**不是**线性表 |
| 序列 | 元素之间有先后次序 | 次序不同则是不同的线性表 |

### 2. 术语（选择题高频）

- **表长**：元素个数 $n$。
- **空表**：$n = 0$ 的线性表。
- **位序**：元素在线性表中的「第几个」，**从 1 开始**，$a_i$ 的位序是 $i$。
- **表头元素** $a_1$，**表尾元素** $a_n$。
- **直接前驱**：$a_i$ 的前一个元素 $a_{i-1}$（$i>1$）；**直接后继**：$a_{i+1}$（$i<n$）。
  - 即：除第一个外都有直接前驱，除最后一个外都有直接后继。

> ⚠️ **位序 vs 数组下标**：位序从 1 开始，C 数组下标从 0 开始。位序 $i$ 对应数组下标 $i-1$。这是后面顺序表所有代码的坑源。

### 3. 基本操作（抽象接口，王道/严蔚敏风格）

> 说明：下面接口**不写具体参数类型**，体现「抽象性」——`ElemType` 可以是 `int`，也可以是自定义结构体，实现时才确定。

```c
// 初始化：从无到有，分配内存、置初值
InitList(&L);

// 销毁：从有到无，释放内存
DestroyList(&L);

// 插入：在位序 i 处插入元素 e
ListInsert(&L, i, e);

// 删除：删除位序 i 处的元素，并用 e 返回被删值
ListDelete(&L, i, &e);

// 按值查找：找值为 e 的元素，返回其位序（找不到返回 0）
LocateElem(L, e);

// 按位查找：取位序 i 的元素
GetElem(L, i);

// 其他常用
Length(L);      // 求表长
PrintList(L);   // 输出所有元素
Empty(L);       // 判空，空返回 true
```

**为什么需要这些基本操作（Why）**：
1. 大型项目多人协作，定义者把操作**封装成函数**，队友才能方便调用；
2. 常用操作封装后**避免重复写代码**，直接调用。

**核心思想**：任何数据结构的基本运算，本质就是 **创建、销毁、增、删、改、查**。「改」的第一步也是「查」（先找到再改）。

### 4. 引用类型参数（本节最重点，必须理解）

**结论**：**如果函数内对参数的修改结果需要带回给调用者，参数就用引用类型 `&`；否则不用。**

C++ 引用示例（C 语言不支持引用，需用 C++ 编译器）：

```cpp
// 值传递：修改带不回来
void test(int x) { x = 1024; }        // 改的是副本

// 引用传递：修改能带回
void test(int &x) { x = 1024; }       // x 与实参是同一份数据
```

运行现象（值传递）：`main` 中 `x=1` → 调用 `test` 内部打印 `1024` → 返回 `main` 再打印仍是 `1`。
原因：值传递时形参是实参的**复制品**，内存中是两份数据，改副本不影响原件。

**对照到基本操作**：
- `ListInsert(&L, i, e)`、`ListDelete(&L, i, &e)`、`InitList(&L)`、`DestroyList(&L)`：要**修改 L 本身**或**带回被删元素**，故加 `&`。
- `LocateElem(L, e)`、`GetElem(L, i)`、`Length(L)`：只读不改，**不加** `&`。

> 408 答题时用 C 语言写，没有引用类型，通常用**指针**（`*L`）达到同样效果；但理解「要不要带回」这个判断标准不变。

### 5. 命名规范

- 函数名、变量名要**可读**：`DestroyList` 一看就懂，取名 `a` 则不可读。
- 王道/严蔚敏的命名是推荐写法，答题用它更讨喜；但不必教条，可读性优先。

## 5. 复杂度分析

本节**只定义逻辑结构和操作接口，未涉及具体存储实现**，因此**没有可分析的算法复杂度**（插入/删除/查找的复杂度要到 2.2 顺序表、2.3 链表才展开）。

- 唯一可说的性质：因「相同数据类型 → 每个元素等长」，为后续顺序表**按位查找 $O(1)$** 埋下伏笔（连续存储 + 等长 + 起始地址 → 地址可直接算出）。此为**推断/铺垫**，本节不展开证明。

## 6. 易错点与考试写法

1. **位序从 1 开始，数组下标从 0 开始**——选择题最爱在此设陷阱，写代码时位序 $i$ 对应下标 $i-1$。
2. **「有限」不能漏**：判断某结构是否为线性表，必须同时满足「同类型 + 有序 + 有限」。无限序列（如全体整数递增）**不是**线性表。
3. **相同数据类型 ≠ 值相同**：是类型一致，不是元素相等。
4. **前驱/后继的边界**：$a_1$ 无前驱、$a_n$ 无后继，其余各恰有一个。
5. **引用类型判断**：只读操作不加 `&`，会修改/需带回的才加 `&`。这是写对代码的前提。
6. **C 与 C++ 区别**：`&` 引用是 C++ 语法，C 不支持；408 用 C 写时用指针替代。

**答题写到什么程度算对**：
- 概念题：能写出「相同数据类型、有限、序列」三要素并各举一反例即可满分。
- 接口题：能列出 6 个核心操作名 + 参数含义，并说明哪些参数用引用/指针及理由。

## 7. 408 题型与解题套路

- **选择题**：
  - 给一个结构判断是否为线性表 → 逐条对「同类型/有限/有序」。
  - 考位序与下标换算、前驱后继个数。
  - 考「哪个操作参数需要引用/指针」。
- **算法题**：本节不直接出算法题，但**所有后续顺序表/链表代码**都以本节接口为骨架；答题时先想「这是增删改查哪一类」，再套对应接口。
- **常见陷阱**：把「无限序列」当线性表；位序下标混用；只读函数误加 `&`。

## 9. 背诵卡

1. 线性表 = **相同数据类型**的 $n$ 个数据元素的**有限序列**。
2. 位序**从 1 开始**，数组下标**从 0 开始**，位序 $i$ ↔ 下标 $i-1$。
3. 除首元素外都有直接前驱，除尾元素外都有直接后继；$n=0$ 为空表。
4. 核心操作：Init / Destroy / Insert / Delete / LocateElem / GetElem；本质是**创建销毁 + 增删改查**。
5. 参数**修改结果要带回就用引用（C++ `&` / C 指针）**，只读不加。
