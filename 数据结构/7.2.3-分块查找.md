# 7.2.3 分块查找（索引顺序查找）

## 1. 本节定位

- **王道书对应**：第 7 章「查找」→ 7.2 顺序查找与分块查找 → 7.2.3 分块查找（又称索引顺序查找，Indexed Sequential Search）。
- **408 大纲对应**：查找表上的查找算法——分块查找的基本思想、平均查找长度（ASL）分析。
- **先修知识**：顺序查找（ASL 为 $\frac{n+1}{2}$）、折半查找（判定树、`low/high/mid` 移动规则）、顺序表与链表的存储特点。
- **在整章中的位置**：位于顺序查找、折半查找之后，是「静态查找表」三种基本方法的最后一节；它把「索引」思想引入查找，为后续 B 树/B+ 树的索引结构做铺垫。

## 2. 一句话结论

分块查找把表分成「块间有序、块内无序」的若干块，先查索引表定位块、再在块内顺序查找；当索引表用顺序查找、且 $n$ 个元素分成 $\sqrt{n}$ 块、每块 $\sqrt{n}$ 个元素时，ASL 取最小值 $\sqrt{n}+1$。

## 3. 知识地图

```
分块查找（索引顺序查找）
├── 数据结构
│   ├── 查找表（数组/链表存放元素，块内无序）
│   └── 索引表（每项：该块最大关键字 key + 该块区间 low~high）
├── 核心性质
│   ├── 块间有序（前一块最大关键字 < 后一块最小关键字，递增；也可递减）
│   └── 块内无序（只能顺序查找）
├── 查找过程
│   ├── 第一步：查索引表，确定目标所属块
│   │   ├── 顺序查找索引表（简单，常考）
│   │   └── 折半查找索引表（索引表有序且顺序存储；注意 low>high 时落在 low 所指块）
│   └── 第二步：在该块内顺序查找
├── ASL 分析
│   ├── 特例：逐元素数比较次数，乘概率求和
│   └── 一般：ASL = ASL_索引 + ASL_块内
│       ├── 顺序查索引：ASL = (b+1)/2 + (s+1)/2
│       └── 最优分块：s = √n，b = √n，ASL_min = √n + 1
└── 动态维护（扩展）
    ├── 顺序存储：插入/删除需大量移位，代价大
    └── 链式存储：索引表、块内均可用链表，插入删除方便
```

## 4. 核心内容

### 4.1 定义与结构

**分块查找**：将长度为 $n$ 的查找表划分为 $b$ 个块（每块 $s$ 个元素，$n=bs$），满足：

- **块间有序**：第 $i$ 块中所有关键字都小于（或都大于）第 $i+1$ 块中所有关键字；
- **块内无序**：块内元素任意排列。

再为每块建立一个索引项，索引表按块顺序存放，每项含：

- 该块的**最大关键字**（若块间递增）；
- 该块的**存储区间** `low`、`high`（数组下标，注意是下标不是位序）。

王道风格的结构定义（顺序存储版）：

```c
#define MaxSize 100

typedef struct {
    int maxKey;   // 该块中的最大关键字
    int low;      // 该块在数组中的起始下标
    int high;     // 该块在数组中的结束下标
} IndexItem;      // 索引项

typedef struct {
    IndexItem index[MaxSize];  // 索引表，按块间关键字递增排列
    int b;                     // 块数
    int elem[MaxSize];         // 存放元素的数组（块内无序）
    int n;                     // 元素总数
} BlockTable;
```

> 说明：索引表本身是**有序的**（按 maxKey 递增），且用数组顺序存储，因此对索引表既可以顺序查找，也可以折半查找。

### 4.2 查找过程（手算模拟是重点）

以讲解中的例子：14 个元素，分 5 块，索引表 maxKey 依次为 10、20、30、40、50，对应区间 0~1、2~4、6~8 等。

**第一步：查索引表定位块。**

- **顺序查找索引表**：从第 1 项起逐项比较，找到第一个 `maxKey ≥ key` 的项，即目标所在块。
- **折半查找索引表**：按普通折半规则在索引表上做 `low/high/mid`。**关键结论**：若折半查找以 `low > high` 结束，则目标（若存在）一定在 **`low` 所指的那一块**中；若此时 `low` 已超出索引表范围，则查找失败。

**第二步：在该块区间 `[low, high]` 内顺序查找**，逐个比较，找到即成功；扫完该块仍未找到则失败（失败时不能越界到下一块）。

**查找成功例（key = 22）**：索引表顺序查到 maxKey=30（第 3 块，区间 6~8），块内从下标 6 起比较，下标 7 处命中。

**查找失败例（key = 29）**：定位到第 3 块（6~8），块内 27、22、30 均不等，扫到下标 9 已越出该块区间，判定失败。

**折半查索引成功例（key = 30）**：第一轮 `mid` 恰指向 maxKey=30 的索引项，直接确定第 3 块，块内顺序查到下标 8 命中。

**折半查索引、目标不在索引表中的例（key = 19）**：折半过程最终 `low > high`，此时 `low` 指向 maxKey=20 的块（第 2 块），在该块内顺序查到 19，成功。

> **为什么停在 `low` 所指块？**（讲解中专门强调，课本未强调）
> `low > high` 的前一步必有 `low == high == mid`，此时：
> - 若 `mid` 项 `maxKey < key`，则 `low = mid + 1`，`low` 所指项的关键字比 `mid` 项更大，自然 $> key$；
> - 若 `mid` 项 `maxKey > key`，则 `high = mid - 1`，`low` 不动，`low` 所指项仍 $> key$。
>
> 两种情况下 `low` 所指索引项的 maxKey 都大于目标 key，而索引表存的是块内最大关键字，所以目标只可能落在 `low` 所指块中。

**折半查索引、目标超范围例（key = 54）**：折半结束于 `low = 5`（已越出索引表末项），`low` 指空 → 直接判定查找失败。

### 4.3 ASL 分析

**（1）特例法（考试常见）**：对给定实例，逐个元素数出「索引表比较次数 + 块内比较次数」，再乘各自概率 $\frac{1}{n}$ 求和：

$$
ASL_{成功}=\sum_{i=1}^{n} p_i \cdot c_i,\qquad p_i=\frac{1}{n}
$$

其中 $c_i$ 为查找第 $i$ 个元素所需的关键字比较总次数。折半查索引时每个元素的 $c_i$ 需完整模拟折半过程，工作量大，故考试一般只考顺序查索引的实例。

**（2）一般公式（顺序查索引）**：设 $n$ 个元素分 $b$ 块、每块 $s$ 个，$n=bs$。

- 索引表顺序查找：平均 $\frac{b+1}{2}$ 次比较（等概率命中各块）；
- 块内顺序查找：平均 $\frac{s+1}{2}$ 次比较（等概率命中块内各位置）。

$$
ASL_{成功}=\frac{b+1}{2}+\frac{s+1}{2}
=\frac{1}{2}+\frac{n}{2s}+\frac{s}{2}+\frac{1}{2}
=\frac{1}{2}+\frac{n}{2s}+\frac{s}{2}+\frac{1}{2}
$$

代入 $b=\frac{n}{s}$，整理得：

$$
ASL_{成功}=\frac{s+1}{2}+\frac{n}{2s}+\frac{1}{2}
$$

（讲解中写作 $\frac{1}{2}+\frac{n}{2s}+\frac{s}{2}$ 的形式，本质相同。）

**（3）最优分块**：把上式对 $s$ 求导并令其为 0：

$$
\frac{d}{ds}ASL=\frac{1}{2}-\frac{n}{2s^2}=0 \;\Rightarrow\; s=\sqrt{n}
$$

即分成 $b=\sqrt{n}$ 块、每块 $s=\sqrt{n}$ 个元素时 ASL 最小：

$$
ASL_{min}=\sqrt{n}+1
$$

例：$n=10000$，最优分 100 块、每块 100 个，$ASL_{min}=101$；而纯顺序查找平均约 5000 次，效率显著提升。

**（4）折半查索引（了解即可）**：$ASL \approx \log_2(b+1)-1+\frac{s+1}{2}$（近似式，王道书扩展，考试极少考），只需知道「折半查索引比顺序查索引更快，但分析复杂、不常考」。

### 4.4 动态维护（王道书扩展）

- **顺序存储**：插入元素须保持块间有序，需在对应块内插入并大量后移元素，代价 $O(n)$；删除同理。
- **链式存储**：索引表用链表、块内元素也用链表，插入删除只需改指针；块过大时还可拆分块。这说明数据结构设计应服从实际需求，不必拘泥课本固定形式。

## 5. 复杂度分析

设 $n$ 个元素、$b$ 块、每块 $s$ 个，$n=bs$，各元素等概率被查（$p=\frac{1}{n}$）。

| 情形 | 索引表查找 | 块内查找 | 总 ASL |
|---|---|---|---|
| 最好 | 1 次（命中第 1 块） | 1 次（命中块首） | $2$ |
| 最坏 | $b$ 次（命中第 $b$ 块） | $s$ 次（命中块尾） | $b+s$ |
| 平均（顺序查索引） | $\frac{b+1}{2}$ | $\frac{s+1}{2}$ | $\frac{b+1}{2}+\frac{s+1}{2}$ |

**平均情况推导**：

- 索引表顺序查找：命中第 $i$ 块需比较 $i$ 次，$i=1,\dots,b$ 等概率，故 $\frac{1}{b}\sum_{i=1}^{b} i=\frac{b+1}{2}$。
- 块内顺序查找：命中块内第 $j$ 个需比较 $j$ 次，$j=1,\dots,s$ 等概率，故 $\frac{1}{s}\sum_{j=1}^{s} j=\frac{s+1}{2}$。
- 两阶段独立相加：$ASL=\frac{b+1}{2}+\frac{s+1}{2}$，代入 $b=n/s$ 后对 $s$ 求导得最优 $s=\sqrt{n}$，$ASL_{min}=\sqrt{n}+1$。

**查找失败**：块内无序导致失败区间难以划分，ASL 失败分析复杂，**考试不考**（讲解明确说明）。

## 6. 易错点与考试写法

1. **「块间有序」不是「块内有序」**：块内元素乱序，块内只能顺序查找，不能折半。
2. **索引表存的是「块内最大关键字」**：定位规则是找第一个 `maxKey ≥ key` 的块（递增情形），不是「等于」。
3. **折半查索引停在 `low > high` 时，去 `low` 所指块找**，不是 `high` 所指块；`low` 越界则直接失败。这是最容易懵的点。
4. **失败判定边界**：块内顺序查找扫完 `[low, high]` 即停，不能顺延到下一块继续比。
5. **下标 vs 位序**：索引项里存的是数组下标 `low/high`，手算时别把「第 6 个元素」和「下标 6」混用。
6. **最优分块结论要记准**：$s=\sqrt{n}$、$b=\sqrt{n}$、$ASL_{min}=\sqrt{n}+1$，选择题常直接考这个数值。
7. **答题程度**：选择题只需选出正确 ASL 或最优块长；手算题要写出「索引比较次数 + 块内比较次数」的分解过程，再乘概率求和，不能只写一个数。

## 7. 408 题型与解题套路

- **选择题（主考）**：
  - 给一个分块表，问某关键字的查找过程/比较次数 → 按「先索引、后块内」两步模拟。
  - 问最优分块与最小 ASL → 直接套 $s=\sqrt{n}$、$\sqrt{n}+1$。
  - 问索引表能否折半查找 → 能，因为索引表有序且顺序存储；但要注意 `low>high` 的落块规则。
- **算法题（极少）**：分块查找很少考代码，若考多为「写出索引表结构 + 查找框架」，重点在结构定义与两步流程，不必写完整可运行程序。
- **常见陷阱**：
  - 把「块间有序」误当「整体有序」，错用折半查找查整个表；
  - 折半查索引失败时误去 `high` 块或直接判失败；
  - 计算 ASL 时漏加索引表那部分比较次数。

## 8. 自测题

**1.** 分块查找对查找表的两条基本要求是什么？块内能否用折半查找？为什么？

**2.** 长度 $n=400$ 的表采用分块查找，索引表顺序查找。为使 ASL 最小，应分多少块、每块多少元素？最小 ASL 是多少？

**3.** 索引表 maxKey 依次为 10、20、30、40、50，对应块区间 0~1、2~4、6~8、9~11、12~13。用折半查找索引表查 key=19，折半结束时 `low`、`high` 各指向哪一项？应在哪个区间内继续查找？

**4.** 承上题，查 key=54，折半结束状态如何？结论是什么？

**5.** 为什么分块查找在「经常插入删除」的场景下，顺序存储实现代价大？有什么改进？

<summary>参考答案</summary>

1. 块间有序（前块所有关键字小于后块所有关键字）、块内无序。块内不能折半，因为块内元素无序，只能顺序查找。
2. $s=\sqrt{400}=20$，即分 $b=20$ 块、每块 20 个元素；$ASL_{min}=\sqrt{400}+1=21$。
3. 折半过程最终 `low > high`，`low` 指向 maxKey=20 的索引项（第 2 块），应在区间 2~4 内顺序查找（19 确实在其中，查找成功）。
4. 折半结束于 `low` 越出索引表（`low=5`，`high=4`），`low` 指空，直接判定查找失败。
5. 插入/删除须维持块间有序，顺序存储需大量元素后移，代价 $O(n)$；可改用链式存储（索引表与块内均用链表），插入删除只改指针，还可方便地拆分块。

## 9. 背诵卡

1. 分块查找 = 索引顺序查找：**块间有序、块内无序**；先查索引定块，再块内顺序查找。
2. 索引项 = 块内最大关键字 + 块区间 `[low, high]`；索引表有序且顺序存储，可顺序查也可折半查。
3. 折半查索引以 `low > high` 结束时，目标（若存在）在 **`low` 所指块**；`low` 越界即失败。
4. 顺序查索引：$ASL=\frac{b+1}{2}+\frac{s+1}{2}$；最优 $s=b=\sqrt{n}$，$ASL_{min}=\sqrt{n}+1$。
5. 查找失败的 ASL 分析复杂，**408 不考**；动态场景宜用链式存储。
