# 7.4.2 B+树

## 1. 本节定位

- **对应王道书**：第 7 章「查找」→ 7.4「B 树和 B+树」→ 7.4.2 B+树。
- **408 大纲对应**：查找 → B+树的基本概念（大纲对 B+树只要求**概念级**掌握，不要求插入/删除算法）。
- **先修知识**：B 树（7.4.1）的定义与查找过程、分块查找（索引顺序表）的思想、m 叉查找树的平衡概念。
- **本章位置**：B 树 → **B+树** → 散列表。B+树是 B 树的变体，本节核心任务是**与 B 树对比**，选择题常把二者放在同一题中考。

## 2. 一句话结论

B+树是「多级分块查找」的树形化：**所有关键字都出现在叶子节点，非叶节点只做索引（只存子树最大关键字 + 指针，不存记录地址）**，因此一个节点能塞下更多关键字、树更矮、读磁盘次数更少——这正是数据库索引用 B+树而不用 B 树的原因。

## 4. 核心内容

### 4.1 定义（m 阶 B+树，以 4 阶为例）

设 m 为阶数，即**每个节点最多 m 棵子树**。B+树满足：

1. 每个节点最多有 $m$ 棵子树（对应最多 $m$ 个关键字）。
2. **非叶根节点**至少 2 棵子树（根即叶子时除外）。
3. 除根外的每个**分支节点**至少有 $\lceil m/2 \rceil$ 棵子树。
4. **节点的关键字个数 = 子树个数**（一一对应）。
5. **所有叶子节点包含全部关键字**，并含指向相应记录的指针；叶子节点按关键字大小顺序用指针 `p` 链接成有序链表。
6. **所有分支节点只含其各子节点中关键字的最大值**及指向子树的指针，不含记录地址。

> 注意「叶子节点」指最下面**一整块**（可含多个关键字），不是其中某个小方块。

性质 2、3 的动机与 B 树相同：保证绝对平衡（任一节点所有子树高度相同）、节点不空，从而压低树高、保证查找效率。

### 4.2 结构示意（4 阶，分支节点存子树最大关键字）

```
                 [15 | 56]                 ← 根（分支节点，只存最大值+指针）
                /    |    \
        [3|9|15]  [..|..|..]  [..|..|56]   ← 分支节点
        / | \ ...
   叶子: 1 3 | 6 8 9 | ... | 50 56 ...      ← 全部关键字 + 记录指针
         └──p──→└──p──→└──p──→ ...          ← 叶子链表（支持顺序查找）
```

分支节点中的 15 表示「它指向的那棵子树中最大关键字是 15」，与分块查找索引表存「每块最大关键字」完全同理。

### 4.3 查找过程

**方式一：从根逐层向下（随机查找）**

以查关键字 9 为例：

1. 根节点：$9 < 15$，进入 15 所指子树（该子树最大关键字为 15，若 9 存在必在其中）。
2. 分支节点：3 < 9，指针后移；遇到 9，**但查找未结束**——分支节点只是索引。
3. 沿 9 所指指针下到叶子层，在叶子中从左到右找到 9，取出其记录指针，读出记录。

以查 7（失败）为例：根 $7<15$ 下行 → 分支中 $3<7<9$，进入 9 所指子树 → 叶子中 $6<7<8$，未找到 → **查找失败**。

**关键结论**：B+树无论成功失败，**都必须走到叶子层**才能判定；B 树则可能在中间层就确定成功。

**方式二：沿叶子链表 p 顺序查找**：从第一个叶子起沿 `p` 逐个比较，找到即取记录。B+树支持顺序查找，B 树不支持。

### 4.4 B+树与 B 树的区别（本节最核心，408 必考）

| 对比项 | B+树 | B 树 |
|---|---|---|
| 关键字数与分支数 | $n$ 个关键字 ↔ $n$ 个分支 | $n$ 个关键字 ↔ $n+1$ 个分支 |
| 关键字出现次数 | 非叶出现的关键字在叶子中**重复出现** | 各节点关键字**不重复** |
| 非叶节点内容 | 只存「子树最大关键字 + 指针」，**不存记录地址** | 存关键字 + **对应记录的存放地址** |
| 查找终止位置 | 必须到叶子层 | 可在中间层成功 |
| 顺序查找 | 支持（叶子链表） | 不支持 |

因「$n$ 关键字 ↔ $n$ 分支」，B+树关键字个数的上下限取值与 B 树不同（本质原因即此对应关系）。

### 4.5 为什么数据库索引用 B+树（王道书扩展，了解即可）

- 节点存于磁盘块，读写以磁盘块为单位，**每下一层 = 一次读磁盘**，磁盘是慢速设备，I/O 开销大。
- 磁盘块大小固定（如 1KB）。B+树非叶节点不存记录地址，**同样空间能放更多关键字** → 阶更大 → 树更矮 → 查找路径上读磁盘次数更少 → 更快。
- 叶子链表还便于范围查询与顺序遍历。
- 典型应用：MySQL 等关系数据库的索引。

## 5. 复杂度分析

设树高为 $h$（叶子层为第 $h$ 层），每个节点关键字数在 $[\lceil m/2\rceil,\ m]$ 之间。

- **查找成功/失败（随机查找）**：比较次数与路径长度成正比，为 $O(h)$。
- **树高推导**：含 $N$ 个关键字时，叶子层节点数至少 $\lceil N/m \rceil$，每上一层节点数至少除以 $m$，故
  $$h \le \log_{\lceil m/2\rceil}\!\left(\frac{N}{m}\right)+1 = O(\log_m N)$$
  即 $h = O(\log_m N)$，故查找为 $O(\log_m N)$。
- **最好**：根即叶子（单节点），$O(1)$。
- **最坏**：沿最长路径走到叶子，$O(h)=O(\log_{\lceil m/2\rceil} N)$。
- **平均**：假设各关键字等概率出现，平均比较次数 ≈ 平均路径长度 × 节点内平均比较次数。节点内为顺序比较，平均约 $(k+1)/2$ 次（$k$ 为该节点关键字数），故平均仍为 $O(\log_m N)$ 量级；**若计入磁盘 I/O，代价 ≈ 树高 $h$ 次读盘**，这才是实际主导开销。
- **顺序查找**：沿叶子链表，平均 $(N+1)/2$ 次比较，$O(N)$。

## 6. 易错点与考试写法

1. **「关键字数 = 分支数」只对 B+树成立**，B 树是「关键字数 + 1 = 分支数」。选择题最爱在此设陷阱。
2. **B+树查找必须到叶子层**才算成功；在分支节点看到相同关键字**不代表查找结束**（分支节点只是索引，无记录地址）。
3. **「叶子节点」是整块而非单个关键字**；叶子节点内关键字有序，且叶子间用指针链接。
4. **B+树关键字可重复出现**（非叶的最大值在叶子中再现），B 树不重复。
5. **非叶根节点至少 2 棵子树**；根同时是叶子时不受此限。分支节点下限是 $\lceil m/2\rceil$ 棵子树（不是 $\lceil m/2\rceil$ 个关键字——B+树二者相等，B 树不等，别混）。
6. **答题程度**：408 对 B+树只考概念，答到「定义 6 条 + 与 B 树 4 点区别 + 查找必须到叶子」即满分；不要求写插入/删除算法，不要展开。

## 7. 408 题型与解题套路

- **选择题（主战场）**：
  - 给一棵 B+树图，问某关键字查找路径 / 比较次数 / 是否成功 → 逐层按「小于等于某最大值则进该分支」走，**务必走到叶子**再下结论。
  - 给 m 阶 B+树，问节点关键字个数范围 → 分支节点关键字数 ∈ $[\lceil m/2\rceil, m]$（根为 $[1,m]$，非叶根至少 2）。
  - B 树 vs B+树对比选项 → 用 4.4 表格逐条排除；「B+树非叶节点存记录地址」「B+树关键字不重复」均为错误表述。
  - 问「数据库索引为何用 B+树」→ 答：非叶不存记录地址 → 单节点容纳关键字多 → 树矮 → 读磁盘次数少；且叶子链表支持顺序/范围查找。
- **算法题**：408 不考 B+树算法实现，无需准备代码。
- **常见陷阱**：把 B 树的「$n+1$ 分支」套到 B+树上；认为在分支节点命中即成功；把叶子链表误认为可有可无。

## 9. 背诵卡

1. **B+树 = 多级分块查找**：分支节点只存「子树最大关键字 + 指针」，纯索引。
2. **关键字数 = 分支数**（B+树）；B 树是关键字数 + 1 = 分支数。
3. **全部关键字在叶子**，叶子含记录指针并按序链表相连 → 支持顺序查找。
4. **查找必到叶子层**才判成功/失败；B 树可在中间层成功。
5. **非叶根 ≥ 2 子树，分支节点 ≥ ⌈m/2⌉ 子树，最多 m 子树**；B+树关键字可重复出现，B 树不重复。

## 10. 关联与下一节

- **回看 B 树（7.4.1）**：B 树由 m 叉查找树加平衡与节点下限条件演化而来，可与二叉查找树类比；B+树则由分块查找多级化而来。二者共同思想：**绝对平衡 + 节点不空 → 压低树高 → 提高查找效率**。
- **与分块查找（7.2）**：B+树分支节点存「子树最大关键字」正是分块查找索引表存「每块最大关键字」的多级推广。
- **与操作系统文件管理**：磁盘块读写、I/O 代价是理解 B+树设计动机的背景（王道书扩展，考研不深究）。
- **下一节**：散列表（Hash 表）——从「有序比较」转向「按关键字直接计算地址」，注意与 B+树在查找方式、平均复杂度、是否支持范围查询上的对比。
