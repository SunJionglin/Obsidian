# 4.2.3 KMP 算法的进一步优化

## 1. 本节定位

- **对应王道书**：第 4 章「串」4.2.3 节，KMP 算法的进一步优化（`nextval` 数组）。
- **408 大纲**：串的模式匹配（大纲中串只作为「字符串的模式匹配」一个小考点出现，未单列成章）。
- **先修知识**：朴素模式匹配、KMP 的 `next` 数组定义与手算方法、KMP 匹配流程（失配时 `j = next[j]`，`j == 0` 时 `i`、`j` 同时加加）。
- **本节位置**：KMP 的收尾。优化对象**只是 `next` 数组**，KMP 主逻辑一行不改；把 `next` 换成 `nextval` 即可。

## 2. 一句话结论

若失配位置 $j$ 的字符与 `next[j]` 所指位置的字符相同，则 `next[j]` 这一步跳转注定再次失配，应直接跳到 `nextval[next[j]]`；否则 `nextval[j] = next[j]`，且恒有 `nextval[1] = 0`。

## 3. 知识地图

```
KMP 优化
├── 优化动机
│   └── 失配字符 == next[j] 所指字符 ⇒ 该次跳转必然再失配，白比一次
├── nextval 数组
│   ├── 定义：next 的「压缩版」，跳过注定失败的比较
│   ├── 手算规则
│   │   ├── nextval[1] = 0（无脑写 0）
│   │   ├── p[j] != p[next[j]] ⇒ nextval[j] = next[j]
│   │   └── p[j] == p[next[j]] ⇒ nextval[j] = nextval[next[j]]
│   └── 求法前提：先求出 next 数组
└── 优化后 KMP
    └── 主逻辑不变，仅把 next 替换为 nextval
```

## 4. 核心内容

### 1. 优化动机（为什么 `next` 会做无用功）

设模式串 `p`（位序从 1 开始），主串当前字符为 `S[i]`，模式串在 `p[j]` 处失配，即 $S[i] \ne p[j]$。

KMP 令 $j \leftarrow next[j]$，下一步比较 $S[i]$ 与 $p[next[j]]$。

- 若 $p[next[j]] = p[j]$，则由 $S[i] \ne p[j]$ 立刻推出 $S[i] \ne p[next[j]]$，**这一步必然再失配**，纯属浪费。
- 此时应继续回退到 $next[next[j]]$ 之后的位置，即直接取 `nextval[next[j]]`。

**例（转写中的模式串 `a b a a b c`，位序 1~6）**：

- `next[3] = 1`，而 $p[3] = p[1] = \text{a}$。第 3 位失配时 `j` 回到 1 仍会失配（主串该字符已确定不是 `a`），故 `nextval[3] = nextval[1] = 0`，直接跳过。
- `next[5] = 2`，而 $p[5] = p[2] = \text{b}$。第 5 位失配时 `j` 回到 2 仍会失配，故 `nextval[5] = nextval[2] = 1`。
- `next[6] = 3`，而 $p[6] = \text{c} \ne p[3] = \text{a}$。主串该字符虽不是 `c`，但**可能是 `a`**，所以第 6 位失配后回到 3 是有意义的，`nextval[6] = next[6] = 3` 保持不变。

> 结论：**只有「新位置字符 == 原失配位置字符」时才压缩，否则保留原值。**

### 2. `nextval` 手算规则（408 必考，只考手算）

前提：已用上一节方法求出 `next` 数组。位序从 1 开始，`next[1] = 0`。

对 $j = 1, 2, \dots, m$：

- `nextval[1] = 0`（无脑写 0）；
- 若 $p[j] \ne p[next[j]]$：`nextval[j] = next[j]`；
- 若 $p[j] = p[next[j]]$：`nextval[j] = nextval[next[j]]`（注意取的是**已求出的** `nextval`，不是 `next`）。

### 3. 两个完整手算示例

**例 1：`a b a b a a`（位序 1~6）**

| j | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| p[j] | a | b | a | b | a | a |
| next[j] | 0 | 1 | 1 | 2 | 3 | 4 |
| 比较 | — | b≠p[1]=a | a=p[1]=a | b=p[2]=b | a=p[3]=a | a≠p[4]=b |
| nextval[j] | 0 | 1 | 0 | 1 | 0 | 4 |

逐项说明：`nextval[2] = next[2] = 1`（不等，保留）；`nextval[3] = nextval[1] = 0`；`nextval[4] = nextval[2] = 1`；`nextval[5] = nextval[3] = 0`；`nextval[6] = next[6] = 4`（不等，保留）。

**例 2：`a a a a b`（位序 1~5）**

| j | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| p[j] | a | a | a | a | b |
| next[j] | 0 | 1 | 2 | 3 | 4 |
| nextval[j] | 0 | 0 | 0 | 0 | 4 |

`nextval[2] = nextval[1] = 0`，`nextval[3] = nextval[2] = 0`，`nextval[4] = nextval[3] = 0`，`nextval[5] = next[5] = 4`（b ≠ p[4] = a）。

### 4. 优化后的 KMP 代码（与未优化版仅差一个数组名）

```c
// 求 nextval 数组，模式串 p 位序 1~m，p[0] 不用
void get_nextval(char p[], int nextval[], int m) {
    int i = 1, j = 0;
    nextval[1] = 0;                 // 恒为 0
    while (i < m) {
        if (j == 0 || p[i] == p[j]) {
            i++; j++;
            if (p[i] != p[j])       // 新位置字符与原失配字符不同
                nextval[i] = j;     // 保留 next 值
            else
                nextval[i] = nextval[j]; // 相同则继承，跳过注定失败的比较
        } else {
            j = nextval[j];         // 回退用 nextval
        }
    }
}

// KMP 匹配：与未优化版完全相同，只是把 next 换成 nextval
int Index_KMP(char S[], char p[], int nextval[], int n, int m) {
    int i = 1, j = 1;
    while (i <= n && j <= m) {
        if (j == 0 || S[i] == p[j]) { i++; j++; }  // j==0 时 i、j 同时加加
        else j = nextval[j];                        // 失配：j 跳到 nextval[j]
    }
    if (j > m) return i - m;   // 匹配成功，返回起始位序
    return 0;                  // 失败
}
```

> 注意：`nextval` 数组的**下标与位序一致**（从 1 开始），`nextval[0]` 不使用；手算题若给的是 0 起始下标，需按题目约定平移，答题时先写清约定。

### 5. 优化效果直观对比（模式串 `a a a a b`，`next = 0 1 2 3 4`，`nextval = 0 0 0 0 4`）

主串在第 4 位失配时：

- 用 `next`：`j` 依次回退 3 → 2 → 1 → 0，连续 3 次注定失败的比较；
- 用 `nextval`：`j` 直接跳到 0，`i`、`j` 同时加加，**一次跳过全部 `a` 的无效比较**。

## 5. 复杂度分析

设主串长 $n$、模式串长 $m$。

- **求 `next` / `nextval`**：`i` 只增不减，`j` 每次失配至少减 1 且总增量不超过 `i` 的增量，故循环总次数 $O(m)$，时间 $O(m)$，空间 $O(m)$。
- **匹配**：`i` 不回退、只增不减，`j` 的回退总量被 `j` 的增量所界，故 $O(n)$。
- **总时间**：$O(n + m)$。**最好**：首字符即失配且 `nextval` 直接跳 0，约 $O(n)$ 次比较；**最坏**：$O(n + m)$；**平均**：在字符独立等概率、字母表大小 $\sigma$ 的假设下，期望比较次数为 $O(n)$，且常数比朴素算法小——`nextval` 相比 `next` 减少的是「注定失败」的比较次数，**不改变渐近阶，只降低常数**（推断：教材未给严格期望推导，408 不要求）。
- 空间：`next` 与 `nextval` 均 $O(m)$。

## 6. 易错点与考试写法

1. **`nextval[1]` 恒为 0**，无论模式串首字符是什么，不要按规则去比较。
2. **相等时取 `nextval[next[j]]` 而不是 `next[next[j]]`**：必须用已求出的 `nextval` 值，这是链式压缩的关键；写成 `next[next[j]]` 是典型错误。
3. **比较对象是「当前字符 $p[j]$」与「$p[next[j]]$」**，不是与 `nextval[j]` 比，也不是与 $p[j-1]$ 比。
4. **`next` 与 `nextval` 的位序约定必须与题目一致**：王道书位序从 1 开始、`next[1] = 0`；若题目给 0 起始下标，则首元素 `nextval = -1`，整体平移，答题时先声明约定。
5. **优化不改变 KMP 主逻辑**：答题写「KMP 算法本身不变，仅将 `next` 替换为 `nextval`」即可得分，不要重写匹配流程。
6. **不是所有 `next` 值都能被优化**：只有字符相等时才压缩，如 `a b a a b c` 的 `nextval[6]` 仍为 3。
7. 考研答题程度：手算题**列出 `next` 表、逐位写出比较结果、给出 `nextval` 表**即算对；代码题写出 `get_nextval` 的「相等继承、不等保留」分支即可，无需证明正确性。

## 7. 408 题型与解题套路

- **选择题（高频）**：给模式串求 `nextval` 数组 / 求某一位的 `nextval` / 比较 `next` 与 `nextval` 不同的位数。套路：先老老实实求 `next`，再逐位套三条规则，**从前往后**求（后面的 `nextval` 依赖前面的）。
- **选择题（概念）**：问「`nextval` 优化的本质」——答：跳过因字符相同而必然再次失配的跳转，减少比较次数，不改变时间复杂度阶。
- **匹配过程题**：给主串、模式串和 `nextval`，问失配后 `j` 的新值或总比较次数。套路：失配即查表 `j = nextval[j]`，`j = 0` 时 `i`、`j` 同时加加。
- **算法题**：408 对 KMP 代码要求低，掌握 `get_nextval` 与 `Index_KMP` 的默写即可；注意数组下标约定与返回值（起始位序 vs 下标）。
- **常见陷阱**：把 `nextval` 当 `next` 用；相等分支写成 `next[next[j]]`；忘记 `nextval[1] = 0`；0 起始与 1 起始混用。

## 9. 背诵卡

1. `nextval[1] = 0`，永远无脑写 0。
2. 先求 `next`，再逐位：`p[j]` 与 `p[next[j]]` **不等 ⇒ 抄 `next[j]`；相等 ⇒ 抄 `nextval[next[j]]`**。
3. 优化本质：跳过「字符相同、注定再失配」的比较；KMP 主逻辑不变，只换数组。
4. 时间复杂度仍是 $O(n+m)$，优化只降常数，不降阶。
5. 位序约定先声明：王道书 1 起始、`next[1]=0`；0 起始则整体平移为 -1。
