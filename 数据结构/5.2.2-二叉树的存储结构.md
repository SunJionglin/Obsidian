# 5.2.2 二叉树的存储结构

## 1. 本节定位

- **王道书对应**：第 5 章「树与二叉树」→ 5.2「二叉树」→ 5.2.2「二叉树的存储结构」。
- **408 大纲对应**：二叉树的概念与存储结构（顺序存储、链式存储）。
- **先修知识**：完全二叉树的编号性质（$i$ 的左孩子 $2i$、右孩子 $2i+1$、父节点 $\lfloor i/2 \rfloor$、层次 $\lfloor \log_2 i \rfloor + 1$）；数组与指针的基本概念。
- **本节位置**：上一节讲二叉树的**逻辑结构**（节点间关系），本节讲**物理存储**（怎么放进内存），是后续遍历、线索二叉树、树与森林转换的基础。

## 2. 一句话结论

**顺序存储只适合完全二叉树（用编号 $i$ 直接算出 $2i$、$2i+1$、$\lfloor i/2 \rfloor$ 反映关系）；一般二叉树用顺序存储会大量浪费空间，实际用二叉链表（左右孩子指针）存储，需要找父节点时再加一个父指针成三叉链表。**

## 3. 知识地图

```
二叉树的存储结构
├── 顺序存储（数组）
│   ├── 完全二叉树：按层序编号，下标=编号，关系由编号公式给出
│   │   ├── 左孩子 2i，右孩子 2i+1，父节点 ⌊i/2⌋
│   │   ├── 有左孩子 ⇔ 2i ≤ n
│   │   ├── 有右孩子 ⇔ 2i+1 ≤ n
│   │   └── 叶子 ⇔ i > ⌊n/2⌋
│   └── 非完全二叉树：补成完全二叉树编号，空位用 isEmpty 标记
│       ├── 判孩子只能查 isEmpty 字段
│       └── 空间浪费，最坏需 2^h − 1 个单元
├── 链式存储
│   ├── 二叉链表：data + lchild + rchild
│   │   ├── n 个节点 → 2n 个指针域，其中 n+1 个为空
│   │   └── 找孩子 O(1)，找父节点需遍历
│   └── 三叉链表：data + lchild + rchild + parent
│       └── 找父节点 O(1)，代价是多一个指针域
└── 结论：实际多用链式；顺序存储仅适合完全二叉树
```

## 4. 核心内容

### 4.1 顺序存储（数组实现）

**思路**：把节点按「从上到下、从左到右」的层序放进一维数组，用**数组下标**反映节点编号。

**结构体定义（王道风格）**：

```c
#define MaxSize 100
typedef struct {
    ElemType data;      // 实际存放的数据元素
    bool isEmpty;       // 该位置是否为空节点（true 表示空）
} TreeNode;

TreeNode t[MaxSize];    // 静态数组，容量固定
```

**初始化**：所有位置 `isEmpty = true`，表示初始全空。

```c
void InitTree(TreeNode t[]) {
    for (int i = 0; i < MaxSize; i++)
        t[i].isEmpty = true;
}
```

**存储完全二叉树**：从 `t[1]` 开始存根节点（`t[0]` 空着不用），这样**数组下标 = 节点编号**，直接套用完全二叉树编号公式：

| 操作 | 公式（编号从 1 开始） | 条件 |
|---|---|---|
| 左孩子 | $2i$ | $2i \le n$ 才有左孩子 |
| 右孩子 | $2i+1$ | $2i+1 \le n$ 才有右孩子 |
| 父节点 | $\lfloor i/2 \rfloor$ | $i > 1$ |
| 所在层次 | $\lfloor \log_2 i \rfloor + 1$ | — |
| 是否叶子 | $i > \lfloor n/2 \rfloor$ | — |

> 若从 `t[0]` 开始存根节点，则下标 = 编号 − 1，公式要相应改写（见易错点）。

**存储非完全二叉树**：必须**补成完全二叉树的形状**再编号（空缺位置 `isEmpty = true`），否则编号无法反映父子关系。此时：

- 判孩子**不能**再用 $2i \le n$，只能查 `t[2i].isEmpty` 是否为 `false`；
- 空间浪费严重：高度为 $h$ 的二叉树，最坏（所有节点只有右分支）也要 $2^h - 1$ 个存储单元，即按满二叉树预留。

**结论（408 必考）**：顺序存储结构**只适合完全二叉树**，实际应用很少用。

### 4.2 链式存储（二叉链表）

**结构体定义**：

```c
typedef struct BiTNode {
    ElemType data;                  // 数据域
    struct BiTNode *lchild, *rchild; // 左、右孩子指针
} BiTNode, *BiTree;
```

- 无左/右孩子时，对应指针置 `NULL`。
- 每个节点 2 个指针域，$n$ 个节点共 $2n$ 个指针域；除根节点外每个节点被一个指针指向，故**空指针域 = $2n - (n-1) = n+1$ 个**（这些空指针域正是线索二叉树的利用对象）。

**构建（从空树到有树）**：

```c
BiTree root = NULL;                 // 空树

BiTNode *p = (BiTNode *)malloc(sizeof(BiTNode)); // 申请根节点
p->data = 1;
p->lchild = p->rchild = NULL;
root = p;                           // root 指向根

p = (BiTNode *)malloc(sizeof(BiTNode)); // 申请新节点
p->data = 2;
p->lchild = p->rchild = NULL;
root->lchild = p;                   // 挂为根的左孩子
```

**找孩子 vs 找父节点**：

- 找左/右孩子：直接读 `p->lchild` / `p->rchild`，$O(1)$。
- 找父节点：二叉链表**没有父指针**，只能从根开始遍历，检查哪个节点的 `lchild` 或 `rchild` 等于 `p`，最坏 $O(n)$。

### 4.3 三叉链表（王道书扩展，了解即可）

若应用频繁需要「逆向找父节点」，在结构体中加一个 `parent` 指针：

```c
typedef struct BiTNode {
    ElemType data;
    struct BiTNode *lchild, *rchild;
    struct BiTNode *parent;   // 父指针
} BiTNode, *BiTree;
```

- 找父节点变为 $O(1)$，代价是多一个指针域的空间。
- **408 常考的是不带父指针的二叉链表**，三叉链表作为对比了解。

## 5. 复杂度分析

设二叉树节点数为 $n$，高度为 $h$。

| 操作 | 顺序存储（完全二叉树） | 二叉链表 | 三叉链表 |
|---|---|---|---|
| 找左/右孩子 | $O(1)$（下标计算） | $O(1)$ | $O(1)$ |
| 找父节点 | $O(1)$（$\lfloor i/2 \rfloor$） | $O(n)$（遍历） | $O(1)$ |
| 找第 $i$ 个节点 | $O(1)$（下标） | $O(n)$ | $O(n)$ |
| 空间 | 最坏 $2^h - 1$ 个单元 | $n$ 个节点 × 3 域 | $n$ 个节点 × 4 域 |

**平均情况推导（找父节点，二叉链表）**：假设目标节点等概率为 $n$ 个节点之一，从根开始遍历，平均需检查约 $n/2$ 个节点，故平均 $O(n)$；最坏（目标在最后被检查到）$O(n)$；最好（目标是根的孩子，第一个就命中）$O(1)$。

**空间浪费推导（顺序存储非完全二叉树）**：高度 $h$ 的二叉树，按满二叉树编号需 $2^h - 1$ 个单元；而实际节点可能只有 $h$ 个（全右分支），浪费率约 $(2^h - 1 - h)/(2^h - 1) \to 1$，故不适合一般二叉树。

## 6. 易错点与考试写法

1. **编号从 1 还是从 0 开始**：王道默认从 1 开始（`t[0]` 空置），此时下标 = 编号。若从 0 开始存根，则左孩子 $2i+1$、右孩子 $2i+2$、父节点 $\lfloor (i-1)/2 \rfloor$。**答题时必须先声明编号起点**。
2. **非完全二叉树判孩子**：不能用 $2i \le n$，必须查 `isEmpty` 字段，因为补空后的「节点总数」不是真实节点数。
3. **空指针域个数 $n+1$**：推导是 $2n - (n-1)$，别记成 $n$ 或 $2n-1$。
4. **顺序存储的「节点总数 $n$」**：完全二叉树中 $n$ 是真实节点数；非完全二叉树补空后数组长度是 $2^h-1$，两者不同，公式不能混用。
5. **答题程度**：选择题考结论（适合完全二叉树、空指针数、编号公式）；算法题只需写出结构体定义 + 基本操作（找孩子/父节点），不必写完整建树代码，但 `malloc` 后必须初始化左右指针为 `NULL`。

## 7. 408 题型与解题套路

- **选择题高频**：
  - 「顺序存储适合什么二叉树」→ 完全二叉树。
  - 「$n$ 个节点的二叉链表有多少空指针域」→ $n+1$。
  - 「高度 $h$ 的二叉树顺序存储至少需要多少单元」→ $2^h - 1$。
  - 给编号求孩子/父节点/层次，注意编号起点。
- **算法题套路**：定义 `BiTNode` 结构体 → 用 `malloc` 建节点 → 递归或遍历挂接；找父节点类题目若要求高效，先声明用三叉链表。
- **陷阱**：题目说「用数组存储二叉树」时，先判断是否完全二叉树；非完全二叉树必须补空，否则编号公式失效。

## 8. 自测题

**题 1** 一棵有 10 个节点的完全二叉树用顺序存储（从 1 开始编号），节点 4 的左孩子、右孩子、父节点编号分别是多少？它是否是叶子？

**题 2** 一棵高度为 5 的二叉树，若所有节点都只有右孩子，用顺序存储至少需要多少个存储单元？

**题 3** 一棵有 20 个节点的二叉树采用二叉链表存储，空指针域有多少个？

**题 4** 非完全二叉树用顺序存储时，判断节点 $i$ 是否有左孩子应该用什么方法？为什么不能用 $2i \le n$？

**题 5** 二叉链表和三叉链表的主要区别是什么？各自适合什么场景？

<details>
<summary>答案</summary>

**题 1**：左孩子 $2 \times 4 = 8$，右孩子 $2 \times 4 + 1 = 9$，父节点 $\lfloor 4/2 \rfloor = 2$。叶子判定：$i > \lfloor n/2 \rfloor = \lfloor 10/2 \rfloor = 5$，$4 \le 5$，故**不是叶子**。

**题 2**：高度 5 的满二叉树有 $2^5 - 1 = 31$ 个节点，顺序存储按满二叉树预留，至少 **31** 个单元（实际只有 5 个节点，浪费 26 个）。

**题 3**：空指针域 $= n + 1 = 20 + 1 = 21$ 个。

**题 4**：查 `t[2i].isEmpty` 是否为 `false`。因为非完全二叉树补空后，数组中的「位置总数」是 $2^h-1$，不是真实节点数 $n$，用 $2i \le n$ 会把空位误判为存在的孩子。

**题 5**：三叉链表比二叉链表多一个 `parent` 指针。二叉链表找孩子 $O(1)$、找父节点 $O(n)$，适合以「向下访问」为主的场景；三叉链表找父节点 $O(1)$，适合频繁「向上找父节点」的场景，代价是多一个指针域空间。408 常考二叉链表。

</details>

## 9. 背诵卡

1. 顺序存储只适合**完全二叉树**；编号从 1 开始，左 $2i$、右 $2i+1$、父 $\lfloor i/2 \rfloor$、层次 $\lfloor \log_2 i \rfloor + 1$。
2. 完全二叉树：有左孩子 ⇔ $2i \le n$；有右孩子 ⇔ $2i+1 \le n$；叶子 ⇔ $i > \lfloor n/2 \rfloor$。
3. 非完全二叉树顺序存储必须**补成完全二叉树编号**，判孩子查 `isEmpty`，空间最坏需 $2^h - 1$ 个单元。
4. 二叉链表：`data + lchild + rchild`；$n$ 个节点有 $2n$ 个指针域，**空指针域 $n+1$ 个**。
5. 二叉链表找孩子 $O(1)$、找父 $O(n)$；三叉链表加 `parent` 后找父 $O(1)$，408 常考二叉链表。
