# 8.2.3 希尔排序（Shell Sort）

## 1. 本节定位

- **王道书**：第 8 章「排序」→ 8.2「插入排序」→ 8.2.3 希尔排序。
- **408 大纲**：排序 → 插入排序（直接插入排序、折半插入排序、**希尔排序**）。希尔排序属于大纲明确要求掌握的基本排序算法之一。
- **先修知识**：直接插入排序（8.2.1）——希尔排序是它的优化；顺序表随机访问特性。
- **位置**：插入排序一族的最后一个算法，是「插入排序」向「分组预处理」思想的延伸，为后面学习「分治类排序」（快速排序、归并排序）做思想铺垫。

## 2. 一句话结论

**希尔排序 = 按增量 $d$ 把序列拆成若干「相距 $d$ 的子表」，对每个子表做直接插入排序，再让 $d$ 逐步缩小到 1，最终整体有序；它是不稳定的、只能用于顺序表的原地排序，时间复杂度依赖增量序列，最坏 $O(n^2)$，平均约 $O(n^{1.3})$。**

## 3. 知识地图

```
希尔排序
├── 思想来源
│   └── 直接插入排序在「基本有序」时效率高 → 先局部有序，再逼近全局有序
├── 核心操作
│   ├── 设定增量 d（初始常取 n/2，每趟减半，直到 d=1）
│   ├── 按「下标相差 d」划分子表
│   └── 对每个子表分别做直接插入排序
├── 增量序列
│   ├── 希尔本人建议：n/2, n/4, …, 1（折半）
│   └── 考试常见：任意给定序列，如 3,1；4,2,1
├── 代码实现（基于顺序表）
│   ├── 外层：d 从 n/2 递减到 1
│   ├── 中层：i 从 d+1 到 n（轮流处理各子表）
│   └── 内层：对子表做直接插入（步长为 d）
└── 性能
    ├── 空间 O(1)

    └── 稳定性：不稳定
```

## 4. 核心内容

### 4.1 定义与思想

**定义**：希尔排序（Shell Sort，又称缩小增量排序）先将待排序表分割成若干形如 $L[i, i+d, i+2d, \dots]$ 的「特殊子表」，对每个子表分别进行直接插入排序；然后缩小增量 $d$，重复上述过程，直到 $d=1$，此时所有记录在同一表中，再做一次直接插入排序。

**思想来源**：直接插入排序在序列**基本有序**时效率很高（元素移动次数少）。希尔排序就是先让序列「部分有序」，再逐步逼近「全局有序」，从而减少总的移动次数。

> 例：序列 `49 38 65 97 76 13 27 49`，取 $d=4$：
> - 子表1：`49, 76` → 已有序
> - 子表2：`38, 13` → 排序后 `13, 38`
> - 子表3：`65, 27` → 排序后 `27, 65`
> - 子表4：`97, 49` → 排序后 `49, 97`
>
> 第一趟结果：`49 13 27 49 76 38 65 97`
> 再取 $d=2$，划分子表继续排序；最后 $d=1$ 整体插入排序。

### 4.2 增量序列

- **希尔建议**：$d_1 = \lfloor n/2 \rfloor$，$d_{i+1} = \lfloor d_i/2 \rfloor$，直到 $d=1$。
- **考试常见**：题目直接给定增量序列（如 $d=3,1$ 或 $d=4,2,1$），按给定值执行即可。
- 增量序列的选取直接影响排序趟数和每趟比较/移动次数，**目前没有数学上证明的最优增量序列**。

### 4.3 代码实现（王道风格，C 语言）

前提：顺序表 `ElemType A[]`，下标从 1 开始，`A[0]` 作哨兵/暂存单元，长度 `n`。

```c
void ShellSort(ElemType A[], int n) {
    int d, i, j;
    // 增量 d 从 n/2 开始，每趟减半，直到 d=1
    for (d = n / 2; d >= 1; d = d / 2) {
        // i 从 d+1 开始，轮流处理各子表的第 2 个元素起
        for (i = d + 1; i <= n; i++) {
            if (A[i] < A[i - d]) {        // 当前元素小于同子表前一个元素
                A[0] = A[i];              // 暂存到 A[0]
                for (j = i - d; j > 0 && A[0] < A[j]; j -= d)
                    A[j + d] = A[j];      // 同子表内后移，步长为 d
                A[j + d] = A[0];          // 插入到正确位置
            }
        }
    }
}
```

**关键行说明**：

- `for (d = n/2; d >= 1; d = d/2)`：增量序列，每趟减半。
- `i = d + 1`：每个子表的第一个元素天然有序，从第二个元素（下标 $d+1$）开始插入。
- `A[i] < A[i - d]`：与**同子表**的前一个元素比较（相距 $d$，不是 $i-1$）。
- `j -= d`：在子表内向前跳，步长为 $d$。
- `A[j + d] = A[j]`：后移也是跳 $d$ 位，不是 $j+1$。
- `A[j + d] = A[0]`：插入位置是 $j+d$。

> **注意**：王道代码中 `i` 是逐个加 1 的，即**轮流**处理不同子表（先处理子表1的第2个、子表2的第2个……），而不是把一个子表处理完再处理下一个。两种写法结果相同，考试按题目要求或按王道代码写即可。

### 4.4 图解（以 $d=4 \to 2 \to 1$ 为例）

```
初始：  49  38  65  97  76  13  27  49
d=4：   [49] 38  65  97 [76] 13  27  49
       子表1: 49,76   子表2: 38,13   子表3: 65,27   子表4: 97,49
       排序后：49  13  27  49  76  38  65  97
d=2：   [49] 13 [27] 49 [76] 38 [65] 97
       子表1: 49,27,76,65   子表2: 13,49,38,97
       排序后：27  13  49  38  65  49  76  97
d=1：   整体直接插入排序 → 13  27  38  49  49  65  76  97
```

## 5. 复杂度分析

### 5.1 空间复杂度

只用 `A[0]` 一个暂存单元和若干循环变量，**$O(1)$**，原地排序。

### 5.2 时间复杂度

- **最坏情况**：$O(n^2)$。理由：若第一趟就取 $d=1$，希尔排序退化为直接插入排序，而直接插入排序最坏为 $O(n^2)$（逆序时每次都要移动前面所有元素）。因此希尔排序最坏不可能优于 $O(n^2)$。
- **平均情况**：约 $O(n^{1.3})$（经验值，非严格证明）。推导思路：增量较大时，每个子表很短，插入排序代价小；增量减小时，序列已「基本有序」，插入排序接近线性。总代价约为各趟代价之和，经验上在 $n$ 的 1.3 次方量级。**注意：这是实验/经验结论，数学上尚未严格证明，考试若问「平均时间复杂度」答 $O(n^{1.3})$ 即可，并说明依赖增量序列。**
- **最好情况**：与增量序列有关，若序列已基本有序，可接近 $O(n \log n)$ 量级（推断，教材未给严格值）；考试一般不考最好情况的具体值。

### 5.3 稳定性

**不稳定**。反例：序列 `49, 38, 65, 97, 76, 13, 27, 49`（两个 49，后一个带下划线），取 $d=2$ 时，带下划线的 49 可能与前面的 49 交换相对次序，最终排序后两个 49 的顺序可能颠倒。

### 5.4 适用性

**只能用于顺序表**，不能用于链表。原因：需要按增量 $d$ 快速定位同子表元素（随机访问），链表无法 $O(1)$ 定位。

## 6. 易错点与考试写法

1. **子表划分看「下标差 $d$」，不是「相邻」**：比较和移动的步长都是 $d$，不是 1。
2. **`i` 的起点是 $d+1$**：每个子表第一个元素天然有序，从第二个开始插入。
3. **增量序列必须递减到 1**：最后一趟 $d=1$ 保证全局有序；若题目给定序列不含 1，需按题目要求执行（但通常最终会到 1）。
4. **稳定性判断**：希尔排序不稳定，选择题常考「以下哪个排序算法不稳定」。
5. **不能用于链表**：选择题常考「希尔排序是否适合链表」——不适合。
6. **时间复杂度不能写 $O(n \log n)$**：最坏是 $O(n^2)$，平均约 $O(n^{1.3})$，不要与快速排序/归并排序混淆。
7. **答题写到什么程度算对**：
   - 选择题：能根据给定增量序列手动模拟每一趟结果。
   - 算法题：能写出上述三重循环代码，注释清楚增量、子表、插入三步即可；不要求证明复杂度。

## 7. 408 题型与解题套路

### 7.1 选择题常见考法

- **给序列和增量序列，问某趟排序后的结果**：按「下标差 $d$ 分组 → 每组直接插入排序 → 合并」逐步模拟。这是最高频考法。
- **问稳定性**：希尔排序不稳定。
- **问时间复杂度**：最坏 $O(n^2)$，平均约 $O(n^{1.3})$。
- **问适用存储结构**：只能顺序表，不能链表。
- **问增量序列是否合法**：必须递减且最终为 1（按题目给定执行）。

### 7.2 算法题套路

- 若要求「写出希尔排序算法」：套用上述三重循环模板，注意步长为 $d$、哨兵 `A[0]`。
- 若要求「分析某增量序列下的比较次数/移动次数」：逐趟模拟，统计每趟每个子表的比较和移动。

### 7.3 常见陷阱

- 把「子表内相邻」误认为「原序列相邻」。
- 忘记最后一趟 $d=1$。
- 把希尔排序当成稳定排序。
- 把平均复杂度写成 $O(n \log n)$。

**题 1**：对序列 `49, 38, 65, 97, 76, 13, 27, 49` 进行希尔排序，增量序列为 $4, 2, 1$，写出第一趟（$d=4$）排序后的结果。

子表1：`49, 76` → 不变；子表2：`38, 13` → `13, 38`；子表3：`65, 27` → `27, 65`；子表4：`97, 49` → `49, 97`。
结果：`49, 13, 27, 49, 76, 38, 65, 97`。
</details>

**题 2**：希尔排序的平均时间复杂度约为多少？最坏情况呢？为什么最坏是 $O(n^2)$？

<details>
<summary>答案</summary>

平均约 $O(n^{1.3})$（经验值，依赖增量序列）；最坏 $O(n^2)$。因为若第一趟增量就取 $d=1$，希尔排序退化为直接插入排序，而直接插入排序最坏为 $O(n^2)$。
</details>

**题 3**：希尔排序是否稳定？是否可用于链表？说明理由。

<details>
<summary>答案</summary>

不稳定（相同关键字元素可能因跨子表移动而改变相对次序）；不可用于链表，因为需要按增量 $d$ 随机访问同子表元素，链表不支持 $O(1)$ 随机访问。
</details>

**题 4**：写出希尔排序的核心代码（C 语言，顺序表下标从 1 开始，`A[0]` 作暂存）。

<details>
<summary>答案</summary>

```c
void ShellSort(ElemType A[], int n) {
    int d, i, j;
    for (d = n / 2; d >= 1; d = d / 2) {
        for (i = d + 1; i <= n; i++) {
            if (A[i] < A[i - d]) {
                A[0] = A[i];
                for (j = i - d; j > 0 && A[0] < A[j]; j -= d)
                    A[j + d] = A[j];
                A[j + d] = A[0];
            }
        }
    }
}
```
</details>

**题 5**：判断：希尔排序的增量序列必须每次减半。（ ）

<details>
<summary>答案</summary>

错误。减半只是希尔本人建议的一种取法，考试中常给定其他增量序列（如 $3,1$），只要按题目给定执行即可，但最终应递减到 1 以保证全局有序。
</details>

## 9. 背诵卡

1. **希尔排序 = 分组直接插入排序**：按增量 $d$ 划分子表（下标差 $d$），对每个子表做直接插入排序，$d$ 逐步减到 1。
2. **增量序列**：常取 $n/2, n/4, \dots, 1$；考试按题目给定序列执行。
3. **代码三要素**：外层 $d$ 递减；中层 $i$ 从 $d+1$ 到 $n$；内层步长 $d$ 的插入。
4. **复杂度**：空间 $O(1)$；时间最坏 $O(n^2)$，平均约 $O(n^{1.3})$；**不稳定**；**只能顺序表**。
5. **最坏退化**：若第一趟 $d=1$，退化为直接插入排序，故最坏 $O(n^2)$。

## 10. 关联与下一节

- **前接**：直接插入排序（8.2.1）——希尔排序是它的分组优化；折半插入排序（8.2.2）——同属插入类，但优化的是「查找插入位置」。
- **后续**：8.3 交换排序（冒泡排序、快速排序）——从「插入」思想转向「交换/分治」思想；希尔排序的「分组预处理」思想与快速排序的「分治」有相通之处。
- **整章位置**：插入排序一族收尾，接下来进入交换排序，最后是选择排序、归并排序、基数排序，形成完整排序算法体系。
