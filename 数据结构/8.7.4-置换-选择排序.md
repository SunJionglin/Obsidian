# 8.7.4 置换-选择排序

## 1. 本节定位

- **对应王道书**：第 8 章「排序」→ 8.7 外部排序 → 8.7.4 置换-选择排序（构造初始归并段）。
- **408 大纲对应**：外部排序（归并趟数、初始归并段的构造、多路平衡归并与败者树、置换-选择排序、最佳归并树）中「置换-选择排序」条目。
- **先修知识**：外部排序的总趟数公式 $s=\lceil \log_k r \rceil$（$r$ 为初始归并段个数，$k$ 为归并路数）；内存工作区（内部排序缓冲区）概念；简单选择排序思想。
- **在整章中的位置**：上一节解决「$k$ 路归并如何减少比较次数」（败者树），本节解决「如何减少初始归并段个数 $r$」，从而减少归并趟数 $s$，减少磁盘 I/O。是外部排序优化的第二条主线。

## 2. 一句话结论

置换-选择排序利用「内存工作区 + 输出缓冲 + 变量 MINIMAX」反复选出工作区中不小于上次输出值的最小记录输出，使生成的初始归并段长度可以**超过内存工作区容量**，从而减少初始归并段个数 $r$，进而减少归并趟数与磁盘读写次数。

## 3. 知识地图

```
外部排序效率优化
├── 减少归并趟数 s = ⌈log_k r⌉
│   ├── 增大归并路数 k（多路平衡归并 + 败者树）   ← 上一节
│   └── 减少初始归并段个数 r                      ← 本节
│       ├── 土办法：内存工作区容量 = 归并段长度上限
│       │      r = ⌈n / l⌉（l 为工作区容量）
│       └── 置换-选择排序
│             ├── 数据结构：内存工作区（容量 w）、输入缓冲、输出缓冲、MINIMAX
│             ├── 规则：选 ≥ MINIMAX 的最小者输出，并更新 MINIMAX
│             ├── 段结束条件：工作区内所有记录都 < MINIMAX
│             └── 效果：归并段平均长度 ≈ 2w（了解即可）
└── 最佳归并树（下一节）
```

## 4. 核心内容

### 4.1 问题背景：土办法的局限

设文件共 $n$ 个记录，内存工作区只能容纳 $l$ 个记录。土办法是：读入 $l$ 个记录 → 内部排序 → 整段写回外存，得到一个长度恰为 $l$ 的初始归并段。于是

$$r=\left\lceil \frac{n}{l}\right\rceil$$

归并段长度被内存容量**硬性卡死**。视频例子：$n=24$，$l=3$，土办法得 $r=24/3=8$ 个归并段。

> 注意：视频中「内存工作区只能容纳两个记录」「只能容纳六个记录」是不同举例场景下的口误/不同设定，核心结论统一为 $r=\lceil n/l\rceil$。

### 4.2 置换-选择排序的思想

**关键观察**：一个归并段只要求**内部递增**，并不要求它一次装下。只要新输出的记录不小于本段上一次输出的记录，就可以继续接在本段后面。因此不必等整个工作区排好序再整段输出，而是「边读边选边输出」。

**核心变量 MINIMAX**：记录**当前归并段上一次输出的关键字值**（即本段已输出记录的最大值）。

**选择规则**（构造递增归并段）：

1. 从内存工作区中选出**关键字 ≥ MINIMAX 的最小记录**输出到当前归并段，并令 MINIMAX ← 该记录关键字；
2. 工作区空出一个位置，从输入文件读入下一个记录填入；
3. 若工作区中**所有记录都 < MINIMAX**，则当前归并段结束，开始下一段（此时 MINIMAX 重置为该段第一个输出值，工作区中记录全部「解冻」参与下一段）。

**为什么能超过工作区容量**：输出一个记录立刻补入一个新记录，工作区始终是满的，但归并段可以不断「接力」变长——只要新读入的记录不比 MINIMAX 小，就能继续接上。

### 4.3 图解（视频例子，$n=24$，工作区容量 $w=3$）

初始读入 3 个记录填满工作区，然后循环执行 4.2 的规则。演示中：

- 归并段一：4, 6, 7, 9, 11, 13, 14, 16, 22, 30（长度 10 > 3）
- 归并段二：2, 3, 10, 17, 19, 20, 23, 36（长度 8 > 3）
- 归并段三：1, 5, 12, …（剩余记录依次输出）

最终只得到 **3 个**初始归并段，而土办法要 8 个。$r$ 从 8 降到 3，归并趟数 $s=\lceil\log_k r\rceil$ 随之下降，磁盘读写次数减少。

> 视频中「标红」的记录 = 当前工作区中 < MINIMAX、本段不能输出的记录，它们留到下一段。

### 4.4 算法伪代码（王道风格，能读懂、能默写）

前提：`WA` 为内存工作区数组，容量 `w`；`MINIMAX` 为当前段已输出最大值；`R` 为待排序文件（外存），按块读入输入缓冲。

```c
// 置换-选择排序：构造初始归并段
// WA[0..w-1] 内存工作区；MINIMAX 当前归并段已输出关键字最大值
void ReplaceSelection(int w) {
    for (int i = 0; i < w; i++)      // 初始填满工作区
        WA[i] = ReadNextRecord();    // 从输入缓冲取一个记录
    MINIMAX = -∞;                    // 第一段开始，任何记录都可输出
    while (工作区非空) {
        // 在工作区中找 >= MINIMAX 的最小记录
        j = SelectMinGE(WA, w, MINIMAX);
        if (j == -1) {               // 工作区所有记录都 < MINIMAX
            // 当前归并段结束，输出段结束标记，开始新段
            MINIMAX = -∞;            // 重置，工作区记录全部解冻
            continue;
        }
        Output(WA[j]);               // 输出到输出缓冲区（满一块才写盘）
        MINIMAX = WA[j];             // 更新本段已输出最大值
        WA[j] = ReadNextRecord();    // 空位补入下一个记录
    }
}
```

要点注释：

- `SelectMinGE` 是「选择」：在满足 ≥ MINIMAX 的记录中选最小者——这就是算法名中「选择」的由来。
- `Output` 先写**输出缓冲区**，缓冲区满一块才整块写回外存；输入同理按块读入——磁盘 I/O 以**磁盘块**为单位，不是逐记录读写（视频专门强调）。
- 「置换」指每次用一个新记录把工作区中被选中的记录**置换出去**。

### 4.5 与土办法对比

| 项目 | 土办法（内部排序整段输出） | 置换-选择排序 |
|---|---|---|
| 归并段长度 | 恰为 $l$（工作区容量） | 可超过 $l$，平均约 $2l$（了解即可） |
| 归并段个数 $r$ | $\lceil n/l\rceil$ | 明显更少 |
| 内存要求 | 工作区 $l$ | 工作区 $w$ + 输入/输出缓冲区 |
| 段内有序性 | 整段内部有序 | 段内递增（靠 MINIMAX 保证） |

## 5. 复杂度分析

设文件 $n$ 个记录，工作区容量 $w$，每个归并段平均长度记为 $L$。

- **归并段个数**：$r \approx n/L$。土办法 $L=w$；置换-选择排序在记录关键字随机分布时 $L\approx 2w$（**了解即可，408 不要求推导**），故 $r$ 约减半。
- **每输出一个记录的选择代价**：在工作区 $w$ 个记录中线性扫描找「≥ MINIMAX 的最小者」，最坏 $O(w)$。共输出 $n$ 个记录，故**总时间 $O(nw)$**（最坏/平均同阶，平均常数更小）。
  - 最好情况：若用堆/败者树维护工作区（王道书扩展，非本节重点），单次选择可降到 $O(\log w)$，总时间 $O(n\log w)$。
- **空间**：工作区 $O(w)$ + 输入/输出缓冲区 $O(1)$ 块，即 $O(w)$。
- **磁盘 I/O**：生成阶段读写各约 $n$ 个记录（按块计为 $\lceil n/\text{块大小}\rceil$ 块）；真正收益在**归并阶段**——$r$ 减小使归并趟数 $s=\lceil\log_k r\rceil$ 减小，每趟都要全量读写一遍文件，故总 I/O 显著下降。

> 平均情况说明：平均长度 $2w$ 的结论基于「关键字随机排列」的假设，属于概率性结论，408 只需记住「可超过工作区容量、$r$ 变小」这一层。

## 6. 易错点与考试写法

1. **MINIMAX 的含义**：是「当前归并段**已输出**记录的最大值」，不是工作区最小值，也不是全局最小值。选记录的条件是「≥ MINIMAX」，不是「> MINIMAX」的严格版本（相等可接，因为归并段允许非递减）。
2. **段结束条件**：工作区中**所有**记录都 < MINIMAX 才结束本段；只要还有一个 ≥ MINIMAX，就继续输出。视频中「标红」的记录是 < MINIMAX 的，不能输出但**不能丢弃**，要留到下一段。
3. **新段开始时 MINIMAX 重置**：重置为 $-\infty$（或该段第一个输出值），工作区中所有记录「解冻」重新参与选择。
4. **磁盘 I/O 单位是块**：答题时若问「输出到外存」，应写「先写输出缓冲区，满一块后整块写回」，不能写成逐记录写盘。
5. **不要与「多路归并」「败者树」混淆**：置换-选择排序只负责**生成初始归并段**，不负责归并过程本身。
6. **答题程度**：408 对该考点以**选择题**为主，要求能：①说出算法目的（减少 $r$）；②按给定序列手工模拟生成归并段；③判断某记录能否接入当前段（比较 MINIMAX）。文字描述题写到「选 ≥ MINIMAX 的最小者输出、工作区全小于 MINIMAX 则换段」即算对。

## 7. 408 题型与解题套路

- **选择题（高频）**：
  - 给出工作区容量与记录序列，问「第一个归并段包含哪些记录 / 长度为多少」——**手工模拟**：维护工作区三格 + MINIMAX，逐次选最小且 ≥ MINIMAX 者输出并补入新记录。
  - 问「置换-选择排序的作用」——答：构造更长的初始归并段，减少归并段个数 $r$，从而减少归并趟数和磁盘 I/O。
  - 问「归并段长度能否超过内存工作区容量」——答：能。
- **算法题（低频，了解即可）**：可能要求写出置换-选择排序的伪代码或描述流程，按 4.4 的框架写即可，重点写清 MINIMAX 更新与换段条件。
- **常见陷阱**：
  - 模拟时忘记「补入新记录」导致工作区变空；
  - 把 < MINIMAX 的记录误输出（破坏段内递增）；
  - 把「段结束」误判为「文件结束」——段结束后工作区还有记录，要继续构造下一段；
  - 混淆 $r$ 与 $s$：$r$ 是初始归并段个数，$s$ 是归并趟数，$s=\lceil\log_k r\rceil$。

## 8. 自测题

**题 1** 置换-选择排序的主要目的是（ ）。
A. 减少归并路数 B. 减少初始归并段个数 C. 减少比较次数 D. 实现稳定排序

**题 2** 设内存工作区容量为 3，待排序关键字序列为 4, 6, 7, 9, 11, 13, 14, 16, 22, 30, 2, 3, …（按视频顺序读入），第一个归并段的前 5 个记录是什么？

**题 3** 判断：置换-选择排序生成的初始归并段长度一定不超过内存工作区容量。

**题 4** 工作区中有记录 {10, 14, 2}，MINIMAX = 13，下一个应输出哪个记录？为什么？

**题 5** 文件共 $n=1000$ 个记录，工作区容量 $w=10$。土办法与置换-选择排序（平均段长 $2w$）分别产生多少个初始归并段？若 $k=4$ 路归并，归并趟数各为多少？

<details>
<summary>答案</summary>

**题 1** B。置换-选择排序构造更长的初始归并段，使 $r$ 减小。

**题 2** 4, 6, 7, 9, 11（MINIMAX 依次更新为 4,6,7,9,11；每次选 ≥ MINIMAX 的最小者）。

**题 3** 错。归并段长度可以超过工作区容量（视频例子中容量 3，段长可达 10）。

**题 4** 输出 14。因为 10 < MINIMAX=13 不能输出，2 < 13 不能输出，只有 14 ≥ 13 且是满足条件的最小者。

**题 5** 土办法：$r=\lceil 1000/10\rceil=100$，$s=\lceil\log_4 100\rceil=\lceil 3.32\rceil=4$ 趟；置换-选择排序：平均段长 $2w=20$，$r\approx 1000/20=50$，$s=\lceil\log_4 50\rceil=\lceil 2.82\rceil=3$ 趟。归并趟数减少 1，磁盘读写次数相应下降。

## 9. 背诵卡

1. **目的**：构造更长的初始归并段 → 减少 $r$ → 减少 $s=\lceil\log_k r\rceil$ → 减少磁盘 I/O。
2. **规则**：选工作区中 **≥ MINIMAX 的最小记录**输出，MINIMAX 更新为该值，空位补入新记录。
3. **换段条件**：工作区**所有**记录都 < MINIMAX 时本段结束，MINIMAX 重置，记录解冻进入下一段。
4. **效果**：归并段长度可**超过**内存工作区容量（平均约 $2w$，了解即可）。
5. **I/O 单位**：输入/输出均经缓冲区，**满一块才整块读写磁盘**。

## 10. 关联与下一节

- **向前关联**：外部排序总趟数 $s=\lceil\log_k r\rceil$；上一节败者树解决「增大 $k$ 后比较次数增多」的问题，本节解决「$r$ 太大」的问题，二者共同压缩归并趟数。
