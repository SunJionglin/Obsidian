# 7.3.3 红黑树的定义和性质

## 1. 本节定位

- **对应王道书**：第 7 章「查找」→ 7.3 树型查找 → 7.3.3 红黑树（第一小节：定义与性质）。
- **408 大纲对应条目**：查找 → 红黑树（定义、性质、插入、删除；2022 年大纲新增）。
- **先修知识**：二叉排序树（BST）的定义与查找、平衡二叉树（AVL）的平衡因子与四种旋转（LL/RR/LR/RL）。
- **本章位置**：BST → AVL → **红黑树（RBT）**，三者同属「用于查找的二叉树家族」，红黑树是本章树型查找的收尾与工程化延伸；下一节讲插入操作。

## 2. 一句话结论

红黑树是一棵**带颜色标记的二叉排序树**，用「根叶黑、不红红、黑路同」三条额外约束代替 AVL 的严格高度平衡，从而在**插入/删除时极少调整、且调整可在常数时间内完成**，同时查找仍保持 $O(\log n)$。

## 3. 知识地图

```
红黑树 RBT（Red-Black Tree，1972 年提出）
├── 家族定位：BST(1960) → AVL(1962) → RBT(1972)，均用于查找
├── 发明动机（对比 AVL）
│   ├── AVL：插入/删除易破坏 |平衡因子|≤1 → 频繁调整
│   │        每次需①重算平衡因子 ②找最小不平衡子树 ③四种旋转
│   └── RBT：插入/删除常不破坏性质；即使破坏，调整在 O(1) 内完成
├── 节点结构
│   ├── key（关键字）
│   ├── lchild / rchild（左右孩子指针）
│   ├── parent（父指针，便于自下而上调整）
│   └── color（红/黑，0 黑 1 红 或枚举/布尔）
├── 五条定义（口诀：左根右、根叶黑、不红红、黑路同）
│   ├── ① 是二叉排序树：左 < 根 < 右
│   ├── ② 每个结点非红即黑
│   ├── ③ 根结点黑
│   ├── ④ 叶结点（NIL 空结点/失败结点/外部结点）黑
│   └── ⑤ 任一结点到其所有叶结点的路径上黑结点数相同
├── 黑高 bh(x)：从 x 出发（不含 x）到任一空结点的黑结点数
├── 性质
│   ├── 最长路径 ≤ 2 × 最短路径（由④⑤推出）
│   └── 含 n 个内部结点时 h = O(log n) → 查找 O(log n)
└── 基本操作
    ├── 查找：同 BST，左小右大，落到空结点即失败
    └── 插入：下一节详讲（本节只给方向）
```

## 4. 核心内容

### 4.1 为什么要有红黑树（对比 AVL）

AVL 要求任一结点左右子树高度差不超过 1。该条件**极易被一次插入/删除破坏**，一旦破坏就要：

1. 重新计算各结点平衡因子；
2. 找到最小不平衡子树；
3. 按 LL / RR / LR / RL 旋转调整。

第 1、2 步时间开销大，且**每次插入删除都要做**，故 AVL 的插入删除代价高。

红黑树放松了平衡条件（只约束颜色），插入/删除**很多时候不破坏性质**，无需调整；即使破坏，调整也能在**常数时间**内完成。因此：

- **查多改少** → 用 AVL；
- **频繁插入删除** → 用红黑树（工程中实际普遍用红黑树）。

> 408 必考：这个「为什么发明红黑树」的对比是选择题常考点。

### 4.2 结点定义（王道风格 C）

```c
#define RED   1
#define BLACK 0

typedef struct RBNode {
    ElemType key;              // 关键字
    struct RBNode *lchild;     // 左孩子
    struct RBNode *rchild;     // 右孩子
    struct RBNode *parent;     // 父结点指针（红黑树调整时常用，自下而上找父亲）
    int color;                 // 颜色：RED 或 BLACK
} RBNode, *RBTree;
```

对比：AVL 结点存 `balance`（平衡因子），红黑树结点存 `color`（只有红/黑两种取值）。

### 4.3 五条定义（核心，必须背）

| 编号 | 定义 | 口诀 |
|---|---|---|
| ① | 首先是一棵二叉排序树：左子树 < 根 < 右子树 | **左根右** |
| ② | 每个结点或是红色，或是黑色 | （含在①的“带色”里） |
| ③ | 根结点是黑色 | **根叶黑** |
| ④ | 叶结点（**NIL 空结点/失败结点/外部结点**）是黑色 | **根叶黑** |
| ⑤ | 从任一结点到其所有叶结点的简单路径上，黑结点数目相同 | **黑路同** |
| 附加 | 不存在两个相邻的红结点（红结点的父、子都必须是黑） | **不红红** |

**关键澄清（易错）**：

- 红黑树中的「叶结点」**不是**最底层含关键字的实结点，而是**查找失败时落到的空结点（NIL）**，一律视为黑色。
- 「不红红」只禁止**父子**连续红；**兄弟**同为红是允许的（如 22、27 两红兄弟合法）。
- ⑤ 对**每一个**结点都成立，不只对根。

### 4.4 黑高（bh）

**定义**：结点 x 的**黑高** $bh(x)$ = 从 x 出发（**不含 x 本身**）到达任一空结点（NIL）路径上经过的黑结点总数。

由于「黑路同」，任取一条路径数即可，结果唯一。

例：根结点黑高为 2，表示从根往下到任一 NIL 都经过 2 个黑结点（不含根本身）。

> 黑高是证明红黑树性质的工具，408 只需理解定义，不要求复杂推导。

### 4.5 红黑树的两条重要性质

**性质 1**：从根到叶结点的**最长路径 ≤ 2 × 最短路径**。

推导：由⑤，任一路径黑结点数相同（设为 $bh$）；由「不红红」，红结点不能相邻，故每条路径上红结点数 ≤ 黑结点数。于是：

- 最短路径：全黑，长度 $= bh$；
- 最长路径：红黑交替，长度 $\le 2bh$。

故最长 ≤ 2 × 最短。

**性质 2**：含 $n$ 个内部结点时，树高 $h = O(\log n)$，从而查找为 $O(\log n)$。

推导思路（了解即可）：由性质 1 及黑高与结点数的关系可证 $h \le 2\log_2(n+1)$，故 $h = O(\log n)$。

### 4.6 查找操作

与 BST 完全一致：从根出发，目标 < 当前则走左，> 则走右，相等则成功；走到 NIL 则失败。

## 5. 复杂度分析

设树中内部结点数为 $n$，树高为 $h$。

- **查找**：
  - 最坏：走到最深叶，比较次数 $\le h$，而 $h = O(\log n)$，故 $O(\log n)$。
  - 最好：$O(1)$（根即目标）。
  - 平均：在关键字等概率、树近似平衡的假设下，平均查找长度与 $h$ 同阶，为 $O(\log n)$。
- **插入 / 删除**：
  - 查找插入位置 $O(\log n)$；**调整（变色 + 旋转）为 $O(1)$**（这是红黑树相对 AVL 的核心优势）。
  - 故总代价 $O(\log n)$，但**常数因子远小于 AVL**。

> 对比记忆：AVL 与 RBT 查找同为 $O(\log n)$；差别在插入删除的**调整代价**——AVL 可能 $O(\log n)$ 次旋转，RBT 至多常数次。

## 6. 易错点与考试写法

1. **「叶结点」含义**：红黑树的叶 = NIL 空结点（失败结点），不是最底层实结点。判断题最爱在此设坑。
2. **「不红红」范围**：只禁父子连续红，兄弟双红合法。
3. **根必须黑**：根为红直接判非红黑树。
4. **黑路同对每个结点成立**：判断某树是否红黑树时，不能只看根，要抽查中间结点。
5. **红黑树首先是 BST**：颜色全对但违反「左 < 根 < 右」也不是红黑树（如把 7 放在 8 右边）。
6. **答题标准**：判断「是否红黑树」类题，须**逐条对照口诀**指出违反了哪一条（如“违反不红红”“违反黑路同”），只写“不是”不给分。

## 7. 408 题型与解题套路

**题型一：判断给定树是否为红黑树（选择题，最可能考）**

套路：按口诀顺序查——
1. 左根右（BST 性质）；
2. 根黑？叶（NIL）黑？
3. 有无父子连续红？
4. 从根（及抽查结点）出发数黑结点，各路是否相等？

任一条不满足即判否，并写明违反哪条。

**题型二：红黑树性质判断（选择题）**

如“最长路径 ≤ 2×最短路径”“$h=O(\log n)$”“红黑树是 BST”等，直接背结论。

**题型三：与 AVL 对比（选择题）**

考「为什么用红黑树」「何种场景选哪种」——查多改少选 AVL，频繁增删选 RBT。

**题型四：插入过程（可能考，下一节）**

给插入序列，要求画出插入后形态；**不考代码**（实现复杂，超出 408 初试难度）。删除操作考的概率低。

**常见陷阱**：把 NIL 当普通叶、把兄弟双红判违规、忽略 BST 性质只查颜色。

## 8. 自测题

**3.** 一棵红黑树根结点黑高为 3，则从根到任一 NIL 的路径上黑结点数（不含根）是多少？最短路径长度至少为多少？

**4.** 下列哪项**不是**红黑树的必要条件？

**5.** 简述红黑树相比 AVL 树在插入删除上的优势及其原因。

<summary>答案</summary>

1. 指查找失败时落到的空结点（NIL / 外部结点 / 失败结点），一律规定为**黑色**。

## 9. 背诵卡

1. **家族**：BST(1960) → AVL(1962) → RBT(1972)，都用于查找；查多改少用 AVL，频繁增删用 RBT。
2. **口诀**：**左根右、根叶黑、不红红、黑路同**。
3. **叶 = NIL 空结点**，恒黑；根恒黑；红结点父子必黑，兄弟可双红。
4. **黑高 bh(x)**：x 到任一 NIL 路径上黑结点数（不含 x），各路相等。
5. **性质**：最长路径 ≤ 2×最短路径；$h=O(\log n)$，查找 $O(\log n)$，插入删除调整 $O(1)$。

## 10. 关联与下一节

- **向前关联**：BST 的查找路径、AVL 的平衡因子与四种旋转——红黑树用「颜色」替换「平衡因子」，用「变色+旋转」替换「重算+旋转」。
- **向后关联**：下一节 **7.3.3 红黑树的插入**——从空树开始按插入序列逐步建树，核心是「新结点先染红 → 违反不红红则看叔叔颜色 → 变色或旋转」。删除操作了解即可，408 初试概率低。
- **工程延伸（了解）**：C++ STL `map/set`、Java `TreeMap`、Linux 内核等均用红黑树。
