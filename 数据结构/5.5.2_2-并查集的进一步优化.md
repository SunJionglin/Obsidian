# 5.5.2 并查集的进一步优化

## 1. 本节定位

- **对应王道书**：第 5 章 树与二叉树 → 5.5 并查集 → 5.5.2 并查集的进一步优化（承接上一节“并查集的基本实现与 union 优化”）。
- **408 大纲对应**：并查集（集合的表示与操作）——属于“树与二叉树”应用部分，大纲只要求“掌握并查集的实现与优化思想”，不要求复杂证明。
- **先修知识**：并查集的存储结构（双亲表示法，根结点存负数表示集合大小/元素个数）、`Find` 与 `Union` 的基本实现、上一节的“小树并入大树（union by size/rank）”优化。
- **本节位置**：并查集优化的第二步。上一节优化 `Union`（让树变矮），本节优化 `Find`（路径压缩），两者叠加后树高几乎为常数级，是并查集这一知识点的“收尾结论”。

## 2. 一句话结论

**在 `Find` 操作中找到根后，把查找路径上所有结点直接挂到根下（路径压缩），可使树高不超过 $O(\alpha(n))$，$\alpha(n)$ 增长极慢，常见 $n$ 下 $\alpha(n)\le 4$，`Find` 近似 $O(1)$。**

## 3. 知识地图

```
并查集优化
├── Union 优化（上一节）
│   └── 小树并入大树（按 size/rank 合并）
│       └── 树高 ≤ O(log₂n)
└── Find 优化（本节：路径压缩）
    ├── 查找路径：从指定结点沿双亲指针上溯到根所经过的结点序列
    ├── 做法：找到根后，第二轮循环把路径上每个结点直接挂到根下
    ├── 效果：树高 ≤ O(α(n))，α(n) 增长极慢
    └── 时间复杂度汇总
        ├── 无优化：单次 Find 最坏 O(n)，n 次 Union 总 O(n²)
        ├── 仅 Union 优化：单次 Find 最坏 O(log₂n)，n 次 Union 总 O(n log₂n)
        └── Union + 路径压缩：单次 Find 近似 O(1)，n 次 Union 总 O(n·α(n))
```

## 4. 核心内容

### 4.1 回顾：基本 `Find` 与“查找路径”

并查集用**双亲表示法**数组 `S[]` 存储：非根结点存双亲下标，根结点存负数（绝对值可表示集合元素个数）。

基本 `Find(x)`：从 `x` 出发，沿 `S[]` 一路向上，直到遇到负值（根）。

- **查找路径**：从 `x` 到根所经过的所有结点构成的路径。例如从结点 `l` 出发，路径为 `l → e → b → a`，`a` 为根（`S[a] < 0`）。
- 路径越长，`Find` 越慢；**优化的核心思想就是让树变矮、让查找路径变短**。

### 4.2 路径压缩（path compression）的做法

分两轮：

1. **第一轮**：和普通 `Find` 一样，从 `x` 上溯找到根 `root`。
2. **第二轮**：再从 `x` 出发沿原路径上溯，把路径上每个结点（除根外）的 `S[]` 直接改为 `root`，即全部挂到根下。

效果：下次再查路径上任一结点，只需一步就到根。原路径 `l → e → b → a` 压缩后，`l`、`e` 直接指向 `a`，`b` 本来就在 `a` 下，无需修改。

### 4.3 代码实现（王道风格，C 语言）

```c
// 并查集：双亲表示法，S[root] < 0 表示根，绝对值可存集合大小
int S[MAXSIZE];

// 带路径压缩的 Find：返回 x 所属集合的根
int Find(int x) {
    int root = x;
    while (S[root] >= 0) {      // 第一轮：上溯找根
        root = S[root];
    }
    // 此时 root 为根结点
    while (x != root) {         // 第二轮：压缩路径
        int parent = S[x];      // 暂存 x 原来的双亲
        S[x] = root;            // 把 x 直接挂到根下
        x = parent;             // 沿原路径继续向上处理
    }
    return root;                // 返回根结点编号
}
```

要点：

- 第一轮循环条件用 `S[root] >= 0`（非根），根存负值。
- 第二轮必须先暂存 `S[x]` 再改写，否则路径断掉、无法继续上溯。
- 若 `x` 本身就是根，第二轮不执行，直接返回。
- `Union` 仍配合上一节的“小树并入大树”：先分别 `Find` 两个根，再按集合大小（根结点负值绝对值）决定谁挂谁。

### 4.4 优化效果

- 引入路径压缩后，树高不超过 $O(\alpha(n))$，$\alpha(n)$ 为反阿克曼函数（inverse Ackermann function），增长极慢，远慢于 $\log_2 n$。
- 常见 $n$（如 $n \le 10^4$ 或 $10^3$ 以内）时，$\alpha(n) \le 4$，故 `Find` 时间可视为不超过 $O(4)$，**近似常数级**。
- 注意：$\alpha(n)$ 的具体定义**不要求掌握**，只需记住“增长极慢、常见规模下 ≤ 4、近似常数”。

## 5. 复杂度分析

设集合元素个数为 $n$，树高为 $h$，单次 `Find` 代价与 $h$ 同阶。

| 策略 | 单次 Find 最坏 | n 个独立元素做 n−1 次 Union 的总代价 |
|---|---|---|
| 无任何优化 | $O(n)$（链状退化） | $O(n^2)$ |
| 仅 Union 优化（小树并入大树） | $O(\log_2 n)$ | $O(n\log_2 n)$ |
| Union 优化 + 路径压缩 | $O(\alpha(n))$，常见 $n$ 下 $\le O(4)$ | $O(n\,\alpha(n))$ |

**推导（总代价）**：

- 把 $n$ 个初始独立元素合并成一个集合，需要 $n-1$ 次 `Union`；每次 `Union` 前要先对两个元素各做一次 `Find` 找根。
- 无优化：单次 `Find` 最坏 $O(n)$，故总代价 $O(n \cdot n) = O(n^2)$。
- 仅 Union 优化：单次 `Find` 最坏 $O(\log_2 n)$，总代价 $O(n\log_2 n)$。
- 加路径压缩：单次 `Find` 摊还 $O(\alpha(n))$，总代价 $O(n\,\alpha(n))$。

**平均情况说明（补充，标注为推断）**：路径压缩的严格摊还分析（Tarjan）给出 $m$ 次操作总代价 $O(m\,\alpha(n))$，即**摊还**每次近似 $O(1)$；本节视频只给结论、不给证明，考试按结论记即可。平均意义下可认为单次 `Find` 接近常数，但**最坏单次**仍可能因首次长路径而为 $O(n)$，摊还后才优。

## 6. 易错点与考试写法

1. **第二轮循环的暂存顺序**：必须先 `parent = S[x]` 再 `S[x] = root`，否则丢失上溯路径。这是代码题最常见的错。
2. **根结点判断**：根存负值，循环条件写 `S[root] >= 0`；若误写成 `> 0` 或 `!= 0` 会出错（根可能是 `-1`、`-2` 等）。
3. **路径压缩不改变根**：压缩只改路径上非根结点的双亲指针，根结点 `S[root]` 不变；若 `Union` 用根结点负值存集合大小，压缩时**不能**改动根的值。
4. **区分“单次最坏”与“摊还”**：路径压缩后单次 `Find` 最坏仍可能是 $O(n)$（第一次走长链），但摊还 $O(\alpha(n))$；选择题若问“最坏时间复杂度”要看语境，问“n 次操作总代价/摊还”答 $O(n\alpha(n))$。
5. **$\alpha(n)$ 不要写成 $\log n$**：两者数量级不同，$\alpha(n)$ 远小于 $\log_2 n$；常见 $n$ 下 $\alpha(n)\le 4$ 是常考结论。
6. **答题程度**：408 对并查集以选择题为主，代码题若涉及，写出上述两轮循环的 `Find` 并注释“第一轮找根、第二轮压缩路径”即可；复杂度结论写“树高 $O(\alpha(n))$，近似 $O(1)$”算对，不要求证明。

## 7. 408 题型与解题套路

- **选择题（高频）**：
  - 给出初始集合与一串 `Union`/`Find` 操作，问最终数组 `S[]` 的状态或某次 `Find` 后树的结构——按“先找根、再压缩”逐步模拟，注意压缩后路径上所有点都指向根。
  - 问优化后树高/时间复杂度的数量级：无优化 $O(n)$、仅 Union 优化 $O(\log_2 n)$、加路径压缩 $O(\alpha(n))$。
  - 问“n 个元素合并为一个集合的总时间”：对应 $O(n^2)$、$O(n\log_2 n)$、$O(n\alpha(n))$ 三档。
- **算法题（低频，了解即可）**：可能要求实现 `Find` 并说明优化；套用两轮循环模板，`Union` 配合按大小合并。
- **常见陷阱**：
  - 压缩后误以为根也变（根不变）。
  - 把“小树并入大树”与“路径压缩”混为一谈：前者优化 `Union`，后者优化 `Find`，二者可叠加。
  - 模拟时忘记压缩会改变后续 `Find` 的路径，导致数组状态算错。

A. $O(n)$　B. $O(n\log_2 n)$　C. $O(n^2)$　D. $O(n\,\alpha(n))$

**题 2**：仅 Union 优化时单次 `Find` 最坏 $O(\log_2 n)$；再加路径压缩后树高不超过 $O(\alpha(n))$，常见 $n$ 下 $\alpha(n)\le 4$。

## 9. 背诵卡

1. 路径压缩在 `Find` 中做：**先找根，再把路径上所有非根结点直接挂到根下**。
2. 代码两轮循环：第一轮 `while(S[root]>=0) root=S[root];`，第二轮暂存 `parent` 后 `S[x]=root`。
3. 优化三档：无优化 $O(n)$；仅 Union 优化 $O(\log_2 n)$；Union+路径压缩 $O(\alpha(n))$。
4. 总代价三档：$O(n^2)$、$O(n\log_2 n)$、$O(n\,\alpha(n))$。
5. $\alpha(n)$ 增长极慢，常见 $n$ 下 $\le 4$，`Find` 近似 $O(1)$；核心思想始终是**让树变矮**。
