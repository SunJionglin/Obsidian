# 2.3.6 顺序表和链表的比较

## 1. 本节定位

- **对应王道书**：第 2 章「线性表」2.3 节末尾的比较与总结（2.3.6）。
- **408 大纲对应**：线性表的顺序存储与链式存储实现及比较；线性表基本操作（初始化、插入、删除、查找）的实现与效率分析。
- **先修知识**：顺序表的静态/动态分配、按位查找与按值查找；单链表的头指针/头结点、插入删除的指针修改；`malloc`/`free` 与静态数组的生命周期。
- **在整章中的位置**：第 2 章的收口小节。前面分别学顺序表、单链表（及扩展），本节用「数据结构三要素」把两者横向拉通，是简答题与选择题的高频命题素材，也是进入第 3 章栈、队列、串之前的复习锚点。

## 2. 一句话结论

顺序表与链表逻辑结构相同（都是线性表），差别全在存储结构，进而决定运算效率：**表长难估、频繁插删用链表；表长可估、查询为主用顺序表**。

## 3. 知识地图

```
顺序表 vs 链表（按数据结构三要素展开）
├── 1. 逻辑结构
│   └── 二者都是线性结构（线性表），元素间一对一
├── 2. 存储结构
│   ├── 顺序表：顺序存储
│   │   ├── 连续空间 + 元素等长 + 起始地址 ⇒ 随机存取 O(1)
│   │   ├── 只存数据，不存指针 ⇒ 存储密度高
│   │   └── 需一整片连续空间 ⇒ 分配不便、扩容不便
│   └── 链表：链式存储
│       ├── 结点离散存放，靠指针相连 ⇒ 不可随机存取
│       ├── 每结点额外存指针 ⇒ 存储密度低
│       └── malloc 按需申请小片空间 ⇒ 分配灵活、扩容方便
└── 3. 基本运算
    ├── 初始化（创建）
    │   ├── 顺序表：预分配大片连续空间（小了难扩、大了浪费）
    │   └── 链表：声明头指针 + 分配头结点（可无头结点），扩容只需 malloc 新结点再链接
    ├── 销毁
    │   ├── 顺序表：length=0；静态分配由系统回收，动态分配需手动 free
    │   └── 链表：循环遍历各结点依次 free
    ├── 插入 / 删除
    │   ├── 顺序表：移动元素，O(n)，时间花在「移动」
    │   └── 链表：改指针，O(n)，时间花在「找位置」
    └── 查找
        ├── 按位查找：顺序表 O(1)（随机存取）；链表 O(n)
        └── 按值查找：顺序表无序 O(n)、有序可折半 O(log n)；链表恒 O(n)
```

## 4. 核心内容

### 4.1 逻辑结构：相同

二者都是**线性结构**，数据元素之间是一对一关系，都属于线性表。比较时这一条只用来「定性」，不产生效率差异。

### 4.2 存储结构：根本差异所在

**顺序表（顺序存储）**

- 用一组**地址连续**的存储单元依次存放元素，元素大小相等。
- 只要知道起始地址（数组名/基址）和下标，就能直接算出元素地址：第 $i$ 个元素的地址 $=\text{基址}+(i-1)\times sizeof(\text{ElemType})$。这就是**随机存取**（random access）的根据：连续 + 等长 + 起始地址，三者缺一不可。
- 结点内只存数据元素本身，不存指针等冗余信息，**存储密度 = 1**（存储密度 = 数据本身占用 / 结点总占用）。
- 代价：必须一次分配**一整片连续空间**，分配不便；扩容不便。

**链表（链式存储）**

- 结点可**离散**存放，靠指针域串起来。
- 找第 $i$ 个结点只能从头指针出发沿 `next` 逐个走，**不可随机存取**。
- 每个结点除数据域外还要存指针域，**存储密度 < 1**。
- 好处：新增结点只需 `malloc` 一小片空间，容量改变方便、灵活。

### 4.3 基本运算对比

**（1）初始化**

顺序表静态分配（王道风格）：

```c
#define MaxSize 50
typedef struct {
    ElemType data[MaxSize];  // 静态数组，空间由系统分配
    int length;              // 当前长度
} SqList;

void InitList(SqList *L) {
    L->length = 0;           // 逻辑上置空即可，数组空间已随变量分配
}
```

顺序表动态分配：

```c
#define InitSize 100
typedef struct {
    ElemType *data;   // 指向动态数组，malloc 申请
    int MaxSize;      // 当前容量
    int length;       // 当前长度
} SeqList;

void InitList(SeqList *L) {
    L->data = (ElemType *)malloc(InitSize * sizeof(ElemType)); // 堆区
    L->length = 0;
    L->MaxSize = InitSize;
}
```

要点：顺序表初始化就要**预分配大片连续空间**——分小了以后难扩，分大了长期空闲、浪费内存。

链表初始化：

```c
typedef struct LNode {
    ElemType data;
    struct LNode *next;
} LNode, *LinkList;

bool InitList(LinkList *L) {          // 带头结点
    *L = (LNode *)malloc(sizeof(LNode)); // 只分配一个头结点
    if (*L == NULL) return false;
    (*L)->next = NULL;
    return true;
}
```

要点：链表初始化只需**头指针 + 一个头结点**（也可不带头结点）；以后扩容只需 `malloc` 新结点再用指针链入，**存储容量弹性好**。

**（2）销毁**

- 链表：本质是「依次删除所有结点」，核心是 `free`，循环扫描逐个释放：

```c
void DestroyList(LinkList *L) {
    LNode *p = *L, *q;
    while (p != NULL) {
        q = p->next;
        free(p);        // 每个结点都是 malloc 来的，必须逐个 free
        p = q;
    }
    *L = NULL;
}
```

- 顺序表：先把 `length` 置 0（逻辑上变空表），空间回收分两种：
  - **静态分配**：空间是静态数组，生命周期结束由系统自动回收，不用管；
  - **动态分配**：空间来自 `malloc`（堆区），必须手动 `free(L->data)`。

结论：`malloc` 申请的空间必须手动 `free`；声明数组/变量申请的空间由系统自动回收。（堆区/栈区的细节本节不展开，记住这条结论即可。）

**（3）插入 / 删除**

- 顺序表：因元素必须相邻且有序，插入要把插入位置之后的元素**后移**，删除要**前移**，时间花在移动元素上。
- 链表：只需**修改指针**（找到前驱后 `p->next = s; s->next = ...` 一类操作），不移动元素；时间花在从头找目标位置上。

**（4）查找**

- 按位查找：顺序表 $O(1)$（随机存取）；链表 $O(n)$（从头走）。
- 按值查找：顺序表无序时逐个比较 $O(n)$，**有序时可用折半查找 $O(\log n)$**；链表无论有序无序都只能从头遍历，恒 $O(n)$。

### 4.4 选型结论

| 场景特征 | 选谁 | 例子 |
|---|---|---|
| 表长难以估计、频繁插入删除 | 链表 | 奶茶店排队取号/叫号 |
| 表长可预估且稳定、查询为主 | 顺序表 | 课堂学生点名 |

## 5. 复杂度分析

设表长为 $n$。

**插入（顺序表）**：在第 $i$ 个位置（$1\le i\le n+1$）插入需后移 $n-i+1$ 个元素。
- 最好：表尾插入，移动 0 个，$O(1)$；
- 最坏：表头插入，移动 $n$ 个，$O(n)$；
- 平均：假设 $n+1$ 个插入位置等概率（各 $\frac{1}{n+1}$），平均移动次数
$$\frac{1}{n+1}\sum_{i=1}^{n+1}(n-i+1)=\frac{1}{n+1}\cdot\frac{n(n+1)}{2}=\frac{n}{2}=O(n).$$

**删除（顺序表）**：删除第 $i$ 个元素（$1\le i\le n$）需前移 $n-i$ 个元素。
- 最好：删表尾，移动 0 个，$O(1)$；最坏：删表头，移动 $n-1$ 个，$O(n)$；
- 平均：$n$ 个位置等概率，
$$\frac{1}{n}\sum_{i=1}^{n}(n-i)=\frac{1}{n}\cdot\frac{n(n-1)}{2}=\frac{n-1}{2}=O(n).$$

**插入/删除（链表）**：若已定位到目标位置的前驱，改指针为 $O(1)$；但定位本身要从头扫描，故整体 $O(n)$。最好（表头附近）$O(1)$，最坏（表尾）$O(n)$，平均 $O(n)$。

**按位查找**：顺序表 $O(1)$（地址公式直接算）；链表最好 $O(1)$（第 1 个）、最坏 $O(n)$（最后一个）、平均 $\frac{1}{n}\sum_{i=1}^{n}i=\frac{n+1}{2}=O(n)$。

**按值查找**：顺序表无序时，假设目标等概率出现在 $n$ 个位置之一，平均比较次数
$$\frac{1}{n}\sum_{i=1}^{n}i=\frac{n+1}{2}=O(n);$$
有序时折半查找 $O(\log n)$。链表恒为 $\frac{n+1}{2}=O(n)$。

**关键辨析（408 必考）**：顺序表与链表的插入删除**大 O 同为 $O(n)$，但常数与物理代价不同**。顺序表的时间花在「移动元素」，元素很大时（如单个元素 1MB，移动一次约 10ms 量级）代价极高；链表的时间花在「沿指针找位置」（每跳一个结点约 1μs 量级），远小于搬移大块数据。所以实际工程中链表插删效率明显更高——这是「大 O 相同不等于效率相同」的经典考法。

## 6. 易错点与考试写法

1. **位序 vs 下标**：顺序表第 $i$ 个元素存于 `data[i-1]`；插入位置 $i$ 合法范围 $1\le i\le n+1$，删除 $1\le i\le n$。答题时写「第 $i$ 个位置」必须与代码下标对齐。
2. **随机存取的三个前提**：连续 + 元素等长 + 已知起始地址。只说「连续」不完整；链表「不可随机存取」不等于「不能查找」。
3. **静态 vs 动态分配的销毁**：静态分配只改 `length=0`，空间系统回收；动态分配必须 `free(L->data)`。写简答时两种都要提，只写一种会丢分。
4. **`malloc` 与 `free` 成对**：链表每个结点、动态顺序表的 `data` 都来自堆区，必须手动释放；这是「销毁」考点的采分点。
5. **存储密度**：顺序表为 1，链表小于 1（有指针域开销）。不要写成「链表存储密度高」。
6. **「链表插删一定比顺序表快」是错的**：若已给出前驱指针，链表插删 $O(1)$；但通常要先查找，整体仍 $O(n)$。正确表述是「链表插删不需移动元素，实际代价更小」。
7. **简答题写法（6 分题）**：按「逻辑结构 → 存储结构 → 基本操作效率 → 结论选型」四段作答，每段一两句，最后落到「表长是否可估、插删是否频繁、查询是否为主」给出选择。逻辑清晰比堆砌细节更得分。

## 7. 408 题型与解题套路

- **选择题**：常考「下列叙述正确的是」型判断，陷阱集中在：随机存取与存储结构挂钩、存储密度、插删复杂度「大 O 相同但实际不同」、静态/动态分配的回收方式、有序顺序表可折半而链表不行。
- **简答/综合题（自主命题常见，408 也可能以问答形式出现）**：直接套三要素框架。先答逻辑结构相同，再答存储结构差异（连续 vs 离散、随机存取、存储密度），再答基本操作（初始化、销毁、插删、查找）效率，最后给选型结论并举例。
- **算法题中的选型**：题目要求频繁在表头/中间插删、表长不定 → 用链表；要求随机访问第 $k$ 个、频繁按位查找、数据量可估 → 用顺序表。写算法前先一句话说明选型理由，是标准得分动作。
- **常见陷阱**：把「按值查找有序顺序表 $O(\log n)$」误推广到链表；把「链表插入 $O(1)$」当成无条件成立；混淆「逻辑结构相同」与「存储结构相同」。

## 8. 自测题

**1.** 顺序表能随机存取的根本原因是什么？链表为什么不能？

**2.** 长度为 $n$ 的顺序表，等概率在任意合法位置插入一个元素，平均移动多少个元素？删除呢？

**3.** 动态分配的顺序表与链表在「销毁」操作上分别要做什么？静态分配的顺序表有何不同？

**4.** 顺序表和链表的插入操作时间复杂度都是 $O(n)$，为什么实际应用中链表插删往往更快？

**5.** 某应用需支持频繁的按位查找且表长基本固定，应选顺序表还是链表？说明理由。

<details>
<summary>参考答案</summary>

1. 顺序表元素存放在**地址连续**的存储单元中且**元素等长**，已知**起始地址**即可由公式直接算出第 $i$ 个元素地址，故 $O(1)$ 随机存取；链表结点离散存放、靠指针相连，只能从头指针沿 `next` 逐个查找，故不可随机存取。
2. 插入：$n+1$ 个位置等概率，平均移动 $\frac{1}{n+1}\sum_{i=1}^{n+1}(n-i+1)=\frac{n}{2}$；删除：$n$ 个位置等概率，平均移动 $\frac{1}{n}\sum_{i=1}^{n}(n-i)=\frac{n-1}{2}$。
3. 动态顺序表：`length=0` 并 `free(L->data)` 手动释放堆区空间；链表：循环遍历所有结点逐个 `free`，最后头指针置空；静态顺序表：只需 `length=0`，数组空间由系统在其生命周期结束时自动回收。
4. 二者大 O 同为 $O(n)$，但顺序表的时间花在**移动大量元素**（元素大时代价极高），链表的时间花在**沿指针定位**（每次跳转代价很小），故链表实际插删效率更高。
5. 选**顺序表**。表长固定说明无需弹性扩容，按位查找顺序表为 $O(1)$（随机存取），链表为 $O(n)$，顺序表明显更优。

</details>

## 9. 背诵卡

1. 逻辑结构相同（都是线性表），差异全在存储结构。
2. 顺序表：连续 + 等长 + 起始地址 ⇒ 随机存取 $O(1)$，存储密度 1，但分配/扩容不便。
3. 链表：离散存放、指针相连 ⇒ 不可随机存取，存储密度 <1，但按需 `malloc`、扩容灵活。
4. 插删大 O 都是 $O(n)$：顺序表花在移元素，链表花在找位置；实际链表更快。
5. 选型口诀：**长难估、频插删 → 链表；长可估、多查询 → 顺序表**。
