# 2.3.2 单链表的查找

## 1. 本节定位

- **王道书对应**：第 2 章线性表，2.3 节「线性表的链式表示」下的单链表基本操作——查找。
- **408 大纲对应**：线性表的链式存储结构，单链表上基本操作（查找、求表长）的实现与复杂度分析。
- **先修知识**：单链表的定义与结点结构（`data` 域 + `next` 指针域）、带头结点单链表的结构、指针遍历的基本写法；上一小节「按位插入 / 按位删除」中「找第 $i-1$ 个结点」的循环。
- **本节位置**：单链表基本操作链条中的一环。前面已学建立、插入、删除，本节补齐「查找」与「求表长」，并为后续「按位插入 / 删除调用封装好的查找函数」做铺垫，同时与顺序表的按位查找形成对比（随机访问 vs 顺序访问）。

## 2. 一句话结论

单链表**不具备随机访问**特性，按位查找、按值查找、求表长都必须从头指针出发沿 `next` 依次扫描，平均与最坏时间复杂度均为 $O(n)$；按位查找返回第 $i$ 个结点（带头结点时头结点视为第 0 个），非法 $i$ 返回 `NULL`。

## 3. 知识地图

```
单链表的查找（带头结点）
├── 按位查找 GetElem(L, i)
│   ├── 语义：返回第 i 个结点（头结点为第 0 个）
│   ├── 边界：i < 0 → NULL；i = 0 → 返回头结点；i > 表长 → NULL
│   └── 实现：p 从头结点起，j 从 0 起，边走边计数
├── 按值查找 LocateElem(L, e)
│   ├── 语义：返回第一个 data == e 的结点，找不到返回 NULL
│   ├── 起点：第一个数据结点（L->next），头结点不参与比较
│   └── 坑：ElemType 为 struct 时不能用 == 直接比较
└── 求表长 Length(L)
    ├── 语义：数据结点个数（不含头结点）
    └── 实现：同一套「p 依次后移 + 计数器累加」循环
```

## 4. 核心内容

### 4.1 按位查找 `GetElem(L, i)`

**定义**：在带头结点的单链表 `L` 中，返回第 $i$ 个结点（位序从 1 开始计数据结点，头结点视为第 0 个结点）。找不到返回 `NULL`。

**代码（王道风格，带头结点）**：

```c
// 返回第 i 个结点；i 非法时返回 NULL
LNode *GetElem(LinkList L, int i) {
    if (i < 0)                 // 位序非法，直接失败
        return NULL;
    LNode *p = L;              // p 指向头结点（视为第 0 个结点）
    int j = 0;                 // j 记录 p 当前所指结点的位序
    while (p != NULL && j < i) { // 边走边数，直到 p 到第 i 个或走空
        p = p->next;
        j++;
    }
    return p;                  // i 合法则返回第 i 个结点；i 超长则 p 为 NULL
}
```

**执行过程（按讲解顺序）**：

- **$i = 0$**：`p = L`、`j = 0`，循环条件 `j < i` 不成立，直接返回 `p`，即返回头结点。这是极端情况，说明「头结点算第 0 个」。
- **$i$ 大于表长（如 $i = 8$ 而表长不足）**：每轮 `p = p->next; j++`，`p` 依次指向第 1、2、3…个结点，直到 `p` 走成 `NULL`，循环因 `p != NULL` 不成立而结束，返回 `NULL`。调用者据此判断查找失败。
- **$i$ 合法（如 $i = 3$）**：循环执行 3 次，`p` 指向第 3 个结点，`j = 3`，返回该结点。

**王道书版本（等价写法，了解即可）**：先把 `j = 1`、`p = L->next`（`p` 直接指向第一个数据结点），再单独判断 `if (i == 0) return L;`，之后同样循环后移。两种写法效果一致，区别只在「头结点是否进入循环」。考试写一种即可。

**封装的意义（王道书扩展，考试不直接考）**：有了 `GetElem`，按位插入、按位删除只需调用 `GetElem(L, i-1)` 找前驱，避免重复写遍历代码；若遍历逻辑有 bug，只改一处即可，代码更简洁、更易维护。

### 4.2 按值查找 `LocateElem(L, e)`

**定义**：在单链表 `L` 中查找第一个数据域等于 `e` 的结点，返回该结点指针；不存在则返回 `NULL`。

**代码**：

```c
// 查找第一个 data == e 的结点；找不到返回 NULL
LNode *LocateElem(LinkList L, ElemType e) {
    LNode *p = L->next;        // 从第一个数据结点开始，头结点不参与比较
    while (p != NULL && p->data != e) { // 未走空且当前值不等，继续后移
        p = p->next;
    }
    return p;                  // 找到返回该结点；走空返回 NULL
}
```

**执行过程**：设 `ElemType` 为 `int`，`e = 8`。`p` 从第一个数据结点起，逐轮比较 `p->data` 与 `8`；一旦相等，循环条件 `p->data != e` 不成立，跳出循环返回 `p`。若 `e = 6` 而表中无 6，`p` 一路后移直到 `NULL`，循环因 `p != NULL` 不成立而结束，返回 `NULL`，调用者据此判定「不存在」。

**结构体比较的坑**：若 `ElemType` 是 `struct` 类型，`p->data != e` 这种写法**不合法**（C 语言结构体不能用 `==` / `!=` 整体比较），必须逐成员比较（如比较学号字段）。C++ 中若重载了 `operator==` 才可直接比较。这一点前面小节已强调，此处复习。

### 4.3 求表长 `Length(L)`

**定义**：统计单链表中数据结点的个数（不含头结点）。

**代码**：

```c
// 求带头结点单链表的长度（数据结点个数）
int Length(LinkList L) {
    int len = 0;               // 计数器
    LNode *p = L;              // 从头结点出发
    while (p->next != NULL) {  // 还有后继数据结点
        p = p->next;
        len++;
    }
    return len;
}
```

核心与上面两个查找完全一致：**`p` 指针从头到尾依次扫描 + 计数器累加**。不带头结点时，起点改为 `p = L`、循环条件改为 `p != NULL`，计数器初值仍为 0（推断：讲解只提示「主动思考区别」，未展开代码）。

### 4.4 与顺序表按位查找的对比

| 对比项 | 顺序表 | 单链表 |
|---|---|---|
| 存储方式 | 连续、等长 | 离散，靠指针链接 |
| 按位查找 | 随机访问，$O(1)$ | 顺序访问，$O(n)$ |
| 按值查找 | $O(n)$（平均 $\frac{n+1}{2}$ 次比较） | $O(n)$（平均 $\frac{n+1}{2}$ 次比较） |

## 5. 复杂度分析

**按位查找 `GetElem`**：

- **最好**：$i = 0$ 或 $i = 1$，循环 0～1 次，$O(1)$。
- **最坏**：$i$ 等于表长 $n$ 或超出表长，循环 $n$ 次（或走到 `NULL`），$O(n)$。
- **平均**：设 $i$ 在合法范围 $1 \sim n$ 内等概率取值，概率各为 $\frac{1}{n}$。查找第 $i$ 个结点需循环 $i$ 次，故平均循环次数
  $$\frac{1}{n}\sum_{i=1}^{n} i = \frac{1}{n}\cdot\frac{n(n+1)}{2} = \frac{n+1}{2}$$
  即 $O(n)$。与顺序表按值查找的平均比较次数推导方法相同。

**按值查找 `LocateElem`**：

- **最好**：第一个数据结点即命中，1 次比较，$O(1)$。
- **最坏**：目标在表尾或不存在，比较 $n$ 次，$O(n)$。
- **平均**：设目标等概率出现在 $1 \sim n$ 个位置之一，平均比较次数 $\frac{n+1}{2}$，$O(n)$。

**求表长 `Length`**：无论何种情况都必须走完全表，最好 = 最坏 = 平均 = $O(n)$（$n$ 为数据结点数）。

## 6. 易错点与考试写法

1. **位序与「第 0 个」**：带头结点时头结点是第 0 个结点，`GetElem(L, 0)` 返回头结点而非 `NULL`；`i < 0` 才返回 `NULL`。不带头结点时没有「第 0 个」的说法，`i` 从 1 起，且 `i < 1` 即非法（推断，讲解要求自行思考）。
2. **循环条件两个都要写**：`while (p != NULL && j < i)`，漏掉 `p != NULL` 会在 $i$ 超长时对空指针解引用；漏掉 `j < i` 会走完整表。
3. **按值查找起点是 `L->next`**：头结点的 `data` 域通常无意义，不能参与比较，否则可能误命中。
4. **结构体不能用 `==` / `!=` 整体比较**：C 语言必须逐成员比较；C++ 需重载运算符。这是按值查找最常见的失分点。
5. **求表长不含头结点**：计数器从 0 起、只对数据结点累加；若从头结点开始且用 `p != NULL` 作条件，会多算 1。
6. **答题标准**：408 算法题中，写出完整可运行函数（含边界判断 `i < 0`、`p != NULL`）并注明「带头结点」前提即可得满分；只写循环体不写边界判断会扣分。复杂度分析要写出平均情况的求和推导，不能只写 $O(n)$。

## 7. 408 题型与解题套路

- **选择题**：常考「单链表按位查找的时间复杂度」「带头结点时第 $i$ 个结点的查找需比较/移动几次」「顺序表与单链表查找性能对比」。套路：单链表任何按位操作都是 $O(n)$，顺序表按位是 $O(1)$；平均次数记 $\frac{n+1}{2}$。
- **算法题**：可能要求「在单链表中查找倒数第 $k$ 个结点」「删除值等于 $x$ 的第一个结点」等，本质都是本节「`p` 依次扫描」的循环骨架。套路：先写遍历框架 `p = L->next; while (p != NULL && ...) p = p->next;`，再补边界与返回值。
- **常见陷阱**：① 把 `GetElem` 的返回值当结点值用（返回的是指针，取值要 `p->data`）；② 忘记判断 `i` 非法导致空指针；③ 按值查找从头结点开始比较；④ 结构体直接 `==`。

```c
typedef struct { int id; char name[20]; } ElemType;
```

**题 5**：求带头结点单链表长度的循环条件写成 `while (p != NULL)`、`p` 初值取 `L`，结果会怎样？如何改正？

<summary>参考答案</summary>

**题 1**：`GetElem(L, 0)` 返回头结点指针（头结点视为第 0 个结点）；`GetElem(L, -1)` 因 `i < 0` 直接返回 `NULL`。

**题 2**：平均循环次数 $\frac{1}{n}\sum_{i=1}^{n} i = \frac{n+1}{2}$，故平均时间复杂度 $O(n)$。

**题 3**：头结点的 `data` 域无实际数据，若从 `L` 开始比较可能误命中头结点；按值查找只应在数据结点中找，故从第一个数据结点 `L->next` 开始。

**题 4**：不能编译通过，C 语言结构体不能用 `!=` 整体比较。应逐成员比较，例如 `p->data.id != e.id`（或按题意比较全部成员）。

**题 5**：`p` 从 `L` 出发、条件 `p != NULL`，会把头结点也计入，长度多算 1。改正：条件改为 `p->next != NULL`（`p` 从 `L` 起），或 `p` 从 `L->next` 起、条件 `p != NULL`。

## 9. 背诵卡

1. 单链表无随机访问，按位查找、按值查找、求表长**全部 $O(n)$**。
2. `GetElem`：`p = L; j = 0; while (p != NULL && j < i) { p = p->next; j++; } return p;`——头结点是第 0 个，`i < 0` 返回 `NULL`。
3. `LocateElem`：`p = L->next; while (p != NULL && p->data != e) p = p->next; return p;`——头结点不参与比较。
4. 平均查找次数 $\frac{n+1}{2}$（等概率假设），推导：$\frac{1}{n}\sum_{i=1}^{n} i$。
5. 结构体 `ElemType` 不能用 `==` / `!=` 整体比较，必须逐成员比较。

## 10. 关联与下一节

- **向前关联**：上一小节按位插入 / 删除中的「找第 $i-1$ 个结点」循环，正是本节 `GetElem` 的原型；封装 `GetElem` 后，插入删除可直接调用，体现代码复用与健壮性（如 `GetElem` 返回 `NULL` 时后插函数返回 `false`）。
- **横向对比**：顺序表按位查找 $O(1)$（连续 + 等长 + 起始地址直接算地址），单链表只能顺序扫描，这是两种存储结构最本质的差异之一。
- **向后关联**：下一节进入**双链表**，其按位查找同样是 $O(n)$，但插入删除时可直接访问前驱，无需再从头找前驱；再往后是循环链表、静态链表。
