## 2. 一句话结论

**串的存储结构 = 把线性表的 `ElemType` 换成 `char`：顺序存储分定长（静态数组）与堆分配（动态数组），链式存储因“1 字节数据 + 4 字节指针”存储密度低，通常一个结点存多个字符；王道书统一采用“舍弃 `ch[0]`、另设 `int length`”的方案，使位序与数组下标一一对应。**

## 4. 核心内容

### 4.1 定长顺序存储（静态数组）

```c
#define MAXLEN 255          // 静态数组最大容量
typedef struct {
    char ch[MAXLEN];        // 每个分量存一个字符
    int  length;            // 串的实际长度
} SString;
```

- 声明后系统分配一片**连续空间**，每字符占 1 字节，另有一小片空间存 `length`。
- 课本称“**定长顺序存储**”，本质是静态数组；缺点：`MAXLEN` 存不下时**无法扩展**。
- 优点：**随机存取**，找任一字符 $O(1)$；缺点：插入/删除（空间伸缩）不便——与顺序表完全一致。

### 4.2 堆分配存储（动态数组）

```c
typedef struct {
    char  *ch;              // 基地址指针，指向堆区连续空间
    int    length;
} HString;

HString S;
S.ch = (char *)malloc(MAXLEN * sizeof(char));  // 申请堆区
// ... 使用 ...
free(S.ch);                                    // 必须手动释放
```

- `malloc` 申请的空间在**堆区**，课本称“**堆分配存储**”，本质是动态数组。
- 与静态数组的关键区别：堆区空间**需手动 `free`**；静态数组空间在函数结束后由系统自动回收。

### 4.3 长度表示的三种教材写法（重点辨析）

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 方案一 | 另设 `int length` | 求长 $O(1)$，长度不受 255 限制 | 多占几字节 |
| 方案二 | `ch[0]` 当 length | 位序与下标一一对应 | `char` 仅 1 字节，长度 $\le 255$ |
| 方案三 | 末尾加 `'\0'`（ASCII=0，8 个二进制 0） | 省去 length 空间 | 求长需从头扫描，$O(n)$ |

> **王道书采用方案一 + 方案二的结合**：**舍弃 `ch[0]` 不用**，另设 `int length`。这样既让位序（从 1 开始）与数组下标一一对应，又不受 255 限制。后续所有示例代码均默认此方案，**访问从 `ch[1]` 开始**。

### 4.4 链式存储

```c
typedef struct StringNode {
    char ch;                        // 每结点 1 个字符：存储密度低
    struct StringNode *next;
} StringNode, *String;
```

- **存储密度低**：32 位机指针占 4 字节，数据仅 1 字节，有用信息占比 $1/5$。
- **改进**：一个结点存多个字符，提高存储密度：

```c
typedef struct StringNode {
    char ch[4];                     // 每结点存 4 个字符（可更多）
    struct StringNode *next;
} StringNode, *String;
```

- 末结点存不满时，用特殊字符（如 `'#'` 或 `'\0'`）填充。
- 优缺点与链表一致：增删方便，但**不支持随机存取**。

### 4.5 基于顺序存储的基本操作（王道方案，`ch[0]` 不用）

**求子串 SubString**：从 `S` 的第 `pos` 个字符起取 `len` 个字符放入 `Sub`。

```c
bool SubString(SString &Sub, SString S, int pos, int len) {
    if (pos + len - 1 > S.length)   // 越界判断：末位序超过串长
        return false;
    for (int i = pos; i < pos + len; i++)
        Sub.ch[i - pos + 1] = S.ch[i];  // 位序从 1 开始，故 +1
    Sub.length = len;
    return true;
}
```

**比较 StrCompare**：从第一个字符起逐位比较，先出现更大字符者更大；前缀全同则**更长者更大**。

```c
int StrCompare(SString S, SString T) {
    for (int i = 1; i <= S.length && i <= T.length; i++) {
        if (S.ch[i] != T.ch[i])
            return S.ch[i] - T.ch[i];   // 差值符号即大小关系
    }
    return S.length - T.length;         // 前缀全同，比长度
}
```

返回值语义：`>0` 表示 S>T，`=0` 表示相等，`<0` 表示 S<T。

**定位 Index**：在主串 S 中找子串 T 第一次出现的位置，找不到返回 0。思路 = 反复取长度 `T.length` 的子串 + 比较。

```c
int Index(SString S, SString T) {
    int i = 1, n = S.length, m = T.length;
    SString sub;
    while (i <= n - m + 1) {            // 最多可取的起始位置
        SubString(sub, S, i, m);        // 取长度 m 的子串
        if (StrCompare(sub, T) != 0)    // 不相等则后移
            i++;
        else
            return i;                   // 相等则返回起始位序
    }
    return 0;                           // 匹配失败
}
```

> 本节 `Index` 是**调用基本操作**的版本；下一节将**直接操作数组**实现 `Index`（朴素模式匹配），再引出 KMP。

## 5. 复杂度分析

设主串长 $n$，子串长 $m$。

- **求串长 / 清空**：$O(1)$（直接读/写 `length`）。
- **求子串 SubString**：复制 `len` 个字符，最好/最坏/平均均为 $O(len)$。
- **比较 StrCompare**：最好 $O(1)$（首字符即不同）；最坏 $O(\min(n,m))$（前缀全同）；平均按“字符随机、首次不同位置均匀分布”假设，期望比较次数约 $O(\min(n,m))$ 量级，通常记 $O(\min(n,m))$。
- **定位 Index（本节基本操作版）**：
  - 外层最多 $n-m+1$ 个起始位置，每个位置做一次 `SubString`（$O(m)$）+ 一次 `StrCompare`（最坏 $O(m)$）。
  - 最好：$O(m)$（第一个位置就匹配）。
  - 最坏：$O((n-m+1)\cdot m)=O(nm)$。
  - 平均：假设每个起始位置匹配成功概率相同、失配位置均匀，单次比较期望 $O(m)$，总期望仍为 $O(nm)$ 量级——这正是下一节朴素模式匹配的复杂度，也是 KMP 要优化的目标。

## 6. 易错点与考试写法

1. **位序 vs 下标**：位序从 1 开始，数组下标从 0 开始。王道方案舍弃 `ch[0]`，使 `ch[i]` 直接对应第 `i` 个字符，**循环从 1 开始**，别写成 0。
2. **`ch[0]` 当 length 的长度上限**：`char` 只有 1 字节，能表示 $0\sim255$，故串长不能超过 255——这是方案二的硬伤，选择题常考。
3. **`'\0'` 方案的求长代价**：不显式存长度，求长必须从头扫描到 `'\0'`，$O(n)$；频繁求长时不可取。
4. **静态 vs 动态的释放**：`malloc` 的堆区必须 `free`；静态数组由系统自动回收。别把两者混为一谈。
5. **链式存储密度**：1 字节数据 + 4 字节指针 → 密度 $1/5$，这是“为什么一结点存多字符”的直接理由。
6. **`StrCompare` 的返回语义**：返回的是**差值**，只需关心符号（`>0/=0/<0`），不要纠结具体数值；前缀全同时返回 `S.length - T.length`。
7. **`SubString` 越界条件**：判断 `pos + len - 1 > S.length`，不是 `pos + len > S.length`（差一位，高频错误）。
8. **答题程度**：简答题问“顺序存储实现串的优缺点”，写“优点：随机存取 $O(1)$；缺点：插入删除/空间伸缩不便、定长版长度不可变”即可得分；问“链式存储优缺点”，写“增删方便；不支持随机存取、存储密度低（单字符结点）”。

## 7. 408 题型与解题套路

- **选择题**：
  - 给结构体定义，问“串长为 255 时用哪种方案会溢出”→ 选 `ch[0]` 当 length 的方案。
  - 问“求串长的时间复杂度”→ `'\0'` 方案 $O(n)$，其余 $O(1)$。
  - 问“链式存储的存储密度”→ 算 $1/(1+4)$。
  - 问“`SubString` 的越界判断条件”→ 注意 `-1`。
- **算法题**：本节代码是模板，`StrCompare`、`SubString`、`Index` 要能默写；`Index` 的“取子串 + 比较”组合思路是朴素匹配的原型，下一节改写为直接数组操作。
- **常见陷阱**：循环起点写成 0；越界判断漏 `-1`；把 `StrCompare` 返回值当布尔用（应判 `!=0` / `==0`）；混淆位序与下标。

## 9. 背诵卡

1. 串 = 元素为 `char` 的特殊线性表，存储结构照搬线性表，`ElemType` 换成 `char`。
2. 顺序存储：定长（静态数组，不可扩展）/ 堆分配（`malloc` 动态数组，需 `free`）。
3. 王道方案：**舍弃 `ch[0]` + 另设 `int length`**，位序=下标，访问从 `ch[1]` 起。
4. `ch[0]` 当 length → 长度 $\le 255$；`'\0'` 结尾 → 求长 $O(n)$。
5. 链串单字符结点存储密度低（$1/5$），一结点存多字符提高密度；`Index` 最坏 $O(nm)$。
