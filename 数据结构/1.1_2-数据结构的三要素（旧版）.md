# 1.1.2 数据结构的三要素

## 1. 本节定位

- **对应王道书**：绪论章「数据结构的基本概念」中“数据结构的三要素”部分（旧版 1.1.2）。
- **408 大纲对应**：数据结构基本概念——逻辑结构与存储结构、数据的运算、数据类型与抽象数据类型。
- **先修知识**：上一节“什么是数据结构”（数据、数据元素、数据项、数据对象等基本概念）。
- **本节位置**：绪论中承上启下。上一节给出“数据结构”的直观定义，本节把它拆成**逻辑结构、数据的运算、物理（存储）结构**三个要素，并补充**数据类型 / 抽象数据类型（ADT）**，为后续第 2、3 章（线性表）、第 4 章（树）、第 5 章（图）提供统一分析框架。

## 2. 一句话结论

**一个数据结构 = 逻辑结构 + 定义在其上的运算；用计算机实现时再选定物理（存储）结构。逻辑结构决定“是什么关系、能做什么”，存储结构决定“怎么存、运算代价多大”。**

## 3. 知识地图

```
数据结构的三要素
├── ① 逻辑结构（数据元素之间的逻辑关系）
│   ├── 集合：元素同属一个集合，别无其他关系（408 大纲已删，不考）
│   ├── 线性结构：一对一，除首元素外唯一前驱，除尾元素外唯一后继
│   ├── 树形结构：一对多
│   └── 图状（网状）结构：多对多
├── ② 数据的运算（针对逻辑结构定义的基本操作）
│   └── 例（线性结构）：查找第 i 个元素、在第 i 个位置插入、删除第 i 个元素
└── ③ 物理结构 / 存储结构（如何在计算机内表示逻辑关系）
    ├── 顺序存储：逻辑相邻 ⇒ 物理相邻（连续存放）
    ├── 链式存储：物理可离散，用指针表示先后关系
    ├── 索引存储：建索引表（关键字 → 地址），元素可离散存放
    └── 散列存储（哈希存储）：由关键字直接计算存储地址（原理留到第 6 章）

补充概念
├── 数据类型 = 值的集合 + 定义在该集合上的一组操作
│   ├── 原子类型：值不可再分（bool、int）
│   └── 结构类型：值可再分为若干分量（struct 坐标）
└── 抽象数据类型 ADT = 抽象的数据组织 + 与之相关的操作（只描述逻辑特性，不涉及实现）
```

## 4. 核心内容

### 4.1 逻辑结构

逻辑结构只关心数据元素之间的**逻辑关系**，与计算机无关。

| 逻辑结构 | 关系 | 典型例子 |
|---|---|---|
| 集合 | 同属一个集合，无其他关系 | “最富有的 400 人”这个集合本身 |
| 线性结构 | 一对一 | 富豪排行榜、排队取号队列 |
| 树形结构 | 一对多 | 思维导图、文件系统（文件夹与文件） |
| 图状/网状结构 | 多对多 | 城市间道路网、好友关系 |

**线性结构的严格刻画**：给元素编号 $1,2,\dots,n$，则
- 1 号元素无前驱，其余每个元素有且仅有一个**唯一前驱**；
- $n$ 号元素无后继，其余每个元素有且仅有一个**唯一后继**。

**408 范围提示**：集合结构在几年前已从 408 大纲中删除，**不考**；重点为线性（第 2、3 章）、树形（第 4 章）、图状（第 5 章）。

### 4.2 数据的运算

针对某种逻辑结构，结合实际需求定义一组**基本操作**，研究的是“这类结构上通常需要哪些共性操作”，而不是某个具体应用。

以线性结构为例的典型运算（用位序 $i$ 描述，$1 \le i \le n$）：
- 查找第 $i$ 个数据元素；
- 在第 $i$ 个位置插入新元素；
- 删除第 $i$ 个位置的元素。

> 注意：这里 $i$ 是**位序**（从 1 开始），与 C 数组下标（从 0 开始）不同，后续写代码时下标 = 位序 − 1。

**关键区分**：运算的**定义**针对逻辑结构（“在第 $i$ 个位置插入”），运算的**实现**针对存储结构（顺序存储要挪元素，链式存储改指针）。

### 4.3 物理结构（存储结构）

存储结构要解决的问题：**如何在计算机内部表示数据元素及其逻辑关系**。

| 存储结构 | 逻辑相邻元素的物理位置 | 逻辑关系的表示方式 |
|---|---|---|
| 顺序存储 | 必须物理相邻（连续） | 物理相邻直接体现前后关系 |
| 链式存储 | 可以离散 | 指针链接 |
| 索引存储 | 可以离散 | 索引表：关键字 → 存储地址 |
| 散列存储 | 可以离散 | 由关键字直接算出地址（哈希） |

- **关键字**：能唯一区分数据元素的数据项，如身份证号。
- 顺序存储之外的后三种统称**非顺序存储 / 离散存储**。
- 散列存储的原理本节不展开，第 6 章散列表再讲（**了解即可，本节不考原理**）。

**存储结构对性能的影响（本节核心对比）**：

1. **空间分配**：顺序存储需要一整片连续空间，内存中没有足够大的连续区就存不下；链式存储“哪里有空往哪钻”，无需连续大块空间。
2. **运算速度**：以“在 b 与 d 之间插入 c”为例——
   - 顺序存储：必须把 d 及其后所有元素整体后移一位，腾出位置再放 c，**移动元素多、代价高**；
   - 链式存储：把 c 放到任意空闲处，修改 b 的后继指针指向 c、c 的后继指针指向 d 即可，**只改指针**。

由此得到本节最重要的两句话：
> **运算的定义是针对逻辑结构设计的；运算的实现是针对存储结构进行的。**

### 4.4 数据类型与抽象数据类型

**数据类型**：一个**值的集合** + 定义在该集合上的**一组操作**的总称。

- **原子类型**：值不可再分。
  - `bool`：取值 {true, false}，可做与、或、非等操作。
  - `int`（4 字节补码）：取值范围约 $-2^{31}\sim 2^{31}-1$，可做加、减、乘、除、取模等操作。
- **结构类型**：值可再分解为若干分量，分量之间有逻辑关系（顺序/含义不可颠倒）。

```c
// 结构类型示例：坐标
struct Point {
    int x;   // 横坐标
    int y;   // 纵坐标
};
// x、y 的含义不可互换，否则坐标的逻辑意义改变
```

针对坐标可定义的操作（C 语言中每个操作封装为一个函数）：

```c
struct Point add(struct Point a, struct Point b) {   // 坐标相加
    struct Point c;
    c.x = a.x + b.x;
    c.y = a.y + b.y;
    return c;
}

struct Point sub(struct Point a, struct Point b) {   // 坐标相减
    struct Point c;
    c.x = a.x - b.x;
    c.y = a.y - b.y;
    return c;
}

double distToOrigin(struct Point a) {                // 到原点距离
    return sqrt((double)a.x * a.x + (double)a.y * a.y);
}
```

**抽象数据类型（ADT, Abstract Data Type）**：抽象的数据组织 + 与之相关的操作。它只描述**逻辑特性**（元素如何组织、能做哪些操作），不涉及内部如何存储、运算底层如何实现。

- **使用者**只需知道 ADT 描述（逻辑结构 + 可用操作）；
- **实现者**才需关心存储结构与运算的底层实现。

> 因此：**定义一个 ADT ≈ 定义一个完整的数据结构（逻辑层面）**；实现它才涉及物理结构。

## 5. 复杂度分析

本节为概念课，未给出具体算法复杂度。仅就“插入一个元素”的**定性代价**说明（不涉及渐进复杂度推导，属概念对比）：

- **顺序存储插入**：为保持物理连续，插入位置之后的元素需整体后移，代价与移动元素个数成正比，最坏需移动约 $n$ 个元素。
- **链式存储插入**：只需修改常数个指针，代价与元素总数 $n$ 无关（前提是已定位到插入位置的前驱）。

> 补充：以上仅为定性对比，具体复杂度在第 2 章线性表展开；本节不要求给出 $O(\cdot)$ 结论。

## 6. 易错点与考试写法

1. **逻辑结构与存储结构混淆**：逻辑结构是“关系本身”（线性/树/图），存储结构是“关系的计算机表示”（顺序/链式/索引/散列）。二者是**两个维度**，不能并列成“线性存储、树形存储”。
2. **“集合结构不考”**：408 大纲已删除集合，选择题若出现“四种逻辑结构”表述要能识别，但不必深究集合的运算。
3. **运算定义 vs 运算实现**：定义针对逻辑结构，实现针对存储结构——这是简答题高频得分点，答题时必须点明这层区分。
4. **位序与下标**：描述运算用位序 $i$（从 1 开始），写 C 代码用下标（从 0 开始），答题时写清“第 $i$ 个位置”对应 `a[i-1]`。
5. **ADT 不等于实现**：ADT 只含逻辑结构与操作声明，不含存储方式与底层实现；说“ADT 包含存储结构”是错的。
6. **答题程度**：简答“数据结构三要素”时，需分别写出逻辑结构（四类）、数据的运算（定义在逻辑结构上）、物理结构（四类），并各举一例，即算完整。

## 7. 408 题型与解题套路

- **选择题常见考法**：
  - 给一个场景（排行榜、文件系统、道路网、好友关系），判断属于哪种逻辑结构；
  - 判断“顺序存储 / 链式存储 / 索引存储 / 散列存储”的归属与特点；
  - 判断某说法对错，如“逻辑结构相同的数据结构，存储结构一定相同”（错）。
- **简答题套路**：先答三要素名称 → 逐条下定义 → 各配一个例子 → 点出“定义针对逻辑结构、实现针对存储结构”。
- **常见陷阱**：
  - 把“集合”当成一种存储结构；
  - 认为链式存储中逻辑相邻元素物理上也相邻；
  - 认为 ADT 规定了具体存储方式；
  - 把“数据类型”与“数据结构”混为一谈（数据类型是值的集合 + 操作，是更基础的编程语言概念）。

## 8. 自测题

**1.** 下列逻辑结构中，数据元素之间为“一对多”关系的是（ ）。
A. 集合　B. 线性结构　C. 树形结构　D. 图状结构

**2.** 判断：逻辑上相邻的数据元素，在物理存储上也一定相邻。

**3.** 简述“运算的定义”与“运算的实现”分别针对什么，并各举一例。

**4.** 抽象数据类型（ADT）描述的是什么？它是否包含存储结构的实现细节？

**5.** 在 b 与 d 之间插入 c，分别说明顺序存储与链式存储的做法，并比较代价。

<details>
<summary>答案</summary>

1. **C**。树形结构为一对多；集合无其他关系；线性为一对一；图状为多对多。
2. **错**。只有顺序存储要求物理相邻；链式、索引、散列存储中逻辑相邻元素可以离散存放，分别用指针、索引表、哈希函数表示关系。
3. 运算的**定义**针对**逻辑结构**设计，如“在第 $i$ 个位置插入元素”；运算的**实现**针对**存储结构**进行，如顺序存储插入需后移元素、链式存储插入只需修改指针。
4. ADT 描述一个数据结构的**逻辑特性**：数据元素如何组织（逻辑结构）以及可执行哪些操作；**不包含**存储结构与底层实现细节，那些由实现者关心。
5. 顺序存储：将 d 及其后所有元素后移一位，腾出位置放入 c，移动元素多、代价高；链式存储：把 c 放到任意空闲处，令 b 的后继指针指向 c、c 的后继指针指向 d，只改常数个指针，代价低。

## 9. 背诵卡

1. **三要素**：逻辑结构、数据的运算、物理（存储）结构。
2. **四种逻辑结构**：集合（不考）、线性（一对一）、树形（一对多）、图状（多对多）。
3. **四种存储结构**：顺序（物理相邻）、链式（指针）、索引（索引表）、散列（关键字算地址）。
4. **一句话区分**：运算定义针对逻辑结构，运算实现针对存储结构。
5. **ADT**：抽象的数据组织 + 相关操作，只描述逻辑特性，不含实现；定义 ADT ≈ 定义数据结构。
