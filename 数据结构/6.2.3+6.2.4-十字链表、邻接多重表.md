# 6.2.3+6.2.4 十字链表、邻接多重表

## 1. 本节定位

- **对应王道书**：第 6 章「图」→ 6.2「图的存储及基本操作」→ 6.2.3 十字链表（Orthogonal List）、6.2.4 邻接多重表（Adjacency Multilist）。
- **408 大纲对应**：图的存储结构（邻接矩阵法、邻接表法、十字链表、邻接多重表）。
- **先修知识**：邻接矩阵、邻接表（含有向图邻接表「找入边难」的问题、无向图邻接表「每条边存两份」的问题）。
- **本章位置**：图的存储结构收尾。前面已学邻接矩阵、邻接表，本节用两种「升级版链式结构」分别修补它们在有向图 / 无向图上的缺陷；之后进入图的遍历（BFS/DFS）。

## 2. 一句话结论

**十字链表存有向图**（同时方便找入边和出边，空间 $O(|V|+|E|)$）；**邻接多重表存无向图**（每条边只存一个边结点，删边删点方便，空间 $O(|V|+|E|)$）。二者都只要求理解特性，**不要求手写代码**。

## 3. 知识地图

```
图的存储结构
├── 邻接矩阵：空间 O(|V|²)，稠密图友好
├── 邻接表
│   ├── 有向图：找出边易，找入边难（需遍历全表）
│   └── 无向图：每条边存两份冗余，删边/删点麻烦
├── 十字链表（只能存有向图）
│   ├── 顶点结点：data + firstin（橙色，入边链）+ firstout（绿色，出边链）
│   └── 弧结点：tailvex + headvex + hlink（同弧头链）+ tlink（同弧尾链）
└── 邻接多重表（只能存无向图）
    ├── 顶点结点：data + firstedge
    └── 边结点：ivex + jvex + ilink（依附 ivex 的下一条边）+ jlink（依附 jvex 的下一条边）
```

## 4. 核心内容

### 一、十字链表（有向图）

**动机**：邻接表存有向图时，找某顶点的**入边**必须遍历整个邻接表；十字链表把「出边链」和「入边链」都挂在顶点上，两个方向都 $O(1)$ 起步。

**结构定义（王道风格 C）**：

```c
// 弧结点
typedef struct ArcBox {
    int tailvex, headvex;          // 该弧的尾顶点、头顶点编号（下标）
    struct ArcBox *hlink, *tlink;  // hlink: 弧头相同的下一条弧；tlink: 弧尾相同的下一条弧
    // InfoType info;              // 权值等，可选
} ArcBox;

// 顶点结点
typedef struct VexNode {
    VertexType data;               // 顶点信息
    ArcBox *firstin, *firstout;    // 该顶点第一条入弧、第一条出弧
} VexNode;

// 十字链表
typedef struct {
    VexNode xlist[MAXV];           // 顶点数组，下标即顶点编号
    int vexnum, arcnum;
} OLGraph;
```

**图解要点**（以视频中 4 顶点有向图 a→b、a→c、c→a、d→a 为例）：

- 顶点数组下标 0=a, 1=b, 2=c, 3=d。
- 从 a 的 **firstout（绿色）** 出发：先到弧 `0→1`（a→b），沿该弧的 **tlink** 到弧 `0→2`（a→c），再 tlink 为空 → a 的全部出边找完。
- 从 a 的 **firstin（橙色）** 出发：先到弧 `2→0`（c→a），沿该弧的 **hlink** 到弧 `3→0`（d→a），再 hlink 为空 → a 的全部入边找完。
- 结论：**绿色链 = 同弧尾（出边），橙色链 = 同弧头（入边）**。

**空间复杂度**：顶点数组 $O(|V|)$ + 每条弧一个弧结点 $O(|E|)$ → $O(|V|+|E|)$，与邻接表同量级，远优于邻接矩阵的 $O(|V|^2)$。

### 二、邻接多重表（无向图）

**动机**：邻接表存无向图时，一条边 (a,b) 会出现两个边结点（a 的表里一个、b 的表里一个），删边要删两份、删点要找到并删掉所有关联的冗余结点。邻接多重表让**每条边只对应一个边结点**。

**结构定义（王道风格 C）**：

```c
// 边结点
typedef struct EBox {
    int ivex, jvex;                // 该边依附的两个顶点编号
    struct EBox *ilink, *jlink;    // ilink: 依附 ivex 的下一条边；jlink: 依附 jvex 的下一条边
    // bool mark;                  // 可选：访问标记，用于遍历/删除
    // InfoType info;              // 权值等，可选
} EBox;

// 顶点结点
typedef struct VexBox {
    VertexType data;
    EBox *firstedge;               // 指向依附该顶点的第一条边
} VexBox;

typedef struct {
    VexBox adjmulist[MAXV];
    int vexnum, edgenum;
} AMLGraph;
```

**图解要点**（以视频中 5 顶点无向图为例，a=0,b=1,c=2,d=3,e=4）：

- 顶点 a 的 firstedge 指向边 `(0,1)`；沿该边中「依附 0 的那一侧」的指针（ilink，因 0 在 ivex 位）找到边 `(0,3)`；再往后为空 → a 的关联边找完。
- 顶点 b 的 firstedge 指向边 `(0,1)`，但 b 的编号 1 在 **jvex** 位，所以沿 **jlink** 找到边 `(2,1)`（c–b）；1 仍在 jvex 位，继续沿 jlink 找到边 `(4,1)`（e–b）；再为空 → b 的三条关联边找完。
- **关键规则**：从顶点 $v$ 出发沿边结点走时，先看 $v$ 等于该边的 `ivex` 还是 `jvex`，**等于 ivex 走 ilink，等于 jvex 走 jlink**。无向图中 ivex/jvex 谁左谁右逻辑等价，但走哪条链必须与位置对应。

**空间复杂度**：顶点 $O(|V|)$ + 每条边**一个**边结点 $O(|E|)$ → $O(|V|+|E|)$，比邻接表（无向图需 $2|E|$ 个边结点）更省。

**删边 / 删点为什么方便**（视频重点）：

- 删边 (a,b)：只有一个边结点要删；只需把 a 侧链上指向它的指针改指向它的后继、b 侧链同理，改两个指针即可。
- 删顶点 e：先沿 e 的 firstedge 链找出所有依附 e 的边结点并逐个删除，同时修正每条被删边另一端顶点的链指针（把被删结点在对方链上的前驱直接接到后继，或把对方 firstedge 置为后继/空）。

## 5. 复杂度分析

设顶点数 $|V|=n$，边/弧数 $|E|=e$。

| 结构 | 空间 | 找某顶点全部出边 | 找某顶点全部入边 | 删除一条边 | 删除一个顶点 |
|---|---|---|---|---|---|
| 邻接矩阵 | $O(n^2)$ | $O(n)$ | $O(n)$ | $O(1)$ | $O(n)$ |
| 邻接表（有向） | $O(n+e)$ | $O(\text{出度})$ | $O(n+e)$ 需遍历全表 | $O(1)$ 定位后删 | 较麻烦 |
| 邻接表（无向） | $O(n+2e)$ | — | — | 需删两份 | 需删所有冗余结点 |
| **十字链表** | $O(n+e)$ | $O(\text{出度})$ | $O(\text{入度})$ | — | — |
| **邻接多重表** | $O(n+e)$ | 关联边 $O(\text{度})$ | 同左（无向不分出入） | 改两个指针，$O(1)$ 定位后 $O(1)$ 改链 | 沿链删所有关联边 |

**推导说明**：

- 十字链表空间：$n$ 个顶点结点 + $e$ 个弧结点，每个结点常数个字段 → $O(n+e)$。找入边代价从邻接表的 $O(n+e)$ 降为 $O(\text{入度})$，因为入边已按弧头串成链。
- 邻接多重表空间：$n$ 个顶点结点 + $e$ 个边结点（**不是 $2e$**）→ $O(n+e)$。相比无向图邻接表的 $O(n+2e)$，常数因子减半。
- 平均情况：以上均为**确定性计数**，不存在随机分布，故无「平均/最坏」之分；若按「随机取一个顶点找其关联边」估计，期望代价为 $O(2e/n)$（平均度），这是均匀假设下的推断。

## 6. 易错点与考试写法

1. **适用对象搞反**：十字链表 ↔ **有向图**；邻接多重表 ↔ **无向图**。这是选择题最高频陷阱，务必记死。
2. **十字链表两条链的含义**：`firstout`/`tlink` 串的是**同弧尾**（出边），`firstin`/`hlink` 串的是**同弧头**（入边）。不要与「前驱/后继」混淆。
3. **邻接多重表走链要看顶点在 ivex 还是 jvex**：编号在 ivex 位走 ilink，在 jvex 位走 jlink。画图题常考「从顶点 v 出发依次经过哪些边结点」。
4. **边结点个数**：邻接多重表无向图有 $e$ 个边结点；邻接表无向图有 $2e$ 个边结点。选择题常拿这个数字做文章。
5. **表示不唯一**：同一图用十字链表或邻接多重表存储，边的链接次序可不同，存储结构**不唯一**（与邻接表一样）。
6. **考试写到什么程度算对**：408 不要求手写这两种结构的完整代码（视频明确说代码逻辑复杂、不会考手写实现）。答题只需：① 说清适用图类型；② 画出/读懂顶点结点与边（弧）结点的字段；③ 说明它解决了什么缺陷（十字链表解决找入边难；邻接多重表解决边冗余、删边删点难）；④ 给出空间复杂度 $O(|V|+|E|)$。

## 7. 408 题型与解题套路

- **选择题（主要考法）**：
  - 「十字链表适用于存储____」→ 有向图。
  - 「邻接多重表适用于存储____」→ 无向图。
  - 「用邻接多重表存储含 $n$ 顶点 $e$ 边的无向图，边结点个数为____」→ $e$。
  - 「十字链表中，从顶点 $v$ 的 firstin 出发沿 hlink 可找到____」→ 所有以 $v$ 为弧头的弧（入边）。
  - 「相比邻接表，十字链表解决了什么问题」→ 有向图找入边需遍历全表的问题。
- **画图/读图题**：给出图与存储结构，问某顶点的链上依次有哪些边结点；或问删除某边后哪些指针要改。套路：先定顶点编号 → 判断该顶点在边结点中的位置（ivex/jvex 或 tailvex/headvex）→ 沿对应指针走。
- **算法题**：本节**不考**手写实现（视频明确说明）。若综合题中出现，只作为「存储结构选择理由」的论述素材。
- **常见陷阱**：把「邻接多重表省空间」说成「因为不用存顶点」；把十字链表的 hlink/tlink 方向记反；把邻接多重表误用于有向图。

## 8. 自测题

**1.** 十字链表和邻接多重表分别适用于存储什么图？各自解决了基础结构的什么缺陷？

**2.** 含 $n$ 个顶点、$e$ 条边的无向图，用邻接表和邻接多重表存储时，边结点个数分别是多少？空间复杂度各是什么？

**3.** 十字链表中，顶点结点有 `firstin` 和 `firstout` 两个指针。从某顶点 $v$ 的 `firstin` 出发沿弧结点的 `hlink` 链，能找到什么？沿 `firstout` 出发走 `tlink` 链呢？

**4.** 邻接多重表中，从顶点 $v$ 出发沿 `firstedge` 走链时，什么情况下走边结点的 `ilink`，什么情况下走 `jlink`？

**5.** 判断：同一无向图用邻接多重表存储，其存储结构是唯一的。

<details>
<summary>答案</summary>

1. 十字链表存**有向图**，解决邻接表找入边需遍历全表的问题（同时保持 $O(|V|+|E|)$ 空间）；邻接多重表存**无向图**，解决邻接表每条边存两份冗余、删边删点不方便的问题。
2. 邻接表：$2e$ 个边结点，空间 $O(n+2e)$；邻接多重表：$e$ 个边结点，空间 $O(n+e)$。
3. `firstin` + `hlink` 链：所有以 $v$ 为**弧头**的弧，即 $v$ 的全部**入边**；`firstout` + `tlink` 链：所有以 $v$ 为**弧尾**的弧，即 $v$ 的全部**出边**。
4. 若 $v$ 等于该边结点的 `ivex`，走 `ilink`；若 $v$ 等于 `jvex`，走 `jlink`。
5. **错**。与邻接表类似，边的链接次序可以不同，存储结构**不唯一**。

</details>

## 9. 背诵卡

1. 十字链表 → **有向图**；邻接多重表 → **无向图**。别记反。
2. 十字链表：`firstout`/`tlink` 串**出边**（同弧尾），`firstin`/`hlink` 串**入边**（同弧头）。
3. 邻接多重表：每条边**一个**边结点；走链看顶点在 `ivex`（走 ilink）还是 `jvex`（走 jlink）。
4. 两者空间都是 $O(|V|+|E|)$；十字链表补「找入边难」，邻接多重表补「边冗余、删边删点难」。
5. 408 只考**特性理解与画图**，不考手写实现；存储结构**不唯一**。
