# 1.2 算法的时间复杂度

## 1. 本节定位

- **对应王道书**：第 1 章「绪论」→ 1.2 算法和算法评价 → 1.2.2 算法的时间复杂度。
- **408 大纲对应**：算法的时间复杂度分析（算法效率度量）。
- **先修知识**：算法的定义与特性（1.2.1）、基本语句/循环结构、简单函数增长阶的直觉。
- **本章位置**：与「空间复杂度」并列，是算法评价的两大指标之一；后续所有章节（线性表、树、图、排序、查找）的算法分析都以本节方法为工具，属于**全书的通用基本功**。

## 2. 一句话结论

算法的时间复杂度是**在算法运行前**预估其时间开销 $T$ 与问题规模 $n$ 之间的函数关系，并**只保留最高阶项、去掉系数**，用大 $O$ 记号表示其数量级。

## 4. 核心内容

### 1. 为什么用「事前估算」而不是「事后统计」

事后统计（让程序跑一遍测运行时间）有四个问题：

1. **与机器性能有关**：好机器快、差机器慢，不能客观评价算法本身。
2. **与编程语言有关**：越高级的语言执行效率越低（如 C 一般快于 Java）。
3. **与编译产生的机器指令质量有关**。
4. **有的算法不能事后统计**：如控制导弹轨迹的算法，等出错再统计毫无意义。

结论：应**排除与算法本身无关的外界因素**，在算法运行前预估 $T$ 与 $n$ 的关系。

### 2. 时间复杂度的定义

算法的时间开销 $T$ 与问题规模 $n$ 之间存在函数关系 $T(n)$。分析时间复杂度的核心任务，就是**用问题规模 $n$ 表示出算法的时间开销**。

### 3. 逐行计数法（以「爱你 n 遍」为例）

```c
void loveYou(int n) {          // n 为问题规模
    int i = 1;                 // ① 执行 1 次
    while (i <= n) {           // ② 条件判断执行 n+1 次
        i++;                   // ③ 执行 n 次
        printf("I love You %d\n", i);  // ④ 执行 n 次
    }
    printf("I love You More Than %d\n", n);  // ⑤ 执行 1 次
}
```

- 当 $n=3000$ 时，总执行次数 $= 1 + 3001 + 3000 + 3000 + 1 = 9003$。
- 一般地：$T(n) = 3n + 3$（假设每行耗时相同，把问题简化）。

> 注意：`while` 的条件判断比循环体多执行 1 次（最后一次判断不成立才跳出）。

### 4. 化简：只保留最高阶项

设三个算法：

- $T_1(n) = 3n + 3$
- $T_2(n) = n^2 + 3n + 1000$
- $T_3(n) = n^3 + 6n^2 + \cdots$

当 $n$ 足够大时，低阶项和常数项影响可忽略：

- $T_1$ 取 $3n$，$n=3000$ 时约 9000，与 9003 差别不大；
- $T_2$ 取 $n^2$，与精确值差别不大；
- $T_3$ 取 $n^3$，与精确值差别不大。

进一步，**常数系数也可忽略**：$3n$ 与 $n$ 是同一数量级（类比 3000 元与 9000 元，而 900 万才是另一个数量级）。

### 5. 大 O 表示法

**数学含义**：$T(n) = O(f(n))$ 表示
$$\lim_{n \to \infty} \frac{T(n)}{f(n)} = k \quad (k \text{ 为常数})$$

**操作口诀**：保留最高阶项 → 系数化为 1 → 外面套 $O$。

**加法规则**：多项相加只保留最高阶项，系数化为 1。
$$T_3(n) = O(n^3) + O(n^2) + O(1) = O(n^3)$$

**乘法规则**：两个大 O 相乘则合并。
$$T(n) = n^2 \log n + n^3 \;\Rightarrow\; O(n^2 \log n) + O(n^3) = O(n^3)$$

### 6. 常见数量级排序（必背）

$$O(1) < O(\log_2 n) < O(n) < O(n\log_2 n) < O(n^2) < O(n^3) < O(2^n) < O(n!)$$

**口诀：常对幂指阶**（常数 < 对数 < 幂函数 < 指数 < 阶乘）。

**比较 $n^3$ 与 $n^2\log_2 n$**：$n^3 = n^2 \cdot n$，只需比较 $n$ 与 $\log_2 n$，因 $n$ 增长更快，故保留 $n^3$。

**用极限证明**（了解即可，408 不要求证明）：
$$\lim_{n\to\infty}\frac{\log_2 n}{n} = 0,\qquad \lim_{n\to\infty}\frac{n^2}{2^n} = 0$$
说明 $n$ 增长快于 $\log_2 n$，$2^n$ 增长快于 $n^2$。

### 7. 三个重要结论（求 $T(n)$ 的简化方法）

1. **顺序执行的代码只影响常数项，可忽略**。在开头插入 1000 行顺序代码，$T(n)$ 从 $3n+3$ 变为 $3n+1003$，仍是 $O(n)$。
2. **只需分析循环中某一条基本操作的执行次数**。系数最终化为 1，不必逐行数循环体。
3. **嵌套循环只看最深层循环的执行次数**。外层 $n$ 次、内层 $n$ 次，则内层语句执行 $n^2$ 次，$T(n)=O(n^2)$。

### 8. 典型例题：指数型循环

```c
void loveYou(int n) {
    int i = 1;
    while (i <= n) {
        i = i * 2;             // 每次翻倍
        printf("I love You %d\n", i);
    }
    printf("I love You More Than %d\n", n);
}
```

设循环执行 $x$ 次，则 $i$ 依次为 $2, 4, 8, \dots, 2^x$。循环结束条件为 $2^x > n$，即 $x = \lfloor \log_2 n \rfloor + 1$。

$$T(n) = O(\log_2 n) + O(1) = O(\log_2 n)$$

## 5. 复杂度分析（最好 / 最坏 / 平均）

以「在乱序数组 `flag[0..n-1]` 中查找值为 $n$ 的元素」为例：

```c
void search(int flag[], int n) {
    for (int i = 0; i < n; i++) {
        if (flag[i] == n) {    // 找到目标
            printf("找到了 %d\n", n);
            break;
        }
    }
}
```

- **最好情况**：目标在第一个位置，循环 1 次，$T(n) = O(1)$。
- **最坏情况**：目标在最后一个位置，循环 $n$ 次，$T(n) = O(n)$。
- **平均情况**（需概率假设）：假设目标等概率出现在 $n$ 个位置中的任意一个，每个位置概率为 $\frac{1}{n}$。

  查找次数分别为 $1, 2, 3, \dots, n$，则平均查找次数：
  $$\bar{x} = \sum_{i=1}^{n} i \cdot \frac{1}{n} = \frac{1}{n} \cdot \frac{n(n+1)}{2} = \frac{n+1}{2}$$
  故 $T(n) = O\left(\frac{n+1}{2}\right) = O(n)$。

**结论**：一般只度量**最坏**和**平均**时间复杂度；最好时间复杂度参考意义不大（评价算法主要看它在不利情况下是否会出现运行时间过长）。

## 6. 易错点与考试写法

1. **`while` 条件判断次数 = 循环体次数 + 1**，逐行计数时容易漏掉最后那次不成立的判断。
2. **大 O 只保留最高阶项且系数化为 1**，写成 $O(3n)$、$O(n^2 + n)$ 均不规范，应写 $O(n)$、$O(n^2)$。
3. **$O(\log n)$ 的底数不写**（408 中默认以 2 为底，写 $O(\log_2 n)$ 或 $O(\log n)$ 均可，但不要写成 $O(\ln n)$ 混淆）。
4. **嵌套循环不是简单相乘**：若内层循环次数依赖外层变量（如 `for(j=0;j<i;j++)`），需用求和 $\sum_{i=1}^{n} i = \frac{n(n+1)}{2} = O(n^2)$，不能直接写 $n \times n$ 了事（结果虽同，但过程要写对）。
5. **平均复杂度必须写概率假设**，不能只给结论；408 简答/分析题中，缺假设会扣分。
6. **答题规范**：考研答题写到「找出基本操作 → 写出执行次数与 $n$ 的关系 → 取最高阶项得大 O」三步即可，不必写极限证明。

## 7. 408 题型与解题套路

**选择题常见考法**：

- 给一段循环代码，问时间复杂度（单层 / 嵌套 / 指数型 / 对数型）。
- 给多个复杂度表达式，问哪个阶数最高 / 最低（考「常对幂指阶」排序）。
- 给 $T(n)$ 的精确表达式，问大 O 表示（考加法规则、乘法规则）。
- 判断「顺序执行代码是否影响复杂度」（答案：不影响数量级）。

**算法题中的套用**：

- 分析自己写的算法复杂度时，找**最深层循环**的基本操作，数执行次数。
- 递归算法：写出递推式 $T(n) = aT(n/b) + f(n)$，用展开法或主定理估算（本节未展开，后续章节补充）。

**常见陷阱**：

- 把 $O(n\log n)$ 误判为高于 $O(n^2)$（实际 $n\log n < n^2$）。
- 忽略 `break` 导致的「最好/最坏」差异。
- 把 $O(2^n)$ 与 $O(n!)$ 顺序搞反（阶乘最大）。

## 8. 自测题

**1.** 分析下列代码的时间复杂度：
```c
int i = 0, sum = 0;
while (i <= n) {
    sum += i;
    i++;
}
```
<details><summary>答案</summary>
循环体执行 $n+1$ 次（$i$ 从 0 到 $n$），条件判断 $n+2$ 次。$T(n) = O(n)$。
</details>

**2.** 下列复杂度按从小到大排序：$O(n^2)$、$O(\log_2 n)$、$O(n!)$、$O(2^n)$、$O(n\log_2 n)$、$O(1)$。
<details><summary>答案</summary>
$O(1) < O(\log_2 n) < O(n\log_2 n) < O(n^2) < O(2^n) < O(n!)$。
</details>

**3.** 化简 $T(n) = 5n^3 + 100n^2 + 7\log_2 n + 50$ 的大 O 表示。
<details><summary>答案</summary>
最高阶项为 $5n^3$，系数化为 1，得 $O(n^3)$。
</details>

**4.** 在长度为 $n$ 的数组中顺序查找某元素，假设目标等概率出现在各位置，求平均时间复杂度并写出推导。
<details><summary>答案</summary>
设目标在第 $i$ 个位置（$1 \le i \le n$），需比较 $i$ 次，概率均为 $\frac{1}{n}$。平均比较次数 $\bar{x} = \sum_{i=1}^{n} i \cdot \frac{1}{n} = \frac{n+1}{2}$，故 $T(n) = O(n)$。
</details>

**5.** 判断：在算法开头插入 1000 行顺序执行代码，会使时间复杂度从 $O(n)$ 变为 $O(n+1000)$，因此复杂度改变。
<details><summary>答案</summary>
错误。顺序执行代码只影响常数项，$O(n+1000) = O(n)$，数量级不变。
</details>

## 9. 背诵卡

1. **时间复杂度定义**：事前预估 $T(n)$ 与问题规模 $n$ 的关系，只关注数量级。
2. **大 O 操作**：保留最高阶项 → 系数化为 1 → 套 $O$。
3. **口诀**：常对幂指阶 —— $O(1) < O(\log n) < O(n^k) < O(2^n) < O(n!)$。
4. **求 $T(n)$ 三招**：顺序代码忽略；单层循环看基本操作次数；嵌套循环看最深层。
5. **三种情况**：重点掌握最坏和平均（平均需概率假设），最好参考意义不大。
