# 6.2.5 图的基本操作

## 1. 本节定位

- **对应王道书**：第 6 章「图」→ 6.2「图的存储及基本操作」→ 6.2.5「图的基本操作」。
- **408 大纲对应**：图的基本概念与存储结构之后，图的遍历之前；大纲要求掌握「图的基本操作（在邻接矩阵、邻接表上的实现）」。
- **先修知识**：图的逻辑结构（顶点、边/弧、有向/无向、$<x,y>$ 与 $(x,y)$ 记号）、邻接矩阵、邻接表（含顶点表 + 边表）。
- **本章位置**：承接 6.2.1–6.2.4 的存储结构，是「数据元素三要素」中第三个要素（基本操作）的落地；本节的两个操作（找第一个邻接点、找下一个邻接点）是 6.3 图遍历（BFS/DFS）的直接前置。

## 2. 一句话结论

**图的基本操作没有唯一实现，其时间开销完全由存储结构决定：邻接矩阵「查边、找邻接点」多为 $O(|V|)$ 但判边 $O(1)$；邻接表「遍历某顶点的邻接点」为 $O(1)\sim O(|V|)$，但判边、找入边需扫链表甚至全表。**

## 3. 知识地图

```
图的基本操作（基于邻接矩阵 / 邻接表）
├── 判边：Adjacent(G, x, y)        判断 <x,y> 或 (x,y) 是否存在
├── 列邻接边：Neighbors(G, x)      列出与 x 相连的所有边
├── 插顶点：InsertVertex(G, x)     新增孤立顶点
├── 删顶点：DeleteVertex(G, x)     删顶点及其关联边
├── 加边：  AddEdge(G, x, y)       不存在则添加
├── 找第一个邻接点：FirstNeighbor(G, x)
├── 找下一个邻接点：NextNeighbor(G, x, y)
└── 边权：  SetEdgeWeight / GetEdgeWeight
```

## 4. 核心内容

### 4.1 记号约定（先分清）

- $<x,y>$：有向边（弧），方向 $x\to y$。
- $(x,y)$：无向边。
- 本节只讨论**邻接矩阵**与**邻接表**两种存储（考研最常考）；十字链表、邻接多重表仅作扩展思考。

### 4.2 判边 `Adjacent(G, x, y)`

**邻接矩阵**：直接取 `M[x][y]`（无向图对称，取任一即可）。

```c
// 邻接矩阵判边：O(1)
bool Adjacent(MGraph G, int x, int y) {
    return G.Edge[x][y] != 0;   // 无权图 0/1；带权图用 INF 表示不存在
}
```

**邻接表**：在顶点 $x$ 的边表中查找是否有编号为 $y$ 的边结点。

```c
// 邻接表判边：最好 O(1)，最坏 O(|V|)
bool Adjacent(ALGraph G, int x, int y) {
    for (ArcNode *p = G.vertices[x].firstarc; p; p = p->nextarc)
        if (p->adjvex == y) return true;
    return false;
}
```

- 最好：$y$ 恰是 $x$ 边表第一个结点 → $O(1)$。
- 最坏：$x$ 与其余 $|V|-1$ 个顶点全相连且 $y$ 在表尾或不存在 → $O(|V|)$。

### 4.3 列邻接边 `Neighbors(G, x)`

- **邻接矩阵（无向图）**：扫描第 $x$ 行（或列），凡为 1 者即邻接边 → $O(|V|)$。
- **邻接矩阵（有向图）**：出边扫第 $x$ 行，入边扫第 $x$ 列，各 $O(|V|)$。
- **邻接表（无向图）**：遍历 $x$ 的边表，最好 $O(1)$（无边或仅一条），最坏 $O(|V|)$。
- **邻接表（有向图）**：出边遍历 $x$ 的边表（$O(1)\sim O(|V|)$）；**入边必须扫描全部顶点表的全部边结点**，$O(|E|)$。

> 结论：有向图找「入边」时邻接矩阵更优；但若图为稀疏图（$|E|$ 很小），邻接表的 $O(|E|)$ 也可接受——**具体问题具体分析**。

### 4.4 插顶点 `InsertVertex(G, x)`

新顶点初始与任何顶点不相连。

- **邻接矩阵**：在顶点数组末尾写入 $x$ 的信息；对应新行、新列全为 0。**这些 0 在矩阵初始化时已置好**，故唯一开销是写顶点信息 → $O(1)$。
- **邻接表**：顶点数组末尾写入 $x$，`firstarc = NULL` → $O(1)$。
- 有向图同理，均 $O(1)$。

### 4.5 删顶点 `DeleteVertex(G, x)`

- **邻接矩阵**：**不要**把后续行列整体前移（大量元素移动，开销大）。做法是把第 $x$ 行、第 $x$ 列全部置 0，并在顶点结构体中加一个布尔标记（如 `isEmpty`）表示该顶点已空 → 只改一行一列，$O(|V|)$。
- **邻接表（无向图）**：删除 $x$ 的边表，还要在**所有与 $x$ 相邻顶点的边表**中删去指向 $x$ 的结点。
  - 最好：$x$ 为孤立点 → $O(1)$。
  - 最坏：$x$ 与所有顶点相连且相关边结点都在各表尾 → 需遍历全部边 → $O(|E|)$。
- **邻接表（有向图）**：删出边容易（删 $x$ 的边表）；**删入边必须遍历整个邻接表**，代价高。

### 4.6 加边 `AddEdge(G, x, y)`

- **邻接矩阵**：`M[x][y] = 1`（无向图再 `M[y][x] = 1`）→ $O(1)$。
- **邻接表**：在 $x$ 边表插入 $y$（无向图再在 $y$ 边表插入 $x$）。**用头插法**，$O(1)$；尾插法需先找表尾，$O(|V|)$。

```c
// 邻接表头插加边（无向图需调用两次，方向互换）
void AddEdge(ALGraph *G, int x, int y) {
    ArcNode *p = (ArcNode *)malloc(sizeof(ArcNode));
    p->adjvex = y;
    p->nextarc = G->vertices[x].firstarc;  // 头插
    G->vertices[x].firstarc = p;
}
```

### 4.7 找第一个邻接点 `FirstNeighbor(G, x)`

- **邻接矩阵**：从左到右扫描第 $x$ 行，找到第一个 1。最好 $O(1)$（第一个元素即为 1），最坏 $O(|V|)$（扫完整行无 1，返回 -1）。
- **邻接表**：取 `G.vertices[x].firstarc` 的 `adjvex` 即可 → $O(1)$。
- **有向图**：邻接矩阵找出边扫行、找入边扫列；邻接表找出边 $O(1)$，找入边最好 $O(1)$、最坏 $O(|E|)$（遍历全表）。**实际更常用找出边**。

### 4.8 找下一个邻接点 `NextNeighbor(G, x, y)`

已知 $y$ 是 $x$ 的邻接点，求 $y$ 之后的下一个邻接点。

- **邻接矩阵**：从第 $x$ 行 $y$ 的下一列继续向右扫，找到下一个 1。最好 $O(1)$，最坏 $O(|V|)$（扫到行尾无果，返回 -1）。
- **邻接表**：在 $x$ 边表中定位到 `adjvex == y` 的结点，取其后继 → $O(1)$。

> **这两个操作（`FirstNeighbor` / `NextNeighbor`）是图遍历算法的核心接口**，BFS/DFS 中反复调用；考研中直接调用函数接口即可，不必手写内部实现。

### 4.9 边权 `SetEdgeWeight` / `GetEdgeWeight`

主要开销在于**先找到这条边/弧**，因此时间复杂度与 `Adjacent` 完全一致：邻接矩阵 $O(1)$；邻接表最好 $O(1)$、最坏 $O(|V|)$。

## 5. 复杂度分析

设 $|V|=n$，$|E|=e$。下表「平均」一列按**目标边在边表中位置等概率分布**推导：边表长度 $k$，查找位置均匀分布于 $1\sim k$，平均比较次数 $\frac{k+1}{2}$，故平均 $O(k)$；对无向图 $k$ 最大为 $n-1$，故平均 $O(n)$（即 $O(|V|)$）。

| 操作 | 邻接矩阵 | 邻接表（最好 / 最坏 / 平均） |
|---|---|---|
| 判边 `Adjacent` | $O(1)$ | $O(1)$ / $O(\vert V\vert)$ / $O(\vert V\vert)$ |
| 列邻接边（无向） | $O(\vert V\vert)$ | $O(1)$ / $O(\vert V\vert)$ / $O(\vert V\vert)$ |
| 列邻接边（有向，入边） | $O(\vert V\vert)$ | $O(1)$ / $O(\vert E\vert)$ / $O(\vert E\vert)$ |
| 插顶点 | $O(1)$ | $O(1)$ |
| 删顶点（无向） | $O(\vert V\vert)$ | $O(1)$ / $O(\vert E\vert)$ / $O(\vert E\vert)$ |
| 删顶点（有向，含入边） | $O(\vert V\vert)$ | — / $O(\vert E\vert)$ / $O(\vert E\vert)$ |
| 加边 | $O(1)$ | $O(1)$（头插） |
| `FirstNeighbor` | $O(1)$ / $O(\vert V\vert)$ / $O(\vert V\vert)$ | $O(1)$ |
| `NextNeighbor` | $O(1)$ / $O(\vert V\vert)$ / $O(\vert V\vert)$ | $O(1)$ |
| 边权读写 | $O(1)$ | $O(1)$ / $O(\vert V\vert)$ / $O(\vert V\vert)$ |

**平均情况推导说明**：以邻接表判边为例，$x$ 的边表长度为 $k$，假设目标 $y$ 等概率出现在 $k$ 个位置或不存在，则平均扫描 $\frac{k+1}{2}$ 个结点；$k\le n-1$，故平均 $O(n)=O(|V|)$。稀疏图下 $k$ 的期望很小，实际接近 $O(1)$。

## 6. 易错点与考试写法

1. **删顶点不要整体前移**：邻接矩阵删顶点用「行列清零 + 空标记」，不是数组搬移；这是本节明确强调的坑。
2. **有向图邻接表找入边是 $O(|E|)$ 而非 $O(|V|)$**：必须扫全部边结点，别写成 $O(|V|)$。
3. **邻接表加边用头插法**：尾插需先找表尾，退化为 $O(|V|)$；答题时写「头插，$O(1)$」。
4. **无向图加边/删边要成对处理**：`M[x][y]` 与 `M[y][x]` 同步，邻接表两个方向各插/删一次。
5. **`FirstNeighbor` 无邻接点时返回 -1**，不是 0；矩阵中 0 号顶点与「无」要区分。
6. **答题深度**：408 对基本操作只要求「给定存储结构，说出思路 + 时间复杂度」，不要求默写全部代码；但 `FirstNeighbor`/`NextNeighbor` 在邻接表上的实现要能写出（遍历边表取 `adjvex`）。

## 7. 408 题型与解题套路

- **选择题（高频）**：给存储结构问某操作的时间复杂度；或反过来「要在 $O(1)$ 内判边，应选哪种存储」。套路：先看操作是「按位置访问」还是「按邻接关系遍历」——矩阵按位置 $O(1)$，链表按遍历 $O(k)$。
- **选择题陷阱**：把邻接表判边写成 $O(1)$；把有向图找入边写成 $O(|V|)$；忽略无向图对称性导致漏写一半。
- **算法题铺垫**：BFS/DFS 代码中调用 `FirstNeighbor`、`NextNeighbor`，只需会调用接口；若题目要求「基于邻接表实现遍历」，则需自己写这两个函数（遍历边表）。
- **综合题**：比较两种存储结构在某操作上的优劣，答「矩阵判边快、链表省空间且遍历邻接点快，稀疏图选链表」即可得分。

A. $O(1)$ B. $O(|V|)$ C. $O(|E|)$ D. $O(|V|^2)$

**3.** 邻接矩阵删除顶点 $x$ 的合理做法及复杂度是？

**4.** 邻接表加边为何推荐头插法？复杂度多少？

**5.** `NextNeighbor(G, x, y)` 在邻接表上的实现思路与复杂度？

<summary>答案</summary>

1. **A**。直接取 `M[x][y]`，$O(1)$。
2. **C**。需遍历所有顶点的边表统计指向 $x$ 的弧，$O(|E|)$。

## 9. 背诵卡

1. 判边：矩阵 $O(1)$；邻接表 $O(1)\sim O(|V|)$。
2. 有向图找**入边**：矩阵 $O(|V|)$，邻接表 $O(|E|)$——矩阵更优。
3. 删顶点：矩阵「行列清零 + 空标记」$O(|V|)$，**不搬移**。
4. 加边：矩阵 $O(1)$；邻接表**头插** $O(1)$。
5. `FirstNeighbor`/`NextNeighbor` 是 BFS/DFS 的接口：邻接表 $O(1)$，矩阵 $O(1)\sim O(|V|)$。
