# 7.2.1 顺序查找

## 1. 本节定位

- **对应王道书**：第 7 章「查找」→ 7.2 线性表的查找 → 7.2.1 顺序查找（Sequential Search，又称线性查找 Linear Search）。
- **408 大纲对应**：查找的基本概念 + 线性表的查找（顺序查找）。
- **先修知识**：顺序表/链表的存储结构、动态数组 `malloc` 初始化、`for` 循环与数组下标越界判断、平均查找长度 ASL 的定义（第 7.1 节）。
- **本节位置**：整章查找算法的第一个算法，是后面折半查找、分块查找的对照基准；「哨兵」「判定树」两个工具会贯穿后续小节。

## 2. 一句话结论

顺序查找就是对线性表做一次无差别遍历，**无论顺序/链式存储、有序/无序都适用，时间复杂度恒为 $O(n)$**；优化只能降低常数或改善某一类 ASL，不能改变数量级。

## 3. 知识地图

```
顺序查找
├── 基本思想：从头到尾（或从尾到头）逐个比较关键字
├── 适用性
│   ├── 存储结构：顺序表（数组）、链表（单/双链表）均可
│   └── 元素次序：有序、无序均可
├── 实现方式
│   ├── 朴素版（下标从 0 开始，需判越界）
│   └── 哨兵版（0 号位存关键字，从后往前扫，免判越界）
├── 效率分析（ASL）
│   ├── 查找成功：ASL_成功 = (n+1)/2，O(n)
│   └── 查找失败：比较 n+1 次（哨兵版），O(n)
└── 两种优化
    ├── 有序表优化：提前终止 → 画判定树，失败 ASL 降低
    └── 概率优化：按查找概率降序排列 → 成功 ASL 降低
```

## 4. 核心内容

### 1. 定义与基本思想

顺序查找：从表的一端开始，依次将每个元素的关键字与目标关键字 `key` 比较，相等则查找成功并返回其位置；扫完全表仍无相等元素则查找失败。

- 因为只是「挨个比」，所以**不依赖元素的存储方式**（顺序/链式都行），也**不要求元素有序**。
- 这是最朴素、最容易想到的查找方式，也是后续所有查找算法的性能下限参照。

### 2. 朴素实现（顺序表，下标从 0 开始）

前提：查找表用动态数组实现的顺序表，`elem` 指向动态数组首地址（`malloc` 申请，见顺序表一节），`length` 为当前元素个数。

```c
typedef struct {
    ElemType *elem;   // 动态数组首地址
    int length;       // 当前表长
} SSTable;

// 查找成功返回数组下标；失败返回 -1
int Search_Seq(SSTable ST, ElemType key) {
    int i;
    for (i = 0; i < ST.length; i++) {   // 注意 i 不能越界
        if (ST.elem[i] == key)          // 逐个比较关键字
            return i;                   // 找到，返回下标
    }
    return -1;                          // 扫完全表未找到
}
```

- 查找成功：循环在 `i` 命中时 `return i` 跳出。
- 查找失败：`i` 增到 `length` 时循环条件不成立而退出，返回 `-1`。
- 若查找表是链表，只需把 `for` 换成指针遍历、`return` 换成返回结点指针或位置，思想完全不变。

### 3. 哨兵实现（王道书/课本写法）

思路：**0 号位置空出来不放数据**，实际数据从下标 1 开始存；查找前把 `key` 写入 0 号位（这个位置就叫「哨兵」），然后从表尾往前扫。

```c
typedef struct {
    ElemType *elem;   // elem[0] 作哨兵，数据存于 elem[1..length]
    int length;
} SSTable;

// 找到返回下标（>=1）；返回 0 表示查找失败
int Search_Seq(SSTable ST, ElemType key) {
    ST.elem[0] = key;                  // 哨兵：把目标关键字放到 0 号位
    int i;
    for (i = ST.length; ST.elem[i] != key; i--)
        ;                              // 只需判「是否相等」，无需判 i 越界
    return i;                          // i==0 即失败
}
```

**为什么能省掉越界判断**：无论表中原来有没有 `key`，`i` 一路减到 0 时必然满足 `elem[0] == key`，循环一定终止。于是每轮循环只做一次比较，而不是「比较 + 判越界」两次判断。

**代价与收益**：省掉的是常数级的判断，数量级仍是 $O(n)$，**没有质的飞跃**。返回 0 表示失败，是因为 0 号位是人为填入的哨兵，不是表中真实数据。

> 「哨兵」名字的直观理解：指针扫到 0 号位这个「站岗的卫兵」时就知道该停下来了。

### 4. 优化一：有序表的顺序查找（提前终止）

若表内元素**递增有序**，查找 `key = 21` 时，扫到 29 发现 $29 > 21$，则后面元素只会更大，**立即判定失败**，不必扫到表尾。

**判定树（本节重点工具）**：

- 圆形结点 = 成功结点（表中真实元素），方形结点 = 失败结点（相邻两元素之间的「空隙」，共 $n+1$ 个）。
- 成功结点的查找长度 = 该结点所在**层数**（根为第 1 层）。
- 失败结点的查找长度 = 其**父结点所在层数**（因为要比较到父结点才确定落入该空隙）。

以递增表 $7, 13, 19, 29, 37, 43$（$n=6$）为例，判定树形如一条「斜链」：

```
        7(1)
         \
        13(2)
          \
         19(3)
           \
          29(4)
            \
           37(5)
             \
            43(6)
   每个成功结点下方挂一个失败结点（方形）
```

- 找 19：比较 7、13、19，共 3 次 = 19 所在层数 3。
- 找落在 13~19 之间的关键字：比较 7、13、19 后确定失败，共 3 次 = 父结点 19 的层数。

### 5. 优化二：按查找概率降序排列

若各关键字被查概率不等，把**概率大的放前面**，可降低查找成功时的 ASL。但这样元素次序被打乱（不再有序），查找失败时又只能扫到表尾，失败 ASL 回到 $O(n)$ 的朴素水平。

**结论**：两种优化各有适用面——查找成功居多用「概率降序」，查找失败居多用「有序表提前终止」，要结合应用场景选择。

## 5. 复杂度分析

设表长 $n$，各元素被查概率相等（等概率假设，这是 ASL 推导的标准前提）。

### 1. 查找成功

第 $i$ 个元素（从表头数起）需比较 $C_i = i$ 次，被查概率 $p_i = \frac{1}{n}$：

$$
ASL_{成功} = \sum_{i=1}^{n} p_i C_i = \frac{1}{n}\sum_{i=1}^{n} i = \frac{1}{n}\cdot\frac{n(n+1)}{2} = \frac{n+1}{2}
$$

- **最好**：目标在第一个被比较的位置，$1$ 次，$O(1)$。
- **最坏**：目标在最后（或不存在），$n$ 次，$O(n)$。
- **平均**：$\frac{n+1}{2}$，即 $O(n)$。

### 2. 查找失败

- 朴素版：扫完 $n$ 个元素，比较 $n$ 次。
- 哨兵版：扫到 0 号位哨兵才停，共比较 $n+1$ 次。
- 有序表优化后：失败情况共 $n+1$ 种（$n+1$ 个失败结点），等概率 $\frac{1}{n+1}$，第 $k$ 个失败结点比较 $k$ 次（前 $n$ 个失败结点）或 $n$ 次（最后两个失败结点，需比完全表）：

$$
ASL_{失败} = \frac{1}{n+1}\left(1+2+\cdots+n + n + n\right)
= \frac{1}{n+1}\left(\frac{n(n+1)}{2} + 2n\right)
$$

（分子末尾「$+n+n$」正是最下方两种失败情况都要比完 $n$ 个元素所致。）

### 3. 总评

无论朴素版、哨兵版还是两种优化，**时间复杂度都是 $O(n)$**；优化只改变常数因子或某一类 ASL，不改变数量级。

## 6. 易错点与考试写法

1. **位序 vs 下标**：哨兵版数据从下标 1 开始存，返回的下标就是「第几个元素」；朴素版从下标 0 开始，返回下标 = 位序 − 1。答题时写清「返回数组下标」还是「返回位序」。
2. **哨兵版返回 0 表示失败**，不是「找到 0 号元素」——0 号位是人为写入的 key，不是表中数据。
3. **哨兵省的是越界判断，不是比较次数**：比较次数反而多 1 次（$n+1$ 而非 $n$），别写成「哨兵减少了比较次数」。
4. **判定树层数从 1 开始数**：成功结点查找长度 = 自身层数；失败结点查找长度 = **父结点**层数，不是自身层数。
5. **有序表优化只优化「失败」**：成功 ASL 不变（仍是 $\frac{n+1}{2}$），失败 ASL 才下降。
6. **概率降序优化只优化「成功」**：失败 ASL 反而退化，别一概而论「优化后一定更好」。
7. **答题标准**：408 算法题/分析题写到「给出代码 + 说明等概率假设 + 写出 ASL 求和式并化简到 $\frac{n+1}{2}$ + 结论 $O(n)$」即满分；判定树题必须画出方形失败结点并标层数。

## 7. 408 题型与解题套路

- **选择题**：常考「顺序查找适用哪些存储结构」（答：顺序、链式都行）、「哨兵的作用」（免判越界，$O(n)$ 不变）、「有序表顺序查找失败的比较次数」、「给定判定树求某关键字的比较次数」。
- **ASL 计算题**：先写 $ASL=\sum p_i C_i$，明确等概率假设，再求和化简；失败情形要数清失败结点个数 $n+1$。
- **判定树画法套路**：成功结点按表中次序排成一条链（有序表），每个成功结点下挂一个失败结点，最末端再补一个失败结点，共 $n+1$ 个方形结点。
- **常见陷阱**：把哨兵版的 $n+1$ 次失败比较写成 $n$ 次；把失败结点查找长度写成自身层数；认为有序表优化能降低成功 ASL。

## 8. 自测题

**1.** 顺序查找是否要求线性表有序？是否要求顺序存储？

**2.** 哨兵版顺序查找中，返回值为 0 意味着什么？为什么循环一定能终止？

**3.** 长度为 $n$ 的顺序表，等概率下查找成功的 ASL 是多少？写出推导。

**4.** 对递增有序表 $\{7,13,19,29,37,43\}$ 顺序查找，查找关键字 21 需要比较几次？查找失败共几种情况？

## 9. 背诵卡

1. 顺序查找 = 线性表无差别遍历，顺序/链式、有序/无序全适用，$O(n)$。
2. 成功 ASL $=\frac{n+1}{2}$（等概率），失败比较 $n+1$ 次（哨兵版）。
3. 哨兵：0 号位存 key，从后往前扫，免判越界，返回 0 即失败。
4. 判定树：圆=成功（长度=层数），方=失败（长度=父结点层数），失败结点共 $n+1$ 个。
5. 有序表优化降失败 ASL；概率降序优化降成功 ASL；数量级都还是 $O(n)$。
