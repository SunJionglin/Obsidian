- **对应王道书**：第 3 章 栈、队列和数组 → 3.3 栈的应用 → 3.3.3 栈在递归中的应用。
- **408 大纲对应**：栈的应用（递归调用与函数调用栈）——属于「栈和队列」基本应用范畴。
- **先修知识**：栈的 LIFO 特性、栈的 push/pop 操作、C 语言函数调用与局部变量/形参/实参概念、递归算法的两个要素（递归表达式 + 边界条件）。
- **本节位置**：3.3 节先讲栈在括号匹配、表达式求值中的应用，本节把「栈」与「函数调用/递归」联系起来，是理解递归空间复杂度、递归转非递归的关键铺垫，也是后续「递归与栈」算法题的理论基础。

## 2. 一句话结论

**递归本质上是函数调用，而函数调用由系统用「函数调用栈」实现：每进入一层递归就把该层的返回地址、实参、局部变量压栈，每返回一层就弹栈——因此递归的空间复杂度正比于递归深度，递归层数过深会导致栈溢出。**

## 4. 核心内容

### 4.1 函数调用栈的原理（本节地基）

任何程序运行前，系统都会为其开辟一片栈空间，称为**函数调用栈**，用来保存函数调用过程中必须保存的信息。每发生一次函数调用，就把被调函数这一层所需的三类信息压入栈顶：

1. **返回地址**：被调函数执行完后，应回到调用处的哪条指令继续执行；
2. **实参**：传给被调函数的参数值（是值的副本，故在被调函数内改形参不影响调用者的实参）；
3. **局部变量**：被调函数内部定义的变量。

函数返回时，依据栈顶保存的返回地址回到调用处，并把该层信息弹出栈（释放空间）。

**关键性质**：最后被调用的函数最先返回——这正是 **LIFO（后进先出）**，与栈的特性一致。所以「函数调用」天然用栈实现。

> 补充：程序入口是 `main`，但编译器会在 `main` 之前插入其他启动代码，故 `main` 之下栈里还有若干系统信息（普通程序员无需关心）。用 IDE 断点调试可直接观察调用栈中每层的参数与局部变量（视频演示了这一点，返回地址一般不显示）。

### 4.2 递归与递归工作栈

- **递归**：函数直接或间接调用自身。可递归求解的问题特点：**把原问题转化为属性相同、规模更小的子问题**（如 $n! = n\times(n-1)!$，规模 $n\to n-1$）。
- **递归两要素**：
  - 递归表达式（递推关系）；
  - 边界条件（递归出口），否则无限递归。
- **递归工作栈**：递归调用时使用的函数调用栈，本质就是函数调用栈，只是场景是递归。

**过程规律（必背）**：
- 每进入一层更深的递归 → 把该层所需信息**压入栈顶**；
- 每执行完一层递归 → 从**栈顶弹出**该层信息，返回上一层继续执行。

### 4.3 阶乘递归的栈过程（以 `fact(10)` 为例）

```c
// 计算 n 的阶乘（王道风格）
int fact(int n) {
    if (n == 0 || n == 1)      // 边界条件（递归出口）
        return 1;
    else
        return n * fact(n - 1); // 递归表达式：n! = n * (n-1)!
}

int main() {
    int x = fact(10);          // 调用结束后需把返回值赋给 x（此即返回地址所指的下一句）
    // ...
    return 0;
}
```

栈的变化（按讲解顺序）：

1. `main` 调用 `fact(10)`：压入返回地址（“把返回值赋给 x”那条指令）、实参 `n=10`、局部变量。
2. `n=10` 不满足出口 → 执行 `return 10 * fact(9)`，调用 `fact(9)`：压入返回地址（“与 n 相乘后 return”那条指令）、实参 `n=9`。
3. 依此类推，`n` 逐层减 1，栈不断增高，直到 `fact(1)`。
4. `fact(1)` 满足出口，`return 1`，弹出该层；回到 `fact(2)` 层，用栈中保存的 `n=2` 计算 `2*1=2` 并返回，弹栈……
5. 逐层返回，直到 `fact(10)` 层算出 `10 × 9!`，返回给 `main`，`x` 得到 $10!$。

**结论**：递归深度为 $n$ 时，栈中同时存在 $n$ 层信息。若传入 100000，则要压 10 万层 → 可能**栈溢出**（系统给调用栈的存储有上限）。这解释了绪论中「递归带来空间复杂度升高」：**递归层数越多，空间复杂度越高**。

### 4.4 斐波那契递归的栈过程（以 `fib(4)` 为例）

```c
// 斐波那契数列：F(0)=0, F(1)=1, F(n)=F(n-1)+F(n-2)
int fib(int n) {
    if (n == 0) return 0;      // 边界条件
    if (n == 1) return 1;      // 边界条件
    return fib(n - 1) + fib(n - 2); // 递归表达式
}
```

`fib(4)` 的调用展开（按讲解顺序）：

```
fib(4)
├── fib(3)
│   ├── fib(2)
│   │   ├── fib(1) → 返回 1，弹栈
│   │   └── fib(0) → 返回 0，弹栈
│   │   ⇒ fib(2) 返回 1，弹栈
│   └── fib(1) → 返回 1，弹栈
│   ⇒ fib(3) 返回 2，弹栈
└── fib(2)  ← 注意：fib(2) 被第二次计算！
    ├── fib(1) → 1
    └── fib(0) → 0
    ⇒ fib(2) 返回 1
⇒ fib(4) = 2 + 1 = 3
```

**两个要点**：
- 调用顺序是「先左后右」：`fib(n-1)` 整棵子树算完返回后，才调用 `fib(n-2)`；每层返回都弹栈。
- **重复计算**：`fib(2)` 被计算两次，`fib(1)`、`fib(0)` 被多次计算——这是递归版斐波那契效率低的原因之一。

### 4.5 递归 → 非递归（栈的视角）

既然递归背后就是栈，**把递归改写成非递归，完全可以自己定义一个栈，用同样的思想模拟系统栈的压栈/弹栈过程**（如手工模拟阶乘、斐波那契的迭代+栈实现）。本节只要求理解「递归与栈的本质联系」，具体改写题在课后习题中出现。

## 5. 复杂度分析

以阶乘递归 `fact(n)` 为例：

- **时间复杂度**：共 $n$ 层调用，每层做常数次乘法，$T(n)=T(n-1)+O(1)$，展开得 $T(n)=O(n)$。最好/最坏/平均均为 $O(n)$（输入规模决定层数，与数据取值无关）。
- **空间复杂度**：递归工作栈同时保存 $n$ 层信息，每层空间为常数，故 $S(n)=O(n)$，**正比于递归深度**。最好/最坏/平均均为 $O(n)$。

以斐波那契递归 `fib(n)` 为例：

- **时间复杂度**：设 $T(n)$ 为计算 $F(n)$ 的调用次数，$T(n)=T(n-1)+T(n-2)+O(1)$，$T(0)=T(1)=O(1)$。该递推与斐波那契同阶，解得 $T(n)=O(\varphi^n)$，其中 $\varphi=\frac{1+\sqrt5}{2}\approx1.618$（即指数级）。**平均情况推导**：在「每个 $n\ge2$ 的结点都严格展开左右两棵子树」这一确定性假设下，调用次数满足上述递推，无随机性，故平均即最坏，均为 $O(\varphi^n)$。
- **空间复杂度**：栈的最大深度出现在沿 `fib(n-1)` 一路向下的路径上，深度为 $O(n)$，故 $S(n)=O(n)$（注意：时间指数级，空间只是线性级，二者不要混淆）。

> 408 必考：递归的空间复杂度 = 递归深度（× 每层常数空间），这是选择题高频结论。

## 6. 易错点与考试写法

1. **「递归工作栈」与「函数调用栈」不是两个东西**：递归工作栈就是递归场景下的函数调用栈，本质相同，不要答成两套机制。
2. **压栈的三类信息要记全**：返回地址、实参、局部变量。漏「返回地址」是最常见失分点。
3. **实参是副本**：被调函数内修改形参不影响调用者的实参（因为栈里存的是值拷贝），这与「传值调用」一致。
4. **空间复杂度看深度，不看调用总次数**：斐波那契递归调用次数指数级，但栈深度只有 $O(n)$，空间是 $O(n)$。
5. **递归不一定比非递归慢在时间上，但一定有栈空间开销**；递归层数过深会栈溢出，这是「递归缺点」的标准答法。
6. **答题程度**：简答/选择只需答出「函数调用用栈实现，压返回地址、实参、局部变量，后进先出，空间复杂度正比于递归深度」即可；算法题若要求「用栈模拟递归」，需自己定义栈并写出压/弹过程，不能只写递归函数。

## 7. 408 题型与解题套路

- **选择题常见考法**：
  - 函数调用时栈中保存哪些信息（返回地址/实参/局部变量）；
  - 给定递归函数与初值，问某时刻栈中元素个数或栈顶内容（按调用顺序逐层压栈数层数）；
  - 递归算法空间复杂度（答递归深度）；
  - 递归与栈的 LIFO 对应关系判断。
- **算法题套路**：题目要求「将递归算法改为非递归」时，标准做法是**自定义栈**，把「递归表达式对应的中间状态」和「返回后要继续做的操作」压栈，循环弹栈处理；本质是手工模拟系统栈。
- **常见陷阱**：
  - 把「调用总次数」当成空间复杂度；
  - 斐波那契递归中忽略重复计算，误判时间复杂度为 $O(n)$；
  - 认为递归一定栈溢出（只有深度过大才溢出）。

## 8. 自测题

**1.** 函数调用时，系统把哪些信息压入函数调用栈？为什么函数调用适合用栈实现？

**2.** 递归算法 `fact(n)` 的空间复杂度是多少？若 `n=100000` 可能出现什么问题？

**3.** 递归版斐波那契 `fib(4)` 执行过程中，`fib(2)` 被调用了几次？这说明递归的什么缺点？

**4.** 判断：递归算法的时间复杂度一定高于对应的非递归算法。

**5.** 简述把递归算法改写为非递归算法的一般思路（从栈的角度）。

1. 压入三类信息：返回地址、实参、局部变量。因为函数调用满足「最后被调用者最先返回」，即 LIFO，与栈的后进先出特性一致。

## 9. 背诵卡

1. 函数调用栈保存三类信息：**返回地址、实参、局部变量**；调用压栈、返回弹栈，LIFO。
2. **递归工作栈 = 递归场景下的函数调用栈**，本质相同。
3. 递归两要素：**递归表达式 + 边界条件（出口）**。
4. 递归空间复杂度 = **递归深度 × 每层常数空间**；层数过深 → **栈溢出**。
5. 递归可改非递归：**自定义栈模拟系统栈**；斐波那契递归有**重复计算**，时间指数级、空间线性级。
