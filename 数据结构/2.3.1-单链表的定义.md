# 2.3.1 单链表的定义

## 1. 本节定位

- **对应王道书**：第 2 章「线性表」→ 2.3 线性表的链式表示 → 2.3.1 单链表的定义。
- **408 大纲对应**：线性表的链式存储结构（单链表），属于「线性表」考点的组成部分。
- **先修知识**：线性表的逻辑结构、顺序表（顺序存储）、C 语言结构体 `struct`、指针、`malloc`、`typedef`。
- **本章位置**：顺序表（2.2）之后，链式存储的开篇。本节只解决「单链表长什么样、怎么用代码定义」，为后续 2.3.2 基本操作（插入、删除、查找、建表）打地基。

## 2. 一句话结论

单链表是用**链式存储**实现的线性表，每个结点由**数据域 `data`** 和**指针域 `next`** 组成；代码上用 `struct` 定义结点、用 `typedef` 起别名，实现方式分**带头结点**与**不带头结点**两种，二者判空条件不同。

## 3. 知识地图

```
线性表
├── 顺序存储 → 顺序表（随机存取、存储密度高、需连续空间）
└── 链式存储 → 链表
    ├── 单链表（每个结点一个指针）← 本节
    │   ├── 结点定义：struct LNode { ElemType data; struct LNode *next; }
    │   ├── typedef 别名：LNode / LinkList
    │   └── 两种实现
    │       ├── 不带头结点：头指针 L 直接指向首元结点；判空 L == NULL
    │       └── 带头结点：头指针 L 指向头结点（不存数据）；判空 L->next == NULL
    ├── 双链表
    ├── 循环链表
    └── 静态链表
```

## 4. 核心内容

### 4.1 什么是单链表

- 单链表结点 = **数据域**（存数据元素）+ **指针域**（存指向下一个结点的指针）。
- 每个结点只含**一个**指针，故称「单」链表。
- 与顺序表对比（408 必考对比点）：

| 维度 | 顺序表 | 单链表 |
|---|---|---|
| 存储方式 | 顺序存储，物理连续 | 链式存储，物理可离散 |
| 随机存取 | 支持 $O(1)$ | **不支持**，只能从头顺 `next` 找 |
| 存储密度 | 高（只存数据） | 低（每结点多一个指针域开销） |
| 扩容 | 不方便，需大片连续空间 | 方便，随便找一块内存挂上新结点即可 |

### 4.2 结点类型的定义（能默写）

```c
// 定义单链表结点类型
struct LNode {              // LNode 是结点
    ElemType data;          // 数据域：存放数据元素
    struct LNode *next;     // 指针域：指向下一个结点
};
```

- 结构体内部引用自身类型，必须写 `struct LNode *next`，不能只写 `LNode *next`（此时 `LNode` 别名尚未生效）。

### 4.3 typedef 重命名（本节重点，跨考必看）

`typedef` 用法：`typedef 原类型名 新别名;`

```c
typedef int 整数;            // 把 int 重命名为“整数”
typedef int *整数指针;        // 把 int* 重命名为“整数指针”
```

对单链表结点：

```c
typedef struct LNode LNode;      // 把 struct LNode 重命名为 LNode
typedef struct LNode *LinkList;  // 把 struct LNode* 重命名为 LinkList
```

王道书更紧凑的等价写法：

```c
typedef struct LNode {      // 声明结点的同时起别名
    ElemType data;
    struct LNode *next;
} LNode, *LinkList;
// 等价于：struct LNode {...}; typedef struct LNode LNode; typedef struct LNode *LinkList;
```

**`LNode *` 与 `LinkList` 完全等价**，区别只在「强调什么」：

- 写 `LNode *L`：强调 **L 是一个指向结点的指针**。
- 写 `LinkList L`：强调 **L 是一个单链表**（头指针）。

王道书示例代码两种混用，读代码时不要懵。典型例子（GetElem 取第 i 个结点）：

```c
LNode *GetElem(LinkList L, int i) {
    // 返回值类型写 LNode*：强调返回的是一个“结点”
    // 参数写 LinkList：强调传入的是一个“单链表”
    ...
}
```

> 408 必考：能读懂 `LNode *` 与 `LinkList` 的等价性；选择题常直接考 typedef 语义。

### 4.4 单链表的两种实现与初始化

**（1）不带头结点**

```c
typedef struct LNode {
    ElemType data;
    struct LNode *next;
} LNode, *LinkList;

// 初始化（C++ 引用写法，王道风格；纯 C 需用二级指针 LinkList *L）
bool InitList(LinkList &L) {
    L = NULL;          // 头指针置空，表示空表；同时避免脏数据
    return true;
}

// 判空
bool Empty(LinkList L) {
    return (L == NULL);   // 可直接 return L == NULL;
}
```

- 头指针 `L` 直接指向**首元结点**（真正存数据的第一个结点）。
- 空表：`L == NULL`。

**（2）带头结点**

```c
bool InitList(LinkList &L) {
    L = (LNode *)malloc(sizeof(LNode));  // 申请头结点空间，L 指向头结点
    if (L == NULL) return false;         // 内存不足，分配失败
    L->next = NULL;                      // 头结点 next 置空，表示空表
    return true;
}

// 判空
bool Empty(LinkList L) {
    return (L->next == NULL);   // 看头结点的 next 是否为空
}
```

- 头指针 `L` 指向**头结点**，头结点**不存数据**，只起「统一操作、方便写代码」的作用。
- 真正的数据从 `L->next` 开始。
- 空表：`L->next == NULL`（注意此时 `L` 本身不为 NULL）。

**（3）两种实现对比（408 必考）**

| | 不带头结点 | 带头结点 |
|---|---|---|
| 头指针指向 | 首元结点（存数据） | 头结点（不存数据） |
| 判空条件 | `L == NULL` | `L->next == NULL` |
| 代码复杂度 | 更麻烦（首结点插入/删除要特判） | 更方便（首结点与其他结点操作统一） |
| 使用倾向 | 少用 | **大多数情况用这种** |

> 为什么带头结点写代码更方便：下一节用具体插入/删除代码演示，本节只需记住结论与判空差异。

## 5. 复杂度分析

本节只讲定义与初始化，不涉及查找/插入算法，故：

- **初始化（带头结点）**：一次 `malloc` + 一次赋值，时间 $O(1)$，空间 $O(1)$（仅头结点）。
- **初始化（不带头结点）**：一次赋值，时间 $O(1)$，空间 $O(1)$。
- **判空**：一次比较，时间 $O(1)$。

> 说明：单链表「按位查找 $O(n)$、插入删除 $O(1)$（已知前驱）」等复杂度属于后续基本操作小节，本节不展开，避免与 2.3.2 混淆。

## 6. 易错点与考试写法

1. **结构体内自引用必须带 `struct`**：`struct LNode *next;`，写成 `LNode *next;` 在别名未定义前是错的。
2. **`LNode *` 与 `LinkList` 等价**，但语义侧重不同；选择题问「`LinkList L` 中 L 是什么」→ 是指向结点的指针 / 单链表的头指针。
3. **判空条件混淆**：不带头结点 `L == NULL`；带头结点 `L->next == NULL`。带头结点时 `L` 本身永远不为 NULL（除非 malloc 失败）。
4. **头结点不存数据**：头结点的 `data` 域无意义，别把它当第一个元素。
5. **初始化函数参数**：王道用 C++ 引用 `LinkList &L`，若题目要求纯 C，需写 `LinkList *L` 并用 `*L` 修改，否则函数内改的是副本（转写中特别强调「没有引用符号改的是复制品」）。
6. **`malloc` 返回值要判空**（工程习惯；408 答题写 `if (L == NULL) return false;` 更严谨）。
7. **答题标准**：定义题写全 `struct` + `typedef` 两行别名；判空题写清「带头/不带头」再给条件；对比题按「存储方式、随机存取、存储密度、扩容」四点作答。

## 7. 408 题型与解题套路

- **选择题**：
  - 考 `typedef` 语义：`typedef struct LNode *LinkList;` 后 `LinkList` 是什么类型 → 指向 `struct LNode` 的指针。
  - 考判空：给带头结点链表，问空表条件 → `L->next == NULL`。
  - 考头结点作用：统一首结点与其他结点的插入删除操作、便于判空。
  - 考顺序表 vs 单链表优缺点对比（随机存取、存储密度、扩容）。
- **算法题（本节不直接出，但是所有链表大题的地基）**：后续插入/删除/逆置/找中点等题，第一步都是正确写出结点定义与初始化；头结点是否存在的假设必须在答题开头声明。
- **常见陷阱**：
  - 题目说「带头结点」却按不带头写判空 → 全错。
  - 把 `LinkList` 当成「链表类型」而非「指针类型」→ 声明变量时多写/少写 `*`。
  - 混淆「头指针」与「头结点」：头指针是变量，头结点是实际分配的一块内存。

<details>
<summary>参考答案</summary>

**1.**
```c
typedef struct LNode {
    ElemType data;
    struct LNode *next;
} LNode, *LinkList;
```
等价于先 `struct LNode {...};`，再 `typedef struct LNode LNode;`、`typedef struct LNode *LinkList;`。

**2.** 带头结点：`L->next == NULL`，因为头结点不存数据，`L` 本身非空，空表体现在头结点后面没有结点。不带头结点：`L == NULL`，因为头指针直接指向首元结点，空表时无结点可指。

**3.** 等价，都是「指向 `struct LNode` 的指针」。混用是为强调语义：`LNode *` 强调「这是一个结点指针」，`LinkList` 强调「这是一个单链表（头指针）」，如 `GetElem(LinkList L, int i)` 返回 `LNode *`。

**4.** 单链表**不支持随机存取**，按位查找必须从头沿 `next` 依次找，$O(n)$；但**扩容方便**，结点物理上可离散存放，新增结点只需再 `malloc` 一块空间挂上，无需大片连续空间。顺序表相反：随机存取 $O(1)$、存储密度高，但扩容需连续空间、不方便。

**5.** 作用是把头结点的指针域置空，表示当前为空表，同时清除 `malloc` 得到的内存中可能残留的脏数据。若省略，`L->next` 为随机值，判空 `L->next == NULL` 会失效，后续遍历可能访问非法地址。

</details>

## 9. 背诵卡

1. 单链表结点 = 数据域 `data` + 指针域 `next`，每个结点一个指针，故称「单」。
2. 定义：`typedef struct LNode { ElemType data; struct LNode *next; } LNode, *LinkList;`
3. `LNode *` ≡ `LinkList`，前者强调结点，后者强调单链表。
4. 不带头结点判空 `L == NULL`；带头结点判空 `L->next == NULL`。
5. 头结点不存数据，作用是统一操作、方便写代码；大多数情况用带头结点。

## 10. 关联与下一节

- **向前关联**：顺序表用顺序存储实现线性表，支持随机存取但扩容难；单链表用链式存储解决「物理连续」的约束，代价是失去随机存取。
- **向后关联**：下一节 2.3.2 单链表的基本操作——按位查找 `GetElem`、按值查找 `LocateElem`、插入 `ListInsert`、删除 `ListDelete`、头插法/尾插法建表。届时会用具体代码演示「带头结点为什么写代码更方便」，本节的头结点判空结论会反复用到。
- **后续扩展**：双链表、循环链表、静态链表均在本节结点定义基础上变形（多一个 `prior` 指针 / 首尾相连 / 用数组模拟指针）。
