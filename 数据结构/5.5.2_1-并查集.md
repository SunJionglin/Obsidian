# 5.5.2 并查集（Disjoint Set / Union-Find）

## 1. 本节定位

- **对应王道书**：第 5 章「树与二叉树」5.5 节「树与二叉树的应用」中 5.5.2「并查集」。
- **408 大纲**：2022 年新增考点「并查集及其应用」，属于「树与二叉树的应用」条目下的内容。
- **先修知识**：树的**双亲表示法**（5.4 节树的存储结构）、森林的定义（$m$ 棵互不相交的树的集合）、集合的逻辑结构（第 1 章逻辑关系分类）。
- **本节位置**：是树的应用之一，与哈夫曼树、二叉排序树、平衡二叉树并列；后续图的最小生成树 Kruskal 算法会直接用到并查集（推断，属于后续章节的衔接）。

## 2. 一句话结论

并查集用**一个长度为 $n$ 的 int 数组（双亲表示法）**表示若干互不相交的集合，核心操作只有**查（find，一路向上找根）**和**并（union，把一棵树的根挂到另一棵树的根下）**；对 union 采用「**小树并到大树**」的优化后，树高不超过 $O(\log_2 n)$，find 最坏复杂度由 $O(n)$ 降为 $O(\log_2 n)$。

## 3. 知识地图

```
并查集
├── 逻辑结构：集合（元素之间只有「同属/不同属一个集合」两种关系）
├── 存储结构：顺序存储，int 数组 s[n]，本质是树的双亲表示法
│     ├── s[i] >= 0：i 的父结点下标
│     └── s[i] <  0：i 是根（未优化时恒为 -1；优化后绝对值为该集合元素个数）
├── 基本操作
│     ├── 初始化 Initial：全部置 -1（n 个独立子集）
│     ├── 查 Find(x)：沿 s 一路向上，直到 s[i] < 0，返回根下标
│     └── 并 Union(root1, root2)：把一棵树的根挂到另一棵树的根下
│           ├── 朴素版：直接挂，可能长成单链
│           └── 优化版：小树并到大树（按规模合并）
└── 复杂度
      ├── Union：O(1)
      └── Find：朴素最坏 O(n)；优化后最坏 O(log2 n)
```

## 4. 核心内容

### 4.1 逻辑结构与「为什么叫并查集」

- 逻辑结构是**集合**：把 $n$ 个元素划分为若干**互不相交**的子集。任取两个元素，关系只有两种——**属于同一集合**或**属于不同集合**。
- 用「森林」表示集合：**同一个集合的元素组织成一棵树**，不同集合对应不同的树，树与树互不相交。
- 需要实现的基本操作只有两个：
  - **并（Union）**：把两个不相交的集合合并为一个；
  - **查（Find）**：给定元素，确定它属于哪个集合（即找它所在树的根）。
- 因此得名「并查集」。判断两元素是否同属一个集合 = 分别 find 两次，比较根是否相同。

### 4.2 存储结构：一个数组搞定

用长度为 $n$ 的 int 数组 `s[n]`，下标即元素编号，**数组值记录父结点下标**（双亲表示法）：

- `s[i] = -1`：$i$ 是根（朴素版）；
- `s[i] = j (j ≥ 0)`：$i$ 的父结点是 $j$。

> 关键：**数组下标是元素编号，数组值是父结点编号**，不要反过来理解。

### 4.3 初始化

```c
#define MAXSIZE 100
int s[MAXSIZE];

// 初始化：n 个元素各自成为一个独立集合
void Initial(int s[], int n) {
    for (int i = 0; i < n; i++)
        s[i] = -1;          // 每个结点都是根
}
```

### 4.4 查 Find：一路向上找根

```c
// 查找元素 x 所属集合，返回其根结点下标
int Find(int s[], int x) {
    while (s[x] >= 0)       // 只要不是根，就继续往上
        x = s[x];           // 走到父结点
    return x;               // s[x] < 0，x 即根
}
```

- 判断两元素是否同集合：`Find(s, a) == Find(s, b)`。
- 例：查 $l$（下标 11），路径 $11 \to 4 \to 1 \to 0$，`s[0] = -1`，返回 0，说明 $l$ 属于以 $a$（下标 0）为根的集合。

### 4.5 并 Union（朴素版）

```c
// 前提：root1、root2 分别是两棵树的根（即 s[root] < 0）
void Union(int s[], int root1, int root2) {
    if (root1 == root2) return;   // 同一集合，无需合并
    s[root2] = root1;             // root2 挂到 root1 下
}
```

- 若给的是任意两个元素 $e$、$g$，先 `Find` 出各自根，再 `Union`。
- 朴素版缺陷：每次都固定把 root2 挂到 root1 下，可能反复让大树挂到小树下，树被拉成单链，高度可达 $n$。

### 4.6 Union 优化：小树并到大树

**思路**：让结点少的树挂到结点多的树下，合并后树高不增加。

**表示法改造**：根的数组值不再固定为 $-1$，而用**负数的绝对值表示该集合元素个数**：

- `s[root] = -6`：该集合共 6 个元素；
- `s[root] = -2`：该集合共 2 个元素。

```c
// 优化版 Union：root1、root2 为两棵树根，s[root] 为负且绝对值为元素个数
void Union(int s[], int root1, int root2) {
    if (root1 == root2) return;
    if (s[root2] > s[root1]) {        // 负数比较：值大者元素少，root2 是小树
        s[root1] += s[root2];         // 大树规模累加小树规模
        s[root2] = root1;             // 小树根挂到大树根下
    } else {                          // root1 是小树（或等大，归入此支）
        s[root2] += s[root1];
        s[root1] = root2;
    }
}
```

> 注意 `s[root2] > s[root1]` 的含义：两者都是负数，**绝对值小（元素少）的那个值反而大**，所以「值大」= 「树小」。

**合并示例**：$a$ 树 6 个结点（`s[0] = -6`）、$c$ 树 2 个结点（`s[2] = -2`），合并后 `s[0] = -8`、`s[2] = 0`，树高不变。

## 5. 复杂度分析

设元素总数为 $n$，树高为 $h$。

**Union**

- 最好 / 最坏 / 平均均为 $O(1)$：只执行常数条赋值与比较语句，与 $n$、$h$ 无关。

**Find（朴素版）**

- 最好：$O(1)$，待查元素本身就是根，或根的孩子。
- 最坏：$O(n)$。构造：$n$ 个元素并成一棵单链（每次 union 都把大树挂到小树下），$h = n$，从叶子查到根需走 $n$ 步。
- 平均：取决于树的形态，无统一公式；**关键结论是 find 的代价正比于树高 $h$**，因此优化目标就是压低 $h$。

**Find（小树并大树优化后）**

- 最坏：$O(\log_2 n)$。推导（数学归纳法思路）：设树高为 $h$，则含 $h$ 层的树至少有 $2^{h-1}$ 个结点（每合并一次，小树规模至少翻倍才会使高度 +1），故 $n \ge 2^{h-1}$，得 $h \le \log_2 n + 1$，find 最坏 $O(\log_2 n)$。
- 最好：$O(1)$。
- 平均：仍与具体形态有关，量级不超过 $O(\log_2 n)$。

**结论对比表**

| 操作 | 朴素版 | 优化版 |
|---|---|---|
| Union | $O(1)$ | $O(1)$ |
| Find 最坏 | $O(n)$ | $O(\log_2 n)$ |

> 408 必考：优化后树高 $O(\log_2 n)$ 与 find 复杂度 $O(\log_2 n)$ 的对应关系，是选择题高频点。

## 6. 易错点与考试写法

1. **数组语义搞反**：`s[i]` 存的是 $i$ 的**父结点下标**，不是孩子；根用负数标记。写代码时 `x = s[x]` 是往上走，不是往下。
2. **根值含义随版本变化**：朴素版根为 $-1$；优化版根为「负的元素个数」。答题时若题目用优化版，`s[i] < 0` 仍是判根条件，但不能再默认等于 $-1$。
3. **Union 参数必须是根**：`Union(s, root1, root2)` 传的是根下标；若传普通元素，必须先 `Find`。题目常故意给两个非根元素让你合并，考这一步。
4. **负数比较方向**：优化版 `if (s[root2] > s[root1])` 中「大于」对应「小树」，这是最易写反的一行。
5. **同集合判断**：`root1 == root2` 时直接返回，不能把根挂到自己下面（会破坏结构）。
6. **答题标准**：408 算法题若考并查集，写出 `Initial`、`Find`、`Union` 三个函数 + 关键注释即可；复杂度要写明「Union $O(1)$，Find 最坏 $O(\log_2 n)$（按规模合并优化后）」，并说明优化依据是「控制树高」。

## 7. 408 题型与解题套路

- **选择题**：
  - 给一个数组状态，问某元素属于哪个集合 / 两元素是否同集合 → 沿 `s` 一路向上找根，比对根下标。
  - 给合并序列，问最终树高或某次 find 的比较次数 → 按「小树并大树」模拟，注意根值绝对值即规模。
  - 问优化前后 find 最坏复杂度 → $O(n)$ vs $O(\log_2 n)$。
- **算法题套路**：
  1. 定义全局数组 `s[]`；
  2. 写 `Initial` 全置 $-1$；
  3. 写 `Find` 循环向上；
  4. 写 `Union`（按规模合并）；
  5. 主逻辑：对满足条件的元素对反复 `Find` + `Union`，最后统计根个数（即集合数）。
- **常见陷阱**：
  - 把「集合个数」当成「根结点个数」统计时，忘记判根条件是 `s[i] < 0`；
  - 优化版中误把根值当父结点下标使用；
  - 合并时未先判 `root1 == root2`。

## 8. 自测题

**题 1** 数组 `s = {-1, 0, 0, 1, 1, 2}`，元素 4 属于以哪个下标为根的集合？元素 3 与元素 5 是否同集合？

**题 2** 用朴素 Union（固定 `s[root2] = root1`）依次合并 $(0,1),(1,2),(2,3),\dots,(n-2,n-1)$，最终树高是多少？此时 Find(0) 需比较几次？

**题 3** 优化版中某根 `s[3] = -5`，另一根 `s[7] = -2`，执行 `Union(s,3,7)` 后 `s[3]`、`s[7]` 分别是什么？

**题 4** 为什么并查集选用双亲表示法而不是孩子表示法或孩子兄弟表示法？

**题 5** 按规模合并优化后，含 $n$ 个结点的树高上界是多少？简述推导。

<details>
<summary>参考答案</summary>

**题 1** 元素 4：$4 \to 1 \to 0$，`s[0] = -1`，根为 0。元素 3：$3 \to 1 \to 0$，根 0；元素 5：$5 \to 2 \to 0$，根 0。两者同集合。

**题 2** 每次把新根挂到前一棵树下，形成单链 $0 \leftarrow 1 \leftarrow 2 \leftarrow \dots$，树高 $n$；Find(0) 中 0 是叶子，需向上走 $n-1$ 次比较，$O(n)$。

**题 3** `s[7] = -2 > s[3] = -5`，7 是小树：`s[3] = -5 + (-2) = -7`，`s[7] = 3`。

**题 4** 并查集的核心操作是「向上找根」和「把根挂到另一根下」，双亲表示法让这两个操作都是沿父指针的常数级跳转；孩子表示法找根需遍历、合并也麻烦，孩子兄弟表示法对本场景无优势。

**题 5** $h \le \log_2 n + 1$，即 $O(\log_2 n)$。推导：高度每增加 1，被合并的小树规模至少翻倍（小树并到大树，只有小树规模 ≥ 大树规模时高度才可能 +1），故高度为 $h$ 的树至少 $2^{h-1}$ 个结点，$n \ge 2^{h-1}$。

## 9. 背诵卡

1. 并查集 = 集合的逻辑结构 + 双亲表示法的顺序存储（一个 int 数组）。
2. `s[i] ≥ 0` 是父结点下标；`s[i] < 0` 是根（朴素版 $-1$，优化版绝对值为集合元素个数）。
3. Find：`while (s[x] >= 0) x = s[x]; return x;` —— 一路向上找根。
4. Union：先判 `root1 == root2`，再把一棵树的根挂到另一棵根下；优化版「小树并大树」，`s[大] += s[小]`，`s[小] = 大`。
5. 复杂度：Union $O(1)$；Find 朴素最坏 $O(n)$，按规模合并优化后最坏 $O(\log_2 n)$。
