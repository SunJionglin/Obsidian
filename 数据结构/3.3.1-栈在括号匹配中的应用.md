# 3.3.1 栈在括号匹配中的应用

## 1. 本节定位

- **对应王道书**：第 3 章 栈、队列和数组 → 3.3 栈的应用 → 3.3.1 括号匹配（栈的经典应用之一）。
- **408 大纲对应**：栈和队列的应用（括号匹配是栈应用的典型代表，属于“掌握”层次）。
- **先修知识**：栈的定义、后进先出（LIFO）特性、顺序栈的基本操作（`InitStack`、`StackEmpty`、`Push`、`Pop`、`GetTop`）。
- **本节位置**：栈的应用开篇。后续还有表达式求值（中缀转后缀）、递归等栈的应用，括号匹配是理解“栈为什么适合处理嵌套/配对结构”的第一课。

## 2. 一句话结论

**从左到右扫描括号串：遇左括号入栈，遇右括号则弹出栈顶左括号检查是否同型匹配；扫描结束后栈必须为空，否则匹配失败。**

## 3. 知识地图

```
括号匹配问题
├── 问题定义
│   ├── 数量匹配：左右括号个数相等
│   └── 形状匹配：小对小、中对中、大对大
├── 为什么用栈
│   └── 越后出现的左括号越先被匹配 → 后进先出（LIFO）
├── 算法流程
│   ├── 遇左括号 → 入栈
│   ├── 遇右括号 → 判栈空？

│   │   └── 栈非空 → 弹出栈顶，检查是否同型
│   │       ├── 不同型 → 失败
│   │       └── 同型 → 继续扫描
│   └── 扫描结束 → 判栈空？

│       └── 栈非空 → 左括号单身，失败

    └── 链栈（实际开发，防溢出）
```

## 4. 核心内容

### 4.1 问题定义

括号匹配要求一个括号串中所有括号**成双成对**出现，且满足：

1. **数量匹配**：左括号与右括号总数相等；
2. **形状匹配**：左小括号配右小括号、左中括号配右中括号、左大括号配右大括号；
3. **嵌套正确**：不允许交叉，如 `([)]` 非法。

IDE 与编译器在语法检查阶段都会做括号匹配检查，这是该问题的现实来源。

### 4.2 为什么用栈（核心思想）

人脑可以“一眼看出”配对关系，但计算机只能**从左到右依次扫描**。观察规律：

> 越往后出现的左括号，越先被匹配。

例如 `{ [ ( ) ] }`：扫描到第一个右括号 `)` 时，与之匹配的是**最近出现的、尚未匹配的**左括号 `(`。这正是**后进先出**的特性——把左括号依次压栈，越晚入栈的越早出栈被匹配。

因此：**左括号入栈，右括号触发一次出栈并配对检查**。

### 4.3 算法流程（详细）

设当前扫描到的字符为 `a`：

1. 若 `a` 是左括号 → `Push(S, a)`，继续扫描下一个；
2. 若 `a` 是右括号：
   - 若栈空 → 右括号单身，**匹配失败**，结束；
   - 否则 `Pop(S, b)` 弹出栈顶左括号 `b`，检查 `b` 与 `a` 是否同型：
     - 不同型 → **匹配失败**，结束；
     - 同型 → 继续扫描下一个；
3. 所有字符扫描完毕：
   - 栈空 → **匹配成功**；
   - 栈非空 → 存在单身左括号，**匹配失败**。

### 4.4 代码实现（C，王道风格）

```c
#define MaxSize 100
typedef char ElemType;

// 顺序栈定义
typedef struct {
    ElemType data[MaxSize];
    int top;            // 栈顶指针，指向栈顶元素
} SqStack;

// 基本操作（考试时可直接调用，建议加中文注释说明接口含义）
void InitStack(SqStack &S);          // 初始化栈
bool StackEmpty(SqStack S);          // 判栈空
bool Push(SqStack &S, ElemType x);   // 入栈
bool Pop(SqStack &S, ElemType &x);   // 出栈，用 x 返回栈顶元素

// 括号匹配主函数
bool bracketCheck(char str[], int length) {
    SqStack S;
    InitStack(S);                       // 初始化空栈
    for (int i = 0; i < length; i++) {
        if (str[i] == '(' || str[i] == '[' || str[i] == '{') {
            Push(S, str[i]);            // 左括号入栈
        } else {                        // 扫描到右括号
            if (StackEmpty(S))
                return false;           // 栈空：右括号单身，失败
            ElemType topElem;
            Pop(S, topElem);            // 弹出栈顶左括号
            if (str[i] == ')' && topElem != '(')
                return false;           // 形状不匹配
            if (str[i] == ']' && topElem != '[')
                return false;
            if (str[i] == '}' && topElem != '{')
                return false;
        }
    }
    return StackEmpty(S);               // 扫描结束：栈空则成功，否则左括号单身
}
```

**关键点**：

- 最后一行 `return StackEmpty(S);` 同时处理了“成功”和“左括号单身”两种情况，是简洁写法。
- 若题目要求不用基本操作、直接操作数组和 `top` 指针，则把 `Push` 换成 `S.data[++S.top] = str[i]`，`Pop` 换成 `topElem = S.data[S.top--]`，`StackEmpty` 换成 `S.top == -1`（具体取决于 `top` 初值约定，王道书顺序栈通常 `top = -1` 表示空）。

### 4.5 图解（以 `{ [ ( ) ] }` 为例）

| 扫描字符 | 动作 | 栈内容（底→顶） |
|---|---|---|
| `{` | 入栈 | `{` |
| `[` | 入栈 | `{ [` |
| `(` | 入栈 | `{ [ (` |
| `)` | 弹出 `(`，同型匹配 | `{ [` |
| `]` | 弹出 `[`，同型匹配 | `{` |
| `}` | 弹出 `{`，同型匹配 | 空 |
| 结束 | 栈空 → 成功 | — |

## 5. 复杂度分析

设括号串长度为 $n$。

- **最好情况**：第一个字符就是右括号且栈空，立即返回失败，$O(1)$。
- **最坏情况**：扫描全部 $n$ 个字符，每个字符做一次入栈或出栈（$O(1)$ 操作），总时间 $O(n)$；空间上最坏所有字符都是左括号，栈深 $n$，空间 $O(n)$。
- **平均情况**：每个字符恰好被扫描一次，入栈/出栈均为 $O(1)$，故平均时间 $O(n)$。**推导**：设串中左括号数为 $k$，则入栈 $k$ 次、出栈至多 $k$ 次，总基本操作次数 $\le 2n$，与 $n$ 同阶。空间平均取决于最大嵌套深度 $d$，为 $O(d)$，最坏 $d = n$。

> 结论：**时间 $O(n)$，空间 $O(n)$（最坏）**。这是 408 选择题常考的复杂度结论。

## 6. 易错点与考试写法

1. **忘记判栈空就 Pop**：扫描到右括号时若栈已空，必须先判空再弹出，否则是非法操作。这是最常见的失分点。
2. **只检查数量不检查形状**：`([)]` 数量相等但形状/嵌套错误，必须逐对比较括号类型。
3. **扫描结束后忘记判栈空**：`(()` 这类串扫描完栈里还剩左括号，属于“左括号单身”，必须返回失败。代码中 `return StackEmpty(S);` 不能漏。
4. **`top` 初值约定混乱**：王道书顺序栈常约定 `top = -1` 为空、`top` 指向栈顶元素；也有教材约定 `top = 0` 为空、`top` 指向栈顶下一位置。写代码时前后必须一致，答题时用注释说明约定。
5. **考试写法要求**：408 算法题中，允许直接调用栈的基本操作，但**建议用中文注释简要说明每个接口的功能**（如 `// 入栈`），即使函数命名不规范，阅卷老师也能看懂，不会扣分。若题目明确要求“不调用库函数/基本操作”，则需展开为对数组和 `top` 的直接操作。
6. **顺序栈容量固定**：实际开发中长括号串可能栈溢出，可用链栈；但**考试中用顺序栈即可**，无需担心溢出。

## 7. 408 题型与解题套路

- **选择题**：
  - 给一个括号串，问“栈的深度最大是多少”“扫描过程中栈内元素变化”“哪个串合法/非法”。
  - 套路：手动模拟入栈出栈，记录栈深峰值；注意 `([)]` 这类“数量对但形状错”的陷阱。
  - 常考结论：合法括号串的必要条件——任意前缀中左括号数 $\ge$ 右括号数，且总数相等。
- **算法题**：
  - 直接考“设计算法判断括号串是否匹配”，按 4.4 的模板写即可，重点写清三处失败分支（栈空遇右括号、形状不匹配、结束时栈非空）。
  - 可能变形：只含一种括号（简化）、要求返回第一个出错位置（在失败分支记录下标）。
- **常见陷阱**：
  - 把“栈空”与“栈满”混淆；
  - 忘记 `return StackEmpty(S)` 而直接 `return true`；
  - 用 `GetTop` 取栈顶后忘记 `Pop`，导致同一左括号被重复匹配。

## 8. 自测题

**题 1**：括号串 `[ ( { } ) ]` 在扫描过程中，栈的最大深度是多少？
<details><summary>答案</summary>
3。依次入栈 `[`、`(`、`{`，此时栈深为 3，之后开始出栈。
</details>

**题 2**：判断括号串 `( [ ) ]` 是否匹配，并说明在哪一步失败。
<details><summary>答案</summary>
不匹配。扫描到 `)` 时弹出栈顶 `[`，`[` 与 `)` 不同型，形状匹配失败，算法在此处返回 false。
</details>

**题 3**：括号串 `( ( )` 扫描结束后算法返回什么？为什么？
<details><summary>答案</summary>
返回 false（匹配失败）。扫描结束后栈中仍剩一个左括号 `(`，属于“左括号单身”，`StackEmpty(S)` 为假。
</details>

**题 4**：写出括号匹配算法的时间复杂度和空间复杂度，并说明空间复杂度的最坏情形。
<details><summary>答案</summary>
时间 $O(n)$，空间 $O(n)$。最坏情形是所有字符均为左括号，栈深达到 $n$。
</details>

**题 5**：若扫描到右括号时栈已空，说明什么问题？代码中应如何处理？
<details><summary>答案</summary>
说明出现了一个没有对应左括号的“单身右括号”，匹配失败。代码中应在 `Pop` 之前先 `if (StackEmpty(S)) return false;`。
</details>

## 9. 背诵卡

1. **核心思想**：越后出现的左括号越先被匹配 → 后进先出 → 用栈。
2. **三条失败分支**：① 遇右括号但栈空（右括号单身）；② 弹出左括号与右括号不同型；③ 扫描结束栈非空（左括号单身）。
3. **代码骨架**：左括号 `Push`；右括号先判空再 `Pop` 比对；最后 `return StackEmpty(S);`。
4. **复杂度**：时间 $O(n)$，空间最坏 $O(n)$。
5. **答题规范**：可调用栈基本操作，但要用中文注释说明接口；`top` 初值约定前后一致。
