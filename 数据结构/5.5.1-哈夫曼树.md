# 5.5.1 哈夫曼树

## 1. 本节定位

- **王道书对应**：第 5 章「树与二叉树」5.5 节「树与二叉树的应用」，5.5.1 哈夫曼树与哈夫曼编码。
- **408 大纲对应**：树与二叉树的应用——哈夫曼（Huffman）树和哈夫曼编码。
- **先修知识**：二叉树的基本概念（根、叶子、分支节点、度）、节点的路径长度（经过的边数）、二叉树的性质（$n_0=n_2+1$）。
- **本章位置**：在二叉树遍历、线索二叉树、树与森林转换之后，属于「二叉树的应用」收尾部分；哈夫曼编码是二叉树性质在压缩编码上的直接落地，也是本章少有的「构造类」考点。

## 2. 一句话结论

给定 $n$ 个带权叶子节点，每次取权值最小的两棵树合并成一棵新树（新根权值为二者之和），重复 $n-1$ 次得到的二叉树就是**带权路径长度（WPL）最小**的哈夫曼树；把字符频度作权值构造哈夫曼树、左 0 右 1 即得**前缀编码**（哈夫曼编码）。

## 4. 核心内容

### 1. 三个基本概念

**（1）节点的权（weight）**：给树中节点附上的数值，用来表示该节点的某种现实含义（如重要性、出现频度）。

**（2）节点的带权路径长度**：设根到该节点的路径长度为 $l$（经过的边数），节点权值为 $w$，则

$$
\text{节点的带权路径长度} = w \times l
$$

例：某节点权值为 3，从根出发经过 3 条边到达它，则其带权路径长度为 $3\times 3=9$。

**（3）树的带权路径长度（WPL, Weighted Path Length）**：

$$
\text{WPL} = \sum_{i=1}^{n} w_i \, l_i
$$

其中 $w_i$ 为第 $i$ 个**叶子节点**的权值，$l_i$ 为根到该叶子的路径长度。

> **关键限定**：WPL 只累加**叶子节点**，分支节点（包括后构造出的合并节点）一律不计入。

**WPL 计算示例**（4 个叶子，权值 1、3、4、5）：

- 形态一：四个叶子路径长度均为 2，$\text{WPL}=2\times(1+3+4+5)=26$。
- 形态二：路径长度分别为 1、2、3、3，$\text{WPL}=5\times1+4\times2+1\times3+3\times3=25$。
- 形态三：$\text{WPL}=1\times3+3\times3+4\times2+5\times1=25$。

可见同一组叶子节点，不同形态 WPL 可能不同；其中最小值为 25，达到最小值的树即哈夫曼树。

### 2. 哈夫曼树的定义

**哈夫曼树（Huffman Tree），又称最优二叉树**：给定 $n$ 个带权叶子节点，在所有含这 $n$ 个叶子节点的二叉树中，**WPL 最小**的那棵（类）二叉树。

定义的两个必要条件缺一不可：
1. 必须恰好含有给定的这 $n$ 个带权叶子节点；
2. 必须是所有可能形态中 WPL 最小的。

### 3. 哈夫曼树的构造算法（408 必考）

**输入**：$n$ 个带权叶子节点，权值集合 $W=\{w_1,w_2,\dots,w_n\}$。

**步骤**：

1. 把每个节点看作一棵只有根的树，构成森林 $F$。
2. 从 $F$ 中选出**根权值最小**的两棵树，作为左右子树合并成一棵新树；新根权值 = 两子树根权值之和。
3. 从 $F$ 中删除这两棵树，把新树加入 $F$。
4. 重复 2、3，直到 $F$ 中只剩一棵树，即为哈夫曼树。

**构造示例**（权值 1、2、3、7，对应节点 a、c、e、d）：

```
第1步：取 1、2 合并 → 新根 3
第2步：取 2、3 合并 → 新根 5      （也可取 3、3 合并，形态不同）
第3步：取 3、5 合并 → 新根 8
第4步：取 7、8 合并 → 新根 15
```

最终 WPL $=31$（按各叶子路径长度 × 权值累加）。换一种合并次序（如先合并 2 与 3）得到的树形态不同，但 WPL 仍为 31。

**参考实现（C，王道风格，仅示意构造逻辑）**：

```c
/* 前提：w[0..n-1] 为 n 个叶子权值，节点按权值升序或每次扫描取最小 */
/* 用数组模拟森林，每个元素记录权值与左右孩子下标 */
typedef struct {
    int weight;          // 权值
    int parent, lchild, rchild;  // 双亲、左右孩子下标，-1 表示无
} HTNode;

/* 构造 n 个叶子的哈夫曼树，返回根下标；数组长度 2n-1 */
int CreateHuffman(HTNode ht[], int w[], int n) {
    int m = 2 * n - 1;                 // 节点总数 2n-1
    for (int i = 0; i < m; i++) {      // 初始化
        ht[i].parent = ht[i].lchild = ht[i].rchild = -1;
    }
    for (int i = 0; i < n; i++) ht[i].weight = w[i];  // 前 n 个为叶子

    for (int i = n; i < m; i++) {      // 共合并 n-1 次，新节点依次放 n..m-1
        int s1 = -1, s2 = -1;          // s1 最小，s2 次小
        for (int j = 0; j < i; j++) {  // 只在已建好的节点中找
            if (ht[j].parent != -1) continue;   // 已被合并的跳过
            if (s1 == -1 || ht[j].weight < ht[s1].weight) { s2 = s1; s1 = j; }
            else if (s2 == -1 || ht[j].weight < ht[s2].weight) { s2 = j; }
        }
        ht[s1].parent = ht[s2].parent = i;      // 两棵最小树挂到新根下
        ht[i].lchild = s1; ht[i].rchild = s2;
        ht[i].weight = ht[s1].weight + ht[s2].weight;  // 新根权值 = 二者之和
    }
    return m - 1;                      // 最后一个节点即根
}
```

> 说明：上面是「每次扫描找最小两个」的朴素写法，便于理解构造过程；考试写构造过程用文字 + 图示即可，不必默写完整代码。

### 4. 哈夫曼树的性质（408 必考）

设叶子节点数为 $n$：

1. **初始节点最终都是叶子节点**，且**权值越小，到根的路径越长**（权大的离根近，从而 WPL 小）。
2. **节点总数为 $2n-1$**：合并 $n-1$ 次，每次新增 1 个分支节点，故总数为 $n+(n-1)=2n-1$。
3. **不存在度为 1 的节点**：每次合并都是「两棵树 → 一个新根」，新根必有左右两个孩子，故所有分支节点度均为 2（严格二叉树）。由 $n_0=n_2+1$ 也可验证：$n_0=n$，$n_2=n-1$。
4. **哈夫曼树不唯一**：权值相同的节点、左右子树次序可互换，可得到不同形态；但**所有形态的 WPL 相同且最小**。
5. 左右孩子交换不改变 WPL，也不改变「是哈夫曼树」这一事实。

### 5. 哈夫曼编码（应用，408 必考）

**背景**：电报用「点/划」即二进制 0/1 传字符；对字符集设计编码，希望总码长最短。

**（1）固定长度编码**：每个字符用等长二进制位表示。如 4 个字符用 2 位（00、01、10、11）。若 100 题中 c 出现 80 次、a 10 次、b 8 次、d 2 次，则总码长 $=100\times 2=200$ 位。等长编码不利用频度差异，不最优。

**（2）可变长度编码**：高频字符用短码、低频字符用长码，可缩短总码长。但必须解决**解码歧义**问题。

**（3）前缀编码（prefix code）**：字符集中任一字符的编码都**不是**另一字符编码的**前缀**。前缀编码可唯一解码（从左到右扫描，一旦匹配到某字符编码即切分）。

- 反例：a=1、b=111、c=0、d=110。串 `0 1 1 1 1 1 1 1 0` 本意 `c a a a b d`，却可能被切成 `c b b d`，产生歧义——因为 a 的编码 1 是 b、d 编码的前缀。
- 正例：a=10、b=111、c=0、d=110，则任一编码都不是另一编码的前缀，解码唯一。

**（4）哈夫曼编码的构造**：

1. 字符集中每个字符作为一个**叶子节点**，以该字符出现的**频度（次数/频率）作为权值**；
2. 按上述规则构造哈夫曼树；
3. 从根到叶：**左分支记 0、右分支记 1**（左右约定可互换，不影响正确性）；
4. 根到该叶路径上的 0/1 序列即为该字符的编码。

**为什么哈夫曼编码是前缀编码**：字符都放在**叶子**上，任一叶子的路径不可能是另一叶子路径的前缀（否则一个叶子会在另一个叶子的路径中间，矛盾）。所以哈夫曼编码天然是前缀编码，解码无歧义。

**为什么哈夫曼编码总码长最短**：总码长 $=\sum \text{频度}_i \times \text{码长}_i$，恰好等于以频度为权的哈夫曼树的 WPL；哈夫曼树 WPL 最小，故总码长最短，实现数据压缩。

**示例**（频度 c=80、a=10、b=8、d=2）：

- 固定 2 位编码：总长 $100\times2=200$ 位。
- 哈夫曼编码（如 c=0、a=10、b=111、d=110）：总长 $=80\times1+10\times2+8\times3+2\times3=130$ 位，即 WPL $=130$。
- 换一种哈夫曼树形态，编码串不同，但 WPL 仍为 130，压缩效果相同。

**（5）哈夫曼编码不唯一**：因哈夫曼树不唯一（左右互换、同权节点互换），编码方案不唯一；但**平均码长 / 总码长（WPL）唯一且最小**。

## 5. 复杂度分析

本节以构造与性质为主，复杂度针对「构造哈夫曼树」的算法：

- **朴素实现（每次线性扫描找最小两个）**：
  - 共合并 $n-1$ 次，第 $i$ 次在 $i$ 个候选节点中扫描找最小两个，代价 $O(i)$；
  - 总代价 $\sum_{i=n}^{2n-2} O(i) = O(n^2)$。
  - 最好 / 最坏 / 平均均为 $O(n^2)$（扫描次数只与 $n$ 有关，与权值分布无关）。
- **用最小堆（优先队列）优化**（王道书扩展，了解即可）：
  - 建堆 $O(n)$；每次取两个最小、插入一个新节点，各 $O(\log n)$，共 $n-1$ 轮；
  - 总代价 $O(n\log n)$。
  - 最好 / 最坏 / 平均均为 $O(n\log n)$（堆操作代价与权值无关）。
- **空间**：需存 $2n-1$ 个节点，$O(n)$。
- **编码/解码**：对每个字符沿根到叶路径走一遍，单字符 $O(\text{码长})$；$n$ 个字符总 $O(\text{总码长})$，即 $O(\text{WPL})$。

> 408 选择题常直接问「构造哈夫曼树的时间复杂度」，朴素法答 $O(n^2)$，堆优化答 $O(n\log n)$，注意题干是否限定实现方式。

## 6. 易错点与考试写法

1. **WPL 只算叶子**：分支节点的权值（合并产生的新根）**不**计入 WPL。这是最高频错误。
2. **路径长度按边数算，不按节点数算**：根到叶经过 $k$ 条边，路径长度就是 $k$，不是 $k+1$。
3. **节点总数是 $2n-1$ 而非 $2n$**：$n$ 个叶子 + $n-1$ 个分支节点。若题目给「哈夫曼树共有 $m$ 个节点」，则叶子数 $n=(m+1)/2$。
4. **哈夫曼树没有度为 1 的节点**：所有分支节点度均为 2。若画出的树有单分支节点，一定构造错了。
5. **哈夫曼树不唯一，但 WPL 唯一**：答题时若题目问「WPL 是否唯一」答唯一；问「树是否唯一」答不唯一。
6. **左右 0/1 约定可互换**：题目若未规定，左 0 右 1 或左 1 右 0 都算对，但同一题内要统一。
7. **前缀编码的判定**：检查是否有某编码是另一编码的前缀；哈夫曼编码因字符全在叶子上，必满足前缀性质。
8. **考试写法要求**：
   - 构造题：写出每步「取哪两个权值合并、新权值多少」，最后画出树并标出各叶路径长度，写出 WPL 计算式，**结果要落到具体数值**。
   - 编码题：先列频度，构造哈夫曼树，再逐字符写 0/1 串，最后算总码长（=WPL）并可与定长编码比较压缩率。
   - 只写「取最小的两个合并」不够，必须体现**重复 $n-1$ 次直到只剩一棵树**。

## 7. 408 题型与解题套路

**（1）选择题常见考法**

- 给一组权值，问构造出的哈夫曼树 WPL 是多少 → 按步骤合并，最后算 $\sum w_i l_i$。
- 给哈夫曼树节点总数，问叶子数 → $n=(m+1)/2$。
- 判断关于哈夫曼树性质的说法（度、唯一性、权值与路径长度关系）→ 对照 5 条性质逐项排除。
- 给编码方案，判断是否为前缀编码 / 能否唯一解码 → 查前缀关系。
- 问哈夫曼编码的平均码长 / 压缩率 → 平均码长 $=\text{WPL}/\sum \text{频度}$。

**（2）算法/构造题套路**

1. 把权值（频度）列成表，按从小到大排序便于取最小两个；
2. 每轮取最小两个合并，新权值写回集合，**保留合并过程图**；
3. 合并 $n-1$ 轮后得树，标出每个叶子的路径长度；
4. 写 $\text{WPL}=\sum w_i l_i$ 并算出数值；
5. 若要求编码，从根出发左 0 右 1 写出各字符编码，验证前缀性质。

**（3）常见陷阱**

- 把分支节点权值也加进 WPL；
- 路径长度多数一层（把根算作第 1 层却当路径长度用）；
- 忘记「共合并 $n-1$ 次」，只合并到一半就停；
- 认为哈夫曼树唯一，或认为不同形态 WPL 不同；
- 编码时把字符放在分支节点上（导致非前缀编码）。

## 8. 自测题

**1.** 权值为 $\{1,2,3,4,5\}$ 的 5 个叶子节点构造哈夫曼树，WPL 是多少？节点总数是多少？

**2.** 一棵哈夫曼树共有 31 个节点，则其叶子节点数是多少？度为 2 的节点数是多少？

**3.** 判断：哈夫曼树中权值越大的叶子节点离根越近；哈夫曼树的形态唯一。这两句话分别对错？

**4.** 字符集 $\{a,b,c,d\}$ 频度分别为 $7,5,2,4$，构造哈夫曼编码，写出一种编码方案并计算总码长（WPL）。

**5.** 编码方案 a=0、b=10、c=110、d=111 是否为前缀编码？为什么它能唯一解码？

<details>
<summary>参考答案</summary>

**1.** 合并过程：1+2=3；3+3=6（取原 3 与新 3）；4+5=9；6+9=15。各叶路径长度：1→3、2→3、3→2、4→2、5→2。WPL $=1\times3+2\times3+3\times2+4\times2+5\times2=3+6+6+8+10=33$。节点总数 $=2n-1=9$。

**2.** $n=(m+1)/2=(31+1)/2=16$ 个叶子；度为 2 的节点数 $=n-1=15$。

**3.** 第一句**对**（权大离根近，使 WPL 小）；第二句**错**（哈夫曼树形态不唯一，但 WPL 唯一且最小）。

**4.** 频度排序 2,4,5,7。合并：2+4=6；5+6=11；7+11=18。一种编码（左 0 右 1）：设 c(2)、d(4) 为兄弟，a(7)、b(5) 为兄弟，则可得如 a=0、b=10、c=110、d=111（具体依树形）。WPL $=7\times1+5\times2+2\times3+4\times3=7+10+6+12=35$。总码长 35 位。（不同形态编码不同，WPL 均为 35。）

**5.** **是**前缀编码：0、10、110、111 中任一都不是另一个的前缀。解码时从左到右扫描，遇到能匹配的完整编码即切分，因无前缀冲突，切分唯一，故可唯一解码。

## 9. 背诵卡

1. **WPL** $=\sum$（叶子权值 × 根到叶路径长度），**只算叶子**，路径长度按边数。
2. **哈夫曼树** = 含给定 $n$ 个带权叶子、WPL 最小的二叉树（最优二叉树）。
3. **构造**：每次取权值最小的两棵树合并，新根权值 = 二者之和，共合并 $n-1$ 次。
4. **性质**：节点总数 $2n-1$；无度为 1 的节点；权小离根远；形态不唯一、WPL 唯一最小。
5. **哈夫曼编码**：字符作叶子、频度作权值建树，左 0 右 1；是前缀编码，总码长 = WPL，用于数据压缩。

## 10. 关联与下一节

- **向前关联**：二叉树的度与节点数关系 $n_0=n_2+1$ 用于验证哈夫曼树无度为 1 的节点；路径长度概念来自二叉树基本术语。
- **向后关联**：哈夫曼编码是「树的应用」的典型；后续 5.5.2 并查集、5.5.3 B 树/B+ 树同属「树结构在检索与压缩中的应用」，可对比「构造类算法」的答题模板。
- **下一节**：并查集（Union-Find）——用双亲表示法存储的树结构，重点掌握查找与合并操作及路径压缩、按秩合并的优化。
