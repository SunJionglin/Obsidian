# 8.7.3 败者树

## 1. 本节定位

- **对应王道书**：第 8 章 排序 → 8.7 外部排序 → 8.7.3 败者树（多路平衡归并的优化）。
- **408 大纲对应**：外部排序（多路平衡归并与败者树）——属于「排序」章节中外部排序部分。
- **先修知识**：多路平衡归并（k 路归并）、完全二叉树的性质（第 $h$ 层最多 $2^{h-1}$ 个结点）、外部排序的「归并趟数」与「关键字比较次数」的关系。
- **本节位置**：上一节说明「增大归并路数 $k$ 可减少归并趟数、减少磁盘 I/O」，但带来「每次从 $k$ 个归并段选最小元素需 $k-1$ 次比较」的内部开销；本节用败者树把这一开销从 $O(k)$ 降到 $O(\log_2 k)$，是外部排序优化的关键一步。

## 2. 一句话结论

**败者树是一棵记录「失败者」的完全二叉树，建好之后每选出一个新的最小元素只需沿一条路径向上比较 $\lceil \log_2 k \rceil$ 次（而非 $k-1$ 次），从而在保持大归并路数的同时压低内部比较开销。**

## 3. 知识地图

```
败者树（Loser Tree）
├── 由来：k 路平衡归并的「选最小」瓶颈
│   ├── 传统方法：k 个归并段选最小 → k-1 次比较
│   └── 目标：把每次选择的比较次数降下来
├── 结构
│   ├── 逻辑上：完全二叉树
│   │   ├── 叶子结点：k 个，分别对应 k 个归并段（虚拟结点）
│   │   └── 非叶子（分支）结点：记录左右子树比较中的「失败者」所属归并段编号
│   └── 存储上：长度约 k 的一维 int 数组（下标 1 起为分支结点，0 号存冠军）
├── 构造（建树）
│   ├── 两两比较，败者写入分支结点，胜者继续向上
│   └── 共 k-1 次比较，根（0 号）记录最小元素所属归并段
├── 调整（输出一个最小元素后）
│   ├── 用该归并段的下一个元素顶替原叶子
│   └── 沿该叶子到根的路径重新比较，只走一条路径
└── 复杂度
    ├── 建树：k-1 次比较
    └── 每次调整：≤ ⌈log₂k⌉ 次比较（与分支结点层数相同）
```

## 4. 核心内容

### 4.1 为什么需要败者树

设 $k$ 路平衡归并。传统做法：每次从 $k$ 个归并段的当前首元素中选最小，需顺序比较 $k-1$ 次。当 $k$ 很大（如 1024 路），每次选最小要 1023 次比较，内部排序时间急剧增加，抵消了减少归并趟数带来的收益。

败者树的作用：**把「从 $k$ 个元素中选最小」的比较次数从 $k-1$ 降到 $\lceil \log_2 k \rceil$**。

### 4.2 定义与结构

- **逻辑结构**：一棵完全二叉树。
  - **叶子结点**：共 $k$ 个，每个对应一个归并段，存放该归并段当前待归并的首元素（逻辑上存在，实际存储中常为虚拟结点）。
  - **非叶子（分支）结点**：记录其左右子树比较中的**失败者**（较大者）来自哪个归并段，只存**归并段编号**，不存元素本身。
  - **根（冠军结点）**：记录最终胜者（最小元素）所属归并段编号。
- **关键点**：分支结点记录的是「失败者」，胜者继续向上比赛，直到根。这正是「败者树」名字的由来。

> 补充：有的教材把最上面的冠军结点称为根，有的把最下面的分支结点层称为根，称呼不影响算法，答题时说明「记录冠军的结点」即可。

### 4.3 构造过程（建树）

以 8 个归并段首元素 `27, 12, 1, 17, 9, 2, 11, 4` 为例（求最小）：

1. 叶子两两比较：`27 vs 12` → 败者 27（段 1）记入分支结点，胜者 12 上；`1 vs 17` → 败者 17（段 4）记入，胜者 1 上；`9 vs 2` → 败者 9（段 5）记入，胜者 2 上；`11 vs 4` → 败者 11（段 7）记入，胜者 4 上。
2. 上一层：`12 vs 1` → 败者 12（段 2）记入，胜者 1 上；`2 vs 4` → 败者 4（段 8）记入，胜者 2 上。
3. 顶层：`1 vs 2` → 败者 2（段 6）记入，胜者 1 上。
4. 冠军结点记录段 3（元素 1 所在归并段）。

共 $k-1=7$ 次比较，与顺序比较次数相同——**建树不省比较，省的是后续每次调整**。

### 4.4 调整过程（输出最小元素后）

1. 冠军（段 3 的元素 1）被输出，用段 3 的下一个元素（如 6）顶替该叶子。
2. 只沿「该叶子 → 根」这一条路径重新比较：`6 vs 17`（段 4 分支结点记录的败者）→ 6 胜；`6 vs 2`（段 6 分支结点记录的败者）→ 2 胜；`2 vs 4`（段 8 分支结点记录的败者）→ 2 胜。
3. 新冠军为段 5（元素 2）。

**只需 3 次比较**（等于分支结点层数），而非重新做 7 次。

### 4.5 存储实现（王道书图示含义）

- 用一个长度约 $k$ 的 `int` 数组 `ls[]`：
  - `ls[1..k-1]`：对应完全二叉树的各分支结点，存失败者归并段编号；
  - `ls[0]`：存冠军（最小元素）所属归并段编号。
- 叶子结点在数组中**不实际占位**，是逻辑上「脑补」的虚拟结点；实际元素存放在各归并段自己的缓冲区里。
- 王道书五路归并图示：`ls[0..4]`，`ls[0]` 为冠军，`ls[1..4]` 为失败者结点，归并段编号从 0 开始（`b0..b4`）。

```c
/* 败者树调整：叶子 leaf 对应的归并段换入新元素后，沿路径向上调整
 * ls[0..k-1]：ls[0] 存冠军段号，ls[1..k-1] 存各分支结点的失败者段号
 * 约定：关键字越小越优；b[段号] 为该段当前首元素
 * 前提：k 为 2 的幂或按完全二叉树编号，父结点编号 = 孩子编号 / 2
 */
void Adjust(int ls[], int k, int leaf, ElemType b[]) {
    int t, parent;
    t = (leaf + k) / 2;          /* 叶子 leaf 对应的父结点编号（叶子虚拟编号为 k..2k-1） */
    while (t > 0) {              /* 沿路径向上，直到冠军结点 */
        if (b[leaf] > b[ls[t]]) { /* 新元素比原记录的失败者大：新元素是失败者 */
            int tmp = leaf;       /* 交换：让胜者继续向上 */
            leaf = ls[t];
            ls[t] = tmp;
        }
        t = t / 2;               /* 继续向父结点 */
    }
    ls[0] = leaf;                /* 冠军段号写入 0 号 */
}
```

> 说明：上面是王道风格的调整框架，核心是「败者留在结点、胜者继续向上」，循环次数等于路径长度。建树时可对每个叶子依次调用 `Adjust`，或自底向上两两比较。

## 5. 复杂度分析

设归并路数为 $k$，败者树高度（分支结点层数）为 $h-1$，其中 $h$ 为完全二叉树的层数。

**建树**：$k$ 个叶子两两比较共 $k-1$ 次比较，时间 $O(k)$。

**每次调整（选出一个最小元素）**：
- 完全二叉树第 $h$ 层最多 $2^{h-1}$ 个结点，叶子数 $k \le 2^{h-1}$，解得 $h-1 = \lceil \log_2 k \rceil$。
- 分支结点层数即路径长度，故调整比较次数 $\le \lceil \log_2 k \rceil$。
- **最好情况**：新元素落在较浅的叶子上，比较次数可少于 $\lceil \log_2 k \rceil$（如五路归并时落在上层叶子只需 2 次）。
- **最坏情况**：新元素落在最深层叶子，比较 $\lceil \log_2 k \rceil$ 次。
- **平均情况**：假设新元素等概率落在 $k$ 个叶子上，则平均比较次数为各叶子深度之和除以 $k$。对完全二叉树，深度为 $d$ 的叶子约占 $2^{d-1}/k$，平均深度约为 $\log_2 k$ 量级，故平均比较次数为 $\Theta(\log_2 k)$，与最坏同阶，常数略小。

**对比**：传统顺序比较每次 $k-1$ 次；$k=1024$ 时，败者树每次仅约 10 次，降幅巨大。

**总外部排序开销**：归并趟数 $S=\lceil \log_k m \rceil$（$m$ 为初始归并段数），每趟内部比较由 $O(k)$ 降为 $O(\log_2 k)$，整体内部时间显著下降，使「增大 $k$」真正有利。

## 6. 易错点与考试写法

1. **分支结点存的是「失败者」不是「胜者」**：胜者继续向上，失败者留在结点。写反则整棵树含义错。
2. **结点里存的是归并段编号，不是元素值**：王道书图示 `ls[]` 中全是段号（如 3、1、4…），不要写成具体关键字。
3. **叶子是虚拟的**：数组中叶子不占实际位置，实际元素在各归并段缓冲区；答题时说明「叶子对应归并段」即可。
4. **建树比较次数 = $k-1$，不省**：省的是「每次调整」，不要误答「建树也只需 $\log k$ 次」。
5. **调整只走一条路径**：从被替换叶子到根，不重新比较其他子树，这是败者树高效的根本。
6. **比较次数上限是 $\lceil \log_2 k \rceil$**：是「最多」，不是「恰好」；五路归并可能 2 次也可能 3 次。
7. **答题程度**：408 考败者树以**手算构造/调整**为主，写清「谁和谁比、败者记入哪个结点、胜者去哪」即可；若考复杂度，答「建树 $k-1$ 次，每次调整 $\lceil \log_2 k \rceil$ 次」并给出完全二叉树高度推导。

## 7. 408 题型与解题套路

- **选择题**：
  - 给 $k$ 路归并，问败者树每次选最小需比较几次 → 答 $\lceil \log_2 k \rceil$（注意是上限）。
  - 问败者树分支结点存什么 → 失败者所属归并段编号。
  - 问建树比较次数 → $k-1$。
  - 给一组归并段首元素，问某次调整后冠军是谁 → 按路径手算。
- **算法/综合题**：408 对败者树直接写完整代码的要求较低（了解即可），更常考「多路归并趟数 + 比较次数」的综合计算；若要求描述调整过程，按「替换叶子 → 沿路径向上比较 → 更新结点 → 写冠军」四步写。
- **常见陷阱**：
  - 把「归并趟数 $\lceil \log_k m \rceil$」与「每次比较次数 $\lceil \log_2 k \rceil$」混淆（底数不同：趟数底为 $k$，比较次数底为 2）。
  - 误以为败者树减少的是磁盘 I/O（减少 I/O 靠增大 $k$ 减少趟数，败者树减少的是内部比较）。
  - 手算时忘记「胜者继续向上、败者留结点」。

## 8. 自测题

**1.** 8 路平衡归并，采用败者树，建树需要多少次关键字比较？之后每选出一个最小元素最多需要多少次比较？

**2.** 败者树的分支结点中存储的内容是什么？为什么叶子结点在实际数组中常常不占位置？

**3.** 五路归并的败者树，分支结点有几层？每次调整的比较次数可能是 2 次还是 3 次？为什么？

**4.** 判断：采用败者树后，k 路归并的归并趟数会减少。（说明理由）

**5.** 1024 路归并，传统顺序选最小与败者树选最小，每次比较次数分别是多少？这对外部排序整体性能意味着什么？

<details>
<summary>参考答案</summary>

1. 建树 $k-1=7$ 次；之后每次最多 $\lceil \log_2 8 \rceil = 3$ 次。
2. 存左右子树比较中的**失败者所属归并段编号**（不存元素值）。叶子逻辑上对应各归并段，实际元素存放在各归并段缓冲区，故数组中叶子为虚拟结点、不占实际位置。
3. 分支结点层数 $=\lceil \log_2 5 \rceil = 3$ 层。新元素落在上层叶子时只需 2 次，落在最深层叶子时需 3 次；$\lceil \log_2 k \rceil$ 是上限。
4. 错。归并趟数由 $k$ 和初始归并段数 $m$ 决定（$\lceil \log_k m \rceil$），败者树不改变趟数；它减少的是每趟内部「选最小」的关键字比较次数。
5. 传统 1023 次，败者树约 $\lceil \log_2 1024 \rceil = 10$ 次。使增大 $k$ 时内部开销不再爆炸，从而能真正通过减少趟数来降低磁盘 I/O，提升外部排序整体性能。

</details>

## 9. 背诵卡

1. 败者树 = 完全二叉树，**分支结点记失败者（段号），胜者向上，根记冠军**。
2. **建树 $k-1$ 次比较；每次调整 $\le \lceil \log_2 k \rceil$ 次**（等于分支结点层数）。
3. 叶子虚拟、对应 $k$ 个归并段；数组 `ls[0]` 存冠军段号，`ls[1..k-1]` 存失败者段号。
4. 败者树**不减少归并趟数**，只减少每趟内部选最小的比较次数。
5. 调整只沿「被替换叶子 → 根」一条路径，不重比其他子树。

## 10. 关联与下一节

- **向前关联**：多路平衡归并（增大 $k$ 减少趟数、减少磁盘 I/O）→ 本节解决其「内部比较次数随 $k$ 线性增长」的副作用。
- **向后关联**：下一节「置换-选择排序」用败者树在内存工作区中选最小元素来生成长初始归并段，进一步减少归并段数 $m$；再往后「最佳归并树（哈夫曼树）」优化归并顺序。败者树是这两节共同的底层工具。
- **本章主线**：外部排序 = 生成初始归并段 + 多路归并；败者树服务于「多路归并」的效率，是 408 外部排序综合题的高频配角。
