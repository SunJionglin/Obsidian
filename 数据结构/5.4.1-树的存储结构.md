# 5.4.1 树的存储结构

## 1. 本节定位

- **对应王道书**：第 5 章「树与二叉树」→ 5.4「树、森林」→ 5.4.1「树的存储结构」。
- **408 大纲对应**：树与二叉树——树的存储结构（双亲表示法、孩子表示法、孩子兄弟表示法）。
- **先修知识**：树的递归定义、二叉树顺序存储（完全二叉树编号规则 $2i$、$2i+1$）、单链表/结构体定义。
- **本章位置**：前面学完二叉树（性质、遍历、线索化），本节把「二叉树」推广到「普通树/森林」的存储问题，是后续「树、森林与二叉树相互转换」「并查集」的直接基础。

## 2. 一句话结论

普通树因分支数不定，不能照搬二叉树的完全二叉树编号法；于是用**双亲表示法（顺序，记父下标）**、**孩子表示法（顺序+链式，记孩子链表）**、**孩子兄弟表示法（纯链式，左孩子右兄弟）** 三种方式存储，三者分别擅长「找父」「找子」「转二叉树」。

## 3. 知识地图

```
树的存储结构
├── 双亲表示法（顺序存储）
│   ├── 结构：数组，每元素 {data, parent下标}
│   ├── 根节点 parent = -1
│   ├── 优点：找父 O(1)
│   └── 缺点：找子 O(n)
├── 孩子表示法（顺序 + 链式）
│   ├── 结构：数组存 {data, 孩子链表头指针}，链表结点存孩子下标
│   ├── 优点：找子方便
│   └── 缺点：找父需遍历所有链表
└── 孩子兄弟表示法（纯链式，二叉链表）
    ├── 结构：{data, firstchild, nextsibling}
    ├── 左指针→第一个孩子，右指针→右兄弟
    └── 可存树、可存森林；形态与二叉树一致 → 树/森林转二叉树
```

## 4. 核心内容

### 1. 为什么不能直接套用二叉树的顺序存储

二叉树顺序存储的前提：每个分支结点最多 2 个孩子，可按**完全二叉树**编号，下标即逻辑关系（下标 $i$ 的左孩子 $2i$、右孩子 $2i+1$，根从 1 开始）。

普通树每个分支结点孩子数不定，**不存在「完全树」编号**，仅靠数组下标无法反映逻辑关系。解决办法：利用「除根外每个结点**有且仅有一个双亲**」这一性质。

### 2. 双亲表示法（顺序存储）

**思想**：数组顺序存各结点，每个元素额外记录其双亲在数组中的**下标**；根结点无双亲，`parent = -1`。

```c
#define MAX_TREE_SIZE 100
typedef struct {          // 树的结点定义
    ElemType data;        // 数据元素
    int parent;           // 双亲在数组中的下标
} PTNode;

typedef struct {          // 树的类型定义
    PTNode nodes[MAX_TREE_SIZE];  // 双亲表示
    int n;                        // 结点数
} PTree;
```

**要点**：
- 数组下标从 0 开始（王道代码习惯），根 `parent = -1`。
- 找父：直接读 `nodes[i].parent`，$O(1)$。
- 找子：必须扫描整个数组，找 `parent == i` 的元素，$O(n)$。
- **可存森林**：多棵树的根 `parent` 都置 `-1` 即可（森林 = $m$ 棵互不相交的树）。

**适用**：找父多、找子少的场景，典型如**并查集**（只需找父）。

### 3. 孩子表示法（顺序 + 链式）

**思想**：数组顺序存各结点，每个元素带一个**孩子链表头指针**；链表结点存该孩子结点的数组下标。

```c
typedef struct CNode {        // 孩子链表结点
    int child;                // 孩子在数组中的下标
    struct CNode *next;       // 下一个孩子
} CNode;

typedef struct {              // 数组元素
    ElemType data;
    CNode *firstchild;        // 孩子链表头指针
} CTBox;

typedef struct {
    CTBox nodes[MAX_TREE_SIZE];
    int n;                    // 结点数
    int r;                    // 根的下标（访问树从根开始，必须记录）
} CTree;
```

**要点**：
- 找子：定位数组下标后遍历其孩子链表，方便。
- 找父：需遍历**所有**链表查找该下标，$O(n)$ 级别，不方便。
- **可存森林**：需在结构体中记录**多个根的下标**（转写中明确提到这一点）。
- 适用：找子多、找父少的场景，如**客服服务流程树**（拨号逐层按键选子结点）。

### 4. 孩子兄弟表示法（纯链式，又称「二叉链表表示法」）

**思想**：每个结点两个指针——**左指针指向第一个孩子，右指针指向右边一个兄弟**。

```c
typedef struct CSNode {
    ElemType data;
    struct CSNode *firstchild;   // 指向第一个孩子
    struct CSNode *nextsibling;  // 指向右兄弟
} CSNode, *CSTree;
```

**建树规则（以转写中的树为例）**：
- A 的第一个孩子是 B → A 左指针→B；A 无右兄弟 → A 右指针 = NULL。
- B 的右兄弟是 C → B 右指针→C；C 的右兄弟是 D → C 右指针→D。
- B 的第一个孩子是 E → B 左指针→E；E 的右兄弟是 F → E 右指针→F。
- C 的第一个孩子是 G → C 左指针→G；D 的第一个孩子是 H → D 左指针→H；H 的右兄弟 I、I 的右兄弟 J 依次用右指针相连。
- E 的第一个孩子是 K → E 左指针→K。

**存森林**：把各棵树的**根视为平级兄弟**，用右指针依次串起来（如 B 的右兄弟 C、C 的右兄弟 D）。

**关键结论（408 必考）**：孩子兄弟表示法存储的树/森林，**形态与二叉树完全一致**（都是二叉链表、两个指针），只是指针含义不同。因此**树/森林可唯一转换为二叉树**——这正是下一节「树、森林与二叉树转换」的接口。

## 5. 复杂度分析

设树有 $n$ 个结点，某结点有 $k$ 个孩子。

| 操作 | 双亲表示法 | 孩子表示法 | 孩子兄弟表示法 |
|---|---|---|---|
| 找父结点 | $O(1)$ | $O(n)$ | $O(n)$（需遍历） |
| 找所有孩子 | $O(n)$ | $O(k)$ | $O(k)$（沿左指针+右兄弟链） |
| 存储空间 | $O(n)$ | $O(n)$ | $O(n)$ |

**推导说明**：
- 双亲表示法找父：数组随机访问一次，$O(1)$；找子：最坏扫完 $n$ 个元素，$O(n)$。
- 孩子表示法找子：先 $O(1)$ 定位数组元素，再遍历长度 $k$ 的链表，$O(k)$；找父：最坏要遍历全部 $n$ 个孩子链表结点，$O(n)$。
- 孩子兄弟表示法找第一个孩子 $O(1)$，找全部孩子需沿「左孩子→右兄弟」链走 $k$ 步，$O(k)$；找父无直接指针，需全树搜索，$O(n)$。
- 三种方法空间均为每个结点常数个字段，合计 $O(n)$；平均情况与最坏同阶（无概率假设影响阶数）。

## 6. 易错点与考试写法

1. **根结点的 parent 值**：王道代码用 `-1` 表示无双亲；有的教材用 0 号单元作哨兵。答题时**写清约定**即可，不要混用。
2. **数组下标 vs 结点编号**：双亲/孩子表示法里存的是**数组下标**，不是结点「名字」。画图题务必标出下标。
3. **森林的孩子表示法**：必须记录**多个根的下标**，只记一个根是错的（转写特别强调）。
4. **孩子兄弟表示法 ≠ 二叉树**：结构相同、**语义不同**。左指针是「第一个孩子」不是「左子树」，右指针是「右兄弟」不是「右子树」。答题时写「形态与二叉树一致，可相互转换」，不要写「就是二叉树」。
5. **森林转孩子兄弟**：各树根互为**兄弟**，用右指针串联——这是转换题的关键一步，漏掉就全错。
6. **答题程度**：408 对该节以**选择题 + 画图/转换题**为主。写结构体定义要能默写字段名与含义；分析优缺点要落到「找父/找子哪个快、复杂度多少、适用场景」。

## 7. 408 题型与解题套路

- **选择题**：
  - 给一种表示法问「找父/找子复杂度」→ 直接套上表。
  - 给一棵树问「孩子兄弟表示法中某结点的右指针指向谁」→ 答「它的右兄弟」，无兄弟则 NULL。
  - 问「哪种表示法适合并查集」→ 双亲表示法。
  - 问「哪种表示法可存森林且形态同二叉树」→ 孩子兄弟表示法。
- **画图/转换题**：给树或森林，画孩子兄弟表示法（即转二叉树）——按「左孩子右兄弟」逐结点连线，森林先把根串成兄弟链。
- **常见陷阱**：
  - 把「右兄弟」误画成「右孩子」；
  - 森林转换时忘记把第二棵及以后的树根挂到前一棵树根的右指针上；
  - 双亲表示法中把根写成 `parent = 0` 却未说明 0 号是哨兵。

## 9. 背诵卡

1. 普通树不能套完全二叉树编号，因分支数不定；靠「除根外每个结点唯一双亲」破局。
2. 双亲表示法：数组存 `{data, parent}`，根 `parent=-1`；找父 $O(1)$，找子 $O(n)$；可存森林（多根 `-1`）；适合并查集。
3. 孩子表示法：数组 `{data, firstchild}` + 孩子下标链表；找子快、找父慢；存森林须记**多个根下标**；适合服务流程树。
4. 孩子兄弟表示法：`{data, firstchild, nextsibling}`，**左孩子右兄弟**；纯链式，形态同二叉树 → 树/森林可转二叉树。
5. 森林用孩子兄弟表示：各树根视为**平级兄弟**，用右指针串联。
