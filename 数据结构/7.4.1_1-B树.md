# 7.4.1 B树（B-Tree）

## 1. 本节定位

- **对应章节**：王道《数据结构》第 7 章「查找」→ 7.4 节「B 树与 B+ 树」→ 7.4.1 B 树。
- **408 大纲对应**：查找 → B 树（定义、性质、查找、插入、删除），B+ 树（了解）。
- **先修知识**：二叉排序树（BST）的查找思想、树的高度与查找效率的关系、平衡二叉树（AVL）的“平衡”概念、等比数列求和。
- **本节位置**：B 树是“多路平衡查找树”，是 BST 的推广；本节只讲**定义与性质、查找过程、高度范围**，插入/删除在后续小节。B 树是 B+ 树、数据库索引的基础。

## 2. 一句话结论

**B 树 = 每个结点“尽量装满”（分叉数有下限）+ 所有子树“绝对等高”（绝对平衡）的 m 叉查找树；这两条约束共同保证树“矮胖”，从而把查找效率稳定在 $O(\log_m n)$ 量级。**

## 3. 知识地图

```
二叉排序树 BST（1 个关键字切 2 个区间，2 个分叉）
        │ 推广
        ▼
m 叉查找树（结点内 n 个有序关键字，n+1 个分叉，切 n+1 个区间）
        │ 加两条约束保证效率
        ▼
        B 树（m 阶）
        ├─ 约束①：分叉数下限（除根外 ≥ ⌈m/2⌉ 个分叉，即 ≥ ⌈m/2⌉−1 个关键字）
        ├─ 约束②：绝对平衡（任一结点所有子树高度相同）
        ├─ 结构：n 个关键字 k1<k2<…<kn，n+1 个指针 p0…pn
        │        p_{i-1} 子树关键字 < ki < pi 子树关键字
        ├─ 查找：结点内顺序/折半比较 → 沿指针下降 → 命中或落到失败结点
        └─ 高度（n 个关键字，不含失败结点层）
                 ├─ 最小高度：各层尽量满 → h ≥ log_m(n+1)
                 └─ 最大高度：各层尽量空 → h ≤ log_{⌈m/2⌉}((n+1)/2)+1
```

## 4. 核心内容

### 4.1 从二叉排序树到 m 叉查找树

BST 的本质：**一个关键字把搜索区间切成两段**（小于往左、大于往右）。推广到 m 叉：一个结点存 $n$ 个**有序**关键字，把区间切成 $n+1$ 段，对应 $n+1$ 个分叉（指针）。

- 结点内关键字递增：$k_1<k_2<\dots<k_n$。
- 指针 $p_0,p_1,\dots,p_n$ 共 $n+1$ 个；$p_{i-1}$ 所指子树中所有关键字 $<k_i$，$p_i$ 所指子树中所有关键字 $>k_i$。
- 失败结点（紫色）对应一段“落空”的数值区间，本质是空指针 NULL。

### 4.2 B 树的定义（m 阶 B 树）

m 阶 B 树是满足下列条件的 m 叉查找树（或为空树）：

1. **每个结点至多 m 棵子树、至多 m−1 个关键字**（阶 = 孩子数上限）。
2. **根结点**：若非终端结点，**至少 2 棵子树**（即至少 1 个关键字）。
3. **除根外的所有非叶结点至少 $\lceil m/2\rceil$ 棵子树**，即至少 $\lceil m/2\rceil-1$ 个关键字。
4. **所有叶结点（失败结点）出现在同一层且不带信息**（是空指针）。
5. 结点结构：$n$ 记录实际关键字个数，$n$ 个关键字有序，$n+1$ 个指针满足 4.1 的大小关系。

> 记忆压缩：**① 分叉数有上下限（根特殊）② 绝对平衡 ③ 结点内关键字与指针的大小关系（同 BST 思想）**。

**为什么根可以例外**：树刚建立时只有 1 个关键字、2 个分叉，无法强求 $\lceil m/2\rceil$ 个分叉，故根放宽为“至少 2 棵子树”。

**为什么要求绝对平衡**：多叉情形下“高度差 ≤ 1”要两两比较、实现复杂；直接要求所有子树等高更简单，且必然推出所有失败结点同层。

### 4.3 查找过程（手算）

从根出发，在结点内**顺序扫描**（关键字有序，也可折半，但手算用顺序即可）：

- 若目标 $=k_i$：查找成功。
- 若 $k_i<$ 目标 $<k_{i+1}$：沿 $p_i$ 下降。
- 若目标 $>$ 结点内全部关键字：沿最后一个指针 $p_n$ 下降。
- 若目标 $<$ 第一个关键字：沿 $p_0$ 下降。
- 下降到失败结点（NULL）：查找失败。

**例**：查 9 → 根 22，9<22 走左 → 结点 [5,11]，5<9<11 走中间 → 命中 9。查 41 → 22<41 走右 → [36,45]，36<41<45 走中间 → [40,42]，40<41<42 走中间 → 失败结点，查找失败。

### 4.4 高度范围（n 个关键字，高度不含失败结点层）

**最小高度**（各层尽量满，每结点 m−1 个关键字、m 个分叉）：

第 1 层 1 个结点，第 2 层 $m$ 个，…，第 $h$ 层 $m^{h-1}$ 个，故

$$n\le (m-1)(1+m+m^2+\dots+m^{h-1})=(m-1)\cdot\frac{m^h-1}{m-1}=m^h-1$$

$$\Rightarrow h\ge \log_m(n+1)$$

**最大高度**（各层尽量空；记 $k=\lceil m/2\rceil$）：

- 根 1 个结点（最少 1 个关键字、2 个分叉）；其余结点最少 $k$ 个分叉、$k-1$ 个关键字。
- 第 $h$ 层结点数至少 $2k^{h-2}$，关键字总数至少
$$1+(2+2k+2k^2+\dots+2k^{h-2})(k-1)=1+2(k-1)\cdot\frac{k^{h-1}-1}{k-1}=2k^{h-1}-1$$
- 故 $n\ge 2k^{h-1}-1$，得
$$h\le \log_k\!\left(\frac{n+1}{2}\right)+1,\quad k=\lceil m/2\rceil$$

**另一条重要性质**：n 个关键字的 B 树必有 **n+1 个失败结点**（n 个关键字把 $(-\infty,+\infty)$ 切成 n+1 段，对应 n+1 种失败情况）。用“失败结点数 ≥ 第 h+1 层结点数下限”同样可推出上式——这是课本思路，与上面的“关键字数下限”思路等价。

### 4.5 结点结构（C 语言，王道风格）

```c
#define M 5                 // 阶数，示例为 5 阶
typedef int ElemType;

typedef struct BTNode {
    int      n;             // 结点中实际关键字个数
    ElemType key[M];        // key[1..n] 存关键字（0 号可不用，便于下标对齐）
    struct BTNode *p[M + 1];// p[0..n] 共 n+1 个孩子指针
} BTNode, *BTree;
```

> 说明：B 树的查找/插入/删除**代码不要求掌握**（408 只考性质与手算），此结构体用于理解“n 个关键字 + n+1 个指针”的对应关系。

## 5. 复杂度分析

设树高为 $h$，结点内关键字个数为 $n_0$。

- **结点内查找**：顺序查找最坏 $O(n_0)$；因关键字有序可折半，$O(\log n_0)$。408 手算默认顺序扫描。
- **整树查找**：沿一条根到叶的路径下降，比较次数 = 各层结点内比较次数之和。
  - **最好**：根结点即命中，$O(1)$。
  - **最坏**：走到失败结点，$O(h\cdot n_0)$；由于 $h=O(\log_m n)$，且 $n_0\le m-1$ 为常数，故 **$O(\log_m n)$**。
  - **平均**：假设 n 个关键字等概率被查、失败情况等概率，平均比较次数与 $h$ 同阶，仍为 $O(\log_m n)$。推导要点：树高被两条约束夹在 $[\log_m(n+1),\ \log_{\lceil m/2\rceil}((n+1)/2)+1]$ 之间，是 $\Theta(\log n)$ 量级；每层比较次数有常数上界 $m-1$，故总代价 $\Theta(h)=\Theta(\log n)$。
- **空间**：$O(n)$ 个关键字 + $O(n)$ 个指针。

> 对比：同样 n 个关键字，BST 退化成链时高 $O(n)$；B 树靠“装满 + 等高”把高压到 $O(\log_m n)$，且 $m$ 越大树越矮（磁盘 I/O 次数越少，这是数据库用 B 树/B+ 树的根本原因）。

## 6. 易错点与考试写法

1. **阶 m 指“孩子数上限”，不是关键字上限**。m 阶 → 最多 m 个分叉、m−1 个关键字；最少（除根）$\lceil m/2\rceil$ 个分叉、$\lceil m/2\rceil-1$ 个关键字。**分叉数与关键字数差 1**，别混。
2. **根结点例外**：根至少 2 棵子树（至少 1 个关键字），不受 $\lceil m/2\rceil$ 约束。
3. **“叶子结点”在 B 树中指失败结点（NULL），不是含数据的终端结点**。含数据的最下层叫终端结点。408 选择题常在此设陷阱。
4. **高度是否含失败结点层**：教材与 408 惯例**不含**，计算高度范围时务必统一。
5. **n 个关键字 ↔ n+1 个失败结点**，与 BST 中“n 个结点有 n+1 个空链域”同理，别记成 n 个。
6. **答题程度**：性质题写清“至多 m 棵子树 / m−1 个关键字；除根外至少 $\lceil m/2\rceil$ 棵子树；所有叶结点同层”即满分；高度题写出不等式与化简结果即可，不必展开等比求和细节。

## 7. 408 题型与解题套路

- **选择题（高频）**：
  - 给阶 m 和结点图，判断“是否合法 B 树”→ 逐结点查分叉数下限、关键字有序性、子树关键字范围、是否等高。
  - 给 m 与 n，求高度范围 → 套 $h\ge\log_m(n+1)$、$h\le\log_{\lceil m/2\rceil}((n+1)/2)+1$；或反过来给高度求关键字数范围。
  - 求某结点的最少/最多关键字数、最少/最多孩子数。
  - 查找路径题：给关键字，写出比较经过的结点序列。
- **算法题**：B 树代码**不考**（大纲只要求性质与手算），插入/删除以手算画图形式出现在选择题或综合题小问。
- **常见陷阱**：把“阶”当关键字上限；忘记根例外；把终端结点当叶子结点；高度含不含失败层不统一；$n+1$ 个失败结点记成 $n$。

## 8. 自测题

**1.** 一棵 5 阶 B 树，除根外每个结点至少有几个关键字？至多几个？

**2.** 含 20 个关键字的 5 阶 B 树，高度 h（不含失败结点层）的范围是多少？

**3.** 判断：B 树中所有叶子结点都在同一层，且叶子结点中含有关键字。

**4.** 在 5 阶 B 树中查找 41，根为 [22]，其右孩子为 [36,45]，[36,45] 的中间孩子为 [40,42]，写出完整查找路径并说明结果。

**5.** 为什么 B 树要求“除根外每个结点至少 $\lceil m/2\rceil$ 棵子树”，而根可以例外？

1. 至少 $\lceil 5/2\rceil-1=2$ 个关键字（3 个分叉）；至多 $5-1=4$ 个关键字（5 个分叉）。
2. 最小高度：$h\ge\log_5(21)\approx1.89$，取整 $h\ge2$。最大高度：$k=\lceil5/2\rceil=3$，$h\le\log_3(21/2)+1=\log_3 10.5+1\approx2.14+1$，即 $h\le3$（取整）。故 $2\le h\le3$。
3. 错。B 树的“叶子结点”指失败结点（NULL），不带信息、不含关键字；含关键字的是终端结点。
4. 路径：根 [22]（41>22，走右）→ [36,45]（36<41<45，走中间）→ [40,42]（40<41<42，走中间）→ 失败结点，查找失败。
5. 下限保证结点“不太空”，树不会又高又瘦，从而保证查找效率；但树刚建立时只有 1 个关键字、2 个分叉，无法满足 $\lceil m/2\rceil$，故根放宽为至少 2 棵子树。

## 9. 背诵卡

1. **m 阶 B 树**：每结点至多 m 棵子树、m−1 个关键字；除根外至少 $\lceil m/2\rceil$ 棵子树、$\lceil m/2\rceil-1$ 个关键字；根至少 2 棵子树。
2. **绝对平衡**：任一结点所有子树等高 ⟹ 所有失败结点（叶子）同层且不带信息。
3. **结点内**：$k_1<\dots<k_n$，$n+1$ 个指针，$p_{i-1}$ 子树 $<k_i<p_i$ 子树（同 BST 思想）。
4. **高度（不含失败层）**：$h\ge\log_m(n+1)$；$h\le\log_{\lceil m/2\rceil}\frac{n+1}{2}+1$。
5. **n 个关键字 ⟺ n+1 个失败结点**；查找代价 $O(\log_m n)$，m 越大树越矮。

## 10. 关联与下一节

- **向前关联**：BST 的“关键字切区间”思想 → m 叉查找树 → 加“装满 + 等高”两条约束 → B 树；AVL 的“平衡”在此升级为“绝对平衡”。
- **向后关联**：下一节 **B 树的插入与删除**（手算核心：插入后结点溢出则“分裂”向上冒，删除后关键字不足则“借/合并”），再往后是 **B+ 树**（数据库索引、与 B 树的区别：B+ 树数据全在叶层、叶层用链表串联）。本节的性质是插入/删除调整规则的直接依据。
