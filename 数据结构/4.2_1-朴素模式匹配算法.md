# 4.2 朴素模式匹配算法

## 1. 本节定位

- **对应王道书**：第 4 章 串 → 4.2 串的模式匹配 → 4.2.1 朴素模式匹配算法。
- **408 大纲对应**：串的模式匹配（朴素算法）。
- **先修知识**：串的定义、串的存储结构（顺序存储，`ch[0]` 弃用或存长度，位序从 1 开始）、串的基本操作 `SubString`、`StrCompare`、`StrLength`。
- **本章位置**：上一小节用 `SubString + StrCompare` 实现了 `Index` 定位操作，本质就是朴素模式匹配；本节把“调基本操作”改为“双指针直接扫数组”，并给出复杂度分析；下一节进入 KMP。

## 2. 一句话结论

朴素模式匹配就是暴力枚举主串中所有长度为 $m$ 的子串，逐个与模式串比较，找到第一个完全匹配的子串则返回其起始位序，否则返回 0；最坏时间复杂度 $O(nm)$。

## 3. 知识地图

```
串的模式匹配
├── 术语
│   ├── 主串 S（长度 n）：被搜索的串
│   ├── 模式串 T（长度 m）：要搜索的内容
│   └── 子串：主串中连续的一段，一定存在；模式串不一定能在主串中找到
├── 朴素模式匹配算法（Brute Force）
│   ├── 思想：枚举 n-m+1 个长度为 m 的子串，逐个比对
│   ├── 实现一：调 SubString + StrCompare（上一小节 Index）
│   └── 实现二：双指针 i、j 直接扫数组（本节重点）
├── 匹配成功：返回子串起始位序
├── 匹配失败：返回 0
└── 复杂度：最坏 O(nm)，最好 O(m)（补充），平均 O(n+m)（补充，见第 5 节）
```

## 4. 核心内容

### 4.1 术语（408 必考，选择题常考概念辨析）

- **主串 S**：被搜索的整段字符串，长度记为 $n$。
- **模式串 T**：想搜索的那段内容，长度记为 $m$。
- **子串**：主串中连续若干个字符组成的串，**一定存在于主串中**。
- **模式串 ≠ 子串**：模式串是“想找的东西”，可能找不到；只有匹配成功时，模式串才等于主串的某个子串。
- **模式匹配**：在主串中找与模式串相同的子串，并返回该子串所在位置。

### 4.2 算法思想

主串长度 $n$，模式串长度 $m$。主串中长度为 $m$ 的子串最多有

$$n-m+1$$

个（起始位序为 $1,2,\dots,n-m+1$）。朴素算法就是把这 $n-m+1$ 个子串依次与模式串比较：

- 某个子串与模式串完全相同 → 返回该子串起始位序；
- 全部比完都不相同 → 返回 0，表示匹配失败。

### 4.3 实现一：调用基本操作（上一小节 `Index`，理解即可）

```c
// 王道风格：串的位序从 1 开始，S.ch[0]、T.ch[0] 可存长度或不用
int Index(SString S, SString T) {
    int i = 1;
    // 主串中最多有 n-m+1 个长度为 m 的子串
    while (i <= S.length - T.length + 1) {
        SString sub;
        SubString(&sub, S, i, T.length);   // 取 S 中从 i 起、长 m 的子串
        if (StrCompare(sub, T) == 0)       // 与模式串比较
            return i;                      // 匹配成功，返回起始位序
        i++;                               // 否则试下一个子串
    }
    return 0;                              // 匹配失败
}
```

### 4.4 实现二：双指针直接扫数组（本节重点，要能默写）

设指针 `i` 扫描主串、`j` 扫描模式串，位序均从 1 开始。

**匹配过程**：`S.ch[i] == T.ch[j]` 时，`i++`、`j++` 同步后移；一旦不等，说明当前子串失败，令 `i` 指向下一个子串的首字符、`j` 回到 1，重新比较。

**关键推导（`i` 的回退公式）**：失配时，当前子串的起始位序为 $i-j+1$，故下一个子串起始位序为

$$i-j+2$$

即 `i = i - j + 2; j = 1;`。

**成功判定**：当 `j > T.length` 时，模式串全部比完，匹配成功，此时子串起始位序为

$$i - T.length$$

```c
// 王道书风格：位序从 1 开始，ch[0] 弃用（或存长度）
int Index(SString S, SString T) {
    int i = 1, j = 1;                       // i 扫主串，j 扫模式串
    while (i <= S.length && j <= T.length) {
        if (S.ch[i] == T.ch[j]) {           // 当前字符相等
            i++; j++;                       // 继续比下一个字符
        } else {                            // 当前子串失配
            i = i - j + 2;                  // i 回退到下一个子串首字符
            j = 1;                          // j 回到模式串开头
        }
    }
    if (j > T.length)                       // 模式串全部匹配完
        return i - T.length;                // 返回子串起始位序
    else
        return 0;                           // 主串扫完仍未匹配，失败
}
```

**图解（以主串 `a b a b c a b c a c`、模式串 `a b c a c` 为例，推断示意）**：

```
第一趟：i=1,j=1 起比，比到 j=3 失配（S[3]=a ≠ T[3]=c）
        i 回退：i = 3-3+2 = 2，j = 1
第二趟：从 S[2] 起比，S[2]=b ≠ T[1]=a，立即失配
        i = 2-1+2 = 3，j = 1
第三趟：从 S[3] 起比，……直到 j > m，返回 i - m
```

> 注意：`i` 的回退公式是本算法最容易写错的地方，务必用“当前子串起点 = $i-j+1$，下一个起点 = $i-j+2$”推一遍，不要死记。

### 4.5 与上一小节 `Index` 的关系

两者是同一个算法的两种写法：上一小节用 `SubString` 取子串、用 `StrCompare` 比较，是“调基本操作”的版本；本节用双指针逐字符比较，是“直接操作数组”的版本。**换了个马甲，思想完全一致**。

## 5. 复杂度分析

设主串长 $n$，模式串长 $m$。

- **最好情况**：第一个子串就匹配成功，且每次首字符即失配或一次比完，比较次数约 $m$，时间 $O(m)$。（补充：若第一个字符就失配，则为 $O(1)$，但通常以“匹配成功”为最好情形讨论，取 $O(m)$。）
- **最坏情况**：主串形如 `aaaa…ab`，模式串形如 `aaaa…ab`（前 $m-1$ 个都是 `a`，最后一个是 `b`）。每个子串都要比到第 $m$ 个字符才失配，共比 $n-m+1$ 个子串：

$$T(n,m) = (n-m+1)\cdot m = nm - m^2 + m$$

在字符串匹配场景中通常 $n \gg m$，保留最高阶项得

$$O(nm)$$

- **平均情况（补充，按等概率假设推导）**：设字符集大小为 $k$，假设每个位置字符随机独立、匹配与失配等概率。对某个子串，比较到第 $t$ 个字符才失配的概率约为 $\left(\frac{1}{k}\right)^{t-1}\cdot\frac{k-1}{k}$，期望比较次数为

$$\sum_{t=1}^{m} t\cdot\left(\frac{1}{k}\right)^{t-1}\frac{k-1}{k} + m\left(\frac{1}{k}\right)^{m} \approx \frac{k}{k-1}$$

即平均每个子串只比常数次，总期望比较次数约 $(n-m+1)\cdot\frac{k}{k-1}$，故**平均时间复杂度为 $O(n+m)$**（近似线性）。注意：这是“随机文本”假设下的结论，408 选择题若问“平均”，一般按此线性结论；若问“最坏”，答 $O(nm)$。

> 408 必考：**最坏 $O(nm)$** 是标准答案，必须会推导“每个子串都比到最后一个字符才失配”这一最坏实例。

## 6. 易错点与考试写法

1. **位序 vs 下标**：王道书串的位序从 1 开始，`ch[0]` 常弃用或存长度。写代码时 `i`、`j` 初值为 1；若题目用 0 起始下标，回退公式变为 `i = i - j + 1; j = 0;`，返回 `i - m`。**答题前先声明下标约定**。
2. **回退公式写错**：`i = i - j + 2` 不是 `i = i - j + 1`。`i-j+1` 是当前子串起点，下一个子串起点要再 +1。
3. **成功返回值**：返回的是 `i - T.length`（位序），不是 `i`，也不是 `i - j + 1`（虽然此时二者相等，但用 `i - m` 更稳）。
4. **循环条件**：`while (i <= S.length && j <= T.length)`，两个条件缺一不可；退出后必须用 `j > T.length` 判断是成功还是失败，不能只看 `i`。
5. **子串个数**：是 $n-m+1$，不是 $n-m$，也不是 $n$。当 $m>n$ 时子串个数为 0（或负数，实际应特判失败）。
6. **“模式串一定能在主串中找到”是错的**：模式串只是“想找的内容”，可能找不到；子串才一定存在。
7. **考研答题写到什么程度算对**：算法题写完整 C 函数（含循环、回退、返回），并注明位序约定；复杂度题写出最坏实例 + 比较次数表达式 $(n-m+1)m$ + 化简到 $O(nm)$，三步齐全才给满分。

## 7. 408 题型与解题套路

- **选择题**：
  - 给主串和模式串，问“比较次数”“第一次失配时 i、j 的值”“返回的位置”——按双指针过程手推，注意回退公式。
  - 概念辨析：主串/模式串/子串的区别；子串个数 $n-m+1$。
  - 复杂度：问最坏时间复杂度，答 $O(nm)$；问平均，答 $O(n+m)$（补充结论）。
- **算法题**：直接考“写出朴素模式匹配算法”或“求子串首次出现位置”，套 4.4 的模板即可；若要求“统计出现次数”，把 `return i - m` 改为计数并令 `i = i - m + 2; j = 1;` 继续。
- **常见陷阱**：
  - 把 `i` 回退写成 `i = i - j + 1`（少加 1，死循环或漏子串）；
  - 忘记 `j` 复位为 1；
  - 返回值写成 `i` 或 `i - j`；
  - 循环条件只写 `i <= n`，导致 `j` 越界访问。

## 9. 背诵卡

1. 主串长 $n$、模式串长 $m$，长度为 $m$ 的子串共 $n-m+1$ 个，起始位序 $1\sim n-m+1$。
2. 朴素思想：枚举所有长度为 $m$ 的子串，逐个与模式串比较，首个全等即成功。
3. 失配回退：`i = i - j + 2; j = 1;`（位序从 1 开始）。
4. 成功返回 `i - m`，失败返回 0；循环条件 `i <= n && j <= m`，退出后看 `j > m`。
5. 最坏 $O(nm)$（每个子串都比到最后一个字符才失配）；平均 $O(n+m)$（随机文本假设，补充）。

## 10. 关联与下一节

- **向前关联**：串的顺序存储（`ch` 数组、位序从 1 开始）、`SubString`、`StrCompare`、上一小节的 `Index` 定位操作——本节是其“去基本操作、直接扫数组”的版本。
- **向后关联**：下一节 **KMP 算法**。朴素算法最坏 $O(nm)$ 的根源是“失配后 `i` 回退、`j` 复位、已比过的字符重新比”；KMP 利用模式串自身的部分匹配信息（`next` 数组），失配时 `i` 不回退、`j` 只回退到 `next[j]`，把复杂度降到 $O(n+m)$。学 KMP 前务必把本节回退公式和手推过程练熟，否则 `next` 数组的推导会看不懂。
