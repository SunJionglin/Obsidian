# 3.2.2 队列的顺序实现

## 1. 本节定位

- **对应王道书**：第 3 章 栈、队列和数组，3.2 队列，3.2.2 队列的顺序实现。
- **408 大纲对应**：队列的顺序存储结构；循环队列的判空、判满、入队、出队、求长度。
- **先修知识**：顺序表（静态数组、`MaxSize`、`ElemType`）、队列的“先进先出（FIFO）”与“队头删、队尾插”的操作受限特性。
- **本章位置**：承接 3.2.1 队列的基本概念，是队列的**第一种存储实现**；后续 3.2.3 队列的链式实现与之对照，3.3 栈和队列的应用会直接调用本节操作。

## 2. 一句话结论

顺序队列用静态数组 + `front`、`rear` 两个指针实现，靠**取模运算**把数组在逻辑上变成环（循环队列）；判空判满必须额外约定（牺牲一个单元 / 增设 `size` / 增设 `tag`），且**一切公式都取决于 `rear` 指向队尾元素还是其后一个位置**。

## 3. 知识地图

```
队列的顺序实现
├── 存储结构
│   ├── 静态数组 ElemType data[MaxSize]
│   └── 两个指针 front（队头）、rear（队尾）
├── 指针约定（两种，考试必辨）
│   ├── 约定 A：rear 指向队尾元素的【后一个位置】（王道主线）
│   └── 约定 B：rear 指向【队尾元素本身】
├── 循环队列（用 % MaxSize 实现逻辑环）
│   ├── 判空 / 判满 的三种方案
│   │   ├── 方案一：牺牲一个存储单元
│   │   ├── 方案二：增设 size 记录元素个数
│   │   └── 方案三：增设 tag 标记最近一次操作
│   └── 基本操作：Init / EnQueue / DeQueue / GetHead / Length
└── 复杂度：全部 O(1)
```

## 4. 核心内容

### 4.1 存储结构定义（约定 A：王道主线）

```c
#define MaxSize 10          // 静态数组最大容量
typedef struct {
    ElemType data[MaxSize]; // 静态数组存放队列元素
    int front;              // 队头指针：指向队头元素
    int rear;               // 队尾指针：指向队尾元素的后一个位置（下次插入位置）
} SqQueue;
```

- 声明 `SqQueue Q;` 时系统分配一整片连续空间，可放 `MaxSize` 个 `ElemType`。
- **位序 vs 下标**：`data[0]` 是第 1 个存储单元，`front`、`rear` 存的是**数组下标**，取值 $0 \sim MaxSize-1$（取模后）。

### 4.2 初始化与判空（约定 A）

```c
void InitQueue(SqQueue &Q) {
    Q.front = Q.rear = 0;   // 初始时两指针指向 0，队列为空
}

bool QueueEmpty(SqQueue Q) {
    return Q.front == Q.rear; // 两指针相等 ⇒ 空
}
```

### 4.3 入队（约定 A，牺牲一个单元判满）

```c
bool EnQueue(SqQueue &Q, ElemType x) {
    if ((Q.rear + 1) % MaxSize == Q.front) // 队尾后一个位置就是队头 ⇒ 满
        return false;                      // 牺牲一个单元，不能插
    Q.data[Q.rear] = x;                    // 先放元素
    Q.rear = (Q.rear + 1) % MaxSize;       // 再后移，取模实现“绕圈”
    return true;
}
```

### 4.4 出队（约定 A）

```c
bool DeQueue(SqQueue &Q, ElemType &x) {
    if (Q.front == Q.rear)   // 空队不能删
        return false;
    x = Q.data[Q.front];     // 取出队头元素
    Q.front = (Q.front + 1) % MaxSize; // 队头后移，取模绕圈
    return true;
}
```

### 4.5 读队头（查）

```c
bool GetHead(SqQueue Q, ElemType &x) {
    if (Q.front == Q.rear) return false;
    x = Q.data[Q.front];     // 只读，front 不动（即出队去掉后移那一句）
    return true;
}
```

### 4.6 求队列长度（约定 A）

$$ \text{length} = (\text{rear} - \text{front} + MaxSize)\ \%\ MaxSize $$

```c
int QueueLength(SqQueue Q) {
    return (Q.rear - Q.front + MaxSize) % MaxSize;
}
```

**为什么加 `MaxSize`**：`rear - front` 可能为负（`rear` 已绕回低位），加 `MaxSize` 保证非负，再取模把结果压回 $0 \sim MaxSize-1$。

**验证**：`rear=2, front=3, MaxSize=10` ⇒ $(2-3+10)\%10 = 9$，即 9 个元素（此时空 1 个单元，正好是“牺牲”的那个）。

### 4.7 判满判空的三种方案（约定 A 下）

| 方案 | 判空 | 判满 | 代价 |
|---|---|---|---|
| ① 牺牲一个单元 | `front == rear` | `(rear+1)%MaxSize == front` | 浪费 1 个存储单元 |
| ② 增设 `size` | `size == 0` | `size == MaxSize` | 多 1 个 int，不浪费空间 |
| ③ 增设 `tag` | `front==rear && tag==0` | `front==rear && tag==1` | 多 1 个 int，不浪费空间 |

- 方案②：入队成功 `size++`，出队成功 `size--`。
- 方案③：`tag=0` 表示最近一次是**删除**操作（只可能删空），`tag=1` 表示最近一次是**插入**操作（只可能插满）。每次入队后置 `tag=1`，每次出队后置 `tag=0`。

### 4.8 约定 B：`rear` 指向队尾元素本身（考试变体）

此时各操作与约定 A **全部不同**，必须重推：

```c
// 初始化：让 rear 指向“队尾元素”的合法前驱，便于第一次入队先后移
void InitQueue(SqQueue &Q) {
    Q.front = 0;
    Q.rear = MaxSize - 1;    // 关键：不是 0！
}

// 入队：先移指针，再写元素
bool EnQueue(SqQueue &Q, ElemType x) {
    if ((Q.rear + 1) % MaxSize == Q.front) // 牺牲 front 前一个单元
        return false;
    Q.rear = (Q.rear + 1) % MaxSize;       // 先后移
    Q.data[Q.rear] = x;                    // 再写入
    return true;
}

// 判空：rear 的下一个位置是 front
bool QueueEmpty(SqQueue Q) {
    return (Q.rear + 1) % MaxSize == Q.front;
}
```

- 判满（牺牲单元方案）：`(Q.rear + 2) % MaxSize == Q.front`（`front` 在 `rear` 后两个位置）。
- 若改用 `size` 或 `tag` 方案，判空判满逻辑与约定 A 相同，只是入队/出队时指针移动顺序不同。

## 5. 复杂度分析

设队列当前元素个数为 $n$，数组容量 `MaxSize = M`。

- **入队 `EnQueue`**：判满 1 次比较 + 1 次赋值 + 1 次加法取模，均为常数次基本操作 ⇒ $T = O(1)$。最好/最坏/平均均为 $O(1)$，与 $n$ 无关。
- **出队 `DeQueue`**：判空 1 次比较 + 1 次取值 + 1 次加法取模 ⇒ $O(1)$。
- **判空/判满/读队头/求长度**：常数次算术与比较 ⇒ $O(1)$。
- **空间复杂度**：结构体固定占 $M$ 个 `ElemType` + 2 个 `int` ⇒ $O(M)$，与元素个数无关。

**平均情况推导**：上述操作每条语句执行次数都是常数（不随 $n$ 变化，也不存在循环），故对任意输入分布，期望执行步数都是常数，平均复杂度即 $O(1)$。这里不需要概率假设——因为**没有循环**。

## 6. 易错点与考试写法

1. **`rear` 指向哪里，决定一切公式**。约定 A（指向队尾后一位置）与约定 B（指向队尾元素）的初始化、入队顺序、判空判满公式**全部不同**。做题第一步先圈出题干的指针约定。
2. **约定 B 的初始化是 `rear = MaxSize - 1`，不是 0**。因为入队是“先移后写”，初始 `rear` 必须处在 0 的前驱位置。
3. **取模不能漏**。`front`、`rear` 每次移动都要 `% MaxSize`，否则越界；求长度公式里 `+MaxSize` 也不能漏，否则 `rear < front` 时得负数。
4. **判满用“牺牲一个单元”时，队列最多存 `MaxSize-1` 个元素**，不是 `MaxSize` 个。题目问“容量为 M 的循环队列最多存多少元素”，答 `M-1`（牺牲方案）或 `M`（`size`/`tag` 方案）。
5. **`front == rear` 单独看不能判空也不能判满**，必须结合所选方案（牺牲单元 / `size` / `tag`）。
6. **答题写到什么程度算对**：408 算法题/选择题只需写出所选约定下的**判空条件、判满条件、指针移动语句（含取模）、长度公式**四件套；不必写完整可编译程序，但取模与 `+MaxSize` 不能省。

## 7. 408 题型与解题套路

- **选择题（高频）**：
  - 给 `front`、`rear`、`MaxSize` 的当前值，问元素个数 ⇒ 套 $(\text{rear}-\text{front}+M)\%M$。
  - 给一串入队/出队序列，问最终 `front`、`rear` 的值 ⇒ 逐步模拟，注意取模绕回。
  - 问“容量 M 的循环队列最多容纳元素数” ⇒ 看判满方案。
  - 给判空/判满表达式，反推 `rear` 的约定 ⇒ 对比 4.7、4.8 两表。
- **算法题套路**：题目若要求“不浪费空间”，必须用 `size` 或 `tag` 方案；若要求“用两个指针判断”，用牺牲单元方案。写代码时先写结构体定义，再写 `Init`，再写 `EnQueue`/`DeQueue`，最后补 `QueueLength`。
- **常见陷阱**：把约定 A 的公式套到约定 B 上；忘记 `% MaxSize`；把“最多元素数”答成 `MaxSize`；求长度忘加 `MaxSize`。

## 9. 背诵卡

1. 约定 A：`rear` 指队尾后一位置；初始化 `front=rear=0`；判空 `front==rear`；判满 `(rear+1)%M==front`；长度 `(rear-front+M)%M`。
2. 约定 B：`rear` 指队尾元素；初始化 `front=0, rear=M-1`；入队**先移后写**；判空 `(rear+1)%M==front`。
3. 三种判满方案：牺牲一单元（最多存 M-1）/ 增设 `size`（存 M）/ 增设 `tag`（存 M）。
4. 所有指针移动必须 `% MaxSize`；求长度必须 `+MaxSize` 再取模。
5. 一切公式先看题干：`rear` 指向哪、用哪种判满方案——这两点决定全部答案。
