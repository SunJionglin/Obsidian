# 1.1 数据结构的基本概念

## 1. 本节定位

- **对应王道书**：第 1 章绪论 1.1 数据结构的基本概念（含 1.1.1 基本概念与术语、1.1.2 数据结构三要素）。
- **408 大纲**：绪论本身不是 408 大纲要求掌握的独立章节（视频明确说明），但“数据结构三要素（逻辑结构、存储结构、数据运算）”是后续所有章节的分析框架，属于**必须内化的思维工具**。
- **先修知识**：C 语言基本语法，尤其是指针与结构体（`struct`）；二进制表示的基本概念。
- **本节位置**：全课程起点，为第 2、3 章线性表、第 4 章树、第 5 章图、第 6 章查找（散列）提供统一术语。

## 2. 一句话结论

数据结构 = 相互存在一种或多种特定关系的**数据元素集合**，学习任何数据结构都要从**逻辑结构、存储结构、数据运算**三要素入手；抽象数据类型（ADT）只定义逻辑结构与运算，不涉及存储结构。

## 3. 知识地图

```
数据（信息的载体，计算机中即二进制符号集合）
└─ 数据对象（性质相同的数据元素的集合，不强调关系）
   └─ 数据元素（数据的基本单位，整体处理）
      └─ 数据项（构成数据元素的不可分最小单位）
         └─ 组合项（可再分的数据项，如“生日”拆为年/月/日）

数据结构（强调元素间的关系）
└─ 三要素
   ├─ 逻辑结构
   │  ├─ 集合（同属一个集合，别无关系）
   │  ├─ 线性结构（一对一，除首元素外唯一前驱，除末元素外唯一后继）
   │  ├─ 树形结构（一对多）
   │  └─ 图状/网状结构（多对多）
   ├─ 存储结构（物理结构）
   │  ├─ 顺序存储（逻辑相邻 ⇒ 物理相邻，需连续空间）
   │  ├─ 链式存储（指针表示逻辑关系，物理可离散）
   │  ├─ 索引存储（索引表：关键字 + 地址）
   │  └─ 散列存储（哈希存储，由关键字直接算地址）
   └─ 数据运算（按逻辑结构定义，按存储结构实现）

数据类型
├─ 原子类型（值不可再分，如 bool、int）
└─ 结构类型（值可分解为若干分量，如 struct）
抽象数据类型 ADT = 数据对象 + 数据关系 + 基本操作（数学化定义，不涉及存储结构）
```

## 4. 核心内容

### 1. 基本术语（定义要能默写关键词）

| 术语 | 定义（王道表述） | 关键点 |
|---|---|---|
| 数据 | 信息的载体，是描述客观事物的数、字符及所有能输入到计算机中并被计算机程序识别和处理的**符号集合** | 计算机视角下最终都是二进制 0/1 |
| 数据元素 | 数据的**基本单位**，通常作为一个整体进行考虑和处理 | 是“整体”，粒度由业务决定 |
| 数据项 | 构成数据元素的**不可分割的最小单位** | 一个数据元素由若干数据项组成 |
| 组合项 | 可再分解为若干数据项的数据项 | 如“生日”拆为年、月、日 |
| 数据对象 | **性质相同**的数据元素的集合，是数据的子集 | 只要求性质相同，**不强调关系** |
| 数据结构 | 相互之间存在一种或多种**特定关系**的数据元素的集合 | 强调元素间的**关系** |

> 数据元素与数据项的划分**取决于业务需求**，没有绝对标准。例：海底捞排号系统中“一波顾客的排队信息”是一个数据元素，其中“号数、取号时间、就餐人数”是数据项；微博中“一个账号”是数据元素，“昵称、性别、生日”是数据项。

### 2. 逻辑结构的四种类型

- **集合**：元素同属一个集合，别无其他关系（本课程基本不讨论）。
- **线性结构**：一对一。除第一个元素外每个元素有唯一**前驱**，除最后一个元素外每个元素有唯一**后继**。
- **树形结构**：一对多（如思维导图、文件目录）。
- **图状/网状结构**：多对多（如微信好友关系，用户为顶点、好友关系为边）。

> 课程对应：线性结构 → 第 2、3 章；树形结构 → 第 4 章；图结构 → 第 5 章。

### 3. 存储结构的四种类型

存储结构要解决的问题：**如何用计算机表示数据元素之间的逻辑关系**。

- **顺序存储**：逻辑上相邻的元素在物理内存中也相邻存放，用**存储位置相邻**表示逻辑相邻。要求分配**一片连续的存储空间**。
- **链式存储**：逻辑相邻的元素物理位置**可以不相邻**，借助**指针**（存放后继元素存储地址）表示先后关系。
- **索引存储**：另建**索引表**，表中每项记录**关键字**与该元素的**存储地址**。关键字 = 能区分不同数据元素的数据项（如排号系统中的号数）。需额外消耗存储空间存放索引表。
- **散列存储（哈希存储）**：根据数据元素的**关键字直接计算出存储地址**。本节只要求模糊印象，第 6 章展开。

> 后三种统称**非顺序存储**。

存储结构的两条结论（本节要求理解的两点）：

1. 顺序存储要求物理连续；非顺序存储物理上可以离散（类比：传统排队 vs 银行取号后就座）。
2. 存储结构影响**存储空间分配的方便程度**（顺序存储插入需整体后移；链式存储只需改指针）和**运算速度**（顺序存储找第 3 个元素可直接定位，链式存储需从头遍历）。

### 4. 数据运算

- **定义**：针对**逻辑结构**，根据实际需求确定需要哪些操作（如队列的“队头元素出队”“新元素入队”）。
- **实现**：针对**存储结构**，同一运算在不同存储结构下实现方式不同。

```c
/* 示意：同一运算“在队尾插入元素 999”，两种存储结构的不同实现思路 */
/* 顺序存储：逻辑相邻即物理相邻，插入位置由下标直接确定 */
/* 链式存储：新结点可放在任意空闲位置，只需修改指针 */
typedef struct LNode {
    int  data;          /* 数据域 */
    struct LNode *next; /* 指针域：指向逻辑上的后继 */
} LNode;

/* 在链式队列尾插入（前提：已知尾指针 rear，且不带头结点的简化写法） */
LNode *p = (LNode *)malloc(sizeof(LNode)); /* 申请新结点，任意空闲位置均可 */
p->data = 999;
p->next = NULL;
rear->next = p;   /* 原尾结点的 next 指向新结点 */
rear = p;         /* 尾指针后移 */
```

> 顺序存储下插入需保证连续空间并可能整体后移；链式存储下只需修改指针，物理位置任意。**运算相同，实现不同**。

### 5. 数据类型与抽象数据类型

- **数据类型**：一个**值的集合**和定义在这个集合上的**一组操作**的总称。
  - **原子类型**：值不可再分。如 `bool`：取值 {true, false}，操作 {与、或、非}；`int`：取值某整数范围，操作 {+、−、×、÷、%}。
  - **结构类型**：值可再分解为若干分量。如 C 语言 `struct`，各分量可为不同数据类型；其取值范围与可进行的操作**由业务需求确定**（如排号 1~9999、每桌人数 1~12；拼桌操作即合并 `people` 分量）。
- **抽象数据类型（ADT, Abstract Data Type）**：抽象数据组织及与之相关的操作。用数学化语言定义**逻辑结构**与**数据运算**，**不讨论存储结构**；只有实际用计算机实现时才涉及存储结构。

> 关系链：定义 ADT ⇒ 确定逻辑结构 + 运算；确定存储结构 ⇒ 才能实现该数据结构，且存储结构不同则运算实现不同。

## 5. 复杂度分析

本节为概念课，无算法，不涉及时间复杂度推导。唯一可量化的是存储结构对运算的影响（定性结论，非渐近复杂度）：

- 顺序存储按位置访问第 $i$ 个元素：地址可由起始地址与元素大小直接算出，$O(1)$（本节仅定性表述“一眼找到”，严格推导见 2.1 顺序表）。
- 链式存储按位置访问第 $i$ 个元素：需从头沿指针走 $i-1$ 步，$O(i)$，最坏 $O(n)$。
- 顺序存储插入元素：最坏需移动其后全部元素，$O(n)$；链式存储插入：修改指针，$O(1)$（前提是已定位插入位置）。

> 本节不要求给出平均情况推导；上述复杂度为后续章节的铺垫，标注为「推断/补充」。

## 6. 易错点与考试写法

1. **数据对象 vs 数据结构**：数据对象只要求元素**性质相同**，不要求有关系；数据结构必须强调元素间的**关系**。选择题常在此设陷阱。
2. **数据元素 vs 数据项**：数据元素是“基本单位”（整体），数据项是“最小单位”（不可再分）。粒度由业务决定，不要死记某个例子。
3. **逻辑结构与存储结构混淆**：逻辑结构是“元素间是什么关系”（集合/线性/树/图），存储结构是“这种关系在计算机里怎么表示”（顺序/链式/索引/散列）。**两者是不同维度的分类，不是一一对应**。
4. **顺序存储 ≠ 线性结构**：线性结构既可用顺序存储也可用链式存储；树、图也可用顺序存储（如数组存二叉树）。分类维度不同，不可混答。
5. **索引存储的关键字**：关键字是“能唯一区分数据元素的数据项”，不是随便某个数据项。
6. **ADT 不含存储结构**：答题时若问“ADT 定义了哪些方面”，答“逻辑结构与数据运算”，**不能**答存储结构。
7. **答题程度**：概念题按王道定义写出关键词即可（如“数据结构是相互之间存在一种或多种特定关系的数据元素的集合”），不要求举例；举例题举一个业务场景并指明数据元素、数据项、逻辑结构即可得分。

## 7. 408 题型与解题套路

- **选择题（主要考法）**：
  - 给一个场景判断属于哪种逻辑结构（如“文件目录系统”→ 树形；“好友关系”→ 图状；“排队”→ 线性）。
  - 判断某说法正误：如“数据对象中的元素一定存在某种关系”（错）、“顺序存储要求物理空间连续”（对）、“ADT 包含存储结构”（错）。
  - 区分数据、数据元素、数据项、数据对象的层级关系。
- **算法题**：本节不直接出算法题，但“三要素”是后续分析框架：拿到任何数据结构题，先问逻辑结构、再问存储结构、最后问运算及其实现。
- **常见陷阱**：把“集合”当成“数据对象”；把“索引存储”与“顺序存储”混为一谈；认为链式存储物理上必须连续。

## 8. 自测题

**1.** 判断：数据对象中的各个数据元素之间必须存在某种关系。

**2.** 海底捞排号系统中，一波顾客的排队信息（号数、取号时间、就餐人数）在数据结构术语中分别对应什么？若把 A、B 两个门店所有排队顾客信息放在一起，这属于数据还是数据对象？

**3.** 逻辑结构分为哪四类？存储结构分为哪四类？二者是什么关系？

**4.** 同一运算“在队尾插入元素”，顺序存储与链式存储的实现有何不同？这说明了什么结论？

**5.** 抽象数据类型（ADT）定义了数据结构的哪几个方面？不涉及哪个方面？

<details>
<summary>参考答案</summary>

1. **错**。数据对象只要求集合中数据元素具有**相同性质**，不强调它们之间的关系；强调关系的是数据结构。
2. 一波顾客的排队信息是**数据元素**；号数、取号时间、就餐人数是**数据项**。两个门店所有排队顾客信息性质相同，合在一起构成一个**数据对象**（不强调跨门店元素间的关系）。
3. 逻辑结构：集合、线性结构、树形结构、图状（网状）结构。存储结构：顺序存储、链式存储、索引存储、散列（哈希）存储。二者是**不同维度的分类**，不存在一一对应：同一逻辑结构可采用不同存储结构实现。
4. 顺序存储需在连续空间中确定插入位置，可能引起其后元素整体后移；链式存储可将新结点放在任意空闲位置，只修改指针。说明**运算按逻辑结构定义，按存储结构实现，存储结构不同则运算实现不同**。
5. ADT 定义**逻辑结构**与**数据运算**，**不涉及存储结构**；只有实际用计算机实现时才考虑存储结构。

## 9. 背诵卡

1. 数据是信息的载体；数据元素是数据的基本单位；数据项是构成数据元素的不可分最小单位；数据对象是性质相同的数据元素的集合。
2. 数据结构 = 相互之间存在一种或多种特定关系的数据元素的集合，强调**关系**。
3. 三要素：**逻辑结构**（集合/线性/树/图）、**存储结构**（顺序/链式/索引/散列）、**数据运算**（按逻辑结构定义、按存储结构实现）。
4. 顺序存储要求物理连续；非顺序存储物理可离散；存储结构影响空间分配方便程度与运算速度。
5. ADT = 数据对象 + 数据关系 + 基本操作，只定义逻辑结构与运算，不含存储结构。
