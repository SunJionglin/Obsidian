# 8.5.2 基数排序

## 1. 本节定位

- 对应王道书：第 8 章「排序」→ 8.5 基数排序 → 8.5.2 基数排序。
- 408 大纲对应条目：内部排序各方法的比较与应用场景（基数排序属于「了解思想、会手算模拟」层次）。
- 先修知识：队列（链队列的队头/队尾指针）、单链表尾插、关键字位的概念、稳定性概念。
- 本章位置：8.5 是「非比较类排序」的代表，前面 8.2~8.4 讲的插入、交换、选择排序全部基于关键字比较；本节是唯一一个**不比较关键字大小**的排序，作为整章收尾，也是「各排序算法适用场景」综合题的常客。

## 2. 一句话结论

基数排序把关键字拆成 $d$ 个位，按**权重从低到高**依次做「分配（进 $r$ 个队列）+ 收集（按队列值从大到小或从小到大串起来）」，$d$ 趟后整体有序；时间 $O(d(n+r))$，空间 $O(r)$，**稳定**，且不基于比较。

## 3. 知识地图

```
基数排序
├── 前提：关键字可拆成 d 个位，每位取值 0 ~ r-1（r 称为基数）
│     ├── 最高位关键字（最主位）：对整体数值影响最大（如百位）
│     └── 最低位关键字（最次位）：影响最小（如个位）
├── 存储：链式存储（单链表 + r 个链队列，每个队列只存队头/队尾指针）
├── 两趟基本操作
│     ├── 分配：顺序扫描元素，当前位 = x 则尾插进 Qx
│     └── 收集：按队列编号从大到小（递减序）或从小到大（递增序）依次摘下整条链
├── 执行顺序：按位权递增（个位 → 十位 → 百位），共 d 趟
├── 结果方向
│     ├── 要递减：收集时从 Q(r-1) 收到 Q0
│     └── 要递增：收集时从 Q0 收到 Q(r-1)
├── 复杂度：T = O(d(n+r))，S = O(r)
├── 稳定性：稳定（同关键字位按原序入队、按原序出队）
└── 适用条件：n 大、d 小、r 小
      ├── 反例1：5 个身份证号（d=18 太大）
      ├── 反例2：中国人姓名排序（r 上万，太大）
      └── 正例：10 亿身份证号（n 极大，d=18 可接受）
```

## 4. 核心内容

### 1. 定义与基本思想（408 必考：思想 + 手算）

基数排序（Radix Sort）不比较关键字大小，而是把每个关键字看成 $d$ 元组：

$$K = (k^{d-1},\, k^{d-2},\, \dots,\, k^{1},\, k^{0})$$

其中 $k^{d-1}$ 为最高位（最主位）关键字，$k^{0}$ 为最低位（最次位）关键字；每一位取值 $0 \sim r-1$，$r$ 称为**基数**。

做法：设 $r$ 个辅助队列 $Q_0, Q_1, \dots, Q_{r-1}$，按**位权递增**次序（先 $k^0$，再 $k^1$，…，最后 $k^{d-1}$）做 $d$ 趟：

- **分配**：从头到尾扫描当前序列，若当前处理位等于 $x$，把该结点**尾插**入 $Q_x$；
- **收集**：按队列编号顺序把各队列整条链摘下、首尾相接成一个新序列。

> 为什么低位先排？因为后一趟（高位）的分配是稳定的：高位相同的元素保持上一趟（低位有序）的相对次序，于是「高位优先、高位相同看低位」的字典序自然成立。这就是**低位优先（LSD, Least Significant Digit first）** 基数排序。

### 2. 手算模拟（以递减序为例，王道原例）

初始序列：`520, 211, 438, 888, 007, 111, 985, 666, 996, 168`（共 10 个，$d=3$，$r=10$）

**第一趟：按个位分配**

| 队列 | 元素（队头→队尾） |
|---|---|
| Q0 | 520 |
| Q1 | 211, 111 |
| Q6 | 996, 666 |
| Q7 | 007 |
| Q8 | 438, 888, 168 |
| Q5 | 985 |

**收集（递减序：从 Q9 收到 Q0）**：

`438, 888, 168, 007, 996, 666, 985, 211, 111, 520`

此时序列按个位递减有序。

**第二趟：按十位分配**（在上一趟结果上顺序扫描）

- 438→Q3，888→Q8，168→Q6，007→Q0，996→Q9，666→Q6（尾插到 168 后），985→Q8（尾插到 888 后），211→Q1，111→Q1，520→Q2。

**收集（Q9→Q0）**：

`996, 888, 985, 168, 666, 438, 211, 111, 520, 007`

此时按十位递减，十位相同者按个位递减。

**第三趟：按百位分配**，收集后得：

`996, 985, 888, 666, 520, 438, 211, 168, 111, 007`

整体递减有序。

> 手算要点：**每一趟都在上一趟的序列上顺序扫描**，同队列内**先扫到的在前**（尾插），收集时**整条链一起摘**，不要打乱队列内部次序。

### 3. 链式存储下的实现要点（了解即可，408 基本不考代码）

```c
#define RADIX 10            // 基数 r
typedef struct LNode {
    int  key;               // 关键字（实际可为 d 位十进制数）
    struct LNode *next;
} LNode, *LinkList;

typedef struct {            // 链队列：只需头、尾两个指针
    LNode *front, *rear;
} Queue;

Queue Q[RADIX];             // r 个辅助队列

// 一趟分配：p 遍历原链表
void Distribute(LinkList L, int pos) {   // pos: 当前处理的位（0=个位）
    for (int i = 0; i < RADIX; i++)      // 队列初始化
        Q[i].front = Q[i].rear = NULL;
    for (LNode *p = L->next; p; p = p->next) {
        int x = GetDigit(p->key, pos);   // 取第 pos 位数字
        if (Q[x].front == NULL)          // 空队列：头尾同时指向
            Q[x].front = Q[x].rear = p;
        else {                           // 非空：尾插
            Q[x].rear->next = p;
            Q[x].rear = p;
        }
    }
}

// 一趟收集：把 r 个队列整条链依次接到结果链表尾部
void Collect(LinkList L, int desc) {     // desc=1 递减，从 Q9 收到 Q0
    LNode *tail = L;                     // tail 指向结果链表尾
    for (int i = 0; i < RADIX; i++) {
        int idx = desc ? (RADIX - 1 - i) : i;
        if (Q[idx].front == NULL) continue;
        tail->next = Q[idx].front;       // 整条链一次挂上，O(1)
        tail = Q[idx].rear;
    }
    tail->next = NULL;                   // 封口
}
```

关键点：**收集一个队列是 $O(1)$**——只需 `tail->next = Q[idx].front; tail = Q[idx].rear;`，不需要遍历队列内部。这是链式存储相对顺序存储的核心优势。

### 4. 稳定性

分配时从左到右扫描，关键字位相同的元素**先扫到的先入队**；收集时整条链按入队次序摘下。因此两个关键字完全相同的元素，相对次序不变 → **基数排序稳定**。（口诀：基你太稳。）

### 5. 适用场景（408 常考判断）

适合：$n$ 大、$d$ 小、$r$ 小。

- 正例：1 万学生按生日（年/月/日，$d=3$，$r \le 31$）排年龄递减；10 亿身份证号排序（$n$ 极大，$d=18$ 可接受）。
- 反例1：只给 5 个人按 18 位身份证号排序——$d=18$ 而 $n=5$，做 18 趟纯属浪费。
- 反例2：按中文姓名排序——$d$ 虽小（约 4），但每位取值上万（汉字），$r$ 巨大，空间与时间都爆炸。

> 结论不能教条化：同一个「身份证号」例子，$n$ 小不适合、$n$ 极大又适合，判断要代 $d(n+r)$ 算。

## 5. 复杂度分析

设元素个数 $n$，关键字位数 $d$，基数 $r$。

**空间**：需要 $r$ 个辅助队列，每个队列只存队头、队尾两个指针，故 $S(n) = O(r)$。（若用顺序存储的队列数组，则需 $O(n+r)$，王道以链式为准。）

**时间**：

- 一趟分配：顺序扫描全部 $n$ 个元素，每个元素做一次取位 + 一次尾插，$O(n)$；
- 一趟收集：依次处理 $r$ 个队列，每个队列 $O(1)$ 摘下，$O(r)$；
- 共 $d$ 趟：$T(n) = O\big(d \cdot (n + r)\big)$。

**最好 / 最坏 / 平均**：三者同阶，均为 $O(d(n+r))$——因为趟数 $d$ 由关键字位数固定，每趟工作量与元素具体取值无关，**不存在输入分布导致的差异**（这一点与比较类排序不同，答题时要写「与初始序列无关」）。

**平均情况的推导**：无随机假设可用，因为算法不比较、不做分支判断；每趟固定扫描 $n$ 个元素、固定扫 $r$ 个队列，故平均即等于最坏，$O(d(n+r))$。

**与比较类排序对比**（$n=10^4$，$d=3$，$r=31$）：$d(n+r) \approx 3\times 10^4$，优于 $O(n^2)=10^8$，也优于 $O(n\log n)\approx 1.3\times10^5$ 的常数级差距（推断：此处仅数量级比较，实际常数另计）。

## 6. 易错点与考试写法

1. **收集方向搞反**：要递减序，收集时从 $Q_{r-1}$ 收到 $Q_0$；要递增序，从 $Q_0$ 收到 $Q_{r-1}$。分配方向永远是从头到尾扫描，不变。
2. **趟序搞反**：必须**低位先做**（个位→十位→百位）。若先做高位，后做低位会破坏高位的有序性（因为低位分配会打乱高位分组）。
3. **同队列内部次序**：必须尾插，保证先扫到的在前；手算时若把同队列元素顺序写反，稳定性结论就错。
4. **$r$ 的含义**：$r$ 是「每一位可能的取值个数」，不是元素个数，也不是关键字位数。十进制数 $r=10$；生日例子中三趟的 $r$ 分别是 31、12、15，取最大者估复杂度。
5. **复杂度写全**：必须写 $O(d(n+r))$，不能只写 $O(n)$；空间写 $O(r)$ 而非 $O(n+r)$（链式前提）。
6. **「不基于比较」的表述**：基数排序与计数排序、桶排序同属非比较排序，选择题常问「下列哪个排序不基于比较」。
7. **答题深度**：408 对本节只要求「思想 + 手算模拟 + 复杂度 + 稳定性 + 适用场景」，**不要求写完整代码**；算法设计题若允许用基数排序，写清「拆位、设 $r$ 个队列、按位权递增做 $d$ 趟分配收集」即可得分。

## 7. 408 题型与解题套路

**选择题常见考法**：

- 给初始序列和基数，问第一趟/第二趟收集后的序列 → 按上表逐趟模拟，注意收集方向。
- 问时间复杂度 → $O(d(n+r))$，注意 $d$、$r$ 的定义。
- 问稳定性 → 稳定。
- 问「哪个排序不基于比较」→ 基数排序（及计数、桶排序）。
- 给场景问「最适合的排序」→ 代 $d(n+r)$ 与 $n\log n$、$n^2$ 比较，看 $n$ 大不大、$d$ 和 $r$ 小不小。

**算法题套路**（若被要求用基数排序）：

1. 判断关键字能否拆成 $d$ 位、每位取值是否有限且小；
2. 说明用链式存储 + $r$ 个链队列；
3. 按位权递增循环 $d$ 趟，每趟「分配 + 收集」；
4. 收尾写复杂度 $O(d(n+r))$、空间 $O(r)$、稳定。

**常见陷阱**：题目给的是「递减」要求，但默认思维按递增收集；或题目中 $r$ 不是 10（如字母 $r=26$、生日 $r=31$），仍套 $r=10$ 算复杂度。

## 8. 自测题

**1.** 对序列 `(278, 109, 63, 930, 589, 184, 505, 269, 8, 83)` 做基数排序（十进制，$r=10$），第一趟按个位分配并**按递增序**收集，所得序列是？

**2.** 基数排序的时间复杂度为 $O(d(n+r))$，其中 $d$、$r$ 分别指什么？为什么收集一趟只需 $O(r)$ 而不是 $O(n)$？

**3.** 判断：基数排序是稳定的，且其时间复杂度与初始序列的排列无关。

**4.** 要给 100 万个 0~999999 之间的整数排序，基数排序与快速排序哪个更合适？说明理由。

**5.** 若把基数排序的趟序改为「百位→十位→个位」（高位优先），最终结果还有序吗？为什么？

<details>
<summary>答案</summary>

**1.** 个位分配：Q0: 930；Q3: 63, 83；Q4: 184；Q5: 505；Q8: 278, 8；Q9: 109, 589, 269。递增收集（Q0→Q9）：`930, 63, 83, 184, 505, 278, 8, 109, 589, 269`。

**2.** $d$ 是关键字可拆分的位数（趟数），$r$ 是每一位可能的取值个数（基数、辅助队列数）。收集时每个队列只需把队头接到结果链尾、更新尾指针，$O(1)$ 摘一整条链，共 $r$ 个队列，故 $O(r)$；元素本身在分配阶段已扫描过，收集阶段不再逐个访问。

**3.** 正确。稳定性由「尾插 + 整链按序摘下」保证；每趟固定扫描 $n$ 个元素、$r$ 个队列，与元素取值分布无关。

**4.** 基数排序更合适（推断，需按数据算）：$d=6$，$r=10$，$T=O(6\times(10^6+10))\approx 6\times10^6$；快排平均 $O(n\log n)\approx 10^6\times 20 = 2\times10^7$，且基数排序稳定、无最坏退化。但若内存紧张，快排原地 $O(\log n)$ 栈空间更省。

**5.** 无序。高位优先时，后做的低位分配会把高位已分好的组打乱；要高位优先必须对每个高位组递归做低位排序（即 MSD 基数排序），不能简单 $d$ 趟线性扫。

</details>

## 9. 背诵卡

1. 基数排序 = 拆 $d$ 位 + $r$ 个链队列 + 按**位权递增**做 $d$ 趟「分配（尾插）+ 收集（整链摘）」。
2. 递减序：收集从 $Q_{r-1}$ 到 $Q_0$；递增序：从 $Q_0$ 到 $Q_{r-1}$。分配永远从头扫到尾。
3. 时间 $O(d(n+r))$，空间 $O(r)$，**稳定**，**不基于比较**，复杂度与初始序列无关。
4. 适用：$n$ 大、$d$ 小、$r$ 小；反例：少量身份证号（$d$ 大）、中文姓名（$r$ 大）。
5. 口诀：基你太稳（基数排序稳定）；低位先排，高位后收。
