# 4.2.2 KMP 算法（新版）笔记

## 1. 本节定位

- **对应王道书**：第 4 章 串 → 4.2 串的模式匹配 → 4.2.2 KMP 算法（紧接 4.2.1 朴素模式匹配算法）。
- **408 大纲对应**：串的模式匹配（KMP 算法思想、next 数组、时间复杂度）。
- **先修知识**：串的顺序存储、朴素（暴力）模式匹配算法、主串指针 $i$ 与模式串指针 $j$ 的含义。
- **本节位置**：本章核心难点。上一节朴素算法最坏 $O(nm)$，本节通过“利用模式串自身信息”把主串指针 $i$ 变为不回溯，得到 $O(n+m)$；next 数组的**手工求法**是 408 选择题高频考点，代码求 next 数组属于后续内容（本节只讲匹配部分代码）。

## 2. 一句话结论

**KMP 的核心是：当模式串第 $j$ 个字符失配时，主串指针 $i$ 不回溯，只把模式串指针 $j$ 改为 `next[j]`，而 `next[j]` 只由模式串本身决定、与主串无关。**

## 3. 知识地图

```
KMP 算法
├── 出发点：朴素算法的缺陷
│   └── 失配后 i 回溯到下一个子串首字符，已匹配信息被浪费
├── 关键观察
│   └── 失配前主串已匹配部分 == 模式串前缀，信息已知
├── 优化思想
│   ├── 跳过必然失配的子串（不逐个试）
│   ├── 跳过子串中已确定匹配的前缀
│   └── i 不回溯，只改 j
├── next 数组
│   ├── 含义：模式串第 j 个字符失配时，j 应改为 next[j]
│   ├── 只与模式串有关，与主串无关
│   └── 手工求法（408 必考）
├── 匹配代码
│   ├── 相等 或 j==0 → i++、j++
│   └── 否则 → j = next[j]
└── 复杂度
    ├── 求 next：O(m)
    ├── 匹配：O(n)
    └── 总计：O(n+m)
```

## 4. 核心内容

### 4.1 朴素算法的浪费在哪里

朴素算法：主串长 $n$、模式串长 $m$，把主串中每个长度为 $m$ 的子串依次与模式串比较，失配则 $i$ 回溯到下一个子串首字符、$j=1$ 重来。

关键观察：若模式串匹配到第 $j$ 个字符才失配，则**主串中该子串的前 $j-1$ 个字符一定与模式串前 $j-1$ 个字符完全相同**。这部分信息是已知的，朴素算法却把它丢掉了。

### 4.2 优化思路（以模式串 `a b a a b c` 为例）

设模式串 $T = \texttt{abaabc}$，讨论第 $j$ 个字符失配时 $j$ 应改为多少（$i$ 始终不动）：

| 失配位置 $j$ | 已确定匹配的前缀 | 可直接跳过的子串 | 新的 $j$ |
|---|---|---|---|
| 6 | `abaab` | 以 2、3 号字符开头的子串 | 3 |
| 5 | `abaa` | 以 2、3 号字符开头的子串 | 2 |
| 4 | `aba` | 以 2 号字符开头的子串 | 2 |
| 3 | `ab` | 以 2 号字符开头的子串 | 1 |
| 2 | `a` | 无（只能试下一个子串） | 1 |
| 1 | 无 | 无 | 0（特殊） |

**为什么是这些值**：失配后要找一个“模式串前缀”与“已匹配部分的后缀”重合最长的情况，从重合处继续比。例如 $j=6$ 时已匹配 `abaab`，其真后缀 `ab` 与模式串前缀 `ab` 重合，故从 $j=3$ 继续。

**$j=1$ 失配的特殊处理**：此时没有任何已知信息，只能让主串前进一位。代码上统一为：先令 $j=0$（指向模式串首字符之前），再让 $i$、$j$ 同时加一，等价于“$i$ 后移、$j$ 回到 1”。

> 结论的通用性：上述对应关系**只依赖模式串**，与主串内容、匹配到主串哪个位置无关。这是 next 数组能预先算出的根本原因。

### 4.3 next 数组

定义（本节采用的口径，与王道书一致）：

$$
\text{next}[j] = \text{模式串第 } j \text{ 个字符失配时，} j \text{ 应改为的值}
$$

对 $T=\texttt{abaabc}$：$\text{next}[1..6] = \{0,\ 1,\ 1,\ 2,\ 2,\ 3\}$。

- `next[1] = 0` 是约定的哨兵，配合“$j=0$ 时 $i$、$j$ 同时加一”统一处理边界。
- 408 选择题常直接问“某模式串的 next 数组”，必须能手算。

### 4.4 匹配代码（王道风格，下标从 1 开始）

```c
// S 主串，T 模式串，next 数组已预先求出
// 串采用「字符数组 + 长度存在 [0]」的存储方式
int Index_KMP(SString S, SString T, int next[]) {
    int i = 1, j = 1;                 // i 扫主串，j 扫模式串
    while (i <= S.length && j <= T.length) {
        if (j == 0 || S.ch[i] == T.ch[j]) {
            i++;                      // 匹配成功，或 j 已退到 0（首字符失配）
            j++;                      // 两者同步后移
        } else {
            j = next[j];              // 失配：i 不动，j 按 next 跳转
        }
    }
    if (j > T.length)
        return i - T.length;          // 匹配成功，返回起始位置
    else
        return 0;                     // 匹配失败
}
```

与朴素算法相比只改两处：失配时 `j = next[j]`（不再回溯 $i$）、循环条件多一个 `j == 0`。

### 4.5 手工模拟要点

以 $S=\texttt{abaabaabc}$、$T=\texttt{abaabc}$ 为例：前 5 个字符匹配，第 6 个失配 → $i$ 不动、$j=\text{next}[6]=3$ → 从 $T$ 第 3 个字符继续比，很快匹配成功。全程 $i$ 单调递增，从不回退。

## 5. 复杂度分析

设主串长 $n$、模式串长 $m$。

- **求 next 数组（预处理）**：$O(m)$。每个位置只做常数次比较与赋值（具体求法见下一节）。
- **匹配过程**：$O(n)$。关键论证：$i$ 只增不减，最多增加 $n$ 次；每次失配执行 `j = next[j]` 会使 $j$ 减小，但 $j$ 的减小总量不超过它此前增加的总量，而 $j$ 每次增加都伴随 $i$ 增加，故 `j = next[j]` 的总执行次数也是 $O(n)$。因此 while 循环总次数为 $O(n)$。
- **总复杂度**：$O(n+m)$。
- **最好情况**：首字符即失配且 next 跳转后立即匹配，约 $O(n)$（仍需扫完主串）。
- **最坏情况**：$O(n+m)$，优于朴素算法的 $O(nm)$。
- **平均情况**：本节未给出概率模型，408 不要求推导平均复杂度，记住 $O(n+m)$ 即可（补充：一般文献在随机文本假设下平均也为线性）。

## 6. 易错点与考试写法

1. **next 数组口径**：王道书 `next[1]=0`，部分教材 `next[1]=-1` 或整体右移一位（`nextval` 另说）。答题必须按题目/王道口径，写清下标起点。
2. **失配时 $i$ 不动**：这是 KMP 与朴素算法的本质区别，写代码时绝不能出现 `i = i - j + 2` 之类的回溯。
3. **`j == 0` 分支不能漏**：首字符失配时靠它让 $i$ 前进，否则死循环。
4. **next 只与模式串有关**：选择题常给一个长主串干扰，判断“next 数组是否改变”时只看模式串。
5. **返回值**：成功返回起始下标（从 1 开始则返回 $i-m$），失败返回 0；注意与“返回匹配长度”区分。
6. **答题程度**：408 中 KMP 以**选择题**为主（手算 next、判断失配后 $j$ 的取值、比较复杂度），代码题概率低；能写出上面匹配框架并说明 $i$ 不回溯即可。

## 7. 408 题型与解题套路

- **题型一：手算 next 数组**。套路：对每个 $j$，取前 $j-1$ 个字符，找“最长相等前后缀”长度 $k$，则 $\text{next}[j]=k+1$；$\text{next}[1]=0$。用表格逐位填，别跳步。
- **题型二：模拟失配跳转**。给主串、模式串、next 数组，问“第几次比较后 $i$、$j$ 各为多少”。套路：严格按 `j = next[j]` 走，$i$ 只增。
- **题型三：复杂度比较**。朴素 $O(nm)$ vs KMP $O(n+m)$，常问“KMP 一定更快吗”——最坏情况更快，但常数因子与预处理开销使短主串时未必占优（推断，属理解性考点）。
- **陷阱**：把 next 与 nextval 混淆；把“失配位置 $j$”与“next 值”错位一格；忘记 $j=1$ 失配要 $i$ 后移。

## 8. 自测题

**1.** 模式串 $T=\texttt{abaabc}$，求 next 数组（王道口径，下标从 1 开始）。

**2.** 承上，若匹配到 $T$ 的第 5 个字符失配，$j$ 应改为多少？主串指针 $i$ 如何变化？

**3.** KMP 匹配过程中，主串指针 $i$ 最多移动多少次？据此说明匹配阶段复杂度。

**4.** 判断：next 数组的值与主串内容有关。（对/错，说明理由）

**5.** 朴素算法与 KMP 的最坏时间复杂度分别是多少？KMP 的 $O(n+m)$ 由哪两部分组成？

<summary>答案</summary>

1. $\text{next}[1..6]=\{0,1,1,2,2,3\}$。逐位：$j=1$ 取 0；$j=2$ 前缀 `a` 无真前后缀重合 → 1；$j=3$ 前两位 `ab` → 1；$j=4$ 前三位 `aba` 最长相等前后缀 `a` 长 1 → 2；$j=5$ 前四位 `abaa` 最长 `a` → 2；$j=6$ 前五位 `abaab` 最长 `ab` → 3。
2. $j=\text{next}[5]=2$；$i$ 保持不变。
3. $i$ 单调递增，最多移动 $n$ 次；每次失配的 `j = next[j]` 总次数不超过 $j$ 增加的总次数（$\le n$），故匹配阶段 $O(n)$。
4. 错。next 只由模式串自身的最长相等前后缀决定，与主串无关。
5. 朴素 $O(nm)$，KMP $O(n+m)$；由预处理求 next 的 $O(m)$ 与匹配的 $O(n)$ 组成。

## 9. 背诵卡

1. KMP 失配时 **$i$ 不回溯，$j=\text{next}[j]$**；next 只由模式串决定。
2. $\text{next}[j]$ = 前 $j-1$ 个字符的**最长相等前后缀长度 $+1$**；$\text{next}[1]=0$。
3. 首字符失配：$j=0$，再 $i$、$j$ 同时加一（等价 $i$ 后移一位）。
4. 匹配代码两处改动：`j = next[j]`、循环条件加 `j == 0`。
5. 复杂度：求 next $O(m)$ + 匹配 $O(n)$ = **$O(n+m)$**，优于朴素 $O(nm)$。
