# 2.2.1 顺序表的定义

## 1. 本节定位

- **王道书**：第 2 章 线性表，2.2 线性表的顺序表示，2.2.1 顺序表的定义。
- **408 大纲**：线性表的顺序存储结构（顺序表的定义、实现、特点）。
- **先修知识**：线性表的逻辑结构（2.1）、C 语言数组、指针、`sizeof`、`malloc/free`。
- **位置**：承接 2.1 线性表的逻辑结构与基本操作，开启 2.2 顺序存储实现；下一节 2.2.2 讲顺序表上的插入、删除等基本操作。

## 2. 一句话结论

顺序表是用**顺序存储**实现的线性表——逻辑上相邻的元素在物理内存上也相邻，因此支持 $O(1)$ 的按位查找（随机访问），但容量扩展和插入删除代价大。

## 3. 知识地图

```
顺序表（用顺序存储实现的线性表）
├── 定义：逻辑相邻 ⇒ 物理相邻；元素类型相同、等长
├── 地址计算：LOC(a_i) = LOC(a_1) + (i-1) × sizeof(ElemType)
├── 实现方式
│   ├── 静态分配：定长数组 + length
│   │   └── 缺点：容量固定，不可扩展
│   └── 动态分配：指针 data + MaxSize + length
│       └── 扩展：malloc 新空间 → 复制 → free 旧空间
└── 特点
    ├── 随机访问 O(1)
    ├── 存储密度高（只存数据，不存指针）
    ├── 扩展容量不方便（静态不可扩；动态需复制）
    └── 插入删除需移动大量元素
```

## 4. 核心内容

### 1. 定义

**顺序表**：用顺序存储方式实现的线性表。**顺序存储**：把逻辑上相邻的数据元素存储在物理上也相邻的存储单元中。

由于线性表各元素**数据类型相同**，每个元素占用空间相等，设起始地址为 $LOC(a_1)$，元素大小为 `sizeof(ElemType)`，则第 $i$ 个元素的地址：

$$LOC(a_i) = LOC(a_1) + (i-1)\times \text{sizeof(ElemType)}$$

这就是按位查找 $O(1)$ 的根本原因：**连续存放 + 元素等长 + 已知起始地址**，地址可直接算出，无需从头遍历。

> 位序 vs 下标：位序 $i$ 从 1 开始，数组下标从 0 开始，$a_i$ 对应 `data[i-1]`。408 选择题常在此设陷阱。

### 2. 静态分配

```c
#define MaxSize 10            // 顺序表最大容量（宏常量）
typedef struct {
    ElemType data[MaxSize];   // 静态数组，容量声明后不可变
    int length;               // 当前实际长度（已存元素个数）
} SqList;                     // Sq = sequence

void InitList(SqList *L) {
    for (int i = 0; i < MaxSize; i++)
        L->data[i] = 0;       // 可选：置默认值，避免脏数据
    L->length = 0;            // 必须：初始长度为 0
}
```

要点：

- `MaxSize` 决定**最多能存几个**；`length` 表示**当前存了几个**，二者含义不同。
- 声明 `SqList L;` 时系统一次性分配 `MaxSize × sizeof(ElemType) + sizeof(int)` 的连续空间。
- **脏数据问题**：内存中残留旧数据，若不初始化 `data`，未使用位置会打印出随机值。但按规范只能访问 `0 ~ length-1`，所以 `data` 的初始化**可省略**；而 `length = 0` **绝不能省**——不能依赖编译器自动清零（不同编译器行为不同）。
- 静态分配的致命局限：**容量声明后不可改变**。开太小会溢出，开太大会浪费，无法两全。

### 3. 动态分配

```c
#define InitSize 10           // 初始容量
typedef struct {
    ElemType *data;           // 指向动态分配数组的首元素
    int MaxSize;              // 当前最大容量
    int length;               // 当前实际长度
} SeqList;

void InitList(SeqList *L) {
    // 申请 InitSize 个元素的连续空间，强制转换为 ElemType*
    L->data = (ElemType *)malloc(InitSize * sizeof(ElemType));
    L->length = 0;
    L->MaxSize = InitSize;
}

void IncreaseSize(SeqList *L, int len) {
    ElemType *p = L->data;                       // p 暂存旧空间首地址
    L->data = (ElemType *)malloc((L->MaxSize + len) * sizeof(ElemType)); // 开新空间
    for (int i = 0; i < L->length; i++)
        L->data[i] = p[i];                       // 复制旧数据到新空间
    L->MaxSize = L->MaxSize + len;               // 更新最大容量
    free(p);                                     // 释放旧空间，归还系统
}
```

要点：

- `malloc(size)` 申请 `size` 字节的**连续**空间，返回首地址（`void*`），必须**强制类型转换**为元素指针类型。
- 参数写法：`元素个数 × sizeof(ElemType)`，即 `InitSize * sizeof(ElemType)`。
- 扩展三步：**开新 → 复制 → 释放旧**，时间复杂度 $O(n)$（复制 `length` 个元素）。
- `p` 是局部变量，函数返回后自动回收，但 `p` 指向的**堆空间**必须 `free`，否则内存泄漏。
- 需 `#include <stdlib.h>`。
- C++ 可用 `new/delete` 替代，但王道统一用 `malloc/free`（照顾跨考生）。
- `realloc` 也能实现扩展，但行为有坑，考试与工程均建议手写 `malloc + 复制 + free`。

### 4. 顺序表的特点（必背）

| 特点 | 原因 |
|---|---|
| **随机访问**，按位查找 $O(1)$ | 连续存放 + 等长 + 起始地址已知，地址可算 |
| **存储密度高** | 每个结点只存数据元素本身，不存指针（链式需额外存指针） |
| **扩展容量不方便** | 静态分配不可扩；动态分配需复制全部数据，$O(n)$ |
| **插入删除不方便** | 需移动大量元素（下一节展开） |

## 5. 复杂度分析

本节操作均为**建表/初始化/扩展**类操作，不涉及查找比较，故无“最好/最坏/平均”三态之分；按位查找的 $O(1)$ 是**确定性结论**，不是平均意义。

- **按位查找**：地址公式一次算术运算，$T(n) = O(1)$，与 $n$ 无关，最好=最坏=平均。
- **初始化（静态）**：若置默认值，循环 `MaxSize` 次，$O(MaxSize)$；若省略，$O(1)$。
- **初始化（动态）**：`malloc` 一次，$O(1)$。
- **动态扩展 `IncreaseSize(L, len)`**：复制 `length` 个元素，$T(n) = O(length) = O(n)$；`malloc/free` 本身视作 $O(1)$（补充：实际分配可能涉及系统调用，408 不考）。

> 按值查找的平均比较次数 $\frac{n+1}{2}$ 属于 2.2.2 基本操作内容，本节不展开；此处仅提示：其推导依赖“每个位置被查找概率相等 $1/n$”的假设，$\sum_{i=1}^{n} i \cdot \frac{1}{n} = \frac{n+1}{2}$。

## 6. 易错点与考试写法

1. **位序与下标混用**：$a_i$ 存于 `data[i-1]`；写地址公式时 $(i-1)$ 不能丢。
2. **`length` 与 `MaxSize` 混淆**：`MaxSize` 是容量上限，`length` 是当前元素个数；判满用 `length == MaxSize`，不是 `length == MaxSize - 1`。
3. **`length = 0` 不能省**：脏数据导致 `length` 初值随机，后续所有操作全错；`data` 初始化可省。
4. **`malloc` 忘强制转换 / 忘乘 `sizeof`**：`malloc(InitSize * sizeof(ElemType))`，漏 `sizeof` 只申请了 `InitSize` 字节。
5. **动态扩展忘 `free(p)`**：内存泄漏；忘复制数据则原数据丢失。
6. **结构体比较的坑**：`ElemType` 为 `struct` 时，C 语言**不能用 `==` 直接比较两个结构体**（编译报错），须逐成员比较；C++ 可重载 `operator==`。408 算法题若元素为结构体，比较处要写成员级比较。
7. **答题标准**：定义题写“逻辑相邻 ⇒ 物理相邻 + 元素等长 + 随机访问”；代码题结构体三要素（`data`、`MaxSize`、`length`）齐全、`InitList` 中 `length=0` 必写、动态版 `malloc` 转换与 `sizeof` 正确，即算对。

## 7. 408 题型与解题套路

- **选择题**：
  - 给起始地址、元素大小、位序，求某元素地址（套公式，注意下标偏移）。
  - 判断“顺序表一定支持随机访问”“静态分配能否扩容”“存储密度比较”。
  - 给 `sizeof(struct)` 场景（如两个 `int` 成员占 8 字节）算地址。
- **算法题**：本节不单独出算法题，但**所有顺序表算法题的前提**是能默写结构体定义与 `InitList`；动态版扩展函数是“顺序表扩容”模板，可被综合题调用。
- **常见陷阱**：把“随机访问”说成“按值查找 $O(1)$”（错，按值查找是 $O(n)$）；把动态分配说成“容量无限”（错，仍受内存限制且扩展 $O(n)$）。

## 8. 自测题

**1.** 顺序表 `L` 起始地址为 1000，`ElemType` 为 `int`（4 字节），则位序为 5 的元素地址是多少？对应数组下标是多少？

**2.** 静态分配与动态分配的顺序表，在“容量不足”时分别如何处理？各自代价是什么？

**3.** 为什么顺序表按位查找是 $O(1)$？请从存储结构角度说明，不能只答“因为用了数组”。

**4.** 下面代码有何错误？

```c
typedef struct { int data[10]; int length; } SqList;
void InitList(SqList *L) { L->length = 0; }
```

**5.** 判断：顺序表的存储密度一定高于链表；顺序表插入删除一定比链表慢。

<details>
<summary>答案</summary>

1. 地址 $= 1000 + (5-1)\times 4 = 1016$；数组下标为 $5-1=4$，即 `data[4]`。
2. 静态分配：容量声明后不可变，存满即溢出，只能“放弃治疗”或预先开大（浪费）；动态分配：`malloc` 更大空间 → 复制旧数据 → `free` 旧空间 → 更新 `MaxSize`，代价 $O(n)$ 时间复制。
3. 三个条件同时成立：元素在内存中**连续存放**、每个元素**等长**（同类型）、**起始地址已知**，故 $LOC(a_i)=LOC(a_1)+(i-1)\times sizeof(ElemType)$ 一次算术即可得地址，与 $n$ 无关。
4. 缺 `data` 初始化（可省，但按规范访问不越界即可）；**致命错误是没写 `length = 0` 之外的初始化？**——本题 `length = 0` 已写，真正问题是：若 `ElemType` 非 `int` 则结构体不通用（属设计问题）；更关键，若省略 `data` 初始化且后续按 `MaxSize` 遍历会读到脏数据。标准答法：`length = 0` 必须保留，`data` 初始化可省但访问必须限制在 `0 ~ length-1`。
5. 前半句对（顺序表只存数据，链表结点额外存指针，存储密度更低）；后半句错——在**表尾**插入删除时顺序表无需移动元素，可 $O(1)$，并非“一定比链表慢”。

</details>

## 9. 背诵卡

1. 顺序表 = 顺序存储实现的线性表；逻辑相邻 ⇒ 物理相邻。
2. $LOC(a_i)=LOC(a_1)+(i-1)\times sizeof(ElemType)$，位序 $i$ 对应下标 $i-1$。
3. 静态分配：`ElemType data[MaxSize]; int length;`，容量不可变；`length=0` 必写，`data` 初始化可省。
4. 动态分配：`ElemType *data; int MaxSize, length;`，扩展 = `malloc` 新 → 复制 → `free` 旧，$O(n)$。
5. 四大特点：随机访问 $O(1)$、存储密度高、扩容不便、插删需移动元素。
