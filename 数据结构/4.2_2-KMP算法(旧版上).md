# 4.2 KMP 算法（旧版上）笔记

## 1. 本节定位

- **对应王道书**：第 4 章 串 → 4.2 串的模式匹配 → 4.2.2 KMP 算法（本节只讲“为什么引入 KMP + next 数组怎么用”，next 数组的求法留到下一节）。
- **408 大纲对应**：串的模式匹配（KMP 算法思想、next 数组、匹配过程）。
- **先修知识**：朴素模式匹配（BF 算法）的代码框架、主串指针 `i` 与模式串指针 `j` 的含义、串的存储（下标从 1 开始，王道风格）。
- **本章位置**：上一节 BF 算法是“每次失配模式串右移一位、主串指针回溯”；本节是 BF 的优化——**主串指针不回溯，只回溯模式串指针**，并引出 `next` 数组。下一节讲 `next` 数组的求法（手算 + 代码）。

## 2. 一句话结论

**KMP 的核心是：匹配失败时主串指针 `i` 不回溯，只让模式串指针 `j` 回退到 `next[j]`，利用模式串自身的前缀信息跳过不可能匹配的位置。**

## 3. 知识地图

```
KMP 算法
├── 动机：BF 的缺陷
│   ├── 主串指针 i 反复回溯（最坏每走 m 步退 m-1 步）
│   └── 模式串每次只右移 1 位，做了大量无用比较
├── 核心思想
│   ├── i 永不回溯（只增不减）
│   └── 失配时 j 回退到 next[j]，等价于模式串“一次右移多步”
├── next 数组（本节只讲“怎么用”，不求法）
│   ├── 含义：j 处失配 → j 改为 next[j]
│   ├── 约定：next[1] = 0（哨兵，用于让 i 后移）
│   └── 例：google 的 next = {0,1,1,1,2,1}（下标 1~6）
└── KMP 匹配代码（BF 改造版）
    ├── 失配：j = next[j]
    ├── j == 0：i++、j++（i 后移，j 回到 1）
    └── 匹配：i++、j++
```

## 4. 核心内容

### 4.1 为什么 BF 慢（动机）

BF 中，主串指针 `i` 每轮从 `i - j + 2` 重新开始（王道写法用 `k` 记录子串起点），即**失配后 i 回溯**。最坏情况（如主串 `aaa…ab`、模式串 `aa…ab`）下，`i` 前进 `m` 步又后退 `m-1` 步，时间 $O(nm)$。

关键观察（视频用“找 google”的例子说明）：人眼扫描时**目光不回溯**也能找到目标，因为大脑记住了已扫描过的字符。KMP 就是把这个“记忆”交给 `next` 数组。

### 4.2 失配时 j 该退到哪（next 数组的含义）

设当前 `i`、`j` 失配，说明**模式串前 `j-1` 个字符已与主串对应位置匹配**。此时不需要让 `i` 回头，只需在模式串中找一个“最长的、既是已匹配部分的前缀又是其后缀”的位置，让 `j` 退到那里继续比。

- 记 `next[j] = k`：表示 `j` 处失配时，`j` 改为 `k`，即用模式串第 `k` 个字符与主串当前 `i` 继续比较。
- **约定 `next[1] = 0`**：`j=1` 失配时无更短前缀可用，令 `j=0`，下一轮 `i++、j++`，效果是“主串后移一位、模式串从头开始”。

视频给出的例子（模式串 `google`，下标 1~6）：

| j | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 字符 | g | o | o | g | l | e |
| next[j] | 0 | 1 | 1 | 1 | 2 | 1 |

视频中逐位分析得到的结论（注意：这是**未优化版** next，`j=4` 失配退到 1 会多比一次，因为已知 `i` 处不是 `g`；这个“多比一次”的优化留到下一节 nextval）：

- `j=6`（e）失配 → 退到 1；
- `j=5`（l）失配 → 退到 2（因为前缀 `g` 与 `j=4` 处的 `g` 对上，可期待 `i` 处是 `o`）；
- `j=4`（g）失配 → 退到 1（视频指出这一步其实可再优化，但先按此方案）；
- `j=3`（o）失配 → 退到 1；
- `j=2`（o）失配 → 退到 1；
- `j=1`（g）失配 → 退到 0。

### 4.3 KMP 匹配代码（王道风格，下标从 1 开始）

```c
// 在主串 S 中找模式串 T，返回首次出现的位置；失败返回 0
// next 数组下标 1~T.length，next[1] = 0
int Index_KMP(SString S, SString T, int next[]) {
    int i = 1, j = 1;                 // i 扫主串，j 扫模式串
    while (i <= S.length && j <= T.length) {
        if (j == 0 || S.ch[i] == T.ch[j]) {
            i++;                      // 匹配成功 或 j 已退到 0（哨兵）
            j++;                      // 两者同时后移
        } else {
            j = next[j];              // 失配：i 不动，j 回退
        }
    }
    if (j > T.length)
        return i - T.length;          // 匹配成功，返回起始位置
    else
        return 0;                     // 失败
}
```

**与 BF 的两处差别（视频明确强调）**：

1. 失配时执行 `j = next[j]`，而不是 `i = i - j + 2; j = 1;`——**i 不回溯**。
2. `j == 0` 时执行 `i++; j++;`——利用 `next[1]=0` 这个哨兵统一处理“模式串第一位就失配”的情况，使 `i` 后移、`j` 回到 1。

**为什么 `next[1]=0` 这样设计**：若 `j=1` 失配，本应“i 后移一位、j 保持 1”。令 `j=0` 后走 `i++; j++;` 分支，正好得到 `i` 后移、`j=1`，无需额外分支，代码更简洁。

### 4.4 图解（google 例子）

```
主串:  ... g o o g l ? ...
模式串:    g o o g l e
                    ↑ j=6 失配（? ≠ e）
→ j = next[6] = 1，i 不动：
主串:  ... g o o g l ? ...
模式串:            g o o g l e
                    ↑ 用 g 与 ? 继续比
```

即模式串“一次右移 5 步”，而 BF 只右移 1 步。

## 5. 复杂度分析

设主串长 $n$，模式串长 $m$。

- **求 next 数组**：$O(m)$（下一节讲，本节只引用结论）。
- **匹配过程**：$O(n)$。推导：`i` 只增不减，最多增到 $n+1$，故 `i++` 至多执行 $n$ 次；每次 `j = next[j]` 使 `j` 严格减小，而 `j` 的增加只来自 `j++`，`j++` 总次数不超过 `i++` 总次数，故 `j` 回退总次数也是 $O(n)$。合计 $O(n)$。
- **总时间**：$O(n+m)$。
- **最好情况**：首轮即匹配，$O(m)$（比较 $m$ 次）。
- **最坏情况**：$O(n+m)$，不存在 BF 的 $O(nm)$。
- **平均情况**：在“字符等概率随机、字母表大小 $\sigma$”的假设下，匹配阶段平均比较次数约为 $O(n)$（常数因子与 $\sigma$ 有关），总平均 $O(n+m)$；**注意**：KMP 的平均性能并不比 BF 显著好（BF 平均也是 $O(n+m)$ 量级），KMP 的优势体现在**最坏情况**和**主串不能回溯的场景**（如流式输入、外存）。这是 408 常考的理解点。

## 6. 易错点与考试写法

1. **下标从 1 开始**：王道代码 `next[1]=0`，数组 0 号位不用。手算 next 时务必先确认题目下标约定（有的教材从 0 开始，`next[0]=-1`），**答错约定全盘皆错**。
2. **`next[j]` 的含义说反**：是“`j` 失配后 `j` 的新值”，不是“模式串右移的位数”。右移位数 = $j - next[j]$。
3. **`j==0` 分支不能漏**：漏掉会导致死循环或越界；考试写代码必须写出 `if (j == 0 || S.ch[i] == T.ch[j])`。
4. **返回值**：成功返回 `i - T.length`（起始下标），失败返回 0；不要返回 `i`。
5. **本节 next 是未优化版**：`j=4` 失配退到 1 会多比一次，这是正常的，下一节用 nextval 修正。答题时若题目明确要求“优化版”，要用 nextval。
6. **“i 不回溯”要能一句话说清**：这是 KMP 区别于 BF 的本质，简答题常考。

**答题写到什么程度算对**：写出 KMP 代码框架（含 `j=next[j]` 与 `j==0` 分支）+ 说明 `next[j]` 含义 + 指出 i 不回溯 + 复杂度 $O(n+m)$，即可拿满简答/算法题要点分。

## 7. 408 题型与解题套路

- **选择题**：
  - 给模式串求 next 数组（下一节重点，本节可先练 `google` 这类短串）；
  - 给主串、模式串和 next 数组，问匹配过程中 `i`、`j` 的变化次数或比较次数；
  - 问 KMP 相比 BF 的优势（i 不回溯、最坏 $O(n+m)$）。
- **算法题**：直接默写 `Index_KMP`，注意函数签名、下标约定、返回值；若题目给的是“求 next 数组”则属于下一节内容。
- **常见陷阱**：
  - 题目下标从 0 开始却套用 `next[1]=0`；
  - 把“模式串右移位数”与 `next[j]` 混淆；
  - 认为 KMP 平均复杂度优于 BF（实际平均同阶，优势在最坏情况）。

## 9. 背诵卡

1. KMP = BF 的优化：**i 不回溯，j 回退到 next[j]**。
2. `next[j]` 含义：j 处失配后 j 的新值；模式串右移位数 = $j - next[j]$。
3. 约定 `next[1]=0`，代码中用 `j==0` 分支统一处理“首位失配”，执行 `i++; j++;`。
4. 匹配代码三行核心：`if (j==0 || S.ch[i]==T.ch[j]) {i++; j++;} else j = next[j];`
5. 复杂度：求 next $O(m)$ + 匹配 $O(n)$ = $O(n+m)$；平均不优于 BF，优势在最坏情况。
