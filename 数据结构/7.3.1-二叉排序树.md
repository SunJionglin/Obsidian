# 7.3.1 二叉排序树（BST）

## 1. 本节定位

- **王道书对应**：第 7 章「查找」→ 7.3 树型查找 → 7.3.1 二叉排序树（BST，Binary Sort Tree，又称二叉查找树 Binary Search Tree）。
- **408 大纲对应**：查找 → 二叉排序树（定义、查找、插入、删除、查找效率分析）。
- **先修知识**：二叉树定义与存储结构、二叉树遍历（尤其**中序遍历**）、递归算法与函数调用栈、树的高度概念。
- **本章位置**：树型查找的第一节。后续 7.3.2 平衡二叉树（AVL）是在本节「树高决定效率」的痛点上做平衡化改进；再往后是 B 树/B+ 树、散列表。本节是整章「动态查找表」的起点。

## 2. 一句话结论

**二叉排序树用「左 < 根 < 右」的递归有序性把查找变成一条从根到叶的路径，查找/插入/删除的时间复杂度都取决于树高 $h$：最好 $O(\log_2 n)$，最坏 $O(n)$。**

## 3. 知识地图

```
二叉排序树 BST
├── 定义与性质
│   ├── 左子树所有结点值 < 根 < 右子树所有结点值（递归成立）
│   ├── 中序遍历 ⇒ 递增有序序列
│   └── 结点值互不相同（不允许重复）
├── 查找
│   ├── 非递归（while 循环，空间 O(1)）
│   └── 递归（空间 O(h)）
├── 插入
│   ├── 先查找插入位置，新结点必为叶子
│   ├── 参数须为引用（要改父结点孩子指针）
│   └── 已存在同值 ⇒ 插入失败
├── 构造
│   └── 从空树起依次插入；插入顺序不同 ⇒ 树形不同
├── 删除（三种情况）
│   ├── 叶子：直接删
│   ├── 只有左/右子树：子树顶替
│   └── 左右都有：直接后继（右子树最左下）或直接前驱（左子树最右下）顶替，再转为前两种情况
└── 查找效率
    ├── 查找长度 = 比较关键字次数
    ├── ASL 成功 / ASL 失败
    └── 时间复杂度 = O(h)，h ∈ [⌈log₂(n+1)⌉, n]
```

## 4. 核心内容

### 4.1 定义与性质

二叉排序树（BST）满足：对任一结点，

- 左子树上所有结点的值 **小于** 根结点的值；
- 右子树上所有结点的值 **大于** 根结点的值；
- 左、右子树本身也分别是二叉排序树（递归定义）。

**关键性质（408 必考）**：对 BST 做**中序遍历**（左→根→右），得到的序列**严格递增有序**。原因：中序访问顺序恰好与「左 < 根 < 右」的大小关系一致。

> 注意：是「左子树**所有**结点」小于根，不是「左孩子」小于根。判断一棵树是否为 BST 必须检查整棵子树的值域，不能只看父子关系。

### 4.2 查找

**非递归版（推荐，空间 $O(1)$）**：

```c
// BST 结点定义（王道风格）
typedef struct BSTNode {
    int key;                        // 关键字，实际可为 ElemType
    struct BSTNode *lchild, *rchild;
} BSTNode, *BSTree;

// 查找关键字 key，找到返回结点指针，失败返回 NULL
BSTNode *BST_Search(BSTree T, int key) {
    while (T != NULL && key != T->key) {   // 当前结点非空且未命中
        if (key < T->key)
            T = T->lchild;                 // 小于 ⇒ 去左子树
        else
            T = T->rchild;                 // 大于 ⇒ 去右子树
    }
    return T;                              // 命中返回结点；T 为 NULL 表示失败
}
```

**递归版（空间 $O(h)$）**：

```c
BSTNode *BST_Search_R(BSTree T, int key) {
    if (T == NULL) return NULL;            // 空树 ⇒ 查找失败
    if (key == T->key) return T;           // 命中
    if (key < T->key)
        return BST_Search_R(T->lchild, key);  // 递归查左子树
    else
        return BST_Search_R(T->rchild, key);  // 递归查右子树
}
```

**查找路径**：从根出发，每比较一次下降一层，命中或走到 `NULL` 为止。**比较次数 = 路径上结点数**，不超过树高 $h$。

### 4.3 插入

思路：先按查找逻辑走到空指针处，在那里挂上新结点。**新结点一定是叶子**。

```c
// 注意：T 是引用（C++ 引用 / C 中用二级指针），因为要修改父结点的孩子指针
int BST_Insert(BSTree &T, int key) {
    if (T == NULL) {                       // 找到空位，插入
        T = (BSTNode *)malloc(sizeof(BSTNode));
        T->key = key;
        T->lchild = T->rchild = NULL;      // 新结点必为叶子
        return 1;                          // 插入成功
    }
    else if (key == T->key)
        return 0;                          // 已存在同值，插入失败（不允许重复）
    else if (key < T->key)
        return BST_Insert(T->lchild, key); // 插入左子树
    else
        return BST_Insert(T->rchild, key); // 插入右子树
}
```

**三个必须记住的点**：

1. 参数 `T` **必须是引用类型**（C 语言写 `BSTree *T` 用二级指针），否则新结点挂不到父结点上。
2. 关键字已存在 ⇒ **插入失败**，BST 中不允许重复关键字。
3. 递归实现空间 $O(h)$；非递归实现空间 $O(1)$（王道要求自己会写）。

### 4.4 构造

从空树开始，按给定序列**依次调用插入**：

```c
void Create_BST(BSTree &T, int str[], int n) {
    T = NULL;                              // 初始为空树
    for (int i = 0; i < n; i++)
        BST_Insert(T, str[i]);             // 逐个插入
}
```

**重要结论（408 常考）**：同一组关键字，**插入顺序不同，得到的 BST 形状可能不同**。例如序列 `{50,66,60,26,21,30,70,68}` 与 `{26,21,30,50,60,66,68,70}` 构造出的树形不一样，但中序序列都是同一个递增序列。

### 4.5 删除（本节最易考细节）

先查找定位，再分三种情况：

| 情况 | 处理方式 |
|---|---|
| ① 被删结点是**叶子** | 直接删除，父结点对应指针置 `NULL` |
| ② 只有**左子树**或只有**右子树** | 用其唯一的子树**顶替**它的位置（子树上移） |
| ③ **左右子树都有** | 用**直接后继**（右子树中最左下结点，即右子树最小值）或**直接前驱**（左子树中最右下结点，即左子树最大值）的**值**替换被删结点，然后转而删除那个后继/前驱结点 |

**为什么情况 ③ 能化简**：直接后继是右子树最左下结点，它**必无左子树**，删除它落入情况 ②；直接前驱是左子树最右下结点，它**必无右子树**，同样落入情况 ②。

**两种方案都合法**：用直接后继或直接前驱替换，得到的树都仍是 BST，但形状不同。408 选择题若给出唯一答案，通常按题目指定（或按「直接后继」默认）处理。

## 5. 复杂度分析

设树高为 $h$，结点数为 $n$。

**查找 / 插入 / 删除的时间复杂度**：三者核心都是「沿一条根到叶的路径下降」，每层做一次关键字比较，故均为 $O(h)$。

**树高的范围**：

- **最好情况**：树尽量「矮胖」，即完全二叉树形态，$h = \lceil \log_2(n+1) \rceil$，此时 $O(\log_2 n)$。
- **最坏情况**：每个结点只有一个孩子，退化成单链表，$h = n$，此时 $O(n)$。
- **平均情况**：在关键字随机插入的假设下，BST 的平均查找长度为 $O(\log_2 n)$（与最好情况同阶）。

**平均查找长度 ASL 的推导（以查找成功为例）**：

设树中 $n$ 个结点，查找每个结点的概率相等，均为 $1/n$。第 $i$ 层有 $n_i$ 个结点，查找该层任一结点需比较 $i$ 次（根为第 1 层）。则

$$
\text{ASL}_{\text{成功}} = \sum_{i=1}^{h} i \cdot \frac{n_i}{n} = \frac{1}{n}\sum_{i=1}^{h} i \cdot n_i
$$

即「各结点所在层数之和 ÷ 结点总数」。例如一棵 8 结点的树，第 1 层 1 个、第 2 层 2 个、第 3 层 4 个、第 4 层 1 个，则

$$
\text{ASL}_{\text{成功}} = \frac{1\times1 + 2\times2 + 3\times4 + 4\times1}{8} = \frac{21}{8} = 2.625
$$

**ASL 失败**：把树中所有空指针（外部结点）补出来，共 $n+1$ 个失败位置，等概率 $1/(n+1)$。查找失败时比较次数 = 到达该空指针所经过的**内部结点数**（即空指针父结点的层数）。故

$$
\text{ASL}_{\text{失败}} = \frac{1}{n+1}\sum_{\text{每个空指针}} (\text{其父结点层数})
$$

**结论**：ASL 的数量级就是查找的时间复杂度，因此 BST 的效率**完全由树高决定**——这正是下一节引入平衡二叉树（AVL）的动机。

## 6. 易错点与考试写法

1. **「左子树所有结点 < 根」不是「左孩子 < 根」**。判断 BST 要传值域上下界递归检查，不能只比较父子。
2. **插入参数必须传引用/二级指针**。写成 `BST_Insert(BSTree T, ...)` 值传递，新结点挂不上，是经典扣分点。
3. **插入的新结点一定是叶子**，且关键字重复时插入失败。
4. **删除情况 ③ 是「值替换 + 转删后继/前驱」**，不是把整棵子树搬上来；替换后要**继续删除**那个后继/前驱结点，不能只改值不删结点。
5. **直接后继 = 右子树最左下**（不是最右下），**直接前驱 = 左子树最右下**（不是最左下），方向极易记反。
6. **ASL 失败的分母是 $n+1$**（空指针个数），不是 $n$；ASL 成功的分母才是 $n$。
7. **答题标准**：定义要写出「递归」二字；删除三种情况要分条列全；ASL 要写出「层数 × 该层结点数之和 ÷ 结点数」的式子再代数字，只写结果不给分。

## 7. 408 题型与解题套路

- **选择题（高频）**：
  - 给关键字序列，问「按此顺序构造的 BST 形状 / 中序序列 / 某结点所在层数」——**逐个数插入，画图**。
  - 给一棵树，判断「是否为 BST」——用值域上下界递归验证。
  - 给 BST 和待删结点，问删除后的树形或中序序列——按三种情况处理，注意后继/前驱方向。
  - 计算 ASL 成功/失败——补空指针，按层数加权。
  - 问「查找某关键字需比较几次」——数路径上结点数。
- **算法题套路**：BST 相关算法几乎都可用「递归 + 利用有序性剪枝」：判断 BST、求第 $k$ 小（中序计数）、查找范围 $[L,R]$ 内结点、插入/删除。**核心是利用「左小右大」决定往哪边走，避免遍历全树**。
- **常见陷阱**：
  - 把「中序有序」误记为「前序/后序有序」；
  - 删除时忘记处理「替换后继续删除」；
  - ASL 失败分母写成 $n$；
  - 认为「插入顺序不影响树形」（实际影响）。

## 8. 自测题

**1.** 对二叉排序树进行哪种遍历可得到递增有序序列？为什么？

**2.** 关键字序列 `{45, 24, 53, 12, 37, 93}` 依次插入构造 BST，画出该树，并求查找成功时的 ASL。

**3.** 在题 2 的 BST 中删除结点 24，写出删除后的树（用直接后继替换）。

**4.** 一棵有 $n$ 个结点的 BST，其查找失败时 ASL 的分母是多少？为什么？

**5.** 判断：BST 中任一结点的左孩子一定小于该结点，右孩子一定大于该结点，因此只要每个结点满足此关系就是 BST。

<summary>答案</summary>

**1.** 中序遍历。因为中序顺序为「左→根→右」，与 BST「左子树值 < 根 < 右子树值」的大小关系一致，故输出严格递增。

**2.** 插入过程：45 为根；24 < 45 作左孩子；53 > 45 作右孩子；12 < 45、< 24 作 24 左孩子；37 < 45、> 24 作 24 右孩子；93 > 45、> 53 作 53 右孩子。
树形：根 45，左 24（左 12，右 37），右 53（右 93）。
层数：45 第 1 层；24、53 第 2 层；12、37、93 第 3 层。
$$\text{ASL}_{\text{成功}} = \frac{1\times1 + 2\times2 + 3\times3}{6} = \frac{14}{6} \approx 2.33$$

**3.** 24 的右子树为 37，右子树最左下结点是 37（37 无左孩子），用 37 替换 24，再删除原 37（叶子，直接删）。删除后：根 45，左孩子 37（左 12），右 53（右 93）。

**4.** 分母是 $n+1$。因为 $n$ 个结点的 BST 共有 $n+1$ 个空指针（外部结点），查找失败必终止于某个空指针，等概率假设下每个失败位置概率为 $1/(n+1)$。

**5.** 错。只比较父子关系不够，必须保证「左子树**所有**结点 < 根 < 右子树**所有**结点」。反例：根 10，左孩子 5，5 的右孩子 12——父子关系 5<10、12>5 都成立，但 12 在根的左子树中却大于根，不是 BST。

## 9. 背诵卡

1. **BST 定义**：左子树所有结点 < 根 < 右子树所有结点，递归成立；中序遍历 ⇒ 递增序列。
2. **查找**：从根比较，小往左、大往右，比较次数 = 路径结点数 ≤ 树高 $h$；非递归空间 $O(1)$，递归 $O(h)$。
3. **插入**：先查找定位到空指针，新结点必为叶子；参数须引用；重复关键字插入失败。
4. **删除三情况**：叶子直接删；单子树顶替；双子树用直接后继（右子树最左下）或直接前驱（左子树最右下）替换后转删之。
5. **效率**：查找/插入/删除均 $O(h)$；$h$ 最好 $\lceil\log_2(n+1)\rceil$、最坏 $n$；$\text{ASL}_{\text{成功}}$ 分母 $n$，$\text{ASL}_{\text{失败}}$ 分母 $n+1$。

## 10. 关联与下一节

- **向前关联**：二叉树遍历（中序有序性）、递归与调用栈（空间复杂度来源）、树高与完全二叉树性质（$h$ 的下界）。
- **向后关联**：本节结论「效率取决于树高」直接引出 **7.3.2 平衡二叉树（AVL）**——通过旋转让任意结点左右子树高度差 ≤ 1，把树高稳定在 $O(\log_2 n)$，从而把查找稳定在 $O(\log_2 n)$。再往后是 B 树/B+ 树（多路平衡，面向外存）与散列表（另一条 $O(1)$ 查找路线）。
- **下一节学什么**：AVL 树的定义（平衡因子）、四种旋转（LL/RR/LR/RL）、插入后调整、AVL 树高与最少结点数递推。
