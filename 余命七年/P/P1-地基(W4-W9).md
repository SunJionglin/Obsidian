## 六 · 验收动作（每章一个，可演示）

- 依赖与环境：空目录 → `uv init` → 锁定依赖 → 别人 clone 后 `uv run` 能跑
- 类型与风格：给一个函数补全类型注解，mypy 零报错
- 日志与调试：一条错误日志带级别、上下文、异常链；断点定位一次真实 bug
- 测试：pytest 三条用例全绿，含一条「故意喂脏数据」的异常断言
- 类进阶：`Todo` 类可打印、可比较、可哈希；dataclass 替代手写样板
- Git 基础：`git log --oneline --graph` 能看懂自己的历史
- Git 分支：建功能分支 → 提交 → 合并 → **故意制造一次冲突并解决**
- Git 回滚：用 `reset --hard` 删错一次，再用 `reflog` 救回来（演练）
- Git 远程：fork → PR 全流程走一遍；`.gitignore` 挡住 `.venv/__pycache__`
- 树与堆：三遍历 + 层序白板 5 分钟；对顶堆讲 1 分钟
- 滑窗/单调结构：单调栈、单调队列各讲 1 分钟「为什么 O(n)」
- 项目 A：README 三步跑通；≥5 个函数；错误输入不崩
- 简历 v0：一页，打印可看
- 408：树/图/查找/排序四张手画图不看书画；章节题 ≥75%
- 蓝桥：背包三种默写；24 题 AC ≥18

## 8 · 坑

1. 树题不会就抄题解——先画图，再写递归三问（终止/单层/返回）。
2. API 报错就换库——先读懂错误码，再决定重试还是换方案。
3. 只做 demo 不做 README——别人跑不起来等于没做。
4. 蓝桥 DP 直接上正解——先暴力档再优化，按测试点给分。
5. Git 冲突就 `--hard` 掀桌——先 `git status` 看局面，`merge --abort` 比 `--hard` 安全。
6. 408 只读不画——不手画图等于没学。
