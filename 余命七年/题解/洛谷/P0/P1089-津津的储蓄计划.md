# P1089 津津的储蓄计划

## 一句话题意

读入 12 个月预算模拟存钱，钱不够花输出 `-X`，否则输出年末总钱数。

## 解题逻辑

**先想什么**：每个月月初固定到账 300，花多少、存多少全按规则一步步推，没有任何「选哪个月存」的自由——这就是一道**按题意顺序模拟**的题，读完直接动手写循环，不用想贪心也不用想动规。

**朴素解法**：手上钱 `cur`、存款 `saved` 两个变量跑 12 轮：月初 `cur += 300`，不够预算就输出 `-i` 退出；够了就 `cur -= budget`，再用 while 循环把整百存走。复杂度 O(12×k)，k 是每月存钱次数（手里最多 300 出头，k ≤ 3）。12 个月是题目定死的规模，这个写法**不会超时**——它的问题不在快慢，而在 while 那段啰嗦、容易写漏 `cur -= 100` 死循环。

**优化观察**：关键观察是「存整百」就是在求 `cur` 里 100 的倍数——存走 `cur / 100 * 100`，手里留 `cur % 100`。靠**整除和取模一次算完**，把每月的 while 循环压成两行算式（k 次运算 → 1 次），代码更短，也杜绝了死循环这个坑。复杂度本来就没得降，这里优化的是写法和出错率。

## 为什么选这个方法

| 方案 | 时间 | 空间 | 缺点 |
| --- | --- | --- | --- |
| 逐月 while 循环存整百 | O(12×k) | O(1) | 存钱要多写个 while，漏减就死循环 |
| 整除取模一步存 | O(12) | O(1) | 无，两行算式搞定 |
| 全读进数组再模拟 | O(12) | O(12) | 多开一个数组，边读边算根本用不上 |

**选整除取模版**：12 个月规模固定，三种写法都秒出，唯独整除取模版代码最短、最不容易写错，是「能一行就不写循环」的入门典型。

## 关键点

1. 模板句：月初 `cur += 300` → **先判 `cur < budget` 后花** → 存走 `cur / 100 * 100`、留 `cur % 100` → 年末输出 `cur + saved + saved / 5`。
2. 不变量：月末 `cur` 恒小于 100（存完只留零头）；`saved` 恒是 100 的倍数，所以 `saved / 5` 一定是整数，不用管浮点。
3. 边界约定：预算是非负整数且 < 350；失败输出的是**第一个**不够花的月份 `-i`，输出完立刻结束，后面月份不再管。

## 实现逻辑

先读当月预算 → 月初加 300 → 判够不够（不够输出 `-i` 直接退出）→ 花掉预算 → 存整百留零头 → 最后年末输出零头 + 本金 + 利息。

拿样例 2（`290 230 280 200 300 170 330 50 90 80 200 60`）手推：

| 月份 i | 月初 cur+300 | 预算 | 够吗 | 存走 | 月末 cur | saved |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 300 | 290 | 够 | 0 | 10 | 0 |
| 2 | 310 | 230 | 够 | 0 | 80 | 0 |
| 3 | 380 | 280 | 够 | 100 | 0 | 100 |
| 4 | 300 | 200 | 够 | 100 | 0 | 200 |
| 5 | 300 | 300 | 够 | 0 | 0 | 200 |
| 6 | 300 | 170 | 够 | 100 | 30 | 300 |
| 7 | 330 | 330 | 够 | 0 | 0 | 300 |
| 8 | 300 | 50 | 够 | 200 | 50 | 500 |
| 9 | 350 | 90 | 够 | 200 | 60 | 700 |
| 10 | 360 | 80 | 够 | 200 | 80 | 900 |
| 11 | 380 | 200 | 够 | 100 | 80 | 1000 |
| 12 | 380 | 60 | 够 | 300 | 20 | 1300 |

年末：手里零头 20 + 本金 1300 + 利息 260 = **1580**。C++ 里 `cur / 100` 是整除，Python 里写成 `cur // 100`。

## 代码

> [!warning]- 先自己写再展开 · C++
> ```cpp
> #include <iostream>
> using namespace std;
>
> int main() {
>     int cur = 0;   // 手里余钱，月末恒小于 100
>     int saved = 0; // 妈妈那里存的整百总和
>     for (int i = 1; i <= 12; ++i) {
>         int budget;
>         cin >> budget;
>         cur += 300;                     // 月初妈妈给 300
>         if (cur < budget) {             // 不够花：失败
>             cout << -i << endl;
>             return 0;                   // 输出后立刻结束
>         }
>         cur -= budget;                  // 花掉预算
>         saved += cur / 100 * 100;       // 整百存妈妈
>         cur %= 100;                     // 手里只留零头
>     }
>     cout << cur + saved + saved / 5 << endl; // 零头 + 本金 + 20% 利息
>     return 0;
> }
> ```

> [!warning]- 先自己写再展开 · Python
> ```python
> import sys
>
> def main():
>     cur = 0    # 手里余钱，月末恒小于 100
>     saved = 0  # 妈妈那里存的整百总和
>     nums = sys.stdin.read().split()  # 12 个预算，无视换行
>     for i in range(1, 13):
>         budget = int(nums[i - 1])
>         cur += 300                  # 月初妈妈给 300
>         if cur < budget:            # 不够花：失败
>             print(-i)
>             return                  # 输出后立刻结束
>         cur -= budget               # 花掉预算
>         saved += cur // 100 * 100   # 整百存妈妈
>         cur %= 100                  # 手里只留零头
>     print(cur + saved + saved // 5) # 零头 + 本金 + 20% 利息
>
> if __name__ == "__main__":
>     main()
> ```

## 复杂度

- 时间：O(12)，12 个月各做常数步，规模固定可看作 O(1)，再快的写法也没有意义。
- 空间：O(1)，只开 `cur`、`saved` 两个变量，外加一个循环变量。

## 易错点

1. 顺序错——先存后花：若月初先存整百再扣预算，样例 2 第 3 个月手里 380 会先存走 300 只剩 80，不够 280 的预算，误报 `-3`（正确是一路存到年末得 1580）。规则是「花完再存」，花完预算后剩多少整百存多少。
2. 失败不退出：样例 1 第 7 个月输出 `-7` 后若还继续往后算，最后会把 `-7` 盖成 1530。输出 `-i` 后要立刻 `return 0` / `return`。
3. 年末漏加手里零头：样例 2 只算 `saved + saved / 5` 会得 1560，漏了手里那 20 元；正确答案是 `cur + saved + saved / 5`，零头也是钱。
4. while 存钱漏减 cur：写成 `while (cur >= 100) saved += 100;` 忘了 `cur -= 100`，循环条件永远成立 → 死循环，样例 2 第 8 个月手里 250 就卡住。
5. 输入用 getline 手动拆：C++ 里 `cin >> x` 自动跳过空白，连续读 12 次就完事；用 `getline` 读整行还得再转数字，纯属自找麻烦。
