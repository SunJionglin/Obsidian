# P1046 陶陶摘苹果

## 一句话题意

读入 10 个苹果高度与伸手高度，输出 ≤ 伸手+30 的苹果个数。

## 解题逻辑

**先想什么**：每个苹果能不能摘，只看一件事——它的高度是否 ≤「伸手高度 + 30」。10 个苹果彼此独立，跟顺序无关，所以直接想「怎么数」而不是「怎么排」。

**朴素解法**：读入 10 个高度存数组，读入伸手高度，循环 10 次逐个和 limit = reach+30 比较，≤ 就 cnt+1。时间 O(n)（n=10）、空间 O(1)。为什么不够好：这个问号其实不存在——n 被题面锁死在 10，一遍扫描已经是理论下限；真要挑毛病，是「有人会先排序再二分」，那才是变慢。

**优化观察**：关键观察是把 `a[i] <= reach + 30` 里的 `reach + 30` 提出来只算一次，每次比较就变成「数组元素 vs 常数」；再配合「只要个数、不要下标、判断与顺序无关」这三点，排除排序和二分。所以这题靠的不是降复杂度，而是「固定规模 n=10 + 判断相互独立」，让 O(n) 一遍扫描直接就是标准解。

## 为什么选这个方法

| 方案 | 时间 | 空间 | 缺点 |
| --- | --- | --- | --- |
| 直接遍历计数（选它） | O(n)，n=10 | O(1) | 无，已是这题的天花板 |
| 排序 + 二分 | O(n log n) | O(1) | 排序本身比直接数还慢；只要个数不要位置，白绕一圈 |
| count_if 一行版 | O(n) | O(1) | 更短但引入 algorithm 和 lambda，入门题反而更难读 |

**选直接遍历**：判断标准是一个常数比较，一遍数完即最优；排序二分属于「为了优化而优化」，多写的代码换不来任何收益。

## 关键点

1. 模板句：`int limit = reach + 30;` 只算一次，循环里 `if (a[i] <= limit) ++cnt;`
2. 不变量：第 i 轮循环结束时，cnt 恰好是前 i+1 个苹果里够得到的个数。
3. 边界约定：条件是 `<=` 不是 `<`——苹果高度恰好等于 limit 时，陶陶踮起手刚好碰到，也算摘得到。
4. 数据约定：高度 100~200、伸手 100~120，limit 最大 150，int 绰绰有余，不用 long long。

## 实现逻辑

先读入 10 个苹果高度存进数组 → 再读入伸手高度，算 limit = reach + 30 → 然后循环 10 次，每个苹果和 limit 比，够得到 cnt+1 → 最后输出 cnt。

拿官方样例 `100 200 150 140 129 134 167 198 200 111`、伸手 `110`（limit=140）手推：

| i | a[i] | 查什么 | 结果 | cnt |
| --- | --- | --- | --- | --- |
| 0 | 100 | 100 ≤ 140？ | 是 → cnt+1 | 1 |
| 1 | 200 | 200 ≤ 140？ | 否 | 1 |
| 2 | 150 | 150 ≤ 140？ | 否 | 1 |
| 3 | 140 | 140 ≤ 140？ | 是（恰好相等也算）→ cnt+1 | 2 |
| 4 | 129 | 129 ≤ 140？ | 是 → cnt+1 | 3 |
| 5 | 134 | ≤ 140？ | 是 → cnt+1 | 4 |
| 6 | 167 | ≤ 140？ | 否 | 4 |
| 7 | 198 | ≤ 140？ | 否 | 4 |
| 8 | 200 | ≤ 140？ | 否 | 4 |
| 9 | 111 | ≤ 140？ | 是 → cnt+1 | 5 |
| 结束 | — | — | 输出 | stdout: 5 |

C++ 里数组下标 0~9 对应第 1~10 个苹果；Python 里 heights 是 list，`for h in heights` 直接遍历，不用管下标。

## 代码

> [!warning]- 先自己写再展开 · C++
> ```cpp
> #include <cstdio>            // scanf / printf
> 
> int main() {
>     int a[10];               // 10 个苹果离地高度
>     for (int i = 0; i < 10; ++i)
>         scanf("%d", &a[i]);  // 第一行：10 个整数
> 
>     int reach;
>     scanf("%d", &reach);     // 第二行：伸手最大高度
> 
>     int limit = reach + 30;  // 踩板凳后的极限高度，只算一次
>     int cnt = 0;             // 能摘到的苹果个数
> 
>     for (int i = 0; i < 10; ++i)
>         if (a[i] <= limit)   // 够得着（含恰好一样高）
>             ++cnt;
> 
>     printf("%d\n", cnt);     // 输出个数
>     return 0;
> }
> ```

> [!warning]- 先自己写再展开 · Python
> ```python
> import sys
> 
> def main():
>     heights = list(map(int, sys.stdin.readline().split()))  # 第一行 10 个高度
>     reach = int(sys.stdin.readline())                       # 第二行伸手高度
> 
>     limit = reach + 30       # 踩板凳后的极限高度，只算一次
>     cnt = 0
>     for h in heights:
>         if h <= limit:       # 够得着（含恰好一样高）
>             cnt += 1
>     print(cnt)               # 输出个数
> 
> if __name__ == "__main__":
>     main()
> ```

## 复杂度

- 时间：O(n)，n=10 固定，每个苹果只比一次，10 次比较毫秒级。
- 空间：O(1)，一个固定 10 格的数组加两个变量，规模与输入无关。

## 易错点

1. 忘了加板凳 30：样例 `100 200 150 140 129 134 167 198 200 111` + `110` 正确答案 5；若直接和 110 比，只剩 100 一个，输出 1。
2. 用 `<` 不用 `<=`：样例 `140 150 160 170 180 190 200 200 200 200` + `110`（limit=140）正确答案 1；写成 `<` 恰好把 140 漏掉，输出 0。
3. 循环写成 `i <= 10`：a 只有下标 0~9，a[10] 越界读到脏值，cnt 可能凭空多 1——官方样例可能输出 6。
4. 两行读反：把第二行的伸手高度也读进苹果数组（或先读伸手再读 10 个数），`... 111` + `110` 会把 110 当第 11 个苹果，答案全乱。
5. Python 忘 `int()`：`input().split()` 出来是字符串，`'140' <= limit` 是 str 和 int 比，直接 TypeError——任何输入都崩。
