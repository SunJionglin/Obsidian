# 20. 评等级（P5742）

## 一句话题意

读 N 名学生的学号与两科成绩，总分 >140 且综合分 ≥80 的输出 `Excellent`，否则 `Not excellent`。

## 解题逻辑

**先想什么**：读完题第一反应是「每人算个综合分 0.7a+0.3b，再和总分条件一起判」，这题没有复杂算法，难点全在「怎么算综合分」和「两个条件的边界符号」。

**朴素解法**：每个学生读入学业 a、素质 b，直接写 `a * 0.7 + b * 0.3 >= 80.0 && a + b > 140`。O(N) 时间、O(1) 空间，复杂度上完全达标。不够好——0.7 和 0.3 在二进制下都是无限循环小数，浮点结果带误差，当数学上恰好等于 80 时，机器可能算出 79.99999999999999（洛谷提示点名了这个坑），边界学生被误判。

**优化观察**：关键观察是——**输入全是整数，不等式两边同乘 10 就能全程整数运算**：`0.7a+0.3b >= 80` ⟺ `7a+3b >= 800`。这题优化不动复杂度，是把「浮点可能错」换成「整数一定对」，代码还短一截。

## 为什么选这个方法

| 方案 | 时间 | 空间 | 缺点 |
| --- | --- | --- | --- |
| 直接浮点 `0.7*a + 0.3*b >= 80.0` | O(N) | O(1) | 边界恰等于 80 时精度翻车 |
| 浮点 + 容差 eps（差值 <1e-9 算达标） | O(N) | O(1) | eps 取多大全凭感觉，治标不治本 |
| 整数判定 `7*a + 3*b >= 800` | O(N) | O(1) | 无明显缺点 |

**选整数判定**：成绩乘 7、乘 3 后最大 1000，int 全程无溢出；不引入浮点、不调 eps，一行整数比较同时消掉误差和纠结。

## 关键点

1. 模板句：`if (a + b > 140 && 7 * a + 3 * b >= 800)`，全整数、无浮点。
2. 不变量：a、b 为整数时，`0.7a+0.3b >= 80` ⟺ `7a+3b >= 800`（两边同乘 10）。
3. 边界约定：总分条件是**严格大于** 140，综合分条件是**不小于** 800（即 80），两个比较符不对称，别顺手写成一样。
4. 学号读进来只占位、不参与判断，但必须读掉——少读一个整数，后面全部错位。

## 实现逻辑

三个动作循环做：**读一行 → 算两个整数判据 → 按位与输出**；不用存任何人，逐行即算即输出。

拿样例手推（3 人：(1,80,80)、(2,90,50)、(3,96,45)）：

| i | 当前值 (学号,a,b) | 查什么 | 结果 | 数据结构状态 |
| --- | --- | --- | --- | --- |
| 1 | (1, 80, 80) | 160 > 140 且 800 ≥ 800 | 都满足 | 无，逐行即算即输出 |
| 2 | (2, 90, 50) | 140 > 140？780 ≥ 800？ | 都不满足 | 无 |
| 3 | (3, 96, 45) | 141 > 140 且 807 ≥ 800 | 都满足 | 无 |

第 2 行正好卡在两个边界上：总分 140 是「不大于」，综合分 780 是「不到 800」，两个都不达标。

## 代码

> [!warning]- 先自己写再展开 · C++
> ```cpp
> #include <iostream>
> using namespace std;
> 
> struct Student {
>     int id, a, b;                        // 学号、学业成绩、素质拓展成绩
> 
>     int total() const { return a + b; }  // 成员函数：两科总分
>     bool excellent() const {             // 成员函数：是否优秀（全整数判断）
>         return total() > 140 && 7 * a + 3 * b >= 800;
>     }
> };
> 
> int main() {
>     ios::sync_with_stdio(false);
>     cin.tie(nullptr);                    // 提速；不要与 scanf 混用
> 
>     int n;
>     cin >> n;
>     while (n--) {
>         Student s;
>         cin >> s.id >> s.a >> s.b;       // 学号只占位，不参与判断
>         cout << (s.excellent() ? "Excellent" : "Not excellent") << '\n';
>     }
>     return 0;
> }
> ```

> [!warning]- 先自己写再展开 · Python
> ```python
> import sys
> 
> def main():
>     n = int(sys.stdin.readline())
>     for _ in range(n):
>         id_, a, b = map(int, sys.stdin.readline().split())  # 学号只占位
>         if a + b > 140 and 7 * a + 3 * b >= 800:  # 全整数判断，无浮点误差
>             print("Excellent")
>         else:
>             print("Not excellent")
> 
> if __name__ == "__main__":
>     main()
> ```

## 复杂度

- 时间：O(N)，每个学生常数次运算（两个整数判定），共 N 个。
- 空间：O(1)，逐行读、逐行输出，只留几个变量，不存任何学生。

## 易错点

1. 总分写成 `>=`：题目是「总分**大于** 140」。样例 `1 90 50` 总分正好 140，应输出 Not excellent，写成 `>=` 会多判一个 Excellent。
2. 直接浮点比较：`0.7*a + 0.3*b >= 80.0`。样例 `1 92 52` 数学上综合分恰为 80（644+156=800），双精度算出来是 79.99999999999999，把 Excellent 判成 Not excellent。
3. 同乘 10 只乘了左边：`7*a + 3*b >= 80`。样例 `1 10 10` 综合分只有 10，却因 100 ≥ 80 被误判 Excellent——右边的 80 也要乘 10 变 800。
4. 漏读学号：`cin >> s.a >> s.b` 少读一个整数。样例 `2` 后面是 `1 80 80 / 2 60 60`，第二个学生的 2 会被读成第一个学生的 b，后面全错位。
5. 拼写与大小写：`Excellent` 和 `Not excellent` 两个单词。样例 `1 80 80` 正确输出是 `Excellent`，写成 `excellent` 或 `Not Excellent` 都判错。
