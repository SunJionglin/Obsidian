# P1035 级数求和

## 一句话题意

输入整数 K，输出最小的 n 使 1+1/2+…+1/n > K。

## 解题逻辑

**先想什么**：Sₙ = 1+1/2+…+1/n 随 n 严格单调递增，题目要「第一个让 Sₙ > K 的 n」，所以顺序枚举即可，第一次超过就停；唯一要先确认的是 K 的范围（1≤K≤15，整数），它决定循环最多跑多远。

**朴素解法**：n 从 1 开始，每轮 sum += 1.0/n，sum 一旦大于 K 就输出 n。时间 O(n)、空间 O(1)。为什么不够好：单看写法没有任何浪费——真正的问号是「n 最大能到哪」。K=15 时答案是 1835421，最多约 180 万次浮点加法，C++ 毫秒级；只有 K 无限放大时调和级数的 n 才会大到朴素必挂，但题目把 K 锁死在 15，这个风险不存在。

**优化观察**：两个观察合起来等于「不用优化」。一是单调性——Sₙ 递增，第一次超过 K 的 n 就是答案，不需要二分、不需要查找；二是调和级数增长极慢（Hₙ ≈ ln n + γ），由 K≤15 可推出 n≤1835421，180 万次循环远在时限内。所以靠的不是降复杂度，而是「输入约束小 + 单调性」直接让 O(n) 模拟成为标准解。

## 为什么选这个方法

| 方案 | 时间 | 空间 | 缺点 |
| --- | --- | --- | --- |
| 顺序累加模拟（选它） | O(n)≈183 万次 | O(1) | K 更大时会慢，但题目 K≤15 不存在这个问题 |
| 近似公式 Hₙ ≈ ln n + γ 反解 | O(1) | O(1) | 只是近似，反解出的 n 还要局部校正，多绕一圈还不精确 |
| 二分 + 前缀和 | O(n) 建表 + O(log n) 查 | O(n) | 建前缀和本来就要算到 180 万，二分省不了时间还白占十几 MB |

**选顺序累加**：这题的答案就是循环计数本身，模拟一遍正好把 n 数出来；近似公式和二分都是「为了优化而优化」，多写代码却没有任何收益。

## 关键点

1. 模板句：`while (sum <= k) { ++n; sum += 1.0 / n; }`——循环退出的那一刻，n 就是答案。
2. 不变量：每次进入循环体前 sum = Hₙ（前 n 项调和级数和），n 自增后加上第 n 项。
3. 边界约定：条件是 `sum <= k` 不是 `sum < k`——题目要**严格大于**，sum 恰好等于 K 时还要继续加下一项。
4. 精度约定：sum 必须用 double；float 在 K=15 时实测输出 1673860（正确答案 1835421），直接 WA。

## 实现逻辑

先读入整数 K → 再把 sum 和 n 初始化成 0 → 然后循环自增 n 并累加 1.0/n，直到 sum 严格大于 K → 最后输出 n。

拿 K=1 手推一遍：

| 轮次 | 循环变量 n | 当前值 sum | 查什么 | 结果 | 状态 |
| --- | --- | --- | --- | --- | --- |
| 初始 | 0 | 0.0 | — | — | n=0, sum=0.0 |
| 1 | 1 | 0.0+1/1=1.0 | sum>1? | 1.0>1 不成立，继续 | n=1, sum=1.0 |
| 2 | 2 | 1.0+1/2=1.5 | sum>1? | 1.5>1 成立，退出 | n=2, sum=1.5 |
| 结束 | — | — | — | 输出 | stdout: 2 |

C++ 里 `1.0 / n` 的 1.0 是 double，触发浮点除法；写成 `1 / n` 两个 int 相除结果恒为 0，sum 就永远停在 1.0 死循环。Python 3 里 `/` 本身就是浮点除法，写 `1 / n` 没问题。

## 代码

> [!warning]- 先自己写再展开 · C++
> ```cpp
> #include <iostream>
> 
> int main() {
>     int k;
>     std::cin >> k;            // 读入整数 K（1 ≤ K ≤ 15）
> 
>     double sum = 0.0;         // 调和级数部分和，必须 double
>     int n = 0;                // 当前项数
> 
>     while (sum <= k) {        // 严格大于 k 才停，等于时继续
>         ++n;
>         sum += 1.0 / n;       // 1.0/n 是浮点除法，别写 1/n
>     }
> 
>     std::cout << n << std::endl;   // 退出循环的 n 就是答案
>     return 0;
> }
> ```

> [!warning]- 先自己写再展开 · Python
> ```python
> import sys
> 
> def main():
>     k = int(sys.stdin.readline())   # 读入整数 K
> 
>     s = 0.0                         # 调和级数部分和
>     n = 0                           # 当前项数
> 
>     while s <= k:                   # 严格大于 k 才停
>         n += 1
>         s += 1.0 / n                # Python3 的 / 就是浮点除法
> 
>     print(n)                        # 退出循环的 n 就是答案
> 
> if __name__ == "__main__":
>     main()
> ```

## 复杂度

- 时间：O(n)，n 就是答案；K≤15 时最多 1835421 次浮点加法，远低于 1 秒时限。
- 空间：O(1)，全程只有 sum 和 n 两个变量。

## 易错点

1. 整数除法死循环：C++ 写 `sum += 1 / n`，两个 int 相除恒为 0——样例 K=1 时 sum 永远等于 1.0，循环出不去直接 TLE。
2. 条件写反：`while (sum < k)` 少了等于号——样例 K=1 第一轮 sum=1.0 就退出，输出 1，而正确答案是 2（要求严格大于）。
3. float 精度不够：样例 K=15，float 实测输出 1673860，正确答案 1835421——180 万次累加的误差把阈值跨过去了，必须用 double。
4. 先加后自增除零：n 从 0 开始且循环体先算 `sum += 1.0 / n` 再 n++，第一轮就是 1.0/0 得 inf——样例 K=1 输出 1（应为 2），思路整个反了。
5. 退出后再加一：样例 K=2 答案 4，若输出 n+1 得 5，WA——循环退出的 n 已经就是答案，别画蛇添足。
