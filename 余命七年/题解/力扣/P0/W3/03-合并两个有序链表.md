# 21. 合并两个有序链表 Merge Two Sorted Lists

## 一句话题意

给两个升序链表，返回合并后仍升序的链表，节点原地拼接、不新建值。

## 解题逻辑

**先想什么**：两条链表各自已经排好序，合并后的最小值只可能出现在两个头节点之间——立刻想到两个指针各指一个头，谁小取谁。

**朴素解法**：把所有节点的值收进数组、排一遍序、再串成新链表。时间 O((m+n) log(m+n))，空间 O(m+n)。不够好——排序把「输入本身有序」这个条件全浪费了，多花的 log 因子完全没必要。

**优化观察**：两个有序序列的合并就像「两堆排好的牌合成一堆」，每次只需要比较两个头，取较小的接到结果尾部，指针前移一步。这其实是**归并排序的 merge 一步**，靠「已有顺序」把排序的 O((m+n) log(m+n)) 压成一次线性扫描 O(m+n)。

## 为什么选这个方法

| 方案 | 时间 | 空间 | 缺点 |
| --- | --- | --- | --- |
| 收值 + 排序 + 重串 | O((m+n) log(m+n)) | O(m+n) | 浪费输入有序条件，还要额外数组 |
| 递归 | O(m+n) | O(m+n) | 递归栈深 m+n，长链表会爆栈 |
| 双指针 + 哨兵 | O(m+n) | O(1) | 几乎无缺点，标准解 |

**选双指针 + 哨兵**：这是合并两个有序序列的标准解，和递归同时间但空间 O(1)，哨兵节点让「空链表」和「非空」两种挂接情况统一成一种写法。

## 关键点

1. **哨兵节点 dummy**：结果链先挂在一个假头上，最后返回 `dummy.next`，省掉「头节点还没建」的特判。
2. 比较用 `<=`（相等优先接 l1），两个分支任选其一即可，保证稳定性，不丢重复值。
3. 循环条件 `while (l1 && l2)`：退出后至少一条为空，**把非空的那条整段挂上**——剩余部分本身有序，不用再逐节点搬。
4. 只改 `next` 指针、不动节点值，新链表是原节点的拼接，空间 O(1)。

## 实现逻辑

四个动作：**建哨兵 → 循环比较两个头、取小挂尾 → 退出后整段挂剩余 → 返回 dummy.next**。

拿 `l1 = [1,2,4]`、`l2 = [1,3,4]` 手推一遍：

| 轮次 | l1 当前 | l2 当前 | 查什么（比较） | 结果（接上谁） | 结果链状态 |
| --- | --- | --- | --- | --- | --- |
| 0 | 1 | 1 | 1 <= 1 | 接 l1 的 1，l1 走到 2 | [1] |
| 1 | 2 | 1 | 2 > 1 | 接 l2 的 1，l2 走到 3 | [1,1] |
| 2 | 2 | 3 | 2 <= 3 | 接 l1 的 2，l1 走到 4 | [1,1,2] |
| 3 | 4 | 3 | 4 > 3 | 接 l2 的 3，l2 走到 4 | [1,1,2,3] |
| 4 | 4 | 4 | 4 <= 4 | 接 l1 的 4，l1 走到空 | [1,1,2,3,4] |
| 退出 | 空 | 4 | — | 整段挂上 l2 剩余 | [1,1,2,3,4,4] |

## 代码

> [!warning]- 先自己写再展开 · C++
> ```cpp
> class Solution {
> public:
>     ListNode* mergeTwoLists(ListNode* l1, ListNode* l2) {
>         ListNode dummy(0);                 // 哨兵节点，省掉「头为空」特判
>         ListNode* cur = &dummy;
>         while (l1 && l2) {                 // 两条都不空才比较
>             if (l1->val <= l2->val) {      // <= 保证相等时优先接 l1，稳定
>                 cur->next = l1;
>                 l1 = l1->next;
>             } else {
>                 cur->next = l2;
>                 l2 = l2->next;
>             }
>             cur = cur->next;               // 别忘了推进 cur
>         }
>         cur->next = l1 ? l1 : l2;          // 剩下的整段挂上（可能都空）
>         return dummy.next;
>     }
> };
> ```

> [!warning]- 先自己写再展开 · Python
> ```python
> class Solution:
>     def mergeTwoLists(self, list1: Optional[ListNode], list2: Optional[ListNode]) -> Optional[ListNode]:
>         dummy = ListNode(0)                     # 哨兵节点
>         cur = dummy
>         while list1 and list2:                  # 两条都不空才比较
>             if list1.val <= list2.val:          # 相等优先接 list1，稳定
>                 cur.next = list1
>                 list1 = list1.next
>             else:
>                 cur.next = list2
>                 list2 = list2.next
>             cur = cur.next                      # 别忘了推进 cur
>         cur.next = list1 if list1 else list2    # 剩下的整段挂上
>         return dummy.next
> ```

## 复杂度

- 时间：O(m+n)，每个节点只被比较一次、挂接一次。
- 空间：O(1)，只多一个哨兵和几个指针，新链表复用原节点。

## 易错点

1. **忘挂剩余段**：`list1 = [1,2,3]`、`list2 = [4]`，循环退出后没写 `cur.next = list1 if list1 else list2`，返回的链丢掉了 4。
2. **返回哨兵本身**：`return dummy` 会把开头的假 0 一起交上去，输出 `[0,1,1,2,3,4,4]`；要 `return dummy.next`。
3. **漏推进 cur**：每轮只改 `cur->next` 不写 `cur = cur->next`，等于反复覆盖同一个节点的 next，最后只剩一个节点。
4. **空链表崩溃**：`[]` 和 `[]` 要能返回空；循环前的判断和退出后的挂接写法要天然兼容空输入，别一上来就解引用 `l1->val`。
5. C++：哨兵写成 `new ListNode(0)` 会忘了 delete 造成泄漏，直接放栈上 `ListNode dummy(0);` 再取 `&dummy`。
