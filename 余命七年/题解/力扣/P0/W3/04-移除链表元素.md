# 203. 移除链表元素 Remove Linked List Elements

## 一句话题意

输入链表头和整数 `val`，删掉所有值等于 `val` 的结点，返回新链表头。

## 解题逻辑

**先想什么**：单链表删除一个结点，必须**站在它的前一个结点上**动手（把前驱的 `next` 拨过去）。所以核心问题是「怎么保证手里始终有要删结点的前驱」。

**朴素解法**：头结点没有前驱，就分两段处理——先 `while (head && head->val == val)` 删掉开头的 val，再用 `prev`、`cur` 双指针扫中后段。O(n) 时间、O(1) 空间，复杂度其实已经到底了，不够好的是**结构**：删头和删中是两套循环、两个判断，连续多个 val 时两段的边界容易写漏。

**优化观察**：关键观察——头的「特殊性」是人为制造的。只要在 `head` 前面**人为挂一个不参与删除的哑节点 `dummy`**，head 就退化成了普通结点，永远「有前驱」。删除逻辑统一成一条：`cur` 站在前驱上，只检查 `cur->next`。复杂度不变（O(n)/O(1)），但两种删除路径合成一种，正确性肉眼可验。

## 为什么选这个方法

| 方案 | 时间 | 空间 | 缺点 |
| --- | --- | --- | --- |
| 先删头再删中 | O(n) | O(1) | 两套循环，删头删中边界分叉多 |
| 递归 | O(n) | O(n) | 递归栈深 n，长链表爆栈，删除释放也麻烦 |
| 哑节点 dummy | O(n) | O(1) | 多建一个结点，返回时要记得返回 dummy->next |

**选哑节点**：时间空间和朴素一样优，但用一个虚拟前驱把「两种删除」合成「一种」，是所有链表删除类题目的标准模板，19、83、237 全用它。

## 关键点

1. 模板句：`cur` 从 `dummy` 出发，循环只看 `cur->next`——命中就跨过去，没命中 `cur` 前进。
2. 不变量：`cur` 永远指向「已确认不用删的最后一个结点」，`cur->next` 是下一个待检查结点。
3. 命中删除后 **`cur` 不动**：连续 val（如 1→6→6→2）靠这一下吃干净。
4. 返回 `dummy->next` 而不是 `head`，head 可能早被删了；C++ 顺手 `delete` 掉 dummy 和被删结点。

## 实现逻辑

四个动作：**建 dummy → cur 出发循环 → 命中删（cur 不动）/ 未命中前进 → 返回 dummy->next**。

拿 `head = [1,6,6,2]`、`val = 6` 手推一遍：

| 轮次 | cur 指 | cur->next | 判断 | 结果 | 链表状态 |
| --- | --- | --- | --- | --- | --- |
| 初始 | dummy | 1 | 1≠6 | cur 前进 | d→1→6→6→2 |
| 1 | 1 | 6 | =6 | 删 6，cur 不动 | d→1→6→2 |
| 2 | 1 | 6 | =6 | 再删，cur 不动 | d→1→2 |
| 3 | 1 | 2 | 2≠6 | cur 前进 | d→1→2 |
| 4 | 2 | null | 循环退出 | 返回 dummy->next | 1→2 |

C++ 断链前先 `tmp` 暂存被删结点再 `delete`；Python 直接 `cur.next = cur.next.next`，被跨过的结点交给垃圾回收。

## 代码

> [!warning]- 先自己写再展开 · C++
> ```cpp
> class Solution {
> public:
>     ListNode* removeElements(ListNode* head, int val) {
>         ListNode* dummy = new ListNode(0, head);  // 虚拟头，head 也有前驱了
>         ListNode* cur = dummy;
>         while (cur->next) {                       // 永远检查下一个结点
>             if (cur->next->val == val) {
>                 ListNode* tmp = cur->next;        // 先暂存，断链后还能释放
>                 cur->next = tmp->next;
>                 delete tmp;                       // 命中后 cur 不动，继续查
>             } else {
>                 cur = cur->next;                  // 没命中才前进
>             }
>         }
>         ListNode* ans = dummy->next;
>         delete dummy;
>         return ans;                               // 不是 head，head 可能已被删
>     }
> };
> ```

> [!warning]- 先自己写再展开 · Python
> ```python
> class Solution:
>     def removeElements(self, head: Optional[ListNode], val: int) -> Optional[ListNode]:
>         dummy = ListNode(next=head)   # 虚拟头，head 也有前驱了
>         cur = dummy
>         while cur.next:
>             if cur.next.val == val:
>                 cur.next = cur.next.next  # 直接跨过，命中后 cur 不动
>             else:
>                 cur = cur.next
>         return dummy.next              # 不是 head，head 可能已被删
> ```
>
> `Optional` 来自 `typing`，力扣环境已注入；本地跑补一句 `from typing import Optional`。

## 复杂度

- 时间：O(n)，每个结点至多被检查一次，删掉的立即跳过。
- 空间：O(1)，只多用 `dummy`、`cur`（C++ 还有临时 `tmp`）几个指针。

## 易错点

1. **返回 `head` 而不是 `dummy->next`**：`head = [7,7,7,7]`、`val = 7`，全部删光后正确返回 `nullptr`；若返回 head，它仍指着已释放的结点，悬垂指针直接出错。
2. **删完顺手 `cur` 前进**：`head = [1,2,2,1]`、`val = 2`，删掉第一个 2 后若前进，就站到了第二个 2 上，永远检查不到它，输出 [1,2,1] 错；正确是命中后 cur 不动，得 [1,1]。
3. **判断 `cur->val` 而不是 `cur->next->val`**：站在待删结点上没法删自己——`head = [1,2]`、`val = 1` 会漏删头。必须站在前驱上检查下一个。
4. **C++ 不暂存就断链**：`head = [6,1]`、`val = 6`，直接 `cur->next = cur->next->next` 后，原结点 6 没有任何指针指着，`delete` 都无从下手，内存泄漏（力扣不判，面试会问）。
5. **空链表瞎特判**：`head = []`、`val = 1`，dummy->next 就是 null，循环不进直接返回 null，天然正确；加特判反而多一处出错机会。
