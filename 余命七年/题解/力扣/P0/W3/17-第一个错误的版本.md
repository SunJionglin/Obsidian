# 278. 第一个错误的版本 First Bad Version

## 一句话题意

版本号从 1 到 `n`，从第一个坏版本起后面全坏；返回第一个坏版本的**版本号**（从 1 开始），调用 `isBadVersion` 越少越好。

## 解题逻辑

**先想什么**：好坏有单调性——某个版本一坏，后面全坏。序列形如 `0 0 0 1 1 1`，要找第一个 `1`，本质是「在有序的 0/1 序列里找分界点」。

**朴素解法**：从 1 扫到 n，遇到第一个 `isBadVersion(v) == true` 就返回。O(n) 时间，但 n 最大 2³¹−1 ≈ 21 亿，最坏要调用 21 亿次 API；力扣会统计 `isBadVersion` 的调用次数，线性扫描必超时。

**优化观察**：每查一个 `mid`，就能据结果丢掉一半区间——`mid` 坏说明答案在 `[left, mid]`，`mid` 好说明答案在 `[mid+1, right]`。靠「坏之后全坏」这个单调性把时间压到 O(log n)，最多 31 次调用。

## 为什么选这个方法

| 方案 | 时间 | 空间 | 缺点 |
| --- | --- | --- | --- |
| 线性扫描 | O(n) | O(1) | n 达 21 亿，API 调用次数爆炸 |
| 哈希/预计算 | — | — | `isBadVersion` 是黑盒函数，结果只能现调现用，没法预先存表 |
| 二分查找 | O(log n) | O(1) | 依赖「坏之后全坏」的单调前提 |

**选二分**：题目给的单调性正是二分的使用条件，且 n 大到必须上 log 级算法；这是「找第一个满足条件」的二分模板题。

## 关键点

1. 模板句：`while (left < right)`，循环退出时 `left == right`，就是第一个坏版本。
2. 不变量：第一个坏版本始终落在 `[left, right]` 里；坏版本收缩用 `right = mid`（mid 可能是答案，不能丢），好版本收缩用 `left = mid + 1`（mid 必不是答案）。
3. mid 用 `left + (right - left) / 2`：`left + right` 可能超过 int 上限（n 最大 2³¹−1）。
4. 版本号从 1 开始，不是 0；n=1 时循环不进入，直接返回 1。

## 实现逻辑

四个动作：**初始化区间 → 算 mid → 按好坏收区间 → 返回 left**。

拿 `n = 5`、第一个坏版本是 4 手推：

| 轮次 | left | right | mid | isBadVersion(mid) | 区间怎么变 |
| --- | --- | --- | --- | --- | --- |
| 1 | 1 | 5 | 3 | false | left = mid + 1 = 4 |
| 2 | 4 | 5 | 4 | true | right = mid = 4 |

两轮后 `left == right == 4`，退出循环返回 4。`isBadVersion` 是判题方给的黑盒函数，笔记里不用实现它。

## 代码

> [!warning]- 先自己写再展开 · C++
> ```cpp
> // The API isBadVersion is defined for you.
> // bool isBadVersion(int version);
> 
> class Solution {
> public:
>     int firstBadVersion(int n) {
>         int left = 1, right = n;                 // 答案一定落在 [1, n]
>         while (left < right) {                   // 退出时 left == right 就是答案
>             int mid = left + (right - left) / 2; // 防溢出，别写 (left + right) / 2
>             if (isBadVersion(mid))
>                 right = mid;                     // mid 是坏 → 答案在 [left, mid]
>             else
>                 left = mid + 1;                  // mid 是好 → 答案在 [mid+1, right]
>         }
>         return left;
>     }
> };
> ```

> [!warning]- 先自己写再展开 · Python
> ```python
> # The isBadVersion API is already defined for you.
> # def isBadVersion(version: int) -> bool:
> 
> class Solution:
>     def firstBadVersion(self, n: int) -> int:
>         left, right = 1, n                    # 答案一定落在 [1, n]
>         while left < right:                   # 退出时 left == right 就是答案
>             mid = left + (right - left) // 2  # 防溢出的中位数写法
>             if isBadVersion(mid):
>                 right = mid                   # mid 是坏 → 答案在 [left, mid]
>             else:
>                 left = mid + 1                # mid 是好 → 答案在 [mid+1, right]
>         return left
> ```

## 复杂度

- 时间：O(log n)，每轮区间减半，n=2³¹−1 时最多 31 次 `isBadVersion` 调用。
- 空间：O(1)，只用了 left、right、mid 三个整型变量。

## 易错点

1. `(left + right) / 2` 溢出：`n = 2147483647`、`bad = 2147483647` 时 left+right 接近 43 亿，超出 int 上限直接溢出成负数，导致死循环或错答案——必须写 `left + (right - left) / 2`。
2. 好版本却写 `left = mid`：`n = 2`、`bad = 2` 时第一轮 mid=1 是好版本，`left = mid` 原地不动死循环——好版本必须 `left = mid + 1` 让区间前进。
3. 下标从 0 初始化：`n = 5`、`bad = 1` 时若写 `left = 0`，答案可能返回 0；版本号从 1 开始，0 不是合法版本。
4. 坏版本就提前 return：`n = 5`、`bad = 2` 时 mid=3 是坏版本，直接 `return 3` 就错——坏版本只说明答案 ≤ mid，还要继续往左找。
5. 循环条件与返回值不配套：写成 `while (left <= right)` 后若返回 right，`n = 1`、`bad = 1` 时退出循环 right 已变成 0——用 `left < right` 则退出即答案，不用挑左右。
