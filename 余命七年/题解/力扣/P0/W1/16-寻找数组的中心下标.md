# 724. 寻找数组的中心下标 Find Pivot Index

## 一句话题意

给一个整数数组，返回**第一个**下标（从 0 开始），其左侧元素和等于右侧元素和；不存在返回 `-1`。下标在两端时，缺失的一侧算 `0`。

## 解题逻辑

**先想什么**：最直白的想法是「每个下标都把它左右两段加起来比一比」，即枚举中心点。

**朴素解法**：外层枚举每个下标 i，内层两次循环分别累加 `[0, i)` 和 `(i, n)`。O(n²)，n 到 1e4 时约 1e8 次加法，力扣会超时，而且左右两段反复重算。

**优化观察**：相邻两个下标的「左侧和」只差一个元素——`leftSum[i+1] = leftSum[i] + nums[i]`。预先算出总和 `total`，那么右侧和不用再累加，直接 `total - leftSum - nums[i]` 一步求出。靠「右侧和 = 总和 - 左侧和 - 自己」这个恒等式，把 O(n²) 压成 O(n)。

## 为什么选这个方法

| 方案 | 时间 | 空间 | 缺点 |
| --- | --- | --- | --- |
| 枚举 + 每次重算左右和 | O(n²) | O(1) | 大数据超时，重复加法太多 |
| 前缀和数组 | O(n) | O(n) | 多存一个数组，本题用不上 |
| 总和 + 滚动左侧和 | O(n) | O(1) | 无 |

**选「总和 + 滚动左侧和」**：前缀和数组已经能 O(n)，但本题只要一个判断点，滚动维护单个变量就够，时间和空间都到最优，是前缀和思想里最省空间的写法。

## 关键点

1. 不变量：走到下标 i 时，`leftSum` 恒等于 `nums[0..i-1]` 之和。
2. 恒等式：右侧和 = `total - leftSum - nums[i]`，两侧相等时返回 i。
3. 边界约定：下标在数组两端时，缺失一侧的和按 `0` 算——`leftSum` 初始为 `0` 天然满足左端；右端靠恒等式算出的右侧和也自然为 `0`。
4. 返回**第一个**满足条件的下标，所以从左往右扫，找到就立刻返回，最后才 `-1`。

## 实现逻辑

先求和得 `total`，再从左往右扫：先**比较两侧和**（相等就返回 i），再**把 `nums[i]` 滚进 `leftSum`**，最后扫完返回 `-1`。

拿 `nums = [1, 7, 3, 6, 5, 6]` 手推一遍：

| i | nums[i] | leftSum | 右侧和 = total - leftSum - nums[i] | 相等吗 | 动作 |
| --- | --- | --- | --- | --- | --- |
| 0 | 1 | 0 | 28 - 0 - 1 = 27 | 否 | leftSum = 1 |
| 1 | 7 | 1 | 28 - 1 - 7 = 20 | 否 | leftSum = 8 |
| 2 | 3 | 8 | 28 - 8 - 3 = 17 | 否 | leftSum = 11 |
| 3 | 6 | 11 | 28 - 11 - 6 = 11 | **是** | 返回 3 |

C++ 里 `numeric` 的 `accumulate` 一行求和；Python 里直接 `sum(nums)`。

## 代码

> [!warning]- 先自己写再展开 · C++
> ```cpp
> class Solution {
> public:
>     int pivotIndex(vector<int>& nums) {
>         int total = accumulate(nums.begin(), nums.end(), 0);  // 总和
>         int leftSum = 0;
>         for (int i = 0; i < (int)nums.size(); i++) {
>             if (leftSum == total - leftSum - nums[i])         // 右侧和一步算出来
>                 return i;
>             leftSum += nums[i];                               // 比较完才滚进左侧
>         }
>         return -1;                                            // 没有中心下标
>     }
> };
> ```

> [!warning]- 先自己写再展开 · Python
> > ```python
> > class Solution:
> >     def pivotIndex(self, nums: list[int]) -> int:
> >         total = sum(nums)                       # 总和
> >         left_sum = 0
> >         for i, x in enumerate(nums):
> >             if left_sum == total - left_sum - x:  # 右侧和一步算出来
> >                 return i
> >             left_sum += x                       # 比较完才滚进左侧
> >         return -1                               # 没有中心下标
> > ```

## 复杂度

- 时间：O(n)，先一趟求和，再一趟扫描，每趟 n 次，共 2n 次。
- 空间：O(1)，只有 `total` 和 `leftSum` 两个变量。

## 易错点

1. `nums = [2, 1, -1]`：答案是下标 `0`（左侧为空算 0，右侧 `1 + (-1) = 0`）。别漏掉**左端**这个边界，`leftSum` 初始 0 必须先比较再累加。
2. `nums = [-1, -1, -1, 0, 1, 1]`：答案是下标 `0`，左侧为空算 0，右侧 `(-1)+(-1)+0+1+1 = 0` 也成立。别默认「中心在中间、元素非负」，负数和 0 都能凑成等式。
3. 比较顺序错了会漏解：先 `leftSum += nums[i]` 再比较，`nums = [1, 7, 3, 6, 5, 6]` 会把下标 3 错过。必须**先比后加**。
4. `nums = [1, 2, 3]`：没有中心下标，要返回 `-1` 而不是 0。
5. C++：`accumulate(nums.begin(), nums.end(), 0)` 的初值 0 是 `int`，元素和可能溢出 `int` 时初值写成 `0LL`；`nums.size()` 和 `int i` 比较记得 `(int)` 转换。
