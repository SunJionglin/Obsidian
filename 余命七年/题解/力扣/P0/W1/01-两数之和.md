# 1. 两数之和 Two Sum

## 一句话题意

给一个整数数组和 `target`，返回**两个下标**（从 0 开始），对应两数相加等于 `target`；保证恰有一组解。

## 解题逻辑

**先想什么**：读完题第一反应是「两两配对」，直接两层循环穷举。

**朴素解法**：外层固定 `nums[i]`，内层从 `i+1` 开始找 `target - nums[i]`。O(n²)，n 到 1e4 时约 1e8 次比较，力扣会超时。

**优化观察**：内层循环其实在反复做同一件事——**在数组里查找一个已知的值**。把「值 → 下标」预先放进哈希表，查找就从 O(n) 变成 O(1)。再进一步：不用预先建表，**边遍历边查边插**，一趟结束。

## 为什么选这个方法

| 方案 | 时间 | 空间 | 缺点 |
| --- | --- | --- | --- |
| 两层循环 | O(n²) | O(1) | 大数据超时 |
| 排序 + 双指针 | O(n log n) | O(n) | 排序会打乱下标，还得另存原下标，绕远路 |
| 哈希表 | O(n) | O(n) | 多用一点内存 |

**选哈希**：返回的是下标不是值，排序方案要额外记账；哈希用 O(n) 空间直接把时间压到最优，是这题的标准解，也是「用空间换时间」最经典的例子。

## 关键点

1. 哈希表存**值 → 下标**，查找 O(1)。
2. **先查后插**：对当前元素先查 `target - nums[i]`，查不到才插入自己，保证两个下标不重复用同一元素。
3. 边遍历边建表，天然保证返回的 `i < j`。

## 实现逻辑

三个动作循环做：**算 need → 查表 → 没查到就把自己插进去**。

拿 `nums = [2,7,11,15]`、`target = 9` 手推一遍：

| i | nums[i] | need | 表里有 need 吗 | 动作 | 表状态（值→下标） |
| --- | --- | --- | --- | --- | --- |
| 0 | 2 | 7 | 没有 | 插入 | {2:0} |
| 1 | 7 | 2 | 有（下标 0） | 返回 | {2:0} |

C++ 里 `find` 返回迭代器，找到就用 `it->second`；Python 里 `if need in idx` 判断，`idx[need]` 取值。

## 代码

> [!warning]- 先自己写再展开 · C++
> ```cpp
> class Solution {
> public:
>     vector<int> twoSum(vector<int>& nums, int target) {
>         unordered_map<int, int> idx;          // 值 -> 下标
>         for (int i = 0; i < (int)nums.size(); i++) {
>             int need = target - nums[i];
>             auto it = idx.find(need);
>             if (it != idx.end())
>                 return {it->second, i};       // 先出现的下标在前
>             idx[nums[i]] = i;                 // 查不到才插入自己
>         }
>         return {};                            // 题目保证有解，兜底防编译警告
>     }
> };
> ```

> [!warning]- 先自己写再展开 · Python
> ```python
> class Solution:
>     def twoSum(self, nums: list[int], target: int) -> list[int]:
>         idx = {}                            # 值 -> 下标
>         for i, x in enumerate(nums):
>             need = target - x
>             if need in idx:                 # 先查
>                 return [idx[need], i]
>             idx[x] = i                      # 后插
>         return []                           # 题目保证有解，兜底
> ```

## 复杂度

- 时间：O(n)，每个元素查一次哈希表（平均 O(1)），共 n 次。
- 空间：O(n)，哈希表最多存 n 个「值 → 下标」。

## 易错点

1. `nums = [3,3]`、`target = 6`：**先插后查**会返回 `[0,0]`，同一个 3 用了两次——正确顺序是先查后插。
2. 返回的是**下标**不是值：`nums = [2,7,11,15]`、`target = 9` 要返回 `[0,1]`，别把 `[2,7]` 交上去。
3. C++：`nums.size()` 是 `unsigned`，和 `int i` 比较会有符号转换警告，先 `(int)` 转一下。
4. C++：用 `idx[need]` 查询会顺手插入一个 0 键，污染哈希表；查存在一律用 `find`。
5. Python：判断存在要用 `if need in idx`，别用 `if idx.get(need)`——值为 0 时 `get` 返回 0 会被当成 False。
