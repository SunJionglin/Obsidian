# 15. 一维数组的动态和 Running Sum of 1d Array

## 一句话题意

给整数数组 `nums`，返回前缀和数组 `runningSum[i]` = 前 i+1 项之和，下标从 0 开始。

## 解题逻辑

**先想什么**：每个位置都要算一个「从头加到这里的和」，最直接的想法是每个 i 都把 0..i 重新加一遍。

**朴素解法**：外层固定 i，内层从 0 加到 i 填 `runningSum[i]`。O(n²)。这题 n ≤ 1000，最多约 5×10⁵ 次加法，其实能过——但它每个前缀都从头重算，i 越大重复劳动越多，是坏习惯，也抓不住这题的考点。

**优化观察**：相邻两个前缀只差一项，`runningSum[i] = runningSum[i-1] + nums[i]`。既然上一个前缀和已经算好了，当前只补一步加法就行，一趟扫描搞定，时间从 O(n²) 降到 O(n)。题目不要求保留原数组，还可以**原地累加**，额外空间 O(1)。

## 为什么选这个方法

| 方案 | 时间 | 空间 | 缺点 |
| --- | --- | --- | --- |
| 两层循环逐前缀求和 | O(n²) | O(1) | 大量重复加法，n 一大就慢，白瞎了「前缀和」的递推 |
| 前缀和数组（另开数组存结果） | O(n) | O(n) | 多占一整个数组，而原数组其实没人要了 |
| 原地累加 | O(n) | O(1) | 会改掉原数组（本题允许，返回的就是它） |

**选原地累加**：递推式让每个位置只做一次加法，一趟扫完；题目只验收返回数组，不查原数组，原地改直接把空间压到 O(1)，是这题的标准解，也是「前缀和」思想的最小样板。

## 关键点

1. 模板句：`nums[i] += nums[i-1]`，当前前缀和 = 上一个前缀和 + 当前元素。
2. 不变量：循环处理到 i 时，`nums[i]` 里存的就是前 i+1 项的和，下一步直接拿来用。
3. 边界约定：`i` 从 **1** 开始，`nums[0]` 本身就是第一个前缀和，不动它。
4. 想保留原数组：先复制一份再累加（Python 的 `accumulate` 天然不动原数组）。

## 实现逻辑

三个动作循环做：**取上一个前缀和 → 加上当前元素 → 覆盖写回原位**，下标 0 跳过不动。

拿 `nums = [1,2,3,4]` 手推一遍：

| i | nums[i]（加之前） | 要加谁 | 结果 nums[i] | 数组状态 |
| --- | --- | --- | --- | --- |
| 0 | 1 | 不动，本身就是前缀和 | 1 | [1,2,3,4] |
| 1 | 2 | nums[0]=1 | 3 | [1,3,3,4] |
| 2 | 3 | nums[1]=3 | 6 | [1,3,6,4] |
| 3 | 4 | nums[2]=6 | 10 | [1,3,6,10] |

注意每一步读的 `nums[i-1]` 都是**改过之后**的值，这正是「不变量」在起作用。

## 代码

> [!warning]- 先自己写再展开 · C++
> ```cpp
> class Solution {
> public:
>     vector<int> runningSum(vector<int>& nums) {
>         for (int i = 1; i < (int)nums.size(); i++)
>             nums[i] += nums[i - 1];      // 上一个前缀和 + 自己
>         return nums;                      // 原地改完直接返回
>     }
> };
> ```
> 一行版（`<numeric>` 的 `partial_sum`，会原地覆盖前 n 个元素）：
> ```cpp
> partial_sum(nums.begin(), nums.end(), nums.begin());
> ```

> [!warning]- 先自己写再展开 · Python
> ```python
> class Solution:
>     def runningSum(self, nums: list[int]) -> list[int]:
>         for i in range(1, len(nums)):
>             nums[i] += nums[i - 1]   # 上一个前缀和 + 自己
>         return nums                  # 原地改完直接返回
> ```
> 惯用写法（`itertools.accumulate`，不动原数组）：
> ```python
> return list(accumulate(nums))   # 别忘了 list()，accumulate 是惰性迭代器
> ```

## 复杂度

- 时间：O(n)，一趟循环共 n-1 次加法。
- 空间：O(1)，原地修改，不另开数组。

## 易错点

1. 循环从 0 开始：`nums = [1,2,3,4]` 时 Python 的 `nums[0] += nums[-1]` 会错误地加上末元素 4，得到 `[5,3,6,10]`；C++ 里 `nums[-1]` 是未定义行为。循环必须从 1 开始。
2. 返回值漏了：`nums = [1,2,3,4]` 要返回整个数组 `[1,3,6,10]`，不是最后一个前缀和 10，也不是 print 完就完事。
3. Python 用 `accumulate` 不包 `list()`：`return accumulate(nums)` 返回的是迭代器对象，力扣判型不对直接 WA。
4. 溢出边界：`nums[i]` 绝对值最大 1e6、n 最大 1000，前缀和最多 1e9，`int` 装得下；但累加的顺序不能跳项，负数和正数都要算进「前 i+1 项」。
5. 变体要求「不修改原数组」：先 `res = nums[:]`（或 `vector<int> res = nums`）再累加，别直接动输入。
