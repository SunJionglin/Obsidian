# 283. 移动零 Move Zeroes

## 一句话题意

给数组原地把所有 0 挪到末尾，非零保持原相对顺序，不返回。

## 解题逻辑

**先想什么**：看到「把 0 移到末尾」，第一反应是扫一遍，遇到 0 就把后面所有元素整体前移一位——删除式搬移。

**朴素解法**：外层遇到一个 0，内层把它后面的元素逐个前移，末尾补 0。最坏情况（数组开头全是 0）每个 0 都要搬动后面 O(n) 个元素，整体 O(n²)，n 到 1e4 时就超时；而且搬移次数依赖 0 的位置，不稳定。

**优化观察**：最终数组长什么样是**确定的**——`[0, slow)` 是原顺序的非零元素，`[slow, n)` 全是 0，`slow` 恰好等于非零个数。所以根本不用管 0，只要把非零元素按原顺序**压到前缀**就行：`fast` 扫全组，`nums[fast] != 0` 就换到 `slow` 位置。0 被交换挤到后面，位置天然正确。靠 `slow` 把「找非零该放哪」从每次搬移 O(n) 变成 O(1)，一次扫描 O(n) 搞定，空间还是 O(1)。

## 为什么选这个方法

| 方案 | 时间 | 空间 | 缺点 |
| --- | --- | --- | --- |
| 遇 0 整体前移 | O(n²) | O(1) | 开头一堆 0 时搬移 n²/2 次，超时 |
| 新数组收非零再拷回 | O(n) | O(n) | 违反原地要求，还要多一趟回拷 |
| 双指针（快慢） | O(n) | O(1) | 无明显缺点 |

**选双指针**：时间是 O(n) 下限，空间是 O(1) 下限，一次扫描原地完成，是「压缩数组前缀」的标准模板，以后很多数组题的母版。

## 关键点

1. 不变量：`[0, slow)` 全是非零且保持原顺序，`slow` 指向**下一个非零该落的位置**。
2. 模板句：`fast` 扫全组，`nums[fast] != 0` 就 `swap(nums[slow], nums[fast])`，`slow` 右移一位。
3. 交换写法一趟完成，0 自然被挤到末尾；搬值写法（`nums[slow] = nums[fast]`）必须收尾补零。
4. `slow` 只在搬完一个非零后 +1；前缀本没有 0 时 `slow == fast`，自交换无副作用。

## 实现逻辑

先让 `slow = 0` 指向下一个非零该落的位置；再让 `fast` 从 0 扫到 n-1，遇到非零就把它和 `slow` 位交换，`slow` 右移一位；最后 `fast` 扫完，`[0, slow)` 全是按原顺序的非零，`[slow, n)` 自然全是 0，直接结束。

拿 `nums = [0,1,0,3,12]` 手推一遍：

| fast | nums[fast] | 是 0 吗 | 动作 | 数组状态 | slow |
| --- | --- | --- | --- | --- | --- |
| 0 | 0 | 是 | 跳过 | [0,1,0,3,12] | 0 |
| 1 | 1 | 否 | 交换 0、1 位 | [1,0,0,3,12] | 1 |
| 2 | 0 | 是 | 跳过 | [1,0,0,3,12] | 1 |
| 3 | 3 | 否 | 交换 1、3 位 | [1,3,0,0,12] | 2 |
| 4 | 12 | 否 | 交换 2、4 位 | [1,3,12,0,0] | 3 |

## 代码

> [!warning]- 先自己写再展开 · C++
> ```cpp
> class Solution {
> public:
>     void moveZeroes(vector<int>& nums) {
>         int slow = 0;                              // 下一个非零该落的位置
>         for (int fast = 0; fast < (int)nums.size(); fast++) {
>             if (nums[fast] != 0) {
>                 swap(nums[slow], nums[fast]);      // 非零换到前缀
>                 slow++;                            // 占好一位，右移
>             }
>         }                                          // 0 已被交换挤到末尾，无需补零
>     }
> };
> ```

> [!warning]- 先自己写再展开 · Python
> ```python
> class Solution:
>     def moveZeroes(self, nums: list[int]) -> None:
>         slow = 0                                   # 下一个非零该落的位置
>         for fast in range(len(nums)):
>             if nums[fast] != 0:
>                 nums[slow], nums[fast] = nums[fast], nums[slow]  # 非零换到前缀
>                 slow += 1                          # 占好一位，右移
> ```

## 复杂度

- 时间：O(n)，`fast` 把数组扫一遍，每个元素只处理一次。
- 空间：O(1)，只用 `slow`、`fast` 两个下标变量，原地交换。

## 易错点

1. 搬值写法忘补零：`nums = [1,0,2]` 用 `nums[slow] = nums[fast]` 且收尾不填零，会得到 `[1,2,2]`——非零被复制了一份。搬值写法的收尾必须把 `[slow, n)` 整段填 0。
2. Python 遍历中 `remove`：`nums = [0,0,1]` 在 `for` 里 `remove(0)` 会让下标错位，第二个 0 被跳过，得到 `[0,1]`。永远不要在遍历中删除当前列表的元素。
3. 返回值：签名是 `void` / 返回 `None`，判题按修改后的原数组判分。C++ 改成 `vector<int> moveZeroes(...)` 直接编译错；Python 返回新列表而原数组没变，一样判错。`nums = [0,1,0,3,12]` 应变成 `[1,3,12,0,0]`。
4. `slow++` 放错位置：把它放在 `if` 外面，`nums = [0,1,2]` 时 `slow` 和 `fast` 同步走，全是自交换，输出还是 `[0,1,2]`。`slow` 只该在搬完一个非零后 +1。
5. 边界样例 `[0]`、`[0,0]`：交换写法一次不换，结果本来就对，别画蛇添足加特判；搬值写法的补零段要写成循环，`nums[slow] = 0` 只补一个会漏。
