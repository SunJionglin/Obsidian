### 1.1 K7 · split / join 文本解析 ★★★

#### 是什么

- `split(sep)`：把字符串按分隔符切成**列表**；
- `join(iterable)`：用某个字符串作胶水，把一堆字符串**粘成一个**。

一个拆、一个合，是「文本 ⇄ 结构」最基础的一对动作。

类比：`split` 是拿剪刀按虚线剪，`join` 是拿胶带按同一个方向粘回去。

#### 为什么

所有日志、CSV、配置、URL 查询串，本质都是「用某个分隔符排好的一行字」。不会拆，就只能一眼一眼看；会拆，就能 `for` 循环处理一万行。

更实际的理由：**split 的参数选错，会留一堆空串**，后面 `int()` 直接炸。这是新手最常见的翻车点。

#### 怎么用

```python
line = "2026-11-11 08:30:01   INFO    user=42  action=login"

# ① 不带参数：按任意空白切，连续空白当一个，自动丢空串
parts = line.split()
print(parts)      # ['2026-11-11', '08:30:01', 'INFO', 'user=42', 'action=login']

# ② 指定分隔符：严格按它切，空的部分保留
line2 = "a,,b"
print(line2.split(","))    # ['a', '', 'b']   ← 中间的空字段留下了

# ③ 最多切几刀
print(line2.split(",", 1)) # ['a', ',b']

# ④ rsplit：从右往左切（取最后一个字段很顺手）
path = "/var/log/app/error.log"
print(path.rsplit("/", 1)) # ['/var/log/app', 'error.log']

# join：只收 str
words = ["我", "爱", "白饭"]
print("-".join(words))     # 我-爱-白饭
# "-".join([1, 2])         # TypeError: sequence item 0: expected str
```

**常用组合（背下来）**：

| 需求 | 写法 |
| --- | --- |
| 去掉行尾换行 | `line.rstrip("\n")` |
| 按空白切成词 | `line.split()` |
| 取最后一个字段 | `s.rsplit("/", 1)[-1]` |
| key=value 解析 | `k, v = pair.split("=", 1)` |
| 拼 CSV 行 | `",".join(map(str, row))` |
| 一行多个空格对齐 | 先 `split()` 再 `join(" ")` |

**解析一行日志的完整写法**：

```python
def parse_line(line):
    parts = line.split()
    if len(parts) < 3:
        return None                       # 脏行，交给调用方处理
    date, time_, level = parts[0], parts[1], parts[2]
    kv = {}
    for item in parts[3:]:
        k, _, v = item.partition("=")     # partition 找不到分隔符时返回 ('原串','','')
        if k and v:
            kv[k] = v
    return {"date": date, "time": time_, "level": level, **kv}

print(parse_line("2026-11-11 08:30:01 INFO user=42 action=login"))
# {'date': '2026-11-11', 'time': '08:30:01', 'level': 'INFO', 'user': '42', 'action': 'login'}
```

`partition` 和 `split` 的区别：`partition` 一定返回**三个**元素，`split` 返回长度不定。

#### 边界与反例

| 反例 | 结果 | 正确做法 |
| --- | --- | --- |
| `"a  b".split(" ")` | `['a','','b']` 留空串 | 用 `split()`（无参） |
| `"a,b,".split(",")` | 末尾多一个 `''` | 过滤或用 `rsplit` |
| `"-".join([1,2])` | TypeError | `map(str, ...)` |
| `line.strip()` 去行尾 | 把有意义的首尾空格也删了 | `rstrip("\n")` |
| 用 `split` 解析带引号的 CSV | 引号里含逗号会被切断 | 用 `csv` 模块 |
| `s.split("=")[1]` | 值里本身有 `=` 就截断 | `split("=", 1)` 或 `partition` |

#### 关系

- 上游 **W1 K8 字符串方法**：`strip`、`replace`、`find` 是兄弟。
- 下游 **K8 正则**：分隔符不固定时，`split` 不够用，要上正则。
- 下游 **K9 异常**：任何一行都可能不合格式，解析必须能兜住。

### 1.2 K8 · 正则入门 ★★

#### 是什么

正则是一种**描述字符串形状**的小语言：用它写出「长什么样」，再让程序去文本里找符合这个形状的片段。

类比：`split` 是「按固定虚线剪」，正则是「按图案找」。

#### 为什么

分隔符不固定时（空格数不定、字段顺序可能变、要提取时间戳/邮箱/IP），`split` 会越写越丑；正则一行就能拿下。

但正则不是万能：**能 split 就别上正则**，正则写复杂了比字符串还慢、还难读。

#### 怎么用

```python
import re

text = "2026-11-11 08:30:01 INFO user=42 login from 10.0.0.7"

# ① 找第一个
m = re.search(r"\d{4}-\d{2}-\d{2}", text)
print(m.group())            # 2026-11-11

# ② 找全部
print(re.findall(r"\d+\.\d+\.\d+\.\d+", text))   # ['10.0.0.7']

# ③ 分组：一次拿多个字段
m = re.search(r"(\d{4}-\d{2}-\d{2}) (\d{2}:\d{2}:\d{2}) (\w+)", text)
print(m.groups())           # ('2026-11-11', '08:30:01', 'INFO')

# ④ 替换
print(re.sub(r"\s+", " ", text))   # 多个空格压成一个

# ⑤ 预编译：循环里用同一模式，别每次重新编译
TS = re.compile(r"\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}")
print(TS.findall(text))     # ['2026-11-11 08:30:01']
```

**最常用的元字符**：

| 写法 | 含义 |
| --- | --- |
| `.` | 任意一个字符（不含换行） |
| `\d` / `\w` / `\s` | 数字 / 字母数字下划线 / 空白 |
| `+` `*` `?` | 一次以上 / 零次以上 / 零或一次 |
| `{n,m}` | n 到 m 次 |
| `[...]` | 括号里任一字符 |
| `(...)` | 分组，能取出来 |
| `^` `$` | 行首 / 行尾 |
| `\b` | 词边界 |

**贪婪 vs 非贪婪**（最容易错）：

```python
s = "<a><b>"
print(re.findall(r"<.+>", s))    # ['<a><b>']  贪婪，一路吃到最后一个 >
print(re.findall(r"<.+?>", s))   # ['<a>', '<b>']  非贪婪，吃最少
```

#### 边界与反例

| 反例 | 结果 |
| --- | --- |
| 忘了 `r""`，写 `"\d"` | Python 先转义一次，`\d` 变成普通字符 d，匹配不到 |
| 用 `.` 匹配真正的点号 | `.` 是通配，要点号写 `\.` |
| 贪婪匹配没有边界 | 一次吃掉整行 |
| 每次循环都 `re.compile` | 慢十倍 |
| 用正则解析 HTML | 嵌套结构会出错，用 parser |

#### 关系

- 上游 **K7 split/join**：分隔符固定的场合优先 split。
- 下游 **K9 异常**：正则没匹配上是 `None`，直接 `.group()` 就 `AttributeError`。
- 后续 **W3 文本处理**：日志统计、字段抽取都会复用。

### 1.3 K9 · 异常四件套 ★★★

#### 是什么

```python
try:
    # 可能出错的代码
except SomeError as e:
    # 处理它
else:
    # 没出错才执行
finally:
    # 无论如何都执行
```

四个关键字各管一段：`try` 圈范围，`except` 接住，`else` 走正常路径，`finally` 做收尾。

#### 为什么

真实数据永远有脏行：缺字段、数字带空格、编码坏、文件不存在。**一段解析脚本能不能跑完一整个文件，就看有没有异常兜底**。

但不该「什么都捕」——`except:` 一把梭会把 KeyboardInterrupt、内存错误也吃掉，程序看着正常，其实已经坏了。

#### 怎么用

```python
def parse_level(line):
    try:
        parts = line.split()
        level = parts[2]                    # 可能 IndexError
        return level.upper()
    except IndexError:
        return "UNKNOWN"                    # 缺字段，给默认值
    except AttributeError as e:
        raise ValueError(f"输入不是字符串: {line!r}") from e
```

**处理一批脏行的标准写法**：

```python
def parse_file(path):
    good, bad = [], []
    with open(path, encoding="utf-8") as f:
        for i, line in enumerate(f, 1):
            try:
                rec = parse_line(line.rstrip("\n"))
                if rec is None:
                    raise ValueError("字段不足")
                good.append(rec)
            except (ValueError, IndexError) as e:      # 只捕预期的
                bad.append({"line": i, "raw": line.rstrip(), "err": str(e)})
    return good, bad
```

要点：

1. **只捕预期异常**（`ValueError`/`IndexError`/`KeyError`），不要 `except:`；
2. 记录**行号 + 原始行 + 原因**，否则排错时什么都查不到；
3. `raise ... from e` 保留原因链，方便回溯；
4. `finally` 里不要 `return`，会覆盖 try 的返回值。

#### 边界与反例

| 反例 | 后果 |
| --- | --- |
| `except: pass` | 所有错误被吞，坏数据静默混进结果 |
| 只 print 不记录 | 排错时不知道是哪一行 |
| `except Exception` 后不 `raise` | 上层拿不到原始栈 |
| 用异常做正常控制流（如 for 循环里大量 raise） | 慢 |
| `finally` 里 `return` | 覆盖 try 的返回值（隐蔽 bug） |
| `assert` 当参数校验 | `python -O` 会被去掉 |

#### 关系

- 上游 **K7/K8**：解析出的数据不可信，必须兜底。
- 下游 **W2 K10 自定义异常**：业务错误要抛自己的类，不要抛裸 Exception。
- 关联 **W1 K16 文件读写**：`FileNotFoundError` 是第一批要接住的异常。

## 2 · 手推与图解

### 2.1 split 的三种切法（同一行）

```
输入："a  b   c"

split()        → ['a', 'b', 'c']          按任意空白，连续空白算一个
split(" ")     → ['a', '', 'b', '', '', 'c']   严格一个空格一刀
split(" ", 2)  → ['a', '', 'b   c']       只切两刀
```

**记忆**：不带参数 = 智能；带参数 = 严格。

### 2.2 异常执行顺序

```
try 里的代码
   ├─ 正常结束 ──► else（如果写了）──► finally
   ├─ 抛异常 ──► 匹配到 except ──► finally
   ├─ 抛异常 ──► 没匹配到 ──► finally ──► 异常继续往上抛
   └─ return / break ──► finally 仍然执行
```

### 2.3 正则提取时间戳（手推）

```
文本：2026-11-11 08:30:01 INFO ...
模式：\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}

① \d{4}      → 2026
② -          → 字面量 -
③ \d{2}      → 11
④ -          → -
⑤ \d{2}      → 11
⑥ 空格        → ' '
⑦ \d{2}:...  → 08:30:01
```

## 5 · 常见报错（病例库）

| 报错 / 现象 | 原因 | 修法 |
| --- | --- | --- |
| `IndexError: list index out of range` | `split` 后字段比预期少 | 先判 `len(parts)` |
| `ValueError: invalid literal for int()` | 字段里混了空格/非数字 | `strip()` 后再转，或 `try/except` 兜 |
| `AttributeError: 'NoneType' object has no attribute 'group'` | `re.search` 没匹配到返回 None | 判 `if m:` 再用 |
| `TypeError: sequence item 0: expected str, int found` | `join` 里混了数字 | `map(str, ...)` |
| 正则匹配不到 | 没写 `r""` 或 `.` 当字面量 | 加 `r`，点号写 `\.` |
| 整个文件跑一半就崩 | 没有逐行 `try/except` | 每行单独兜，坏的记进 `bad` |
