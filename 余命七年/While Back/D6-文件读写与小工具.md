### 1.1 K16 · 文件读写 ★★★

#### 是什么

`open()` 打开文件后拿到一个**文件对象**，读写都通过它；`with` 负责在离开代码块时**自动关闭**；`encoding` 决定字节怎么翻译成文字。

一句话类比：`open` 是「把抽屉拉开」，`with` 是「用完自己把抽屉推回去」，`encoding` 是「你读的是中文还是乱码的翻译本」。

#### 为什么

不开 `with`、忘了 `close()`，文件描述符就泄漏——进程能开的 fd 有上限（通常 1024），跑久了报 `OSError: Too many open files`。

不写 `encoding`，Python 用系统默认编码：macOS/Linux 是 UTF-8，Windows 常是 GBK。同一份中文文件，你的机器能读，同学的报 `UnicodeDecodeError`——这是最常见的「在我机器上是好的」。

#### 怎么用

**读：**

```python
with open("data.txt", "r", encoding="utf-8") as f:
    text = f.read()          # 全读成 str

with open("data.txt", encoding="utf-8") as f:   # r 可省
    for line in f:                                # 逐行，惰性，首选
        print(line.rstrip("\n"))
```

三种读法的区别：

| 方法 | 返回 | 内存 | 什么时候用 |
| --- | --- | --- | --- |
| `f.read()` | 整个文件 str | 全量 | 小文件 |
| `f.readline()` | 一行 | 一行 | 自己控制节奏 |
| `f.readlines()` | 列表（每行一个元素） | 全量 | 小文件、要按下标取行 |
| `for line in f` | 逐行 | 一行 | **默认选这个** |

**写：**

```python
with open("report.txt", "w", encoding="utf-8") as f:
    f.write("hello\n")        # 只收 str，不自动换行
    f.writelines(["a\n", "b\n"])   # 也不自动加换行
    print("c", file=f)        # print 会加换行
```

**模式（背下来）：**

| 模式 | 含义 | 文件不存在 | 已存在 |
| --- | --- | --- | --- |
| `r` | 只读（默认） | `FileNotFoundError` | 从头读 |
| `w` | 只写 | 新建 | **清空再写** |
| `a` | 追加 | 新建 | 末尾追加 |
| `x` | 独占创建 | 新建 | `FileExistsError` |
| `+` | 加读写 | — | — |
| `b` | 二进制（`rb`/`wb`） | — | 不参与编码 |

**pathlib：不用手写斜杠**

```python
from pathlib import Path

p = Path("data") / "report.txt"      # 跨平台拼路径
p.parent.mkdir(parents=True, exist_ok=True)
p.write_text("hello", encoding="utf-8")
print(p.read_text(encoding="utf-8"))
print(p.exists(), p.suffix, p.stem)
for f in Path(".").glob("*.py"):     # 只当前层；rglob 递归
    print(f.name)
```

**今天要产出的工具（读 → 算 → 写）：**

```python
from pathlib import Path

def read_lines(path):
    with open(path, encoding="utf-8") as f:
        return [ln.rstrip("\n") for ln in f if ln.strip()]

def count_words(lines):
    counts = {}
    for ln in lines:
        for w in ln.split():
            counts[w] = counts.get(w, 0) + 1
    return counts

def write_report(path, counts, n=10):
    top = sorted(counts.items(), key=lambda kv: (-kv[1], kv[0]))[:n]
    with open(path, "w", encoding="utf-8") as f:
        for w, c in top:
            f.write(f"{w}\t{c}\n")

if __name__ == "__main__":
    lines = read_lines("input.txt")
    write_report("report.txt", count_words(lines))
```

这就是「第一个真工具」：读文件 → 算词频 → 写报告。三个函数各干一件事。

#### 边界与反例

| 反例 | 会发生什么 | 正确写法 |
| --- | --- | --- |
| `open("a.txt", "w")` 后写，想保留原内容 | 原内容被清空 | 用 `a` 追加 |
| 不写 `encoding` | Windows 上中文乱码 / 解码错误 | 一律 `encoding="utf-8"` |
| `f.write(123)` | `TypeError: write() argument must be str` | `f.write(str(123))` |
| `f.write("没有换行")` 连写多行 | 全挤在一行 | 自己加 `\n` 或改用 `print(..., file=f)` |
| `line.strip()` 去行尾 | 把有意义的首尾空格也删了 | `line.rstrip("\n")` |
| `f.read()` 读 1 GB 日志 | 内存爆 | `for line in f` 逐行 |
| 数字当文件名拼字符串 | 路径错、Windows 反斜杠被转义 | 用 `Path` + `/` |

#### 关系

- 上游 **K15 函数**：读写要拆成「读 → 算 → 写」三个函数，别写一坨。
- 下游 **K17 复杂度**：`for line in f` 是 O(文件大小)，`readlines()` 额外占 O(行数) 内存。
- 同族 **K2 终端**：`find`/`grep` 是命令行版的「找文件、搜内容」，和 `Path.glob` / 字符串查找互为参照。

### 1.2 K18 · C++ 提交模板 ★★★

#### 是什么

一份固定不变的单文件骨架：头文件、`using`、快读、常量、数组大小、主函数。竞赛/蓝桥提交时，先敲模板，再填逻辑。

#### 为什么

蓝桥与多数 OJ 按**总时长**计，模板每敲一次都是一分钟；模板不熟，考试时会在「`#include` 忘了」这种地方丢时间。

更关键的是**模板正确性**：`int` 相乘溢出、数组开小越界、递归爆栈、`endl` 刷缓冲——这些坑都在模板层面，模板对了一次就对。

#### 怎么用

```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long ll;
const int MAXN = 1e5 + 10;

int a[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    for (int i = 0; i < n; ++i) cin >> a[i];

    // 逻辑

    cout << '\n';
    return 0;
}
```

逐行说明：

| 片段 | 作用 |
| --- | --- |
| `bits/stdc++.h` | 一把梭头文件；非 GCC 环境（如 MSVC）不支持 |
| `typedef long long ll` | 之后写 `ll` 省事，防溢出 |
| `const int MAXN` | 数组上界统一管理，改一处 |
| 数组开在全局 | 全局区大（约 256 MB），`main` 里栈只有几 MB |
| `ios::sync_with_stdio(false)` | 关同步，`cin/cout` 快 3–5 倍 |
| `cin.tie(nullptr)` | 解绑，避免每次输出前 flush |
| `'\n'` 而不是 `endl` | `endl` 每次都 flush，大量输出时慢一倍以上 |

#### 边界与反例

| 反例 | 后果 | 正确做法 |
| --- | --- | --- |
| 数组开在 `main` 里 + 1e6 | 栈溢出，程序直接崩 | 开全局或 `static` |
| 用 `int` 存 `1e5 * 1e5` | 溢出成负数 | `ll` 或先转 `long long` |
| 递归深度 1e5 | 爆栈 | 改迭代 / 手动开栈 |
| `endl` 循环里用 | TLE | `'\n'` |
| `bits/stdc++.h` 在 MSVC | 编译失败 | 本机自测用显式 include，提交用 GCC |

#### 关系

- 下游 **K19 cmp**：模板里 `sort` 需要 cmp。
- 下游 **K20 二分**：模板里数组与 `ll` 直接复用。
- 相关 **K17 复杂度**：模板只解决常数，复杂度还得看算法。

### 1.3 K19 · 排序与 cmp ★★★

#### 是什么

`sort(begin, end, cmp)`：对 `[begin, end)` 排序，`cmp(a, b)` 回答「**a 是否应该排在 b 前面**」。

类比：`cmp` 是裁判，只看两个人谁先；它不需要知道全局顺序。

#### 为什么

`cmp` 必须满足**严格弱序**：不满足时 `sort` 会越界访问，轻则 RE，重则 UB（结果随机）。

最常见错误：相等时返回 `true`（`<=`），裁判对两个一样大的人说「两个都该在前」，排序直接乱掉。

#### 怎么用

**三组必会 cmp：**

```cpp
// ① 升序（默认，不用写）
sort(a, a + n);

// ② 降序
sort(a, a + n, [](int x, int y) { return x > y; });

// ③ 结构体多关键字：先按分数降序，分数相同按学号升序
struct Node { int id, score; };
sort(v.begin(), v.end(), [](const Node& x, const Node& y) {
    if (x.score != y.score) return x.score > y.score;   // 分数不同：高的在前
    return x.id < y.id;                                  // 分数相同：学号小的在前
});
```

`pair` 自带字典序（先比 first 再比 second），所以 `sort(v.begin(), v.end())` 就是按第一关键字升序。

**稳定性**：`sort` 不保证稳定，需要稳定用 `stable_sort`（代价是多一点内存）。

#### 边界与反例

```cpp
// 错法 1：相等返回 true —— 违反严格弱序，可能 RE
sort(a, a + n, [](int x, int y) { return x <= y; });

// 错法 2：比较函数里改了外部状态（计数器）—— 未定义行为
int cnt = 0;
sort(v.begin(), v.end(), [&](int x, int y) { ++cnt; return x < y; });

// 错法 3：浮点数直接比 —— 精度误差导致顺序随机
```

| 反例 | 后果 |
| --- | --- |
| `<=` / `>=` 当 cmp | RE 或结果错乱 |
| cmp 不满足传递性（如比绝对值） | 未定义行为 |
| 只写一个关键字却要求多关键字有序 | 结果不对 |
| 大规模数据用 `sort` 后又要求稳定 | 用 `stable_sort` |

#### 关系

- 上游 **K18 模板**。
- 下游 **K20 二分左边界**：二分的前提就是有序。
- 同族 **K17 复杂度**：`sort` 是 O(n log n)，计数排序 O(n+k) 但要求值域小。

## 2 · 手推与图解

### 2.1 `with` 的生命周期

```
open(path, encoding=...)  ──►  f（文件对象，已占一个 fd）
        │
        ├─ 读写（read / for line / write）
        │
   退出 with 块（正常 return 或抛异常都一样）
        │
        ▼
   f.close() 自动执行 ──►  fd 归还、缓冲刷盘
```

要点：**异常也会关**。手写 `f = open(); ...; f.close()` 时，中间抛异常就漏了。

### 2.2 文件模式对照

```
r  ── 只读，不存在就报错
w  ── 清空后写（危险：原内容没了）
a  ── 追加，指针在末尾
x  ── 独占创建，已存在就报错（防止误覆盖）
```

### 2.3 cmp 的严格弱序（手推）

要求三条同时成立（以 `<` 为例）：

```
① 不自反：cmp(a, a) 必须为 false
② 非对称：cmp(a, b) 为 true ⇒ cmp(b, a) 必须为 false
③ 传递：cmp(a,b) 且 cmp(b,c) ⇒ cmp(a,c)
```

用 `<=` 当 cmp，第 ① 条就破了（`cmp(a,a)` 为 true），所以排序会乱。

## 5 · 常见报错

| 报错 / 现象 | 原因 | 修法 |
| --- | --- | --- |
| `FileNotFoundError` | 路径错 / 文件不存在 / `r` 模式打开不存在的文件 | `print(Path.cwd())` 确认工作目录；用绝对路径 |
| `UnicodeDecodeError: 'utf-8' codec can't decode...` | 文件本身不是 UTF-8（常见 GBK） | 先确认编码，用 `encoding="gbk"` 或 `errors="replace"` 兜底 |
| `TypeError: write() argument must be str, not int` | 写入了非字符串 | `f.write(str(n))` |
| 文件内容被清空 | 用了 `w` 模式打开已有文件 | 改用 `a` |
| C++ 提交 RE | cmp 用了 `<=`，或数组开小 | 改严格弱序；数组开 `1e5+10` |
| C++ 输出超时 | 循环里用 `endl` | 改 `'\n'` |
