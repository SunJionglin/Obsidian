### 1.1 K4 写入与缓冲　`★★★ 50 分钟`

**是什么**　往文件里写内容的三条路，和一个「缓冲」概念。

| 写法 | 行为 | 什么时候用 |
| --- | --- | --- |
| `f.write(s)` | 只接受 str，**不自动换行**，返回写入字符数 | 精确控制内容 |
| `print(..., file=f)` | 自动加换行，能打多个对象 | 日志、多值一行 |
| `f.writelines(list)` | **不自动加换行**，要自己拼 `"\n"` | 一次写多行 |

**为什么**　两个坑。① `write` 和 `print(file=)` 的换行差异，混用会让文件里一行多一句、一句断两行。② 缓冲，`write` 后内容先待在内存缓冲区，没落盘；进程被 kill 的那一瞬间，缓冲里没 flush 的全丢——这就是「日志缺了最后几行」的真相。

**怎么用**：

```python
lines = ["甲\n", "乙\n", "丙\n"]
with open("out.txt", "w", encoding="utf-8") as f:
    f.write("第一行\n")            # 要自己加 \n
    print("第二行", file=f)        # 自动加 \n
    f.writelines(lines)            # 每项都要带 \n
    f.flush()                      # 立刻把缓冲区刷到磁盘
# 出 with 后 close 也会 flush，所以正常程序不用手动 flush
```

**缓冲与断电**：

```python
with open("t.txt", "w", encoding="utf-8") as f:
    f.write("重要数据")
    # 此刻还没 flush，直接 os._exit(1) 模拟断电 → t.txt 可能为空
```

**边界与反例**：
- `f.write(42)` → TypeError，数字要先 `str(42)`。
- `f.writelines(["a","b"])` 写出 `ab` 连在一起——不自动加换行。
- `open(p, "w")` 打开即截断，write 之前文件已经空了。
- `flush` 太勤会拖慢性能，循环里每条都 flush 是大忌。

**扩展（缓冲区什么时候刷）**：`close`、`flush`、缓冲写满（默认约 8KB 文本）三种时机。所以小文件出 with 自动落盘，大文件边写边流。

**易错清单**：
1. `write` 忘加 `\n`
2. `writelines` 以为会自动换行
3. 数字直接 `write`
4. 用 `w` 追加数据（该用 `a`）
5. 关键数据没 flush 就断电

**关系**：承接 K2（with 负责关、close 负责 flush）；K6 的编码决定「写出去的字在别的机器上长什么样」。

### 1.2 K5 pathlib　`★★★ 50 分钟`

**是什么**　`pathlib.Path` 把「路径」变成对象，自带拼路径、判断、遍历、读写的一整套方法。现代 Python 写文件操作，一律用它，不用 `os.path`，更不用字符串拼接。

**为什么**　字符串拼路径有三个死穴：Windows 用 `\`、拼错了少个斜杠、判断存在要另调 `os.path.exists`。`Path("data") / "a.txt"` 一次解决，还跨平台。

**怎么用**：

```python
from pathlib import Path

p = Path("data") / "logs" / "run.log"     # 用 / 拼，不要用 +
print(p.parent)      # data/logs
print(p.name, p.suffix, p.stem)           # run.log, .log, run
print(p.exists())    # 是否存在
p.parent.mkdir(parents=True, exist_ok=True)   # 一次建多层目录

for f in Path("data").glob("*.txt"):      # 只当前层
    print(f)
for f in Path(".").rglob("*.py"):         # 递归所有子目录
    print(f)

text = Path("a.txt").read_text(encoding="utf-8")     # 一行读
Path("b.txt").write_text(text.upper(), encoding="utf-8")  # 一行写

p.unlink()          # 删文件
p.parent.rmdir()    # 删空目录
```

**命令行对照（先会用命令，再知道 pathlib 在替你做什么）**：

| 命令行 | pathlib |
| --- | --- |
| `find . -name "*.py"` | `Path(".").rglob("*.py")` |
| `grep -n "def " f` | 逐行读 + `in` |
| `mkdir -p a/b` | `mkdir(parents=True, exist_ok=True)` |
| `ls` | `iterdir()` |

**边界与反例**：
- `glob("*.py")` 不递归，`rglob` 才递归——写错就是「找不到明明存在的文件」。
- `read_text()` 默认按系统编码，中文必须显式 `encoding="utf-8"`。
- `unlink()` 删文件没有回收站，删之前 `exists()` 确认。
- `Path("a") / "b.txt"` 中如果 `a` 不存在，不会自动建目录——读写前先 `mkdir(parents=True, exist_ok=True)`。

**易错清单**：
1. 用 `"data/" + name` 拼路径
2. glob/rglob 混用
3. `read_text` 不写 encoding
4. 目录没建就直接写文件

**关系**：K1 的 open 收 `Path` 对象和收字符串一样；K6 的编码是 `read_text/write_text` 的必带参数。

### 1.3 K6 编码与 BOM　`★★★ 45 分钟`

**是什么**　字符在磁盘上的字节表示方案。UTF-8 是现在的默认答案；GBK 是 Windows 老文件的遗留；BOM 是文件开头的三个隐形字节，告诉别人「我是 UTF-8」。

**为什么**　编码不一致，中文必乱码。Windows 记事本老文件是 GBK，用 `utf-8` 读直接 `UnicodeDecodeError`；带 BOM 的文件用普通 `utf-8` 读，字符串开头会多一个看不见的 `\ufeff`，`split` 出来的第一列永远对不上。

**怎么用**：

```python
# 中文文件三件套
with open("a.txt", encoding="utf-8") as f:       # 标准
    pass
with open("old.txt", encoding="gbk") as f:        # Windows 老文件
    pass
with open("bom.txt", encoding="utf-8-sig") as f:  # 带 BOM，读时自动吃掉
    pass

# 实在不知道什么编码，兜底替换
with open("x.txt", encoding="utf-8", errors="replace") as f:
    s = f.read()      # 坏字节变成 �，不崩
```

**验证 BOM 的坑**：

```python
# 用 utf-8 读带 BOM 的文件
s = open("bom.txt", encoding="utf-8").read()
print(repr(s[:4]))     # '\ufeff你好' ← 多了个看不见的字符
s.split(",")[0]        # 第一列永远不等于预期
```

**换行也在这里说清**：Windows 文件行尾是 `\r\n`，Linux/macOS 是 `\n`。所以跨平台的稳妥去行尾写法是 `line.rstrip("\r\n")`，不是 `strip()`。

**边界与反例**：
- `encoding="utf-8"` 读 GBK 文件 → `UnicodeDecodeError`。
- `errors="replace"` 兜底会静默吞掉坏字节，解析数据时先别用它，先想「文件到底是什么编码」。
- `gbk` 覆盖面小，有些生僻字读不了。
- 写文件用 `utf-8` 不带 BOM 就行，别用 `utf-8-sig` 去写（会在文件头加 BOM，别的工具可能不认识）。

**易错清单**：
1. 不写 encoding，换机器乱码
2. BOM 文件用 utf-8 读，第一列多个幽灵字符
3. `strip()` 代替 `rstrip("\r\n")`，误删字段空格
4. 报错就 `errors="replace"`，坏数据悄悄混进来

**关系**：K5 的 `read_text/write_text`、K1 的 `open` 都要带 encoding；K7（split/join）踩的 BOM 坑，根子在这里。

## 4 · 常见报错（病例库）

| 报错 | 原因 | 修法 |
| --- | --- | --- |
| `TypeError: write() argument must be str` | 写了数字/列表 | `str(x)`；列表用 `"\n".join` |
| `FileNotFoundError`（写入时） | 目录不存在，open 不会建目录 | 先 `mkdir(parents=True, exist_ok=True)` |
| `UnicodeDecodeError: 'utf-8' codec can't decode` | 文件是 GBK 或带 BOM | 试 `gbk` / `utf-8-sig` |
| 字符串开头多 `\ufeff` | BOM 文件用 utf-8 读 | `encoding="utf-8-sig"` |
| 写入后文件是空的 | 没 close / 没 flush 就断电 | 用 `with`；关键数据手动 `flush` |
