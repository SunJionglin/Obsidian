### 1.1 K11 · 类与 `__init__`/`self` ★★★

#### 是什么

- **类（class）**：一张图纸，描述「这类东西有哪些数据、能做什么」。
- **实例（instance/对象）**：按图纸造出来的具体东西。
- `__init__`：造实例时自动执行的初始化函数，负责给属性赋值。
- `self`：实例方法里的第一个参数，指向**当前这个实例**。

类比：类是「鱼形模具」，实例是「压出来的那条鱼」；`self` 就是「我这一条」，不是别的鱼。

#### 为什么

不用类，你会写出「一组并行变量 + 一堆 `_todo_add`、`_todo_done` 函数」，数据和方法散在各处；用类，数据和操作绑在一起，调用处变成 `todo.add("买米")`，一眼能看懂。

更实际的理由：**状态会变的东西最适合用对象**。一个「待办列表」有 items、有完成标记、有新增/完成/统计三个动作，天然是一个对象。

#### 怎么用

```python
class Todo:
    """一个最小的待办清单"""

    def __init__(self, owner):
        self.owner = owner          # 实例属性：每个对象各自一份
        self.items = []             # 千万不要写成类属性（见 K12）

    def add(self, text):
        self.items.append({"text": text, "done": False})
        return self                 # 返回 self 可以链式调用

    def done(self, idx):
        self.items[idx]["done"] = True

    def pending(self):
        return [it["text"] for it in self.items if not it["done"]]

    def __len__(self):
        return len(self.items)


t = Todo("炯霖")
t.add("买米").add("洗衣服")          # 链式调用
t.done(0)
print(len(t), t.pending())           # 2 ['洗衣服']
```

**逐个概念拆开：**

| 写法 | 含义 |
| --- | --- |
| `class Todo:` | 定义类，类名习惯大写开头 |
| `def __init__(self, owner):` | 构造时自动调用，`self` 必在第一 |
| `self.owner = owner` | 把参数存到实例上，之后 `t.owner` 能取到 |
| `def add(self, text):` | 实例方法，第一个参数必须是 `self` |
| `t.add("买米")` | 调用时**不用传 self**，Python 自动把 `t` 塞进去 |
| `len(t)` | 有 `__len__` 就能用内置 `len` |

`self` 不是关键字，只是**约定名**；写成 `this` 也能跑，但所有人都写 `self`。

**如何确认「self 就是那个实例」**：

```python
print(t.add)        # <bound method Todo.add of <__main__.Todo object at 0x...>>
print(t.__dict__)   # {'owner': '炯霖', 'items': [...]}
```

#### 边界与反例

| 反例 | 结果 |
| --- | --- |
| `def add(text):` 忘了 `self` | 调用时 `TypeError: add() takes 1 positional argument but 2 were given` |
| `__init__` 里写 `return` 返回值 | `TypeError: __init__() should return None` |
| 参数名写 `self` 但方法里用 `this` | `NameError` |
| 类里直接写 `items = []`（不在 `__init__`） | 变成类属性，所有实例共享（见 K12） |
| `t = Todo` 不写括号 | `t` 是类本身，不是实例 |
| 方法名和属性同名 | 方法会把属性覆盖掉 |
| 在 `__init__` 里做重活（读大文件） | 构造变慢、异常难定位；改到显式方法里 |

#### 关系

- 上游 **W1 K15 函数**：方法是「绑定到对象上的函数」。
- 下游 **K12 实例 vs 类属性**：`self.x` 和 `Class.x` 是两回事。
- 下游 **K10 自定义异常**：异常也是类（继承 `Exception`）。
- 408：[[07-408章节量化]] 数据结构里「结构 + 操作」的封装，正是类的思想。

### 1.2 K12 · 实例属性 vs 类属性 ★★

#### 是什么

| 类型 | 写在哪 | 归属 | 访问 |
| --- | --- | --- | --- |
| 实例属性 | `__init__` 里 `self.x = ...` | 每个实例各一份 | `t.x` |
| 类属性 | 类体里直接 `x = ...` | 类一份，所有实例共享 | `Todo.x` / `t.x` |

#### 为什么

**类属性是共享的**。如果它是**可变对象**（list、dict），一个实例改它，所有实例都变——这是新手最典型的「我明明只改了一个」翻车现场。

反过来，类属性适合放**常量**（比如 `species = "犬科"`），省内存也表达「大家都一样」。

#### 怎么用

```python
class Bad:
    items = []              # 类属性，所有实例共享同一个 list

    def add(self, x):
        self.items.append(x)


a, b = Bad(), Bad()
a.add(1)
print(b.items)              # [1]  ← b 没动过，却也有了


class Good:
    def __init__(self):
        self.items = []     # 实例属性，各自一份

    def add(self, x):
        self.items.append(x)


a, b = Good(), Good()
a.add(1)
print(b.items)              # []
```

**赋值 vs 修改（关键区分）**：

```python
class C:
    tag = "default"         # 类属性
    items = []

c = C()
c.tag = "mine"              # 赋值 = 在实例上新建属性，类属性不动
print(C.tag, c.tag)         # default mine

c.items.append(1)           # 修改 = 原地改共享的那个 list
print(C.items)              # [1]  ← 类属性被改了
```

记忆：**读的时候向上找（实例 → 类），写的时候就地建（除非你改的是可变对象内部）**。

`__dict__` 能看清归属：

```python
print(c.__dict__)   # {'tag': 'mine'}   ← items 不在里面，它在类上
```

#### 边界与反例

| 反例 | 结果 |
| --- | --- |
| 类属性放 `[]`/`{}`，实例里 `.append` | 所有实例共享，互相污染 |
| 以为 `c.tag = x` 改的是类属性 | 只在实例上新建，类属性不变 |
| 用类属性做计数器 `count += 1` | 实际在实例上新建，类属性永远不变 |
| 多线程改类属性 | 无锁并发写，数据竞争 |

#### 关系

- 上游 **K11 类与 self**。
- 相关 **W1 K5 变量绑定**：同一个对象被多个名字引用，原理相同。
- 下游 **K13 `__repr__`/`__eq__`**：那也是在类里定义、作用于实例。

### 1.3 K10 · 自定义异常与 `raise from` ★★

#### 是什么

```python
class ConfigError(Exception):
    """配置相关的错误"""

raise ConfigError("缺少 api_key")
```

自定义异常就是**自己定义一种错误类型**，让别人能精确地 `except ConfigError`，而不是笼统地接 `Exception`。

`raise ... from e` 表示「这个新错误是由底层错误 e 引起的」，Python 会保留两条栈，打印时显示 `The above exception was the direct cause of...`。

#### 为什么

函数内部可能抛 `KeyError`、`ValueError` 这类底层异常，但对调用方来说，真正有意义的信息是「配置缺字段」，不是「字典没这个键」。

自定义异常 = 给错误起一个人话名字，同时**保留原始原因**，排错时两层都能看到。

#### 怎么用

```python
class AppError(Exception):
    """本项目所有业务异常的基类"""


class ConfigError(AppError):
    """配置错误"""


class ParseError(AppError):
    """解析错误"""


def load_config(d):
    try:
        return {"key": d["api_key"]}
    except KeyError as e:
        raise ConfigError("配置缺少 api_key") from e      # 保留原因链


try:
    load_config({})
except ParseError:
    print("不会走到这里")
except ConfigError as e:
    print("配置错：", e)
    print("原因：", e.__cause__)       # KeyError('api_key')
```

**什么时候该自定义**：

| 场景 | 是否自定义 |
| --- | --- |
| 业务规则不满足（余额不足、配置缺失） | ✅ |
| 只是包装底层异常、想加信息 | ✅（配 `from e`） |
| 想替换 `ValueError`/`TypeError` 的语义 | ✅ |
| 纯粹为了「看起来专业」 | ❌ |

**异常类的层级**：一般让业务异常继承 `Exception`，不要继承 `BaseException`（那是给 `SystemExit`/`KeyboardInterrupt` 用的）。

#### 边界与反例

| 反例 | 后果 |
| --- | --- |
| `raise Exception("错了")` | 调用方无法精确捕获 |
| `raise ConfigError` 不带信息 | 报错只有类名，排错困难 |
| 捕获后 `raise ConfigError(...)` 不加 `from` | 原始栈丢失，只剩「配置错」 |
| 继承 `BaseException` | 会被 `except Exception` 漏掉 |
| 用异常做正常流程控制 | 慢，且难读 |

#### 关系

- 上游 **K9 异常四件套**：`try/except/else/finally` 是语法，自定义异常是语义。
- 上游 **K11 类**：异常就是类。
- 下游 **W2 K14 模块与包**：多个模块共享一套异常定义，通常放 `errors.py`。

## 2 · 手推与图解

### 2.1 类的内存归属（手推）

```
class C:
    tag = "default"        ← 类属性，存在 C.__dict__
    def __init__(self):
        self.n = 0         ← 实例属性，存在 c.__dict__

c1 = C(); c2 = C()

c1.__dict__ = {'n': 0}     ← 各自的 n
c2.__dict__ = {'n': 0}
C.__dict__  = {'tag': 'default', '__init__': ..., ...}

c1.tag  → 先查 c1.__dict__（没有）→ 再查 C.__dict__（'default'）
c1.tag = 'x' → 只写进 c1.__dict__，C.tag 不变
```

### 2.2 异常原因链（手推）

```
load_config({}) 调用
   └─ d["api_key"] → KeyError('api_key')
        └─ except KeyError as e:
             raise ConfigError("配置缺少 api_key") from e
                  │
                  ├─ 新异常：ConfigError("配置缺少 api_key")
                  └─ __cause__ = KeyError('api_key')

打印时两段都显示；e.__cause__ 能拿到原始异常
```

### 2.3 可变类属性的翻车现场（手画）

```
Bad.items ──► [ ]        ← 只有一个 list
              ▲  ▲
              │  │
           a.items b.items   ← 两个实例都指向它

a.add(1) → Bad.items.append(1) → 两个实例都看到 [1]
```

## 5 · 常见报错（病例库）

| 报错 / 现象 | 原因 | 修法 |
| --- | --- | --- |
| `TypeError: add() takes 1 positional argument but 2 were given` | 方法定义忘写 `self` | 第一个参数写 `self` |
| `TypeError: __init__() should return None` | `__init__` 里写了 `return x` | 去掉返回值 |
| `NameError: name 'self' is not defined` | 方法定义漏了 `self` 参数 | 补上 |
| 两个实例的数据互相污染 | 可变对象写成了类属性 | 移到 `__init__` 里 |
| `except ConfigError` 抓不到 | 抛的是 `Exception` 而不是 `ConfigError` | 抛对类型 |
| 排错时看不到原始错误 | `raise X(...)` 没带 `from e` | 加 `from e` |
