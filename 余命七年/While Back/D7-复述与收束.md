## 1 · 正文

### 1.1 K20 · 二分左边界 ★★★

#### 是什么

`lower_bound(a, l, r, x)`：在**有序**数组里找**第一个 ≥ x** 的位置。找不到就返回 `r`（数组尾后）。

它和「二分查找某个值」不是一回事：查找要求「正好等于」，左边界只要求「第一个不小于」。

#### 为什么

90% 的二分写错都错在**边界收缩**：

```cpp
// 错法：r = mid - 1，会漏掉答案
while (l < r) {
    int mid = (l + r) / 2;
    if (a[mid] < x) l = mid + 1;
    else r = mid - 1;        // ← 错
}
```

因为 `a[mid] >= x` 时，`mid` 本身**可能就是答案**，把 `r` 挪到 `mid - 1` 就把它排除了。

正确写法只有一个记忆点：**`r = mid`，不动 `mid`**。

#### 怎么用

```cpp
// 返回第一个 >= x 的下标；不存在返回 r
int lower_bound_idx(int a[], int l, int r, int x) {
    while (l < r) {
        int mid = l + (r - l) / 2;      // 防溢出写法
        if (a[mid] < x) l = mid + 1;    // 小了，答案在右边
        else r = mid;                   // 不小于，mid 可能是答案
    }
    return l;
}
```

C++ 标准库直接用：

```cpp
int p = lower_bound(a, a + n, x) - a;   // 第一个 >= x
int q = upper_bound(a, a + n, x) - a;   // 第一个 > x
```

**四种常见需求，一套模板：**

| 需求 | 判定 | 返回 |
| --- | --- | --- |
| 第一个 ≥ x | `a[mid] < x` 右移 | `l` |
| 第一个 > x | `a[mid] <= x` 右移 | `l` |
| 最后一个 < x | 第一个 ≥ x 的位置 − 1 | `l - 1` |
| 计数 x 出现次数 | `upper − lower` | — |

#### 边界与反例

| 反例 | 后果 |
| --- | --- |
| `r = mid - 1` | 漏答案（尤其答案就在 mid） |
| `while (l <= r)` 配 `r = mid` | 死循环（l=r 时 mid=l，r 还是 mid） |
| `mid = (l + r) / 2` 且 l、r 很大 | 理论上溢出（本题不会，但要养成 `l + (r-l)/2` 习惯） |
| 在无序数组上用二分 | 结果随机 |
| 找「最后一个 ≤ x」却直接套 lower_bound | 结果差一位 |

#### 关系

- 上游 **K19 排序 cmp**：二分前提是有序。
- 上游 **K18 模板**：数组与 `ll` 直接复用。
- 下游 **W2 双指针/滑窗**：都要「有序 + 区间收缩」的思维。

### 1.2 K21 · 数据结构三要素 ★★

#### 是什么

任何数据结构都由三样东西定义：

| 要素 | 回答什么 | 例子 |
| --- | --- | --- |
| 逻辑结构 | 元素之间是什么关系 | 线性（一对一）、树（一对多）、图（多对多）、集合 |
| 存储结构 | 在内存里怎么放 | 顺序存储（数组）、链式存储（指针）、索引、散列 |
| 操作 | 能对它做什么、代价多少 | 增删改查、遍历、排序 |

#### 为什么

初学者常把「数组」和「线性表」混为一谈。实际上：

- **线性表**说的是**逻辑结构**（一对一排成一条线）；
- **数组**说的是**存储结构**（连续内存）；
- 同一个线性表，可以用顺序存储（顺序表）实现，也可以用链式存储（链表）实现。

分不清这两层，408 选择题会反复错（「线性表的顺序存储一定是数组吗」这类）。

#### 怎么用

判断一个新结构的顺序：

```
先问：元素之间什么关系？（逻辑）→ 再问：内存里怎么摆？（存储）→ 最后问：常用操作代价？（操作）
```

例：哈希表 —— 逻辑上是「集合/映射」，存储上是「数组 + 链表（或开放寻址）」，操作上「查找平均 O(1)、最坏 O(n)」。

#### 边界与反例

| 说法 | 对不对 | 为什么 |
| --- | --- | --- |
| 「链表是逻辑结构」 | 错 | 链表是存储结构（链式存储） |
| 「复杂度是数据结构的属性」 | 错 | 复杂度属于**操作**，同一个结构不同操作代价不同 |
| 「顺序表一定是数组」 | 基本对 | 顺序表就是顺序存储的线性表，通常用数组 |
| 「栈是存储结构」 | 错 | 栈是逻辑结构（操作受限的线性表），可用数组或链表实现 |

#### 关系

- 上游 **K17 复杂度**：三要素里的「操作」要谈复杂度。
- 下游 **K22 线性表**：三要素的第一个具体例子。
- 408：[[07-408章节量化]] 数据结构第 1 章就是这一块。

### 1.3 K22 · 线性表（408 视角）★★

#### 是什么

线性表 = 逻辑上一对一排成一列的 n 个元素。两种主流实现：

| | 顺序表（数组） | 链表 |
| --- | --- | --- |
| 存储 | 连续内存 | 节点 + 指针，分散 |
| 随机访问 | O(1)（`a[i]`） | O(n)（要数过去） |
| 按值查找 | O(n) | O(n) |
| 插入/删除（已定位） | O(n)（要挪元素） | O(1)（改指针） |
| 插入/删除（未定位，要找位置） | O(n) | O(n) |
| 内存 | 紧凑，可能浪费（预留） | 每节点多一个指针的开销 |
| 缓存友好 | 好（连续） | 差（跳着访问） |

#### 为什么

408 爱考「什么时候用哪个」：

- 频繁**按下标访问**、很少增删 → 顺序表；
- 频繁在**中间增删**、少访问 → 链表；
- 数据量大且只追加 → 顺序表（尾部 O(1) 摊还）。

面试版问法：「为什么 Redis 用跳表不用红黑树」「为什么 MySQL 索引用 B+ 树」——本质都是「存储结构 + 操作代价」的取舍。

#### 怎么用

**手写顺序表插入（408 常考代码）**：

```cpp
// 在第 i 个位置插入 x，返回是否成功
bool insert(int a[], int &n, int i, int x) {
    if (i < 1 || i > n + 1) return false;    // 位置非法
    if (n == MAXN) return false;             // 满了
    for (int j = n; j >= i; --j) a[j] = a[j - 1];   // 从后往前挪
    a[i - 1] = x;
    ++n;
    return true;
}
```

**手写链表插入（头插）**：

```cpp
struct Node { int val; Node* next; };
void push_front(Node*& head, int x) {
    Node* p = new Node{x, head};
    head = p;
}
```

#### 边界与反例

| 反例 | 后果 |
| --- | --- |
| 顺序表从前往后挪 | 覆盖数据，元素全乱 |
| 插入位置从 0 开始数 | 差一位（408 常按 1 开始） |
| 链表插入忘了先接后断 | 丢链 |
| 删除后没释放节点 | 内存泄漏（408 大题可能扣分） |
| 认为「链表插入一定 O(1)」 | 定位仍要 O(n) |

#### 关系

- 上游 **K21 三要素**。
- 相关 **K9 list 与切片**：Python 的 list 是动态数组，`insert(0, x)` 是 O(n)，这就是顺序表的代价。
- 408：[[07-408章节量化]] 数据结构第 2 章。

## 2 · 手推与图解

### 2.1 二分左边界的手推（对 `a = [1,3,3,5,7]`，找 x=3）

```
l=0 r=5
mid=(0+5)/2=2  a[2]=3  不 < 3 → r=2
l=0 r=2
mid=1          a[1]=3  不 < 3 → r=1
l=0 r=1
mid=0          a[0]=1  < 3   → l=1
l=1 r=1  结束 → 返回 1（第一个 3 的下标）
```

注意：每一步 `r = mid`，从不 `-1`。

### 2.2 三要素图（手画）

```
            数据结构
        ┌───────┼───────┐
   逻辑结构   存储结构   操作
   线性/树/图  顺序/链式   增删改查
        │         │         │
     线性表 ── 顺序表(数组) ── 随机访问 O(1)、插入 O(n)
              └ 链表 ──────── 随机访问 O(n)、插入 O(1)
```

### 2.3 顺序表 vs 链表（手画对比）

```
内存布局：
顺序表  [0][1][2][3][4]      ← 连续，缓存友好
链表    [0]→[3]→[1]→[4]      ← 分散，靠指针连

插入第 2 位：
顺序表  后面全往后挪一位（O(n)）
链表    找到第 2 位，改两个指针（O(1)，定位 O(n)）
```

## 5 · 常见报错（病例库）

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 二分死循环 | `l <= r` 配 `r = mid` | 改成 `l < r`，或 `r = mid - 1` 并保证不漏答案 |
| 二分答案差一位 | 用了 `r = mid - 1` | 改 `r = mid` |
| 二分结果随机 | 数组没排序 | 先 `sort` |
| 顺序表插入后数据乱 | 从前往后挪 | 从后往前 `for (j=n; j>=i; --j)` |
| 链表节点丢失 | 先断后接 | 先接新节点，再断 |
| `lower_bound` 返回 n 却当成找到 | 没判 `a[p] == x` | 判存在性要额外检查 |
