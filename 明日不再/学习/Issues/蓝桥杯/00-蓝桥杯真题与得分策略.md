## 二 · 4 小时怎么切（省赛 09:00–13:00）

| 时段 | 分钟 | 做什么 | 硬规则 |
| --- | --- | --- | --- |
| 09:00–09:08 | 8 | **只读题**，把 8 题分三堆：能拿满 / 能拿部分 / 没思路 | 不许碰键盘写代码 |
| 09:08–09:25 | 17 | 两道填空算完就交（各 5 分） | 算完就走，不追求优雅 |
| 09:25–09:50 | 25 | 第一道 10 分题 | 25 分钟没 AC → 交暴力，走人 |
| 09:50–10:15 | 25 | 第二道 10 分题 | 同上 |
| 10:15–10:55 | 40 | 第一道 15 分题 | 出不了正解 → 写暴力档（n≤20 爆搜）拿 30% |
| 10:55–11:35 | 40 | 第二道 15 分题 | 同上 |
| 11:35–12:25 | 50 | 20 分题里「看起来有思路」的那道 | 50 分钟没进展 → 切下一道 |
| 12:25–13:00 | 35 | 剩下那道 20 分题：**先写暴力再想正解**；最后 20 分钟不再开新题，只对拍已有代码 + 补边界 | 绝不空题 |

**两条铁律**

1. **每题先写「能过 3 个测试点」的版本，再去想正解**。按测试点给分意味着：暴力交上去就是分，正解想不出来是 0 分。先拿分，再优化。
2. **到点必切**。一道题超过时限 10 分钟还没进展，说明这道题不在你的能力圈里，继续投入的期望收益低于补边界。

## 三 · 部分分怎么设计（这是省赛真正的技术）

按数据范围分档，先满足小档，再往上爬：

| 数据范围 | 能写什么 | 大概能拿 |
| --- | --- | --- |
| n ≤ 10–20 | 全排列 / 爆搜 / DFS 枚举所有方案 | 20–30% |
| n ≤ 100–500 | O(n³) / Floyd / 区间 DP 朴素 | 40–50% |
| n ≤ 1e5 | O(n log n) 正解（排序 + 二分 / 树状数组 / 线段树） | 70–100% |
| 特殊性质档（如「所有数相同」「是一条链」「权值全为 1」） | 单独 if 分支特判 | 往往白送 10–20% |

**读题时必须先看数据范围表**——它就是分数地图。很多题的「特殊性质」子任务比正解更容易，先扫一眼有没有「保证图是一棵树 / 保证 a_i 互不相同」这种白送档。

## 四 · 提交环境与坑

- **C/C++**：GNU C++，单文件、无文件读写、stdin/stdout。本地用 `g++ -std=c++17 -O2` 对齐。
- **Python**：官方环境是 **Python 3.8.6**——不要写 3.10+ 语法（`match`、`int | None`、海象表达式可以但要 3.8 支持）。同样逻辑 Python 比 C++ 慢 10–50 倍，**A 组难题一律用 C++ 交，Python 只用来快速验算**。
- **整型**：`int` 装不下 1e9×1e9，乘之前先 `1LL*`；输出用 `%lld` / `cout`。
- **数组**：全局开 `1e7` 级；`n` 是 1e5 时开 `1e5+10`，别开 `1e5`。
- **递归深度**：1e5 层的 DFS 会爆栈（A 组常见），要么改成迭代，要么确认评测栈大小。
- **多组数据**：看到 `T` 就 `while(T--)`，并且每组都要清空数组/计数器——这是丢分重灾区。
- **纸质资料**：按往年规则可以带书和打印模板（U 盘、网络禁止），以当年《比赛手册》为准。**所以 T0 模板包打印一份带进去**，比背强。

## 五 · 对拍模板（蓝桥不给测试点反馈，这是唯一自测手段）

```cpp
// brute.cpp：暴力，永远正确但慢
// solve.cpp：正解
// gen.cpp：随机生成器
// 循环：gen > in.txt; brute < in.txt > a.txt; solve < in.txt > b.txt; diff a.txt b.txt
```

```cpp
// gen.cpp 骨架
#include <bits/stdc++.h>
using namespace std;
int rnd(int l, int r) { return l + rand() % (r - l + 1); }
int main() {
    srand(time(0) ^ (unsigned long long)new char);
    for (int T = 0; T < 100; T++) {          // 跑 100 组
        int n = rnd(1, 8);                    // 先小数据
        printf("%d\n", n);
        for (int i = 1; i <= n; i++) printf("%d ", rnd(1, 5));
        puts("");
    }
}
```

```bash
# 一行对拍（macOS / Linux 通用）
for i in $(seq 1 200); do ./gen > in.txt; ./brute < in.txt > a.txt; ./solve < in.txt > b.txt; diff a.txt b.txt > /dev/null || { echo "WA at $i"; break; }; done
```

**什么时候必须对拍**：线段树、树状数组、树形 DP、Tarjan、KMP 这类「模板对但边界错」的题。手算 5 组不如对拍 200 组。

## 六 · 蓝桥题解怎么写（在 [[00-题解笔记生成提示词]] 基础上补三段）

文件放 `Issues/蓝桥杯/`，命名 `{{届次}}-{{组别}}-{{试题字母}}-{{题名}}.md`，例如 `17-A-A-均衡数.md`。

1. **部分分档位表**（蓝桥特有，必须有）：

   | 数据档 | 写法 | 复杂度 | 预估得分 | 实际通过 |
   | --- | --- | --- | --- | --- |
   | n≤20 | 爆搜 | O(2^n) | 30% | — |
   | n≤1e5 | 正解 | O(n log n) | 100% | — |

2. **正解的关键一步**：只写「这题从暴力到正解，中间那个观察是什么」，不要复述题面。
3. **卡点记录**：卡了多久、卡在哪（读题/建模/边界/调错）、下次遇到同类怎么第一眼认出来。

填空类题解单独写「怎么手算 + 怎么用程序验算（写个小 DFS 暴力跑一遍对答案）」。

## 七 · 赛后复盘模板（48 小时内填完，写进 `Issues/蓝桥杯/`）

```markdown
## 第 N 届 · 省赛/国赛复盘（日期）

- 实际得分：__ 分（估）／做对 __ 题，部分分 __ 题
- 时间分配：填空 __ 分钟，10 分题 __ ，15 分题 __ ，20 分题 __
- 每题一行：题号 | 我的分数 | 丢分原因（读题/算法/边界/时间/没交）
- 最大失误是哪一道、哪一步：
- 如果重来一次，前三件事怎么改：
- 这次暴露的知识点缺口（回填到 [[蓝桥杯A组-知识点地图]]）：
- 下次模拟要改的一个动作：
```

**复盘只回答三件事**：哪道题本该拿分没拿到、为什么、下次用什么动作避免。不写「下次要更努力」。
