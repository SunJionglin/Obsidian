## 2. 正文

### 2.1 打开与 `with`

**机制**：`open()` 拿到的是文件描述符 + 缓冲区。不 `close()` 会占 fd，进程开太多就 `Too many open files`。`with` 是语法糖：进入时调 `__enter__`，退出时**无论有没有异常**都调 `__exit__`（里面做 `close`）。

**四种模式**：`r` 读（不存在报错）、`w` **先清空再写**、`a` 追加、`x` 独占创建（已存在报错）。

**最小复现**：

```python
with open("a.txt", "w", encoding="utf-8") as f:
    f.write("第一行\n")
print(f.closed)          # True：出了 with 就关了
```

**常见错**：拿 `w` 去「打开已有文件看看」——文件被清空了，tab 都不提示。改数据前先 `Path.exists()` + 备份，或者先开 `r` 读一遍。

### 2.2 三种读法

| 写法 | 内存 | 什么时候用 |
| --- | --- | --- |
| `f.read()` | 整个文件进内存 | 小文件、要整体处理（如 json） |
| `f.readline()` / `f.readlines()` | 一行 / 全部行成列表 | 只需要几行；大文件里 `readlines` 也是坑 |
| `for line in f:` | 惰性一行 | **默认选它** |

行尾：逐行读到的 `line` 带 `\n`（最后一行可能没有）。去掉用 `line.rstrip("\n")`，**不要用 `strip()`**——它会把行首尾的空格也吃掉，而 CSV 字段里的空格可能是有意义的。

### 2.3 写入与缓冲

- `f.write(s)`：只接受 `str`，不自动换行，返回写入字符数。
- `print("x", file=f)`：自动加换行，能直接打多个对象。
- `f.writelines(list)`：**不自动加换行**，要自己拼 `"\n".join(...)`。
- `flush()`：把缓冲区刷到磁盘；`close()` 会 flush。断电丢数据，通常就丢在没 flush 的那段。

### 2.4 pathlib 与命令行

```python
from pathlib import Path
p = Path("data") / "a.txt"
p.exists(), p.suffix, p.stem, p.parent
for f in Path("data").glob("*.py"): ...     # 只当前层
for f in Path(".").rglob("*.py"): ...       # 递归
```

**别用字符串拼路径**：`"data/" + name` 在 Windows 上要反斜杠，`Path` 用 `/` 就跨平台；而且 `Path` 自带 `exists` / `suffix` 这些方法。

**命令行对照**：`find . -name "*.py"` ↔ `rglob("*.py")`；`grep -n "def " f.py` ↔ 逐行读 + `in`。先会用命令行，才知道 `pathlib` 在替你做什么。

## 5. 常见报错（病例库）

| 报错 | 原因 | 修法 |
| --- | --- | --- |
| `FileNotFoundError: [Errno 2]` | `r` 模式打开不存在的文件 / 路径拼错 | `Path(p).exists()` 先判；用绝对路径调试 |
| `UnicodeDecodeError: 'utf-8' codec can't decode` | 文件不是 UTF-8（常见 GBK/带 BOM） | 试 `gbk`、`utf-8-sig`；确认来源编码 |
| `TypeError: write() argument must be str` | 写了数字/列表 | `str(x)`；列表用 `"\n".join` |
| `IsADirectoryError` | 把目录当文件打开 | `is_file()` 先判 |
| `PermissionError: [Errno 13]` | 无权限 / 文件被占用 | 换目录或改权限；别用 sudo 硬来 |
| `FileExistsError` | `x` 模式已存在 | 改用 `w`（会清空）或先判断 |
| 文件内容「看起来写进去了但打开是空的」 | 没 `close()` / 没 `flush()` | 用 `with`；进程被 kill 前手动 `flush` |

## 6. 平台差异

| 点 | macOS / Linux | Windows |
| --- | --- | --- |
| 默认编码 | 多为 UTF-8 | 常是 GBK / cp936 → **必须显式 `encoding`** |
| 换行 | `\n` | 文本模式会转成 `\r\n`，读出来行尾可能带 `\r` |
| 路径分隔符 | `/` | `\`（`Path` 已处理，别手拼字符串） |
| 文件名大小写 | 区分 | 不区分（`A.txt` 与 `a.txt` 冲突） |

## 7. 自测

<details>
<summary>Q1：为什么 `with` 能保证关闭，即使 `raise` 了？</summary>

它把关闭放进 `__exit__`，而 `with` 在退出代码块时（正常或异常）都会调用 `__exit__`；异常会先经过 `__exit__` 再向上抛。
</details>

<details>
<summary>Q2：`for line in f` 与 `f.readlines()` 的差别到底在哪？</summary>

`readlines()` 一次性把**所有行读成 list 放内存**；`for line in f` 每次只取一行（文件对象是迭代器）。1GB 文件用前者直接 OOM。
</details>

<details>
<summary>Q3：`strip()` 处理行尾，什么时候会出事？</summary>

字段首尾有有意义空格时（CSV、对齐文本）。`strip()` 会一起剥掉；`rstrip("\n")` 只去换行。Windows 文件还要考虑 `\r`：`rstrip("\r\n")`。
</details>

<details>
<summary>Q4：dry-run 不是「多此一举」吗？</summary>

改文件名/删除类操作**不可撤销**（没有回收站）。dry-run 让「危险动作」先变成「可预览的输出」，跑一次确认列表对不对，再执行——和上线前灰度、SQL 先 BEGIN 看影响行数是同一个思路。
</details>

<details>
<summary>Q5：异或找唯一数，为什么不用 set？</summary>

set 能过，但空间 O(n)。异或是 O(1) 空间、O(n) 时间；面试要的是「你知道存在不占空间的解法」。前提：除了那个数，其余都出现两次。
</details>
