## 8. 面试题按章归

**一 SQL**：JOIN 的几种类型差别；WHERE 与 HAVING 的区别；为什么建议避免 SELECT *。

**二 索引**：为什么用 B+ 树；聚簇索引与非聚簇索引；最左前缀；覆盖索引与回表；索引失效的常见场景。

**三 事务**：ACID 各自靠什么保证；四种隔离级别解决什么；MVCC 怎么实现；幻读怎么处理。

**四 日志**：redo 与 undo 各管什么；binlog 与 redo 的区别；两阶段提交为什么需要。

**五 性能**：慢查询怎么定位；深分页怎么优化；连接池打满的表现。

**六 缓存**：缓存穿透/击穿/雪崩；双写一致性方案；Redis 过期与淘汰策略。

## 9. 红线

1. 不许只看图不建表：三张表的库必须自己写过，索引效果必须自己比过。
2. 不许背「八股答案」当机制：MVCC 讲不清版本链，就等于没学。
3. W23 之前不背面试题，先把执行计划与事务跑通。
4. 分库分表停在「概念 + 触发条件」，不要在没有数据量的项目里上分布式。

## 10. 自测

<details>
<summary>Q1：为什么 MySQL 索引用 B+ 树，不用 B 树或哈希？</summary>

B+ 树非叶子节点只存键、不存数据，同样一页能放更多分支，树更矮（磁盘 IO 少）；叶子节点串成链表，范围查询顺扫即可。哈希只适合等值查询，不支持范围与排序。
</details>

<details>
<summary>Q2：为什么「给这列加了索引还是不生效」？</summary>

常见四种：列上用了函数或运算、隐式类型转换（字符串列传数字）、以 % 开头的 LIKE、复合索引没走最左列。本质都是「优化器判断用索引不如全表」。
</details>

<details>
<summary>Q3：MVCC 是怎么让「读」不加锁的？</summary>

每行有两个隐藏字段（事务 id、回滚指针），版本链串起历史；读的时候按自己的 ReadView 判断哪个版本可见，于是读不加锁、写不阻塞读（快照读）。
</details>

<details>
<summary>Q4：redo log 和 binlog 有什么区别？为什么要两阶段提交？</summary>

redo 是 InnoDB 的物理日志（页级），负责崩溃恢复；binlog 是 Server 层的逻辑日志，负责主从复制与归档。两阶段提交保证两份日志一致：先写 redo 预提交，再写 binlog，最后 redo 提交。
</details>

<details>
<summary>Q5：缓存穿透、击穿、雪崩，分别怎么防？</summary>

穿透（查不存在的数据）：布隆过滤器或空值缓存；击穿（热点 key 过期）：互斥锁重建或逻辑过期；雪崩（大量 key 同时过期）：过期时间加随机、多级缓存、限流降级。
</details>
