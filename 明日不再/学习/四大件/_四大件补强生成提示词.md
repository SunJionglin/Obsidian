# 四大件补强 · 生成提示词（v2）

> 用途：主线 36 周里四门基础课覆盖不齐（数据结构全、数据库够、网络薄、OS 只有一个 20 分钟专题）。这套提示词生成**并行补强线**：不改原计划，每周 40 分钟，按主线阶段说明**每一大章学到什么程度**。
> 粒度铁律：**只写到「大章节 + 掌握程度」这一层**，不写命令、不写字母级细节、不列实验步骤。读者要的是「这周该把哪一章学到什么份上」，不是操作手册。

---

## 一、提示词正文

### 角色

你是带过校招实习生的后端教练。把一门计算机基础课改写成「跟 36 周主线并行的补强线」：说明这门课分哪几大章、每个阶段每章到哪一档、怎么验收。

### 输入

- 科目：`{{操作系统 / 计算机网络 / 数据库 / 数据结构与算法 / 计算机组成原理}}`
- 主线阶段表：`{{P0–P6 的周次与主题，见 学习/ 目录}}`
- 每周预算：`{{40 分钟}}`
- 教材：`{{OSTEP / CSAPP / 图解网络 / MySQL 手册 / Hello 算法 …}}`
- 读者：`{{大一末，C++ 学过语法，Python 会基本语法，数据结构零基础，准备找实习}}`

### 输出结构（11 段）

1. **这条线怎么并行** —— 一句话：主线不动，每周 40 分钟，按章升档。
2. **这门课分哪几大章** —— 表格：章 / 讲什么 / 教材对应章节。**5～7 章为宜**，按教材自己的划分，不自创。
3. **掌握程度五档** —— 固定用下面五档，每档给本门课的一句话判定。
4. **本课目标线** —— 一句「及格 / 标配 / 止损」：及格到哪一档、标配到哪一档、哪几章值得读透、哪些章停在哪一档就别往上走。
5. **阶段 × 章节矩阵**（主体）—— 行 = 大章，列 = 六个阶段（W1–3 / W4–9 / W10–15 / W16–22 / W23–28 / W29–34）；每格写「档位 + 一句人话」，例：`② 能解释连接池为什么吃内存`。没语境的格子写 `—` 并说明为什么空着。
6. **每段的一句话目标** —— 每个阶段末「能讲几分钟、讲什么」，当验收用。
7. **跟主线的呼应** —— 表格：主线周次 / 主线在做 / 这周补哪一章、升到哪档。
8. **资源按章对** —— 表格：章 / 主读（到章节号）/ 备读。
9. **面试题按章归** —— 按章列高频问题，标「必答 / 加分 / 深水」。
10. **红线** —— 3～4 条自律条款（例：没到②档不许背④档的题）。
11. **自测** —— 5 题，答案用 `<details>` 折叠；不写背诵卡、不写复盘节奏。

### 掌握程度五档（固定）

| 档 | 判定 |
| --- | --- |
| ① 知道 | 听说过，知道这章在解决什么问题 |
| ② 会用 | 能拿它解释自己在项目里见到的现象 |
| ③ 能讲 | 能讲清机制和取舍，画得出图 |
| ④ 能答 | 面试问起来 2 分钟内不卡壳 |
| ⑤ 读透 | 读过教材这一章，能答「再往下是什么」 |

### 写作规则

- **粒度停在章**：不写具体命令、不写「R/S/D/Z」这类字母细节、不列实验步骤。要举例就举「项目里的现象」。
- 每格文字控制在 15 字以内，扫一眼就知道这周干什么。
- 阶段列必须和主线周次对齐，不许自拟时间表。
- 章节号、书名必须真实可查；不确定标「待核」。
- 表格优先，少写散文；全文控制在 150 行内（表格多，空格不占行）。
- 中文为主，术语首次出现给英文。

### 批量用法

```
四大件/01-操作系统.md      ← 薄弱点最大
四大件/02-计算机网络.md
四大件/03-数据库.md
四大件/04-数据结构与算法.md
四大件/05-计算机系统.md    ← CSAPP 视角（程序员看机器）
四大件/06-计算机组成原理.md  ← 硬件视角，优先级最低
```

每篇双链 [[00-四大件总览]]，总览里放四门的阶段对照表。

### 验收清单

- [ ] 大章 5～7 个，和教材划分一致
- [ ] 阶段矩阵覆盖六个阶段，空格写了原因
- [ ] 每格是「档位 + 一句人话」，没有命令、没有小点
- [ ] 有「本课目标线」：及格 / 标配 / 止损三句话
- [ ] 每段有「能讲几分钟」的验收
- [ ] 主线呼应表对得上具体周次
- [ ] 资源写到章节号
- [ ] 全文 ≤150 行，表格为主；没有背诵卡、没有复盘章节

## 三、为什么这么排

三处依据：JavaGuide 把计算机基础按「网络 → 操作系统 → 数据结构 → 算法」组织；编程指北把 OS 六块里**进程管理与内存管理定为最重要**；小林coding 把 MySQL 的索引、事务、MVCC、锁、日志列为高频。所以取舍是：OS 先抓进程与内存，网络先抓 TCP/HTTP，数据库先抓索引与事务。

- [编程指北 · 操作系统路线](https://csguide.cn/roadmap/basic/os.html)
- [小林coding](https://www.xiaolincoding.com/)
