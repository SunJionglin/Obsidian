# 06 计算机组成原理（并行补强）

## 1. 这条线怎么并行

这是四门（加系统线共六门）里**优先级最低**的一门。原因很简单：后端实习面试很少深问数据通路和流水线，问到的多是「一条指令怎么执行」「Cache 为什么快」「中断和 DMA 区别」这三类常识。

和另外两门的边界要划清：

| 线 | 视角 | 典型问题 |
| --- | --- | --- |
| [[01-操作系统]] | 管理者 | 进程怎么调度、内存怎么分 |
| [[05-计算机系统]] | 程序员 | 代码编译成什么、为什么慢 |
| 本线 | 造机器的人 | CPU 内部怎么算、流水线怎么填、总线怎么连 |

所以这门课定位是「**把机器拆开看一眼**」：W29 之后再升档，平时不占主线时间。

## 8. 面试题按章归

**一 运算器**：为什么用补码表示负数；整数溢出怎么发现。

**二 指令系统**：RISC 与 CISC 的区别；寻址方式有哪些（面试偶尔问）。

**三 数据通路**：一条指令的取指-译码-执行-写回（必答的常识题）。

**四 流水线**：流水线为什么能提高吞吐；数据冒险怎么解决；分支预测是做什么的（深水）。

**五 存储系统**：Cache 为什么快；三种映射方式的区别；写命中怎么处理；Cache 一致性是什么（加分）。

**六 总线与 IO**：中断和 DMA 的区别；为什么 IO 密集的程序要减少系统调用。

## 9. 红线

1. 这门课**不许占主线时间**：没有明确需求（面试/考研/嵌入式）就只做 ② 档。
2. 不许背流水线公式而不懂图；不懂就先画五级流水再算。
3. 数据通路这种「画大图」的章节，非考研可以只读不画。
4. 与 [[05-计算机系统]] 重叠的部分（数据表示、存储层次），以系统线为主，本线只补硬件实现视角。

## 10. 自测

<details>
<summary>Q1：为什么流水线能提高吞吐却不一定降低单条指令的延迟？</summary>

流水线让多条指令的不同阶段重叠执行，单位时间完成的指令数变多（吞吐上升）；但单条指令要走完所有阶段，加上寄存器开销，延迟反而可能变长。
</details>

<details>
<summary>Q2：Cache 三种映射方式各有什么取舍？</summary>

直接映射：简单、冲突多；全相联：冲突少、比较电路昂贵；组相联：折中，实际 CPU 常用。核心矛盾是「查找速度」与「冲突概率」。
</details>

<details>
<summary>Q3：中断和 DMA 的区别？</summary>

中断是「设备通知 CPU 来处理」，数据仍要 CPU 搬运；DMA 是让外设直接和内存交换数据，CPU 只在开始时配置、结束时收通知，适合大批量传输（磁盘、网卡）。
</details>

<details>
<summary>Q4：为什么说「Cache 一致性」是多核才有的问题？</summary>

单核只有一个 Cache 视角，内存与 Cache 由硬件保证一致；多核各有私有 L1，同一地址可能在不同核的 Cache 里不一致，需要 MESI 之类的协议协调。
</details>

<details>
<summary>Q5：作为一名后端开发，这门课最值得记住的三件事是什么？</summary>

一是存储层次的速度差（寄存器/ Cache /内存/磁盘差几个数量级）；二是中断与 DMA 说明「IO 贵在次数不贵在大小」；三是流水线与分支预测解释「为什么分支多的代码慢」。
</details>
