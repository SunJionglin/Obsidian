## 六、项目 B：文档问答 Web 应用（W10 立项 → W15 收尾）

**功能**

- 上传 PDF/Markdown → 切分 → 向量化入库。
- 提问 → 检索 → 带引用回答；检索不到时诚实兜底。
- 历史记录、访问码（简单登录）。
- 管理页：查看文档列表与切分结果。

**技术栈**：FastAPI + MySQL + 向量库（Chroma）+ embedding API + LLM API + Docker。

**为什么用 MySQL**

- 国内招聘和公司存量最多，面经、资料、踩坑帖都多，面试八股（InnoDB、索引、MVCC、binlog）直接对口。
- InnoDB 的 B+ 树索引、事务与 MVCC、redo/undo log、主从复制，是后端面试的主力考点。
- 向量检索不押数据库扩展，业务数据放 MySQL，向量单独放 Chroma，架构更贴近国内公司常见做法。
- 面试被问「为什么不用 PostgreSQL」，答业务数据用 MySQL 更贴近团队栈，向量检索交给独立向量库；PG 的差异点了解，需要能切。

**里程碑**

| 周 | 任务 |
| --- | --- |
| W10 | 立项：需求清单、接口设计、架构图（数据流） |
| W11 | 数据层：用户/文档/切片/消息四张表；迁移 |
| W12 | 摄入：上传接口、切分、embedding、入库 |
| W13 | 问答：检索 top-k、拼接 prompt、引用、历史 |
| W14 | 部署：Docker + Nginx + CI；wrk 压测 100 并发 |
| W15 | 评估：20 问测试集，记录命中率/延迟；README + 简历 v1 |

**验收**：线上可访问；面试官能当场用；能讲清「检索不到时怎么办」「长文档怎么切」。

**简历写法**：「FastAPI + MySQL + Chroma 的 RAG 文档问答：上传→切分→检索→带引用回答，Docker 部署上线，20 问测试集命中率 X%。」
