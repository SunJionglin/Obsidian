## 六、项目 C：旗舰 AI 应用（W16 立项 → W22 收尾）

**选题四选一**

1. 课程/个人知识库助手：多文档、混合检索、引用、评估面板。
2. 代码库问答助手：仓库解析、切片、检索、引用到文件行。
3. 客服/工单助手：意图识别、工具调用（查订单）、人工兜底。
4. **后端研发助手（偏「AI 辅助后端开发」）**：代码库检索 + Git/数据库/日志的 MCP 工具 + 自动 review/测试生成 + 采纳率评估。

**如果目标是「AI 辅助后端开发」而不是做 AI 产品**，把项目选第 4 种，并额外补齐四块

- AI 编码工具工作流：Cursor / Claude Code / Codex 类工具的规则文件、上下文管理、diff 审阅，会用不等于用得好。
- 代码库上下文工程：repo 索引、AST/符号检索、diff 与调用链理解，这是「AI 辅助开发」和「通用 RAG」的分界。
- 接进研发流程：issue → PR、自动 review、测试生成，CI 里跑 AI 检查。
- 验收 AI 产出：测试、静态检查、评估建议采纳率与缺陷发现率。

评估指标相应换成「建议采纳率、缺陷发现数、单次 review 耗时」；面试时讲的是「我把 AI 接进了研发流程」，不是「我做了个问答机器人」。

**必须包含**

- eval 集 30–50 条 + 指标面板（命中率/忠实度/延迟/成本）。
- 错误日志与请求追踪。
- 部署上线 + README 架构图 + 技术博客。
- 10 个真实用户试用反馈。

**加分项**：一个 C++/pybind11 性能模块（文本预处理或相似度计算），配 benchmark——这是「跨语言优化」的面试素材。

**里程碑**

| 周 | 任务 |
| --- | --- |
| W16 | 选题、架构图、eval 集设计（能答/不能答/误导三类） |
| W17 | 检索层：BM25+向量+rerank，跑通 20 条 eval |
| W18 | 评估面板 + 回归脚本，输出指标报告 v1 |
| W19 | 工具层：MCP server（文件/数据库/搜索之一） |
| W20 | 加固：限流、缓存、超时、注入防护、成本统计 |
| W21 | 上线、10 人试用、写博客 |
| W22 | 30 分钟讲稿 + 演示视频 + 简历 v2 |

**验收**：面试官能当场用；能回答「为什么不用现成框架」「检索错了怎么修」「流量涨 10 倍怎么办」。

**简历写法**：「带评估的 RAG 知识库：混合检索 + rerank + MCP 工具，eval 30+ 条、命中率 X%、成本每问 Y 分，10 人试用，部署上线。」

**选第 4 种时**：「后端研发助手：代码库检索 + Git/DB/日志 MCP 工具 + 自动 review 与测试生成，建议采纳率 X%、单次 review 耗时降 Y%。」
