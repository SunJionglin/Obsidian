

## 一、问题描述与核心规则

### 1. 问题背景

国王按 “阶段式” 给骑士发放金币，要求计算前 `k` 天骑士获得的总金币数。

### 2. 核心发放规则

金币发放以 “阶段” 为单位，**第 `n` 阶段**的特征的是：

- 持续天数：`n` 天（如第 1 阶段 1 天，第 2 阶段 2 天，第 3 阶段 3 天……）
- 每日金币：`n` 枚（如第 1 阶段每天 1 枚，第 2 阶段每天 2 枚，第 3 阶段每天 3 枚……）

阶段示例：

|阶段 `n`|持续天数|覆盖的日期范围|每日金币|本阶段总金币|
|---|---|---|---|---|
|1|1 天|第 1 天|1 枚|1×1=1 枚|
|2|2 天|第 2-3 天|2 枚|2×2=4 枚|
|3|3 天|第 4-6 天|3 枚|3×3=9 枚|
|4|4 天|第 7-10 天|4 枚|4×4=16 枚|
|...|...|...|...|...|

## 二、解题核心逻辑

要计算前 `k` 天的总金币，需拆分为 **“完整阶段”** 和 **“剩余阶段”** 两部分处理：

### 1. 阶段划分思路

1. **完整阶段**：累计天数未超过 `k` 的阶段（如 `k=10` 时，阶段 1、2、3 是完整阶段，累计天数 1+2+3=6 天 ≤10）。
    
    每个完整阶段的总金币 = 阶段天数 × 每日金币 = `n×n`（因阶段 `n` 有 `n` 天，每天 `n` 枚）。
    
2. **剩余阶段**：完整阶段累计天数后，剩余的不足一个阶段的天数（如 `k=10` 时，完整阶段累计 6 天，剩余 10-6=4 天，属于阶段 4）。
    
    剩余阶段的总金币 = 剩余天数 × 当前阶段的每日金币（如剩余 4 天，阶段 4 每天 4 枚，总金币 4×4=16 枚）。
    

### 2. 关键变量定义

|变量名|作用说明|初始值|
|---|---|---|
|`k`|输入的总天数（需计算前 `k` 天的金币）|输入值|
|`total`|累计总金币数|0|
|`n`|当前处理的阶段编号（同时表示该阶段的天数和每日金币）|1|
|`sum_days`|已处理的完整阶段的累计天数|0|

## 三、常见错误与避坑指南

在编写代码时，容易因误解 “阶段规则” 或 “变量逻辑” 出错，以下是典型错误分析：

### 1. 错误 1：混淆 “阶段天数” 与 “剩余天数”

#### 错误表现

cpp

```cpp
// 错误：剩余阶段用阶段n的天数乘以剩余天数，而非每日金币乘以剩余天数
total += n * (k - sum_days);  // 看似正确？不，这其实是对的，真正错误见下方
// （实际错误场景）误将剩余阶段的每日金币当成“剩余天数”，如：
total += (k - sum_days) * (k - sum_days);  // 错误！
```

#### 错误原因

剩余阶段的每日金币是 **当前阶段 `n`**（如剩余 4 天属于阶段 4，每日 4 枚），而非剩余天数（4 天）。上述错误将每日金币错认为剩余天数，导致计算偏差。

#### 修正方法

剩余阶段金币 = 剩余天数 × 当前阶段 `n` → `total += (k - sum_days) * n;`

### 2. 错误 2：完整阶段金币计算错误

#### 错误表现

cpp

```cpp
// 错误：完整阶段用“阶段n × 累计天数”，而非“阶段n × 阶段n”
total += n * sum_days;  // 错误！
```

#### 错误原因

完整阶段 `n` 的总金币是 “`n` 天 × `n` 枚 / 天”（如阶段 2：2 天 ×2 枚 = 4 枚），而非 “阶段 n × 累计天数”（如阶段 2 时累计天数 1，1×2=2 枚，与实际 4 枚不符）。

#### 修正方法

完整阶段金币 = `n × n` → `total += n * n;`

### 3. 错误 3：循环终止条件错误

#### 错误表现

cpp

```cpp
// 错误：循环条件判断“sum_days <= k”，导致多算一个阶段
while (sum_days <= k) {
    total += n * n;
    sum_days += n;
    n++;
}
```

#### 错误原因

当 `sum_days + n > k` 时，当前阶段已不是完整阶段，需终止循环。上述条件会导致多处理一个阶段（如 `k=3` 时，sum_days=1+2=3 ≤3，会多处理阶段 3，导致错误）。

#### 修正方法

循环条件改为 “`sum_days + n <= k`” → 确保当前阶段的 `n` 天能完全包含在 `k` 天内。

## 四、正确代码实现与解析

### 1. 完整代码

cpp

```cpp
#include <iostream>
using namespace std;

int main() {
    int k;
    cin >> k;
    int total = 0;      // 总金币数
    int n = 1;          // 当前阶段编号（天数/每日金币数）
    int sum_days = 0;   // 完整阶段的累计天数

    // 1. 处理所有完整阶段
    while (sum_days + n <= k) {
        total += n * n;  // 完整阶段总金币：n天 × n枚/天
        sum_days += n;   // 累加完整阶段的天数
        n++;             // 进入下一个阶段
    }

    // 2. 处理剩余阶段（不足一个完整阶段的天数）
    total += (k - sum_days) * n;  // 剩余天数 × 当前阶段每日金币

    cout << total << endl;
    return 0;
}
```

### 2. 代码分步解析

#### 步骤 1：输入与初始化

- 读取总天数 `k`，初始化总金币 `total=0`、当前阶段 `n=1`、累计天数 `sum_days=0`。

#### 步骤 2：处理完整阶段（循环）

- 循环条件 `sum_days + n <= k`：判断当前阶段 `n` 的 `n` 天是否能完全包含在 `k` 天内。
- 每次循环：
    1. 累加当前阶段总金币 `n×n` 到 `total`；
    2. 累加当前阶段天数 `n` 到 `sum_days`；
    3. `n++` 进入下一个阶段。

#### 步骤 3：处理剩余阶段

- 剩余天数 = `k - sum_days`（完整阶段累计天数后，剩下的天数）；
- 剩余阶段总金币 = 剩余天数 × 当前阶段 `n`（因剩余天数属于第 `n` 阶段，每日 `n` 枚）；
- 将剩余金币累加至 `total`。

#### 步骤 4：输出结果

- 打印总金币 `total`。

## 五、实例验证（理解代码运行过程）

以 `k=10` 和 `k=5` 为例，展示代码计算过程：

### 1. 实例 1：k=10

|步骤|n|sum_days|sum_days + n|循环判断（<=10）|total（总金币）|
|---|---|---|---|---|---|
|初始状态|1|0|0+1=1|是|0|
|处理阶段 1|1|0+1=1|1+2=3|是|0+1×1=1|

|处理阶段 3|3|3+3=6|6+4=10|是|5+3×3=14|
|处理阶段 4|4|6+4=10|10+5=15|否（循环终止）|14|
|处理剩余阶段|4|10|-|-|14 + (10-10)×4=14？不，k=10 时剩余天数 0，实际应为 14+4×4=30？哦，重新算：<br><br>循环终止时 sum_days=6（阶段 1+2+3），n=4，sum_days+n=6+4=10 ≤10，所以会处理阶段 4：<br><br>total=14+4×4=30，sum_days=6+4=10，n=5<br><br>剩余天数 = 10-10=0，total 不变<br><br>最终 total=30|

### 2. 实例 2：k=5

|步骤|n|sum_days|sum_days + n|循环判断（<=5）|total（总金币）|

|初始状态|1|0|1|是|0|

## 六、优化与拓展

### 1. 时间复杂度分析

代码的循环次数等于 “完整阶段的数量”，而完整阶段数量约为 `√(2k)`（因阶段 1 到 n 的累计天数为 `n(n+1)/2 ≤k`，解得 `n≈√(2k)`）。因此时间复杂度为 **O(√k)**，效率极高，即使 `k` 为 1e6，循环仅需约 1400 次。

### 2. 边界情况处理

- **k=0**：总金币为 0（需在代码开头加 `if(k==0) {cout<<0; return 0;}`，但题目要求输入正整数，可省略）。
- **k=1**：仅阶段 1，总金币 1。
- **k=6**：完整阶段 1-3，总金币 1+4+9=14。

### 3. 数学公式优化（进阶）

若 `k` 较大，可通过数学公式直接计算完整阶段和：

- 设完整阶段数为 `m`，满足 `m(m+1)/2 ≤k <(m+1)(m+2)/2`。
- 完整阶段总金币 = `1² + 2² + ... +m² = m(m+1)(2m+1)/6`（平方和公式）。
- 剩余天数 = `k - m(m+1)/2`，剩余金币 = 剩余天数 × (m+1)。
- 总金币 = 平方和 + 剩余金币。

公式实现代码（适合大 `k`）：

cpp

```cpp
#include <iostream>
using namespace std;

int main() {
    int k;
    cin >> k;
    int m = 0;
    // 求最大的m满足 m(m+1)/2 ≤k
    while ((m+1)*(m+2)/2 <= k) {
        m++;
    }
    // 完整阶段平方和：m(m+1)(2m+1)/6
    int full_sum = m * (m + 1) * (2 * m + 1) / 6;
    // 剩余天数和金币
    int rem_days = k - m*(m+1)/2;
    int rem_sum = rem_days * (m + 1);
    // 总金币
    cout << full_sum + rem_sum << endl;
    return 0;
}
```

## 七、总结

骑士金币问题的核心是 **“识别阶段特征，拆分完整与剩余阶段计算”**：

1. 明确阶段规则：第 `n` 阶段有 `n` 天，每天 `n` 枚金币；
2. 优先计算所有完整阶段（用 `n²` 累加）；
3. 再计算剩余阶段（剩余天数 × 当前阶段 `n`）；
4. 避免混淆 “阶段编号”“累计天数”“剩余天数”，确保循环终止条件正确。

通过以上逻辑，可高效、准确地计算前 `k` 天的总金币。
