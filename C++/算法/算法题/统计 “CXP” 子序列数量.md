# 统计 “CXP” 子序列数量：代码错误分析与优化笔记

## 一、问题背景

需求：给定仅包含大写字母 C、X、P 的字符串，统计其中不同 “CXP” 子序列的数量（子序列按字符位置不同视为不同，需满足 C 在 X 前、X 在 P 前）。

## 二、初始代码思路与致命错误

### 1. 初始代码核心逻辑

通过**三层嵌套循环**遍历所有可能的字符组合：

- 外层循环（i）：遍历所有 “C” 的位置；
- 中层循环（j）：遍历 i 之后所有 “X” 的位置；
- 内层循环（k）：遍历 j 之后所有 “P” 的位置；
- 每找到一组符合条件的（i,j,k），计数 + 1。

### 2. 致命错误：内层循环变量更新错误

#### 错误代码段

cpp

```cpp
for(int k=j+1; k<n; j++)  // 错误：循环变量更新为j，而非k
```

#### 错误原因与后果

- **循环变量未正确更新**：内层循环的控制变量是`k`，但更新语句写为`j++`，导致`k`始终等于初始值（j+1），永远满足`k < n`，陷入**无限循环**；
- **中层循环变量被篡改**：`j`是中层循环的控制变量，被内层循环意外修改后，中层循环的遍历逻辑完全混乱，无法正确找到 X 的位置。

## 三、代码修正方案

### 1. 关键修正点

将内层循环的`j++`改为`k++`，确保`k`能正常自增，遍历 j 之后的所有字符。

### 2. 修正后的完整代码

cpp

```cpp
#include <iostream>
#include <vector>
#include <string>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<char> str(n);  // 用vector存储字符串字符
    for(int i=0; i<n; i++) {
        cin >> str[i];
    }
    
    int count = 0;
    // 三层循环：按C→X→P的顺序查找合法子序列
    for(int i=0; i<n; i++) {
        if(str[i] == 'C') {  // 外层：找到当前C的位置i
            for(int j=i+1; j<n; j++) {
                if(str[j] == 'X') {  // 中层：找到i之后X的位置j
                    // 内层：找到j之后P的位置k（修正：k++）
                    for(int k=j+1; k<n; k++) {  
                        if(str[k] == 'P') {
                            count++;  // 符合条件的子序列计数+1
                        }
                    }
                }
            }
        }
    }
    cout << count << endl;
    return 0;
}
```

### 3. 修正后逻辑验证（示例）

测试用例：字符串`"CXCP"`（n=4）

- 外层 i=0（str [0]='C'）：
    - 中层 j=1（str [1]='X'）：
        - 内层 k=2（str [2]='C'，不计数）、k=3（str [3]='P'，count=1）；
    - 中层 j=2（str [2]='C'，跳过）、j=3（str [3]='P'，跳过）；
- 外层 i=1（str [1]='X'，跳过）、i=2（str [2]='C'）：
    - 中层 j=3（str [3]='P'，跳过）；
- 最终 count=1（正确，仅 “C (0) X (1) P (3)” 一个子序列）。

## 四、时间复杂度分析

### 1. 修正后三层循环的复杂度

- 时间复杂度：**O(n³)**（n 为字符串长度），三层循环需遍历所有可能的 i<j<k 组合；
- 适用场景：仅当 n 较小时（如 n≤100）可正常运行；
- 局限性：n 较大时（如 n≥1000），循环次数过多（10⁹次以上），会导致超时。

## 五、高效优化方案（前缀和 + 后缀和）

### 1. 优化核心思路

利用 “每个 X 的贡献 = 左侧 C 的数量 × 右侧 P 的数量”，将三层循环降为两层遍历：

- 预计算**后缀 P 数量**：用数组存储每个位置右侧（包括自身）的 P 总数；
- 实时统计**左侧 C 数量**：遍历字符串时，遇到 C 则累计计数；
- 遇到 X 时，直接累加 “左侧 C 数 × 右侧 P 数”，无需遍历 P。

### 2. 优化后代码

cpp

```cpp
#include <iostream>
#include <string>
using namespace std;

int main() {
    int n;
    string s;
    cin >> n >> s;  // 直接用string存储，简化输入
    
    long long count = 0, left_c = 0;  // left_c：实时统计左侧C的数量
    long long suffix_p[n + 2] = {0};  // suffix_p[i]：i位置右侧（含i）的P总数
    
    // 第一步：计算后缀P数量（从后往前遍历）
    for (int i = n - 1; i >= 0; --i) {
        suffix_p[i] = suffix_p[i + 1] + (s[i] == 'P');
    }
    
    // 第二步：遍历字符串，统计C并计算X的贡献
    for (int i = 0; i < n; ++i) {
        if (s[i] == 'C') {
            left_c++;  // 遇到C，左侧C数量+1
        } else if (s[i] == 'X') {
            // X的贡献 = 左侧C数 × 右侧P数（i+1右侧的P）
            count += left_c * suffix_p[i + 1];
        }
    }
    
    cout << count << endl;
    return 0;
}
```

### 3. 优化后复杂度与优势

- 时间复杂度：**O(n)**（仅两次遍历字符串：一次算后缀 P，一次统计 C 和 X 的贡献）；
- 空间复杂度：O (n)（仅存储后缀 P 数组，可进一步优化为 O (1)）；
- 适用场景：支持大规模输入（如 n=1e5），无超时风险；
- 防溢出：用`long long`存储计数，避免因乘积过大导致整数溢出。

## 六、总结

1. **错误关键**：内层循环变量更新错误（j++→k++），是导致程序崩溃的核心，需注意循环控制变量的一致性；
2. **方法选择**：
    - 小规模数据（n≤100）：修正后的三层循环（逻辑直观，代码简单）；
    - 大规模数据（n≥1000）：前缀和 + 后缀和（O (n) 复杂度，高效稳定）；
3. **核心思想**：统计子序列时，若需满足 “前→中→后” 顺序，可通过 “预计算后续元素数量 + 实时统计前置元素数量” 降低循环层数，优化效率。
