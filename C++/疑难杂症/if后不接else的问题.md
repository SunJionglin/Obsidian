在代码中，有些`if`语句后不需要`else`，核心原因是：**`if`块中使用了`continue`（或`return`等跳转语句），已经通过 “跳过后续代码” 实现了逻辑分支，无需再用`else`包裹 “不满足条件时的代码”**。

以修复后代码中 “跳过分隔符” 的`if`语句为例：

cpp

运行

```cpp
for (int i = 0; i < 12; i++) {  // 遍历前12位（不含最后一位识别码）
    if (i == 1 || i == 5 || i == 11) {  // 判断是否为分隔符位置
        continue;  // 若满足条件，直接跳过本次循环的后续代码
    }
    // 以下代码：只有不满足上面的if条件时，才会执行（处理数字字符）
    cin >> arr[i];
    int num = arr[i] - '0';
    jud += num * weight;
    weight++;
    numCount++;
}
```

### 为什么这里不需要`else`？

1. **`continue`的作用**：
    
    当`if`条件成立（`i`是分隔符位置）时，`continue`会立即结束本次循环，跳过循环体中`continue`后面的所有代码，直接进入下一次循环（`i`递增）。
    
2. **逻辑自动分支**：
    
    - 若满足`if`条件：执行`continue`，跳过后续代码（不处理分隔符）；
    - 若不满足`if`条件：不执行`continue`，自然会执行`if`块后面的代码（处理数字字符）。
    
    这种情况下，“不满足条件时要执行的代码” 直接写在`if`块后面即可，无需用`else`包裹 —— 用`else`反而会增加代码嵌套，降低可读性。
    

### 类似场景：`return`语句也可省略`else`

如果`if`块中用了`return`（函数返回），同样不需要`else`，例如：

cpp

运行

```cpp
bool isPositive(int num) {
    if (num <= 0) {
        return false;  // 不满足“正数”，直接返回
    }
    // 若走到这里，说明num>0，直接返回true（无需else）
    return true;
}
```

### 总结

当`if`块中包含`continue`（循环中）、`break`（循环或 switch 中）、`return`（函数中）等 “跳转语句” 时，**不满足`if`条件的逻辑会自动执行`if`块后面的代码**，此时`else`是多余的 —— 省略`else`能让代码更简洁、逻辑更清晰。

在 ISBN 代码中，“跳过分隔符” 的`if`语句正因为用了`continue`，所以无需`else`就能正确区分 “处理分隔符” 和 “处理数字” 两种逻辑。
