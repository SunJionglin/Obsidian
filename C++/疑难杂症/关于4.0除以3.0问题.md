为什么有时是4.0/3.0而不是4/3

在 C/C++ 等编程语言中，`4.0/3.0` 和 `4/3` 的区别源于**整数除法**和**[[浮点数]]除法**的不同规则，这直接影响计算结果的精度。

### 核心原因：[[数据结构]]决定除法规则

- **`4/3` 是整数除法**：两个操作数（4 和 3）都是整数，此时除法会执行**整数除法**—— 结果只保留整数部分，小数部分被截断（不是四舍五入）。
    
    因此 `4/3` 的结果是 `1`（而非 1.333...）。
    
- **`4.0/3.0` 是[[浮点数]]除法**：两个操作数（4.0 和 3.0）是[[浮点数]]（double 类型），此时除法会执行**[[浮点数]]除法**—— 结果保留小数部分，得到精确的浮点结果。
    
    因此 `4.0/3.0` 的结果是 `1.333333...`。
    

### 举例说明差异

看一段简单的代码：

cpp

运行

```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "4/3 = " << 4/3 << endl;         // 整数除法，结果为 1
    cout << "4.0/3.0 = " << 4.0/3.0 << endl; // [浮点数]除法，结果为 1.33333
    return 0;
}
```

输出结果：

plaintext

```plaintext
4/3 = 1
4.0/3.0 = 1.33333
```

### 什么时候需要用 `4.0/3.0`？

当计算需要**保留小数精度**时，必须使用[[浮点数]]除法。例如：

计算球体体积的公式是 `(4/3) * π * r³`，如果用 `4/3` 会导致结果错误：

cpp

运行

```cpp
#include <iostream>
#include <cmath>
using namespace std;

int main() {
    double r = 3.0;
    // 错误：4/3 是整数除法，结果为 1
    double wrong = (4/3) * M_PI * pow(r, 3);
    // 正确：4.0/3.0 是[浮点数]除法，结果为 1.333...
    double correct = (4.0/3.0) * M_PI * pow(r, 3);
    
    cout << "错误结果：" << wrong << endl;   // 约 84.823
    cout << "正确结果：" << correct << endl; // 约 113.097
    return 0;
}
```

### 总结

- `4/3`：整数除法，结果是整数（截断小数），适用于只需要整数部分的场景。
- `4.0/3.0`：[[浮点数]]除法，结果是带小数的[[浮点数]]，适用于需要精确小数结果的场景（如科学计算、几何公式等）。

本质是通过**操作数的类型**（整数 / [[浮点数]]）告诉编译器：需要执行哪种除法规则。
