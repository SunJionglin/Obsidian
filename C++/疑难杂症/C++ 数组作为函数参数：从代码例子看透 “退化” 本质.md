

## 引言：一段代码引发的疑问

先看这段代码（来自你的实现）：

cpp

运行

```cpp
#include<iostream>
#include<string>
using namespace std;

struct person
{
    string name;
    int score[3];  // 存储三科成绩的数组
    int tot;       // 总分
};

// 计算数组中三个元素的和（三科总分）
int add(int score[3])  
{
    int tot = score[0] + score[1] + score[2];
    return tot;
}

int main()
{
    int N;
    cin >> N;
    person p[1000];
    for(int i=0; i<N; i++)
    {
        cin >> p[i].name;
        for(int j=0; j<3; j++)
        {
            cin >> p[i].score[j];  // 给数组赋值
        }
        p[i].tot = add(p[i].score);  // 传递数组作为参数
    }
    return 0;
}
```

这段代码中，`struct person` 里定义了 `int score[3]`（一个存储 3 个成绩的数组），而 `add` 函数的参数也是 `int score[3]`，调用时却直接传 `p[i].score`—— 为什么数组可以这样传递？`int score[3]` 作为参数时，真的是 “传递整个数组” 吗？

## 核心知识点：数组作为函数参数的本质

在 C++ 中，**数组作为函数参数时，不会传递整个数组的副本，而是隐式转换为 “指向数组首元素的指针”**。这种特性称为 “数组退化”（Array Decay）。

### 1. 数组名的双重身份

数组名在不同场景下含义不同：

- **大多数情况**：数组名代表 “数组首元素的地址”（即指针）。例如 `p[i].score` 作为数组名，本质是指向 `score[0]` 的指针（类型为 `int*`）。
- **少数例外**：当数组名用于 `sizeof`、`&`（取地址）等操作时，代表 “整个数组”。例如 `sizeof(p[i].score)` 会返回整个数组的大小（3 个 int，即 `3*4=12` 字节，取决于编译器）。

### 2. 函数参数中的 “数组” 其实是指针

`add` 函数的参数 `int score[3]` 看起来是 “接收一个大小为 3 的 int 数组”，但编译器会自动将其解读为 `int* score`（指向 int 的指针）。

这意味着以下三种函数声明是**完全等价**的：

cpp

运行

```cpp
// 三种写法本质相同，都是接收int*指针
int add(int score[3]);   // 你的代码中使用的形式
int add(int score[]);    // 省略大小的写法
int add(int* score);     // 显式指针写法
```

编译器只关心 “传递的是指针”，不检查数组的实际大小（即使你写了 `[3]`，也不代表只能传递大小为 3 的数组）。

### 3. 为什么你的代码能正常工作？

在你的例子中：

- `p[i].score` 是 `person` 结构体中的数组，存储 3 个成绩（语文、数学、英语）。
- 调用 `add(p[i].score)` 时，传递的是 `score` 数组首元素的地址（即 `&score[0]`）。
- `add` 函数内部的 `score[0]`、`score[1]`、`score[2]`，本质是通过指针访问数组元素：
    - `score[0]` 等价于 `*(score + 0)`（首元素）
    - `score[1]` 等价于 `*(score + 1)`（第二个元素）
    - `score[2]` 等价于 `*(score + 2)`（第三个元素）

因为你明确知道数组有 3 个元素（三科成绩），所以即使函数不知道数组实际大小，也能正确计算总和。

## 注意事项：数组退化的 “坑”

数组退化带来了效率（无需复制整个数组），但也有隐患：

### 1. 函数内部无法获取数组实际大小

如果在 `add` 函数中用 `sizeof(score)` 计算 “数组大小”，得到的是**指针的大小**（而非数组大小）：

cpp

运行

```cpp
int add(int score[3])
{
    // 错误！sizeof(score)是指针的大小（例如8字节，取决于系统）
    cout << "sizeof(score) = " << sizeof(score) << endl;  // 输出8（64位系统）
    return score[0] + score[1] + score[2];
}
```

这是因为 `score` 已退化为指针，`sizeof(score)` 计算的是指针变量本身的大小，而非数组总字节数。

### 2. 必须手动保证访问不越界

如果传递的数组大小小于 3，函数内部访问 `score[2]` 会导致**数组越界**（未定义行为，可能崩溃）：

cpp

运行

```cpp
int main()
{
    int small_arr[2] = {10, 20};
    add(small_arr);  // 危险！add会访问small_arr[2]（越界）
    return 0;
}
```

你的代码之所以安全，是因为逻辑上保证了 `score` 数组一定有 3 个元素（三科成绩），但其他场景需格外注意。

### 3. 如何传递数组大小？

如果数组大小不固定，需额外传递一个参数表示大小：

cpp

运行

```cpp
// 计算n个元素的和（更通用）
int add(int score[], int n)  
{
    int tot = 0;
    for(int i=0; i<n; i++)
    {
        tot += score[i];
    }
    return tot;
}

// 调用时传递数组和大小
p[i].tot = add(p[i].score, 3);  // 明确告诉函数：数组有3个元素
```

## 总结

1. **本质**：C++ 中数组作为函数参数时，会退化为指向首元素的指针，传递的是地址而非整个数组。
2. **等价写法**：`int score[3]`、`int score[]`、`int* score` 在函数参数中完全等价。
3. **你的代码为何正确**：通过指针访问数组元素，且逻辑上保证了数组有 3 个元素（三科成绩）。
4. **注意**：函数无法获取数组实际大小，需手动控制访问范围，避免越界。

理解数组退化机制，能帮你更清晰地处理函数与数组的交互，避免隐藏的 bug~
