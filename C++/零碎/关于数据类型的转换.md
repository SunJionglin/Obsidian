在 C++ 中，推荐使用 `static_cast<double>(i)` 而非 C 风格的 `(double)i`，核心原因是 **`static_cast` 是类型安全的、语义清晰的显式转换**，能规避隐式转换和旧式强制转换的风险。

具体优势可以分为三点：

1. **语义明确，可读性更强**`static_cast<double>(i)` 明确表达了 **“将整数 `i` 静态转换为 `double` 类型”**的意图，属于 C++ 标准的**静态类型转换 **。而 C 风格的 `(double)i` 是一种**万能强制转换**，语法上可以把任意类型转成目标类型，阅读代码时无法直观判断转换的目的和合法性。
    
2. **编译期类型检查，更安全**`static_cast` 会在**编译阶段**进行类型兼容性检查，只有符合规则的转换才会通过编译。比如：可以在数值类型（`int`/`float`/`double`）之间转换，但不能用 `static_cast` 直接把指针类型转成 `double`（这种非法转换会直接报错）。而 C 风格强制转换 `(double)ptr`（`ptr` 为指针）可能会绕过检查，编译通过但运行时出现未定义行为。
    
3. **避免与其他强制转换混淆**C++ 还有 `const_cast`、`reinterpret_cast` 等专用强制转换，各自有明确的使用场景：
    
    - `const_cast`：用于移除变量的 `const` 属性
    - `reinterpret_cast`：用于不同类型指针 / 引用的底层二进制重解释
        
        `static_cast` 专门负责**良性的、符合类型系统规则的转换**，和其他转换的职责边界清晰，代码更易维护。

### 补充对比示例

cpp

```cpp
int i = 3;
// C++ 推荐写法：语义清晰+类型安全
double res1 = 1 / static_cast<double>(i);  // 结果 0.333333...

// C 风格写法：万能转换，无类型检查
double res2 = 1 / (double)i;  // 结果一样，但安全性差

// 非法转换示例：static_cast 会报错，C 风格转换可能“蒙混过关”
int* ptr = &i;
// double res3 = 1 / static_cast<double>(ptr);  // 编译报错！类型不兼容
// double res4 = 1 / (double)ptr;  // 可能编译通过，但运行结果无意义
```
