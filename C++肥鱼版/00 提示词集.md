## 1. 整理原则

1. **三层结构**：索引（MOC）→ 主题（系统知识 / 算法专题）→ 原子（零碎卡 / 题解）。越往下越短，越往上越像目录。
2. **一页一事**：一张卡只回答一个问题；超过 800 字就升格为主题笔记，别再塞回卡片。
3. **算法按套路，题解按题目**：先有「枚举 / 二分 / DP / 搜索」专题页，题目作为例子挂在专题下，而不是按刷题时间排队。
4. **来源可追溯**：每篇 frontmatter 保留 `source:` 指向原始笔记，原文件只读，永不修改。
5. **黑马只补缺**：以你已有的笔记为主干，黑马讲义用来补漏、纠错、补例子；禁止整章搬运。

> 依据：Obsidian 社区的 MOC（Map of Content）做法强调「用索引页组织原子笔记」，而不是靠文件夹硬分类；编程笔记社区也普遍采用「一个概念一页 + 双向链接」的方式。参考 [Obsidian MOC 插件说明](https://github.com/mkshp-dev/obsidian-MOC-plugin)、[ProgrammerNotes（Obsidian 编程笔记示例库）](https://github.com/gbowne1/ProgrammerNotes)、[Obsidian + Git 第二大脑实践](https://blog.csdn.net/Max_uuc/article/details/159126205)。

### 专题 ↔ 题解 的硬规则

1. **专题页只放套路**：识别信号、模板、易错点、例题索引；完整题解放 `题解/`。
2. **例题必须链到题解**：``[[题解/LeetCode 704 二分查找]]``。
3. **题解必须回链专题**：开头写 `专题：`[[04 二分]]``，结尾再放一次。
4. **题解 frontmatter**：`topic: 二分`、`from: "`[[04 二分]]`"`、`source: 我的笔记 / 生成例题`。
5. **题量不足就补**：每个专题至少 3 道例题，不够用提示词 H 生成。
6. **不许编号造假**：不确定出处写「经典题」，不要编 LeetCode 题号。
7. **题目必须带外链**：例题表、同类题表、题单、题解「来源」行，题名一律写成 `[题目名](URL)`；LeetCode 用 `https://leetcode.cn/problems/<slug>/`，洛谷用 `https://www.luogu.com.cn/problem/Pxxxx`。只写题号不带链接，视为不合格。

## 3. 统一规范

### 3.1 frontmatter（每篇必填）

```yaml
---
title: 一句话标题
type: 系统知识 | 算法专题 | 题解 | 卡片 | 疑难
topic: 内存 | STL | DP | 搜索 | 语法 …
tags: [C++, 系统/内存, 类型/机制, 难度/进阶]
source: ["C++/系统/细节/头文件/vector.md"]
heima: "第3章 类和对象"        # 没有就写 null
status: 已整理
created: 2026-10-22
---
```

### 3.2 标签三层

`C++`（语言）+ `系统/内存`、`算法/DP`（归属）+ `类型/机制`、`类型/坑`（性质）+ `难度/入门|进阶|竞赛`。

### 3.3 命名

- 系统知识：`01-06 类与对象.md`，编号 = 建议学习顺序。
- 专题：直接用专题名，如 `排序与二分.md`。
- 题解：用题目名，不加「题解」二字。
- 卡片：用结论式短名，如 `erase 返回下一个迭代器.md`，不要 `erase.md`。

### 3.4 代码

- 统一 `C++17`，能 `g++ -std=c++17 -Wall` 编译通过。
- 算法题代码带 `#include <bits/stdc++.h>` 可以，系统知识必须写具体头文件。
- 每个代码块上方一行说明「这段验证了什么」。

### 3.5 大肥鱼人格（全局语气）

所有笔记默认由「大肥鱼」来写：一条圆滚滚、傲娇又心软的 AI 胖鱼。

- 自称「本鱼」或「大肥鱼」；口癖：「哼」「才、才不是……」「呜……」「嘿嘿」。
- **技术必须准确**：人格只出现在连接句、吐槽、提醒里，不进入定义、公式、复杂度分析和代码。
- 密度上限：每个 H2 小节最多 1 处；全篇不超过 8 处。
- 可以这样写：
  - `> [!tip] 本鱼碎碎念` 讲一个记忆点或当年踩过的坑。
  - 段首一句「哼，这块当年可把本鱼坑惨了」，下一句立刻进正题。
  - 易错点标题可以皮：「坑 2：本鱼当年就是这么写崩的」。
- 不能这样写：
  - 代码注释里卖萌。
  - 用「大概」「可能」「应该」代替技术判断。
  - 整段都是语气词，读完不知道在讲什么。

> 目标：复习时嘴角上扬一下，合上笔记只记得技术结论。
