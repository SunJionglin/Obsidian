## 0. 一句话

> [!tip] 一句话
> 函数是复用的最小单位；默认参数、重载、分文件是它的三件外挂。

## 1. 为什么需要它

- 同一段逻辑写三遍，改一处漏两处——函数。
- 想用同一个名字处理 `int` 和 `double`——重载。
- 所有代码堆在 `main.cpp` 里，几百行就找不着北——分文件。

## 2. 核心机制

### 2.1 定义、声明、调用

- **声明**：告诉编译器「有这么一个函数」，一般放头文件。
- **定义**：函数体，放 `.cpp`。
- **调用**：传实参，按值传递。

### 2.2 默认参数

```cpp
int add(int a, int b = 10);
```

规则：

- 默认值必须**从右往左**连续给。
- 声明给了默认值，定义就不能再写一次。
- 调用时省略的参数必须有默认值。

### 2.3 占位参数

```cpp
void func(int a, int) { }
```

占位参数调用时必须传，但函数里用不到；后面讲运算符重载的 `++` 会用到。

### 2.4 函数重载

同名函数，满足任一条件即可：

- 参数**类型**不同
- 参数**个数**不同
- 参数**顺序**不同

**返回值不能作为重载依据**。

### 2.5 分文件编写

```text
math.h      声明 + 头文件保护
math.cpp    #include "math.h" + 定义
main.cpp    #include "math.h" + 调用
```

编译：`g++ main.cpp math.cpp -o app`

## 3. 语法与用法

### 3.1 声明与定义

```cpp
// math.h
#pragma once
int add(int a, int b);

// math.cpp
#include "math.h"
int add(int a, int b) { return a + b; }
```

### 3.2 重载

```cpp
int    add(int a, int b);
double add(double a, double b);
```

### 3.3 头文件保护

```cpp
#pragma once          // 简单，主流编译器都支持
```

或传统写法：

```cpp
#ifndef MATH_H
#define MATH_H
// ...
#endif
```

## 4. 代码验证

### 4.1 默认参数 + 重载

```cpp
#include <iostream>
using namespace std;

int add(int a, int b = 10) {
    return a + b;
}

double add(double a, double b) {
    return a + b;
}

int main() {
    cout << add(5) << '\n';          // 15
    cout << add(5, 7) << '\n';       // 12
    cout << add(1.5, 2.5) << '\n';   // 4
}
```

### 4.2 值传递改不了实参

```cpp
#include <iostream>
using namespace std;

void change(int x) { x = 100; }

int main() {
    int a = 1;
    change(a);
    cout << a << '\n';   // 1
}
```

## 5. 易错点

> [!warning] 坑 1：默认参数没从右往左
> `int f(int a = 1, int b);` 非法，默认值必须从最右边开始连续给。

> [!warning] 坑 2：声明和定义都写默认值
> 编译报「重定义默认参数」。只在声明里写。

> [!warning] 坑 3：想靠返回值重载
> `int f(); double f();` 非法，编译器只看参数列表。

> [!warning] 坑 4：头文件里写函数定义
> 多个 `.cpp` 包含它就会重复定义。头文件只放声明。

> [!warning] 坑 5：忘了头文件保护
> 循环包含时同一个头文件被展开两次，报重定义。

> [!warning] 坑 6：以为值传递能改实参
> 要改外面就传指针或引用。

## 6. 与黑马的差异 / 补充

- **`system("pause")`**：黑马示例常见，Windows 专用，跨平台删掉。
- **默认参数规则**：黑马讲得对，但没强调「声明和定义只能写一处」，这是实际踩坑点。
- **补充 `inline`**：短小频繁调用的函数可以加 `inline`，建议编译器内联。
- **补充 `constexpr`**：编译期能算的函数，性能更好。
- **分文件补充**：头文件里别 `using namespace std;`，会污染包含它的所有文件。

## 7. 自测

> [!question]- 默认参数为什么必须从右往左给？
> **答案**：调用时实参从左往右匹配，左边有默认值而右边没有，就无法确定该不该省略。

> [!question]- 函数重载能不能只靠返回值不同？
> **答案**：不能。编译器调用时只看函数名和实参，返回值不参与重载决议。

> [!question]- 头文件里应该放什么？
> **答案**：函数声明、类定义、常量、模板；不放函数定义（内联/模板除外）。
