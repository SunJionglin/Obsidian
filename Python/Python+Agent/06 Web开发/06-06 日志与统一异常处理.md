## 0. 速记

> [!tip] 五句话
> - `print` 没法分级、没法关、没有时间行号，生产环境不能用
> - `logging.basicConfig(level, format)` 一次配置，全局生效
> - 级别从低到高：DEBUG → INFO → WARNING → ERROR → CRITICAL
> - FastAPI 用 `@app.exception_handler(Exception)` 捕获所有未处理异常
> - 处理器必须返回 `Response`，通常是 `JSONResponse`

## 1. 语法速查

### 1.1 配置日志

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s - %(levelname)s - %(filename)s:%(lineno)d - %(message)s",
)

logging.info("服务启动")
logging.warning("库存不足")
logging.error("调用模型失败")
```

| 占位符 | 含义 |
|---|---|
| `%(asctime)s` | 时间 |
| `%(levelname)s` | 级别 |
| `%(filename)s` | 文件名 |
| `%(lineno)d` | 行号 |
| `%(message)s` | 日志内容 |

### 1.2 统一异常处理

```python
from fastapi import Request
from fastapi.responses import JSONResponse

@app.exception_handler(Exception)
def handle_exception(request: Request, exc: Exception):
    logging.exception("未捕获异常")          # 自动带堆栈
    return JSONResponse(
        status_code=500,
        content={"code": 500, "message": "服务器内部异常", "data": None},
    )
```

### 1.3 自定义业务异常

```python
class BusinessError(Exception):
    def __init__(self, message, code=400):
        self.message = message
        self.code = code

@app.exception_handler(BusinessError)
def handle_business(request: Request, exc: BusinessError):
    return JSONResponse(
        status_code=exc.code,
        content={"code": exc.code, "message": exc.message, "data": None},
    )
```

## 2. 与 C++ 的差异

| 维度 | C++ | Python |
|---|---|---|
| 日志 | 自己封装 / spdlog | 标准库 `logging` |
| 分级 | 自定义 | 内置五级 |
| 输出目标 | 手写文件流 | Handler 配置 |
| 全局异常 | `try/catch` 包 main | 框架级 exception handler |
| 堆栈 | 平台相关 | `logging.exception` 自动带 |
| 热配置 | 重新编译 | 改配置即生效 |

## 3. 易漏点

- **`basicConfig` 只生效一次**：重复调用不会改配置，测试时要 `force=True`。
- **默认级别是 WARNING**：`logging.info` 不配置根本看不到。
- **`logging.exception` 只能在 except 里用**：它会自动附加堆栈。
- **处理器要返回 Response**：返回 dict 会报错。
- **状态码要设**：`JSONResponse(status_code=500, ...)`，否则默认 200。
- **自定义异常要单独注册**：只注册 `Exception` 的话，业务错误也会变成 500。
- **别把异常吞掉**：处理器里至少 `logging.exception` 记一笔。

## 4. 易错点

> [!warning] `logging.info` 不输出
> 默认级别 WARNING，`basicConfig(level=logging.INFO)` 才看得到。

> [!warning] 处理器返回 dict
> `TypeError: expected Response`。用 `JSONResponse`。

> [!warning] 处理器签名写错
> 必须是 `(request, exc)` 两个参数，少一个启动就报错。

> [!warning] 所有异常都 500
> 参数错误、业务错误应该有 400/404，注册更具体的处理器。

> [!warning] 日志里打印敏感信息
> 密码、API Key 不要进日志，日志常被集中收集。

> [!warning] 用 print 代替日志
> 无法分级、无法关闭、没有时间戳，上线后排查全靠猜。

## 5. 自测

> [!question]- 为什么生产环境不能用 `print` 记日志？
> **答案**：没有级别、时间、位置，无法按需开关，也不能统一收集。

> [!question]- 统一异常处理器必须返回什么？
> **答案**：`Response` 对象，通常用 `JSONResponse` 指定状态码和 JSON 体。

> [!question]- 怎么让日志同时带时间和行号？
> **答案**：在 `format` 里加 `%(asctime)s` 和 `%(lineno)d`。
