## 0. 速记

> [!tip] 五句话
> - 项目 = `main.py` + `static/`（前端）+ `sessions/`（会话 JSON）
> - 静态资源用 `app.mount("/static", StaticFiles(...))`
> - 会话 API 五个：新建、列表、详情、删除、对话
> - 请求体用 Pydantic 模型接，自动校验
> - 对话流程七步：读会话 → 拼 messages → 调模型 → 存会话 → 返回

## 1. 语法速查

### 1.1 项目结构

```
汉字谜盒/
├── main.py
├── static/
│   ├── index.html
│   ├── style.css
│   └── script.js
└── sessions/
    └── 2026-10-22_12-00-00.json
```

### 1.2 初始化

```python
app = FastAPI(title="汉字谜盒")
app.mount("/static", StaticFiles(directory="static"), name="static")

if not os.path.exists("sessions"):
    os.mkdir("sessions")
```

### 1.3 五个接口

| 方法 | 路径 | 作用 |
|---|---|---|
| `POST` | `/api/sessions` | 新建会话 |
| `GET` | `/api/sessions` | 会话列表 |
| `GET` | `/api/sessions/{session_id}` | 加载指定会话 |
| `DELETE` | `/api/sessions/{session_id}` | 删除会话 |
| `POST` | `/api/chat` | 与 AI 对话 |

### 1.4 数据模型

```python
from pydantic import BaseModel
from typing import Any

class ApiResponse(BaseModel):
    code: int
    message: str
    data: Any

class ChatRequest(BaseModel):
    session_id: str
    message: str
```

### 1.5 对话七步

```python
@app.post("/api/chat")
def chat(req: ChatRequest) -> ApiResponse:
    path = f"sessions/{req.session_id}.json"

    with open(path, encoding="utf-8") as f:
        session = json.load(f)

    messages = [{"role": "system", "content": SYSTEM_PROMPT}]
    messages += session["messages"]
    messages.append({"role": "user", "content": req.message})

    resp = client.chat.completions.create(
        model="deepseek-chat",
        messages=messages,
    )
    answer = resp.choices[0].message.content

    session["messages"] = messages[1:] + [{"role": "assistant", "content": answer}]
    with open(path, "w", encoding="utf-8") as f:
        json.dump(session, f, ensure_ascii=False, indent=2)

    return ApiResponse(code=200, message="请求成功", data=answer)
```

## 2. 与 C++ 的差异

| 维度 | C++ | FastAPI |
|---|---|---|
| 前端 | 手写 HTML/JS | 同样手写，放 `static/` |
| 路由 | 手写注册 | 装饰器 |
| JSON | nlohmann/json | 内置 + Pydantic |
| 会话存储 | 文件 / DB | JSON 文件 |
| 参数校验 | 手写 | 模型自动校验 |
| 启动 | 编译后运行 | `uvicorn` |

## 3. 易漏点

- **路由顺序**：`/api/sessions/{id}` 不能写在 `/api/sessions` 前面（同方法会被吞）。
- **静态目录相对启动目录**：在项目根目录启动，别在 `static/` 里启动。
- **文件名就是会话 ID**：`2026-10-22_12-00-00.json`。
- **JSON 存中文**：`ensure_ascii=False` + `encoding="utf-8"`。
- **列表排序**：会话名按时间倒序，`sort(reverse=True)`。
- **`messages` 不含 system**：system 每次临时拼，不落盘。
- **删除不存在的会话**：先 `os.path.exists` 判断。

## 4. 易错点

> [!warning] 会话文件不存在
> 直接 `open` → `FileNotFoundError` → 500。先判断或捕获。

> [!warning] 请求体字段名写错
> 前端传 `sessionId`，模型写 `session_id` → 422。

> [!warning] 把 system 消息存进文件
> 下次再拼一次就重复了。存之前 `messages[1:]` 去掉 system。

> [!warning] 文件句柄没关
> `json.load(open(...))` 泄漏句柄，用 `with`。

> [!warning] 前端拿不到数据
> 返回的是 Pydantic 模型，FastAPI 会自动转 JSON；别自己再 `json.dumps`。

> [!warning] 静态资源 404
> HTML 里写 `/static/xxx.css`，挂载点必须是 `/static`。

## 5. 自测

> [!question]- 新建会话接口做了什么？
> **答案**：生成时间戳 ID、创建 `sessions/{id}.json`、写入空 messages、返回 ID。

> [!question]- 为什么每次对话都要重新拼 system 消息？
> **答案**：system 是固定规则，不存进会话文件，避免重复和篡改。

> [!question]- 删除会话为什么先判断文件存在？
> **答案**：避免删不存在的文件抛 `FileNotFoundError`，保证接口幂等。
