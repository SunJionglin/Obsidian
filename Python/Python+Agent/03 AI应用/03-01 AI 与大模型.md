## 0. 速记

> [!tip] 五句话
> - LLM 是概率模型：同一个问题，两次回答可能不一样
> - 三种用法：本地 Ollama、官方 API、第三方聚合平台
> - API 三要素：`base_url`、`api_key`、`model`
> - token 是计费和上下文的最小单位，不等于字数
> - 幻觉：模型会一本正经地编造不存在的事实

## 1. 语法速查

### 1.1 三个概念

| 概念 | 英文 | 说明 |
|---|---|---|
| 人工智能 | AI | 让机器模拟人类思考、推理、学习的学科 |
| 大语言模型 | LLM | 用海量数据训练、参数量巨大的神经网络，输入输出都是语言 |
| AI 应用 | AI Application | 把 LLM 接到具体业务上，解决实际问题 |

关系：AI ⊃ LLM ⊃ 你写的 AI 应用。

### 1.2 三种部署方式

| 方式 | 代表 | 优点 | 缺点 |
|---|---|---|---|
| 本地部署 | Ollama | 数据不出本机、长期成本低 | 吃显存、效果受模型规模限制 |
| 官方 API | DeepSeek、Kimi | 开箱即用、模型强 | 按 token 付费、数据出网 |
| 第三方聚合 | 各类中转平台 | 一个 key 调多家 | 稳定性与合规性参差 |

### 1.3 Ollama 常用命令

```bash
ollama run deepseek-r1:1.5b   # 下载并运行
ollama list                   # 已安装模型
ollama ps                     # 正在运行的模型
ollama serve                  # 启动服务，默认 11434 端口
```

### 1.4 调 API 的三要素

```python
from openai import OpenAI

client = OpenAI(
    api_key="sk-xxx",                        # 身份，别写进代码
    base_url="https://api.deepseek.com",     # 服务地址
)
resp = client.chat.completions.create(
    model="deepseek-chat",                   # 模型名
    messages=[{"role": "user", "content": "你好"}],
)
```

### 1.5 计费与上下文

- 计费单位是 token，中文大约 1 字 ≈ 1～2 token。
- 上下文窗口有限，历史消息越长越贵，还可能超限。
- `temperature` 越低越稳定，越高越发散。

## 2. 与 C++ 的差异

本节是概念课，和 C++ 没有语法差异。真正要换的是思维方式：

| 维度 | 传统 C++ 程序 | 大模型应用 |
|---|---|---|
| 输出 | 确定，同样输入同样输出 | 概率性，可能每次不同 |
| 开发 | 写逻辑、写算法 | 写提示词、调 API |
| 依赖 | 编译链接库 | 网络 + API Key |
| 成本 | 一次性开发 | 按 token 持续计费 |
| 出错 | 异常、崩溃 | 幻觉、答非所问 |
| 测试 | 断言输出 | 人工评估、评测集 |

## 3. 易漏点

- **本地模型 ≠ API 模型**：1.5B 的本地模型和线上大模型效果差一个量级。
- **API Key 用环境变量**：`os.environ["DEEPSEEK_API_KEY"]`，不要硬编码。
- **`base_url` 别照抄**：OpenAI 是 `https://api.openai.com/v1`，DeepSeek 是 `https://api.deepseek.com`。
- **token 不等于字数**：英文一个单词可能 1～2 token，中文一字约 1～2 token。
- **上下文会超限**：历史消息全带上迟早超窗口，需要截断或摘要。
- **模型名要精确**：`deepseek-chat` 和 `deepseek-reasoner` 是两个模型。
- **流式输出不是一次性返回**：`stream=True` 要逐块拼接。

## 4. 易错点

> [!warning] 把 API Key 写进代码
> 一旦推到 GitHub 就会被盗刷。用环境变量或 `.env`，并加 `.gitignore`。

> [!warning] 忘记装 SDK
> `ModuleNotFoundError: No module named 'openai'`，先 `pip install openai`。

> [!warning] 网络不通
> 国内直连部分 API 会超时，需要配置代理或换可访问的服务地址。

> [!warning] 余额不足
> 返回 402 或 `Insufficient Balance`，去控制台充值。

> [!warning] 模型名写错
> 返回 404 / `model not found`。去官方文档抄准确名字。

> [!warning] 以为模型会记住上下文
> API 是无状态的，每次都要把历史 `messages` 一起传。

## 5. 自测

> [!question]- 本地部署、官方 API、第三方聚合各适合什么场景？
> **答案**：数据敏感/离线 → 本地；效果优先/快速上线 → 官方 API；要多模型对比/统一入口 → 聚合平台。

> [!question]- 为什么说大模型 API 是「无状态」的？
> **答案**：服务端不保存你的对话历史，每次请求都要把完整 `messages` 传过去。

> [!question]- `temperature` 调高会怎样？
> **答案**：输出更随机、更发散；调低更稳定、更保守。
