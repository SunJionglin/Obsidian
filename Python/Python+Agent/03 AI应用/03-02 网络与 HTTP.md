## 0. 速记

> [!tip] 五句话
> - IP 定位设备，端口定位程序，域名是 IP 的别名（靠 DNS 解析）
> - HTTP 是文本协议、请求-响应模型、无状态
> - 请求 = 请求行 + 请求头 + 请求体；响应 = 状态行 + 响应头 + 响应体
> - `200` 成功、`400` 参数错、`404` 找不到、`500` 服务器错
> - 无状态意味着每次请求都要自己带上身份（token / cookie）

## 1. 语法速查

### 1.1 网络三要素

| 概念 | 作用 | 例子 |
|---|---|---|
| IP | 定位一台设备 | `127.0.0.1` 本机 |
| 域名 | 好记的 IP 别名 | `api.deepseek.com` |
| 端口 | 定位设备上的程序 | `443`（HTTPS）、`80`（HTTP） |

域名到 IP 的转换由 DNS 完成；端口范围 `0–65535`。

### 1.2 请求格式

```http
POST /chat/completions HTTP/1.1
Host: api.deepseek.com
Content-Type: application/json
Authorization: Bearer sk-xxxx

{"model": "deepseek-chat", "messages": [...]}
```

三部分：请求行（方法 + 路径 + 协议）、请求头（`key: value`）、请求体（GET 通常没有）。

### 1.3 响应格式

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"choices": [{"message": {"content": "你好"}}]}
```

三部分：状态行、响应头、响应体。

### 1.4 常见方法与状态码

| 方法 | 语义 | 典型场景 |
|---|---|---|
| `GET` | 查询 | 获取列表、详情 |
| `POST` | 新增 / 提交 | 登录、调用大模型 |
| `PUT` | 全量修改 | 更新资源 |
| `DELETE` | 删除 | 删除资源 |

| 状态码 | 含义 |
|---|---|
| `200` | 成功 |
| `301` / `302` | 重定向 |
| `400` | 请求参数错误 |
| `401` / `403` | 未认证 / 无权限 |
| `404` | 资源不存在 |
| `500` | 服务器内部错误 |

## 2. 与 C++ 的差异

| 维度 | C++ | Python |
|---|---|---|
| 发 HTTP 请求 | socket 手写 / libcurl | `requests` 一行，或 SDK 封装 |
| 解析响应 | 自己拆字符串 / 第三方库 | `resp.json()` |
| HTTPS | 依赖 OpenSSL 配置 | 库内置 |
| 超时控制 | `setsockopt` / 库参数 | `timeout=` |
| JSON 处理 | 无标准库 | 内置 `json` |
| 并发请求 | 线程 / epoll | `asyncio` / 线程池 |

协议本身两边一样，差的是「谁帮你干了脏活」。

## 3. 易漏点

- **`127.0.0.1` 和 `localhost`**：都指本机，但解析路径不同，代理环境可能表现不一致。
- **`443` 是 HTTPS 默认端口**：URL 里不写端口时自动补。
- **GET 没有请求体**：参数放在 URL 的 query string 里。
- **请求头 key 大小写不敏感，值敏感**：`Bearer` 后面必须空格再跟 token。
- **`Content-Type` 决定 body 怎么解析**：JSON 必须是 `application/json`。
- **HTTP 无状态**：登录态靠每次带 token 或 cookie。
- **3xx 默认不会自动跳转**：`requests` 默认跟随，自己写 socket 要处理。

## 4. 易错点

> [!warning] 把 404 当服务器错误
> 404 是「你请求的资源不存在」，多半是 URL 写错；500 才是服务端挂了。

> [!warning] 忘记 Authorization 头
> 返回 401。格式是 `Authorization: Bearer <token>`，`Bearer` 后面有空格。

> [!warning] GET 里塞请求体
> 有些服务器直接忽略，有些报 400。查询参数放 URL。

> [!warning] 端口被占用
> `Address already in use`，换端口或杀掉占用进程。

> [!warning] 用 http 访问 https 端口
> 返回 400 或直接断开。协议和端口要配套。

> [!warning] 把 token 拼进 URL
> 会留在日志和浏览器历史里。放请求头。

## 5. 自测

> [!question]- HTTP 请求由哪三部分组成？
> **答案**：请求行（方法、路径、协议）、请求头（key: value）、请求体（GET 通常为空）。

> [!question]- 404 和 500 分别是谁的问题？
> **答案**：404 是客户端 URL 写错或资源被删；500 是服务端代码异常。

> [!question]- 为什么每次调用大模型 API 都要重新传 messages？
> **答案**：HTTP 是无状态的，服务端不保存上一次对话。
