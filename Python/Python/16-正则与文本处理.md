## 二、基础元字符

| 写法 | 含义 | 例子 |
| --- | --- | --- |
| `.` | 任意一个字符（默认不含换行） | `a.c` 匹配 abc |
| `\d` / `\D` | 数字 / 非数字 | `\d{3}` 匹配 123 |
| `\w` / `\W` | 字母数字下划线 / 反之 | `\w+` 匹配单词 |
| `\s` / `\S` | 空白 / 非空白 | `\s+` 匹配空格 |
| `[abc]` | 其中任一字符 | `[0-9a-f]` 十六进制 |
| `[^abc]` | 不在其中 | `[^\d]` 非数字 |
| `^` / `$` | 行首 / 行尾 | `^\d+$` 纯数字行 |
| `\b` | 单词边界（零宽） | `\bcat\b` 不匹配 scatter |
| `\A` / `\Z` | 字符串开头 / 绝对结尾 | `\Aabc\Z` 整串等于 abc |
| `*` `+` `?` `{n,m}` | 0+ / 1+ / 0或1 / n 到 m 次 | `\d{2,4}` |
| 竖线 | 或：两边任选一个 | `cat` 或 `dog` |
| `()` | 分组，可取值 | `(\d{4})-(\d{2})` |
| `(?:...)` | 只分组，不捕获 | `(?:ab)+` |
| `(?P<name>...)` | 命名分组 | `(?P<year>\d{4})` |

## 三、re 的常用函数

```python
import re

s = "订单 A123，金额 99 元，日期 2026-11-02"

re.search(r"\d+", s).group()      # '123'（第一个匹配）
re.match(r"订单", s)               # 只从开头匹配，没匹配返回 None
re.fullmatch(r"\d+", "123")        # 整串必须完全匹配
re.findall(r"\d+", s)             # ['123', '99', '2026', '11', '02']
re.sub(r"\d+", "#", s)            # '订单 A#，金额 # 元，日期 #-#-#'
re.split(r"[，,]", s)             # 按中文/英文逗号切
```

| 函数 | 从头匹配？ | 返回 |
| --- | --- | --- |
| `match` | 是 | Match 或 None |
| `search` | 否（任意位置） | Match 或 None |
| `fullmatch` | 整串 | Match 或 None |
| `findall` | 否 | 列表（有分组时返回分组内容） |
| `finditer` | 否 | Match 的迭代器 |
| `sub` | 否 | 替换后的字符串 |
| `split` | 否 | 列表 |

`sub` 的替换值可以是函数，按每次匹配动态生成：

```python
re.sub(r"\d+", lambda m: str(int(m.group()) * 2), "a1 b22")   # 'a2 b44'
re.sub(r"(\d{4})-(\d{2})-(\d{2})", r"\1年\2月\3日", "2026-11-02")
re.sub(r"(?P<y>\d{4})-(?P<m>\d{2})", r"\g<m>/\g<y>", "2026-11")   # '11/2026'
```

**预编译**：同一个正则在循环里反复用，先 `compile`：

```python
pat = re.compile(r"\d{4}-\d{2}-\d{2}")
pat.findall(text)

# 等价于 re.findall(r"...", text, re.MULTILINE)
pat2 = re.compile(r"^\d+", re.MULTILINE)
```

`re` 模块内部会缓存最近用过的模式（默认 512 个），所以不预编译也不会每次都重新解析；但预编译能顺手绑 flags、让代码更清楚。

**常用 flags**：

| flag | 作用 |
| --- | --- |
| `re.I` / `IGNORECASE` | 忽略大小写 |
| `re.M` / `MULTILINE` | `^` `$` 按行匹配，而不是整串 |
| `re.S` / `DOTALL` | `.` 也匹配换行 |
| `re.X` / `VERBOSE` | 忽略空白和 `#` 注释，可把长正则拆行写 |
| `re.A` / `ASCII` | `\w` `\d` `\s` 只按 ASCII 解释 |

## 四、分组与命名

```python
m = re.search(r"(\d{4})-(\d{2})-(\d{2})", "日期 2026-11-02")
m.group(0)     # '2026-11-02'（整体）
m.group(1)     # '2026'
m.groups()     # ('2026', '11', '02')

m = re.search(r"(?P<y>\d{4})-(?P<m>\d{2})", "2026-11-02")
m.group("y")   # '2026'
m.groupdict()  # {'y': '2026', 'm': '11'}
```

**反向引用**：在模式里引用前面捕获到的内容。

```python
re.search(r"(\w+)\s+\1", "hello hello").group()      # 'hello hello'
re.search(r"(?P<w>\w+)\s+(?P=w)", "hi hi").group()   # 'hi hi'
```

**替换里的分组**：`\1` / `\g<name>` 引用分组，`\g<0>` 是整体。

**`findall` 的分组陷阱**：

```python
re.findall(r"(\d{4})-(\d{2})", "2026-11 2025-03")
# [('2026', '11'), ('2025', '03')]：返回元组，不是整体匹配
re.findall(r"(?:\d{4})-(\d{2})", "2026-11")
# ['11']：非捕获组不参与返回
```

## 五、贪婪与非贪婪

```python
re.findall(r"<.+>", "<a><b>")     # ['<a><b>']  贪婪：尽量多吃
re.findall(r"<.+?>", "<a><b>")    # ['<a>', '<b>']  非贪婪：加 ?
```

- `*` `+` `?` `{n,m}` 默认贪婪；后面加 `?` 变非贪婪（`*?` `+?` `??` `{n,m}?`）。
- 非贪婪不是「越短越好」的万能药：它仍然从左边第一个可能的位置开始，只是每次尽量少匹配。要限定位置还得靠锚点/断言。
- 解析 HTML 别用正则，用 lxml/XPath（见 [[18-网络与爬虫]]）。

**原生字符串**：正则一律写 `r"..."`，否则 `\d`、`\n` 会被 Python 先转义一次。

## 六、前后向断言：只定位，不消费

断言是**零宽**的：只要求「这个位置左边/右边满足条件」，匹配结果里不包含断言的内容。

| 写法 | 名字 | 含义 |
| --- | --- | --- |
| `(?=...)` | 正向前瞻 | 右边必须是 ... |
| `(?!...)` | 负向前瞻 | 右边不能是 ... |
| `(?<=...)` | 正向后顾 | 左边必须是 ... |
| `(?<!...)` | 负向后顾 | 左边不能是 ... |

```python
# 只取 ¥ 后面的数字，不把 ¥ 取进来
re.findall(r"(?<=¥)\d+(?:\.\d+)?", "¥99 ¥128.5 $30")   # ['99', '128.5']

# 取 foo，但后面不能跟 bar
re.findall(r"foo(?!bar)", "foobar foo baz")              # ['foo']

# 密码：至少 8 位，含数字和小写字母（多个断言叠加）
re.fullmatch(r"(?=.*\d)(?=.*[a-z]).{8,}", "abc12345")    # Match
```

**后顾的长度限制**：Python 的 `re` 要求 lookbehind 是**固定宽度**。

```python
re.compile(r"(?<=ab|cd)x")     # OK：两个分支都是 2 个字符
re.compile(r"(?<=a|bc)x")      # 报错：look-behind requires fixed-width pattern
```

需要变长后顾时，改用「捕获组 + `group(1)`」，或换第三方 `regex` 模块（它支持变长后顾）。

**断言里可以捕获**：

```python
re.search(r"(?=(\d{3}))\d+", "12345").group(1)   # '123'
```

**常见坑**：`(?<=...)` 是「左边」，别和 `(?=...)` 写反；断言不消耗字符，所以多个断言可以叠在同一位置（密码校验就是这么写的）。Python 不支持 `\K`，别把 PCRE 的写法直接搬过来。

## 七、finditer 与 Match 对象

`findall` 只给字符串/元组，要位置、要分组名、要逐个处理就用 `finditer`：

```python
import re

text = "a=1 b=22 c=333"
for m in re.finditer(r"(?P<key>\w+)=(?P<value>\d+)", text):
    print(m.group(0), m.group("key"), m.group("value"))
    print(m.span())        # (start, end)
    print(m.start(), m.end())
    print(m.groupdict())   # {'key': 'a', 'value': '1'}
```

| 成员 | 作用 |
| --- | --- |
| `m.group(0)` / `m.group()` | 整体匹配 |
| `m.group(n)` / `m.group("name")` | 第 n 个 / 命名分组 |
| `m.groups()` | 所有捕获组组成的元组 |
| `m.groupdict()` | 命名分组组成的 dict |
| `m.span()` | `(start, end)`，左闭右开 |
| `m.start()` / `m.end()` | 起止下标 |
| `m.expand(template)` | 用 `\1` / `\g<name>` 展开替换模板 |
| `m.lastindex` | 最后一个匹配的捕获组编号 |
| `m.re` / `m.string` | 用的 Pattern / 原字符串 |

```python
m = re.search(r"(?P<k>\w+)=(?P<v>\d+)", "x=42")
m.expand(r"\g<v>:\g<k>")     # '42:x'
```

## 八、回溯风险与优化

正则引擎默认是**回溯**的：一条路走不通就退回去换下一种可能。嵌套量词会让可能性指数爆炸。

```python
# 危险：嵌套量词 + 失败结尾
re.match(r"(a+)+$", "a" * 30 + "b")     # 30 个 a 就可能卡很久
re.match(r"(a|aa)+$", "a" * 30 + "b")   # 分支重叠也会爆
```

**判断信号**：正则里有「量词套量词」`(a+)+`、`(a*)*`，或「多个分支能匹配同一段」`(a|aa)+`，且输入长、结尾不匹配——最容易炸。

**优化手段**：

1. 能具体就具体：用 `[^"]*` 代替 `.*?`，用字符类代替宽泛的 `.`；
2. 加锚点 `^` / `\A`，让失败尽早发生；
3. 消灭嵌套量词，把 `(a+)+` 改成 `a+`；
4. 3.11+ 用**原子组** `(?>...)` 或**占有量词** `a++` / `a*+`，一旦匹配就不再回退；
5. 限制输入长度，或先做一次廉价的前置判断；
6. 需要硬超时用第三方 `regex` 模块的 `timeout=`，标准库 `re` 没有超时参数。

```python
# 3.11+
re.match(r"(?>a+)+$", "a" * 30 + "b")   # 原子组：不 backtrack，快速失败
re.match(r"a++$", "a" * 30 + "b")       # 占有量词
```

调试正则：`re.compile(r"...", re.DEBUG)` 会打印解析树；`re.escape(s)` 把普通字符串转成字面量模式。

## 九、常见坑

1. 忘了 `r` 前缀，`"\d"` 变成普通字符 d，匹配不上。
2. `match` 只在开头找，找子串用 `search`；要整串匹配用 `fullmatch`。
3. `findall` 有分组时返回的是分组内容，不是整体匹配。
4. 想匹配真正的点号要写 `\.`，`.` 是通配。
5. 手机号/邮箱别自己硬写，用成熟正则并做边界测试。
6. `^` `$` 默认匹配整串开头结尾；按行匹配要加 `re.M`；`$` 还会匹配结尾换行前的位置，要绝对结尾用 `\Z`。
7. `\w` 默认包含中文等 Unicode 字母；只想要 ASCII 加 `re.A`。
8. `re.split` 的模式里如果有捕获组，分隔符也会出现在结果里。
9. 大文本上跑复杂正则前先做基准测试，别等线上卡住才发现回溯爆炸。
