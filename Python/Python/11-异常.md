# 11 异常

> 在知识树里的位置：错误处理。[[08-函数与作用域]] 决定代码怎么拆，这篇决定出错时怎么收场。
> 模块与包见 [[12-模块与包]]；`with` 的自动清理见 [[14-文件与IO]]。

## 一、异常是什么

**规则**　异常是**一个对象**，表示「当前操作没法继续」。解释器发现错误会 `raise`，你也可以主动 `raise`。没人接住，它一路冒泡到顶层，打印 traceback 并让进程以非 0 退出码结束。

```python
def div(a, b):
    return a / b

div(1, 0)
# Traceback (most recent call last):
#   File "<stdin>", line 1, in <module>
#   File "<stdin>", line 2, in div
# ZeroDivisionError: division by zero
```

traceback **从下往上读**：最后一行是异常类型和消息，上面是调用栈（越往下越接近出错点）。报错先看最后一行，再看最下面那层自己的代码。

**为什么需要异常**　错误码要每层判断、容易漏；异常把「正常路径」和「错误路径」分开，错误可以跨多层函数直接交给能处理的人。

## 二、异常层次

```
BaseException
├── SystemExit                 # sys.exit()
├── KeyboardInterrupt          # Ctrl-C
├── GeneratorExit              # 生成器 close()
└── Exception                  # 绝大多数「程序错误」
    ├── ArithmeticError
    │   ├── ZeroDivisionError
    │   └── OverflowError
    ├── LookupError
    │   ├── IndexError
    │   └── KeyError
    ├── ValueError             # 类型对、值不对
    ├── TypeError              # 类型不对
    ├── AttributeError
    ├── NameError
    ├── OSError                # IO / 系统调用
    │   ├── FileNotFoundError
    │   ├── PermissionError
    │   └── TimeoutError
    └── StopIteration          # 迭代器耗尽
```

- **捕获 `Exception` 不会吞掉 `KeyboardInterrupt` / `SystemExit`**，这是设计好的：Ctrl-C 和退出请求必须能生效。
- 裸 `except:` 等价于 `except BaseException:`，会把上面这些也吞掉，几乎总是错的。
- 3.11+ 还有 `ExceptionGroup` / `except*`，用于一次抛多个异常（并发、批量校验场景）。

## 三、try / except / else / finally

```python
try:
    n = int(input("数字："))
    print(10 / n)
except ValueError:
    print("不是整数")
except ZeroDivisionError as e:
    print("不能除以 0：", e)
except (TypeError, OverflowError) as e:   # 多个类型共用一段处理
    print("类型/溢出问题：", e)
except Exception as e:                    # 兜底，必须放最后
    print("其他错误：", e)
else:
    print("没出错才执行")                  # 成功路径放这里
finally:
    print("无论如何都执行")                # 清理资源
```

| 子句 | 什么时候执行 | 用途 |
| --- | --- | --- |
| `except X` | try 里抛出 X 或其子类 | 处理特定错误 |
| `else` | try 没有抛异常 | 放成功后的逻辑，避免被自己的 except 误抓 |
| `finally` | 无论如何，包括 return / 异常 | 关文件、释放锁、回滚 |

**匹配顺序**：从上往下，第一个匹配的 `except` 生效。所以**具体的放前面，宽的放后面**；`except Exception` 放最后，否则后面的分支永远到不了。

**几个细节**：

- `except ... as e` 里的 `e` 在 except 块结束时被删除（为了打断 traceback 引用环），块外再用会 `NameError`。
- `finally` 里写 `return` 会**覆盖** try 里的返回值，也会吞掉异常——别这么写。
- `try` 里 `return`，`finally` 仍会执行；`finally` 没有 return 时，返回值保持不变。

## 四、主动抛出、自定义异常与断言

```python
def set_age(age):
    if not 0 <= age <= 150:
        raise ValueError(f"年龄不合法：{age}")
    return age
```

自定义异常：继承 `Exception`（不要继承 `BaseException`），需要携带结构化信息就写 `__init__`。

```python
class InsufficientBalance(Exception):
    def __init__(self, balance, amount):
        self.balance = balance
        self.amount = amount
        super().__init__(f"余额 {balance} 不足以取 {amount}")

try:
    raise InsufficientBalance(100, 200)
except InsufficientBalance as e:
    print(e.balance, e.amount, e)
```

**异常链**：转换异常时用 `raise ... from ...` 保留原因，traceback 会显示「The above exception was the direct cause...」。

```python
try:
    int("abc")
except ValueError as e:
    raise RuntimeError("配置解析失败") from e

raise RuntimeError("不想显示原始异常") from None   # 切断上下文
```

`raise` 不带参数 = 重新抛出当前异常，保留原栈；`raise e` 会重置 traceback 起点（一般不这么写）。

**assert**：只用于「调试期断言内部不变量」，`python -O` 会整条移除，**不能拿它做用户输入校验**。

```python
assert isinstance(x, int), "x 必须是 int"
```

## 五、反模式

| 反模式 | 问题 | 正确做法 |
| --- | --- | --- |
| `except: pass` | 吞掉所有错误，包括 Ctrl-C，问题被隐藏 | 捕获具体类型；至少 `logging.exception(...)` |
| `except Exception: print(e)` | 丢了 traceback，无法定位 | `raise` 或 `logging.exception` |
| 用异常做正常流程 | 慢、难读 | 能 `if` 判断就用 `if` |
| `try` 包住几十行 | 不知道哪行出错，容易误抓 | 只包住真正可能出错的那一句 |
| 在 `finally` 里 `return` | 覆盖返回值、吞异常 | 清理逻辑不要 return |

## 六、常见坑

1. `except` 顺序反了：`except Exception` 写在前面，后面的具体分支永远不执行。
2. 只 `print` 不 `raise`：上层拿不到错误，日志里也没有栈；要记录用 `logging.exception`。
3. `finally` 里的 `return` 覆盖 try 的返回值。
4. `e` 出了 `except` 块就没了，需要留存就赋给别的变量。
5. `assert` 被 `-O` 移除，线上校验失效。
6. 捕获了异常却只做半截恢复，对象处于不一致状态；要么处理干净，要么让它抛。

## 七、练习

1. 写一个「求两数相除」函数，对非数字与除零分别报不同的错。
2. 自定义 `InsufficientBalance(Exception)`，在「取款超过余额」时抛出，并带上余额与取款额。
3. 读一个可能不存在的配置文件：捕获 `FileNotFoundError` 返回默认配置，其他 `OSError` 继续抛。
4. 把一段 `int(x)` 的 `ValueError` 转成自己的 `ConfigError`，用 `raise ... from` 保留原因。
