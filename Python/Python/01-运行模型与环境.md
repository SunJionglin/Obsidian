# 01 运行模型与环境

## 1.1 一段 Python 是怎么跑起来的

1. **读源码**：按 UTF-8 解码 `.py` 文件。
2. **编译**：解析成 AST，再编译成 **字节码**（bytecode）。
3. **缓存**：字节码存到 `__pycache__/xxx.cpython-312.pyc`，下次源码没变就直接用。
4. **执行**：CPython 的**虚拟机**逐条执行字节码；函数调用、对象创建都在这里发生。

```python
import dis
def add(a, b): return a + b
dis.dis(add)      # 看到 LOAD_FAST / BINARY_OP / RETURN_VALUE
```

这解释了三个现象：改源码后第一次运行变慢（要重编译）、`__pycache__` 可以删（会自动重建）、`import` 比重复启动快（复用缓存）。

| 概念 | 含义 | 常见误解 |
| --- | --- | --- |
| CPython | 官方实现（C 写的解释器） | 「Python」有多个实现：CPython、PyPy、Jython、IronPython |
| 字节码 | 虚拟机指令，不是机器码 | 它不是 `.pyc` 里的二进制机器码 |
| GIL | 全局解释器锁，见 15 篇 | 它不是语言规范，是 CPython 的实现细节 |

## 1.2 四种运行方式

```bash
python3 script.py            # 跑脚本
python3 -c "print(1+1)"      # 跑一行
python3 -m http.server 8000  # 把模块当脚本跑（-m 会进 sys.path）
python3                      # 进 REPL，退出用 exit() 或 Ctrl-D
```

`python3 -m 模块` 与 `python3 文件.py` 的区别：`-m` 会把**当前目录加进 `sys.path`**，包内相对导入才正常工作。

## 1.3 模块搜索顺序

```python
import sys
print(sys.path)
```

顺序：脚本所在目录（或 `-m` 时的当前目录）→ `PYTHONPATH` → 标准库目录 → site-packages（第三方）。

坑：自己写的 `random.py`、`json.py`、`string.py` 会**覆盖标准库**，报出莫名其妙的错误。项目里别用标准库名做文件名。

模块与包的完整规则（包、相对导入、循环导入、打包）见 [[12-模块与包]]。

## 1.4 虚拟环境与包管理

```bash
python3 -m venv .venv          # 建
source .venv/bin/activate      # 激活（Windows: .venv\Scripts\activate）
pip install requests           # 装进这个环境
pip freeze > requirements.txt  # 导出
pip install -r requirements.txt
deactivate                     # 退出
```

| 工具 | 定位 |
| --- | --- |
| venv | 标准库自带的虚拟环境 |
| pip | 标准包管理 |
| uv | 极快的替代（`uv venv`、`uv pip install`、`uv run`） |
| conda | 科学计算生态，管非 Python 依赖 |

为什么要虚拟环境：全局只有一套 site-packages，项目 A 要 `requests==2.28`、项目 B 要 `2.32` 就会打架。虚拟环境把依赖按项目隔离。

## 1.5 编码

```python
"中文".encode("utf-8")            # b'\xe4\xb8\xad\xe6\x96\x87'
b'\xe4\xb8\xad'.decode("utf-8")   # '中'
open("a.txt", encoding="utf-8")   # 读文件永远显式写编码
```

- 源码默认 UTF-8（PEP 3120）；老代码可能在文件头写 `# -*- coding: gbk -*-`。
- `str` 是「字符序列」，`bytes` 是「字节序列」，两者转换必须显式 `encode/decode`。
- 乱码几乎只有一个原因：**写入与读取用了不同的编码**。
- 文件的打开模式、换行与编码细节见 [[14-文件与IO]]。

## 1.6 解释器实现与版本差异

| 实现 | 特点 | 什么时候用 |
| --- | --- | --- |
| CPython | 官方，生态最全 | 默认 |
| PyPy | JIT，纯计算快数倍 | 计算密集、无 C 扩展依赖 |
| 其他 | Jython / IronPython / MicroPython | 特殊宿主环境 |

版本要记的：3.6 f-string、3.8 海象 `:=`、3.9 `dict |` 合并与 `list[int]`、3.10 `match`、3.11 更快且报错更细、3.12 支持 f-string 内嵌套同种引号。

## 1.7 常见坑

1. `python` 与 `python3` 可能不是同一个解释器；装过 brew/uv 后 PATH 里可能有多个。
2. 在 venv 里装了包，换终端没激活就用不了——看 `which python3` 确认。
3. `pip install` 权限报错，多半是装到了系统 Python；别加 `sudo`，用 venv。
4. `__pycache__` 里是旧字节码时，删掉即可（Python 按 mtime 判断，正常不会错，但手工改过时间戳会）。
