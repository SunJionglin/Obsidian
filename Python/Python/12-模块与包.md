# 12 模块与包

> 在知识树里的位置：代码组织。[[08-函数与作用域]] 把逻辑收进函数，这篇把函数收进文件与目录。
> `import` 的搜索路径、venv、字节码缓存见 [[01-运行模型与环境]]；异常见 [[11-异常]]。

## 一、模块就是一个 `.py` 文件

```python
import math                 # 整个模块，用 math.sqrt
from math import sqrt       # 只导入一个名字
from math import sqrt as s  # 起别名
import numpy as np
from math import *          # 不推荐：污染命名空间，看不出名字从哪来
```

- 模块名 = 文件名去掉 `.py`；包名 = 目录名。
- `import` 只执行一次：第一次导入后模块对象缓存在 `sys.modules`，再 import 直接拿缓存。
- **模块顶层的代码在 import 时就会执行**，所以别在顶层写耗时逻辑或 `print`。

```python
import sys
"math" in sys.modules      # True（导入后）
```

## 二、`import` 背后发生了什么

1. 查 `sys.modules`，有就直接返回；
2. 找不到就按**搜索顺序**找模块：
   - 内置模块（`sys`、`builtins` 等，编译进解释器）；
   - `sys.path` 里的目录，顺序大致是：脚本所在目录 / 当前目录 → `PYTHONPATH` → 标准库 → `site-packages`；
3. 找到后创建模块对象、执行模块顶层代码；
4. 把模块对象绑定到当前命名空间的名字上。

```python
import sys
sys.path          # 一个列表，就是搜索路径
```

**坑**：`sys.path[0]` 是「脚本所在目录」或当前目录，优先级高于标准库。自己写一个 `random.py`、`json.py`，就会把标准库顶掉，报 `AttributeError: module 'random' has no attribute 'randint'`。**别用标准库名当文件名。**

## 三、包：带层次的模块

```
mypkg/
├── __init__.py        # 包的初始化，可以为空
├── core.py
└── utils/
    ├── __init__.py
    └── io.py
```

```python
import mypkg.core
from mypkg import core
from mypkg.core import run
from . import core           # 相对导入：当前包
from ..utils import io       # 上一级包
```

- `__init__.py` 在包被导入时执行，常用来做初始化、定义 `__all__`、暴露快捷入口。
- 3.3+ 支持**命名空间包**（没有 `__init__.py` 的目录也能当包），但普通项目仍建议保留，边界更清楚。
- **导入子模块不会自动导入它的兄弟**；`import mypkg` 不等于 `import mypkg.core`，除非 `__init__.py` 里写了。
- 相对导入只能在包内使用。直接 `python mypkg/core.py` 会报 `ImportError: attempted relative import with no known parent package`；用 `python -m mypkg.core`。

## 四、`__name__` 与两种运行方式

```python
def main():
    print("主逻辑")

if __name__ == "__main__":
    main()
```

- 直接运行：`__name__ == "__main__"`，脚本顶层代码执行；
- 被 import：`__name__` 是模块名，上面的 `main()` 不会自动跑。

| 运行方式 | `sys.path[0]` | 适合 |
| --- | --- | --- |
| `python path/to/mod.py` | `path/to` | 单文件脚本 |
| `python -m pkg.mod` | 当前工作目录 | 包内模块，相对导入可用 |

## 五、循环导入

`a.py` 导入 `b.py`，`b.py` 又导入 `a.py`：先被导入的那个只执行到一半，另一个拿到的是**半成品模块**，常见报错 `ImportError: cannot import name 'x' from partially initialized module`。

三种解法：

1. **延迟导入**：把 `import` 挪进函数体，调用时才执行；
2. **抽公共层**：把双方都依赖的东西放到第三个模块 `common.py`；
3. **只导入模块，不导入名字**：`import b` 然后 `b.func()`，比 `from b import func` 更抗循环。

类型注解场景可以用 `from __future__ import annotations` 或 `if TYPE_CHECKING:` 把仅用于注解的导入移到运行时之外。

## 六、打包与发布（简述）

一个可安装项目的最小 `pyproject.toml`：

```toml
[build-system]
requires = ["setuptools>=61"]
build-backend = "setuptools.build_meta"

[project]
name = "mypkg"
version = "0.1.0"
description = "示例包"
requires-python = ">=3.10"
dependencies = ["requests>=2.31"]
```

```bash
pip install -e .        # 开发模式：改源码立刻生效
python -m build         # 生成 dist/*.whl 与 *.tar.gz
pip install dist/mypkg-0.1.0-py3-none-any.whl
```

- `wheel` 是二进制分发包，`sdist` 是源码包；上传 PyPI 用 `twine upload dist/*`。
- 版本号遵循语义化：`主.次.修订`，不兼容改动升主版本。
- 命令行入口在 `[project.scripts]` 里声明，例如 `mytool = "mypkg.cli:main"`。

## 七、常见坑

1. 文件名与标准库/第三方包重名（`random.py`、`email.py`）。
2. 忘了 `__init__.py`（老项目/老教程），包识别失败。
3. 循环导入：现象是「partially initialized module」，不是「找不到模块」。
4. 在包内用相对导入，却用 `python 文件.py` 直接跑。
5. `from x import *` 把几十个名字倒进当前命名空间，调试时不知道名字来源。
6. 改了源码但 import 的还是旧模块：Python 有 `.pyc` 缓存，交互环境用 `importlib.reload`。

## 八、练习

1. 建一个包 `shapes/`，含 `circle.py`、`rect.py`，在 `__init__.py` 里暴露 `area()` 统一入口。
2. 把一个「可 import 也可直接运行」的脚本改成 `main()` + `if __name__ == "__main__"` 结构。
3. 故意造一个循环导入，分别用「延迟导入」和「抽公共层」修好。
4. 给练习 1 的包写 `pyproject.toml`，`pip install -e .` 后在任意目录 import。
