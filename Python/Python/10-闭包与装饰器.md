# 10 闭包与装饰器

> 对应分P：P26–P28

## 一、这一篇要掌握什么

- 闭包是什么：内层函数记住了外层函数的变量
- 装饰器的本质：把函数当参数传进去、返回一个新函数
- `@语法糖` 与 `functools.wraps`
- 带参数的装饰器（三层函数）
- 缓存装饰器 `lru_cache` / `cache`、权限校验装饰器
- 类装饰器与注册表

## 二、闭包

```python
def outer(n):
    def inner(x):
        return x + n     # inner 记住了 n
    return inner

add5 = outer(5)
add5(10)                 # 15
```

三个条件：有嵌套函数、内层引用了外层变量、外层返回内层函数。外层变量保存在 `inner.__closure__` 里。

坑：循环里创建闭包会共享同一个变量（延迟绑定），要用默认参数固定：`lambda x, i=i: ...`。

## 三、装饰器

```python
import functools

def timer(func):
    @functools.wraps(func)          # 保留原函数的名字和文档
    def wrapper(*args, **kwargs):
        import time
        t0 = time.perf_counter()
        r = func(*args, **kwargs)
        print(f"{func.__name__} 用时 {time.perf_counter()-t0:.4f}s")
        return r
    return wrapper

@timer
def work():
    sum(range(100000))
```

`@timer` 等价于 `work = timer(work)`：调用时先执行 wrapper，wrapper 里再调原函数。

## 四、带参数的装饰器

```python
def retry(times):
    def deco(func):
        def wrapper(*a, **kw):
            for _ in range(times):
                try:
                    return func(*a, **kw)
                except Exception:
                    pass
            raise RuntimeError("重试完仍失败")
        return wrapper
    return deco

@retry(3)
def fetch():
    ...
```

形状是三层：`retry(3)` 返回 `deco`，`deco` 装饰 `fetch`。

## 五、缓存：lru_cache / cache

**解决什么问题**　纯函数同样的输入反复算，纯属浪费。`functools.lru_cache` 把「参数 → 返回值」存起来，下次直接取。

```python
from functools import lru_cache, cache

@lru_cache(maxsize=128)          # 最多存 128 组，淘汰最久没用的
def fib(n: int) -> int:
    return n if n < 2 else fib(n - 1) + fib(n - 2)

fib(100)                          # 瞬间出结果
fib.cache_info()                  # CacheInfo(hits=98, misses=101, maxsize=128, currsize=101)
fib.cache_clear()                 # 清空

@cache                            # 3.9+：无上限，等价 maxsize=None
def parse(s: str) -> tuple:
    return tuple(s.split(","))
```

| 参数 | 作用 |
| --- | --- |
| `maxsize=128` | LRU 容量；`None` 表示不限 |
| `typed=True` | `1` 和 `1.0` 算不同 key（默认 `False`，认为相等） |

**规则与坑**：

- 参数必须**可哈希**；传 list/dict 会 `TypeError: unhashable type`。
- 只适合**纯函数**：有副作用、依赖时间/随机数/文件内容的函数别缓存，会拿到旧值。
- 调用写法影响 key：`f(1, 2)` 和 `f(a=1, b=2)` 通常是两个不同的缓存项，循环里保持同一种写法。
- 装饰**实例方法**时，`self` 也是 key 的一部分，缓存会一直持有实例，造成内存泄漏；改用 `@cached_property`，或把缓存放在实例属性上。
- `lru_cache` 内部有锁，多线程下不会崩，但同一个 key 可能被并发计算两次。
- 递归函数加缓存是动态规划的懒人版；但递归深度仍受 `sys.setrecursionlimit` 限制。

**缓存属性**：

```python
from functools import cached_property

class Report:
    def __init__(self, rows):
        self.rows = rows

    @cached_property
    def total(self):              # 第一次访问才计算，结果写回 __dict__
        print("只算一次")
        return sum(self.rows)
```

`cached_property` 要求实例有 `__dict__`；用了 `__slots__` 的类不行。

## 六、权限校验装饰器

把「谁能调这个函数」写在函数头上，比每个函数开头复制 `if` 干净：

```python
from functools import wraps

def require(role):
    def deco(func):
        @wraps(func)
        def wrapper(user, *args, **kwargs):
            if role not in user.roles:
                raise PermissionError(f"需要 {role} 权限")
            return func(user, *args, **kwargs)
        return wrapper
    return deco

class User:
    def __init__(self, name, roles=()):
        self.name = name
        self.roles = set(roles)

    @require("admin")
    def delete(self, uid):
        return f"删除 {uid}"

admin = User("管理员", ["admin"])
admin.delete(1)          # '删除 1'
User("访客").delete(1)    # PermissionError
```

- 装饰器在**类定义时**执行一次，`user` 是运行时才传进来的第一个参数（实例方法就是 `self`）。
- 权限判断尽量基于**已认证的身份**，不要在装饰器参数里传密码/令牌。
- 多个权限用 `@require("admin")` 叠加；要一次写多个角色，把 `require(role)` 改成 `require(*roles)`，在 wrapper 里用 `set(roles) & user.roles` 判断。
- 异步函数要用异步 wrapper，否则 `wrapper` 返回的是协程对象，没人 `await`：

```python
def require_async(role):
    def deco(func):
        @wraps(func)
        async def wrapper(user, *a, **kw):
            if role not in user.roles:
                raise PermissionError(role)
            return await func(user, *a, **kw)
        return wrapper
    return deco
```

## 七、类装饰器

类装饰器和函数装饰器是同一个东西：接收一个类，返回一个类（通常是原类，改完再返回）。

```python
def add_repr(cls):
    def __repr__(self):
        attrs = ", ".join(f"{k}={v!r}" for k, v in self.__dict__.items())
        return f"{cls.__name__}({attrs})"
    cls.__repr__ = __repr__
    return cls

@add_repr
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

Point(1, 2)      # Point(x=1, y=2)
```

**注册表**：插件/命令/模型类常用「定义即注册」：

```python
registry = {}

def register(cls):
    registry[cls.__name__] = cls
    return cls

@register
class JsonParser:
    ...

registry            # {'JsonParser': <class ...>}
```

**类装饰器 vs `__init_subclass__`**：只想在「被子类继承时」做登记，用父类的 `__init_subclass__` 更自然：

```python
class Base:
    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        registry[cls.__name__] = cls
```

**坑**：

- 返回一个**新类**会切断原类的引用：`isinstance`、`super()`、pickle 都可能出问题；优先原地改原类再返回它。
- 类装饰器在 import 时执行，别在里面做耗时 IO。
- `@dataclass`、`@functools.total_ordering` 都是标准库的类装饰器（见 [[13-面向对象]] 的 dataclass 一节）。

## 八、常见坑

1. 忘了 `@functools.wraps(func)` → 函数名变成 `wrapper`，日志和调试都乱。
2. 装饰器在**导入时**就执行一次（装饰那一刻），不是每次调用都执行外层。
3. 多个装饰器叠加时从下往上装饰、从上往下执行：

```python
@a
@b
def f(): ...
# f = a(b(f))
```

4. `lru_cache` 装饰方法会连 `self` 一起缓存，实例无法释放；长生命周期进程里尤其危险。
5. 异步函数被同步装饰器包住，调用方拿到的是协程对象，既不执行也不报错，最难查。
6. 装饰器顺序：`@classmethod` / `@staticmethod` 要放在最外层（最上面），自定义装饰器放在它们下面，先包函数再变类方法。
7. 类装饰器返回新类会让旧的 `isinstance` 判断失效；能原地改就别替换。
