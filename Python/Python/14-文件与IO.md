# 14 文件与 IO

> 对应分P：P37–P39

## 一、这一篇要掌握什么

- `open()` 的 mode：`r/w/a/x/b/+`
- `with` 为什么能自动关闭，以及上下文管理器协议
- 读的三种方式、写的两种方式
- 编码、路径、`os`/`pathlib` 常用操作
- `newline`、缓冲、`encoding` 的边界细节

## 二、基本读写

```python
# 写
with open("a.txt", "w", encoding="utf-8") as f:
    f.write("第一行\n")
    f.writelines(["第二行\n", "第三行\n"])

# 读
with open("a.txt", "r", encoding="utf-8") as f:
    text = f.read()          # 一次读完
    # f.readline()           # 读一行
    # f.readlines()          # 读成列表
```

```python
# 逐行读（大文件推荐）
with open("big.log", encoding="utf-8") as f:
    for line in f:
        if "ERROR" in line:
            print(line.rstrip())
```

## 三、访问模式

| mode | 含义 | 已存在 | 不存在 |
| --- | --- | --- | --- |
| `r` | 只读 | 读到原内容 | 报错 |
| `w` | 只写 | **清空**再写 | 新建 |
| `a` | 追加 | 末尾追加 | 新建 |
| `x` | 独占新建 | **报错** | 新建 |
| `r+` | 读写 | 从开头写 | 报错 |
| `w+` | 读写 | **清空**再写 | 新建 |
| `a+` | 读写 | 写永远在末尾 | 新建 |
| `rb` / `wb` | 二进制 | 用于图片、压缩包 | — |

- `+` 只是「多开一个方向」，不代表能随便切：文本模式下读完要 `seek(0)` 才能从头写。
- `b` 和 `t` 不能混用；二进制模式**不能**传 `encoding`。
- 坑：`w` / `w+` 会清空文件；不确定用 `a`、`x` 或先判断。

## 四、路径与目录

```python
from pathlib import Path

p = Path("data") / "a.txt"     # 跨平台拼路径，别手写 "/"
p.exists(); p.suffix; p.stem; p.parent
p.read_text(encoding="utf-8")
p.write_text("hi", encoding="utf-8")

Path("out").mkdir(parents=True, exist_ok=True)
for f in Path(".").glob("*.py"):
    print(f.name)
for f in Path(".").rglob("*.log"):     # 递归
    print(f)
```

```python
import os
os.getcwd(); os.listdir("."); os.makedirs("a/b", exist_ok=True)
os.path.join("a", "b.txt"); os.path.getsize("a.txt")
```

## 五、二进制与序列化

```python
with open("logo.png", "rb") as f:
    data = f.read()          # bytes

import json
json.dump({"a": 1}, open("d.json", "w"))     # 写 JSON
json.load(open("d.json"))                     # 读 JSON

import csv
with open("t.csv", newline="") as f:
    for row in csv.reader(f):
        print(row)
```

坑：上面 `json.dump` 里直接 `open(...)` 没有关闭文件，正式代码要用 `with`；`json.dump` 默认 `ensure_ascii=True`，中文会写成 `\uXXXX`，要加 `ensure_ascii=False`。

## 六、上下文管理器协议

`with` 不是语法糖那么简单，它靠两个方法：

```python
class Timer:
    def __enter__(self):
        import time
        self.t0 = time.perf_counter()
        return self                 # as 后面拿到的就是它

    def __exit__(self, exc_type, exc, tb):
        import time
        self.cost = time.perf_counter() - self.t0
        print(f"耗时 {self.cost:.4f}s")
        return False                # False/None：异常继续往外抛

with Timer() as t:
    sum(range(100000))
print(t.cost)
```

| 方法 | 什么时候调 | 返回值 |
| --- | --- | --- |
| `__enter__` | 进入 `with` 时 | 绑定给 `as` 的变量 |
| `__exit__` | 离开 `with` 时（**包括异常**） | 真值 → 吞掉异常；假值 → 继续抛 |

- `__exit__` 收到 `(exc_type, exc, tb)`；没有异常时三个都是 `None`。
- 多个 `with` 嵌套时，退出顺序与进入相反；`with a as x, b as y:` 等价于两层嵌套。
- `__exit__` 自己抛异常，会替换掉原来的异常（原异常挂在新异常的 `__context__` 上）。
- 上下文管理器实例通常是一次性的；要复用就在 `__enter__` 里重置状态。

## 七、contextlib 工具箱

写一个类只为了 `__enter__`/`__exit__` 太重，用生成器版：

```python
from contextlib import contextmanager
import time

@contextmanager
def timer():
    t0 = time.perf_counter()
    try:
        yield                    # yield 之前 = __enter__，之后 = __exit__
    finally:
        print(f"耗时 {time.perf_counter()-t0:.4f}s")

with timer():
    sum(range(100000))
```

- `yield` 必须**恰好一次**；yield 两个值会 `RuntimeError: generator didn't stop`。
- `with` 块里的异常会在 `yield` 处抛回生成器，所以清理逻辑放 `finally`。
- 想吞异常就在 `yield` 外面 `try/except` 并且不重新抛——但这会掩盖错误，少用。

常用工具：

```python
from contextlib import suppress, closing, ExitStack, redirect_stdout

with suppress(FileNotFoundError):      # 指定异常直接忽略
    Path("nope.txt").unlink()

with closing(open("a.txt")) as f:      # 只保证 close，不吞异常
    ...

with ExitStack() as stack:             # 动态数量的一堆资源
    files = [stack.enter_context(open(p, encoding="utf-8")) for p in paths]
    ...

with redirect_stdout(open("out.txt", "w")):
    print("进文件")
```

异步版本是 `__aenter__` / `__aexit__` 和 `contextlib.asynccontextmanager`，配合 `async with` 用（见 [[15-并发]]）。

## 八、newline、缓冲、encoding 的边界

### 8.1 newline：换行符不是小事

文本模式默认开启**通用换行**：

- 读：`\r\n`、`\r`、`\n` 都统一成 `\n`；
- 写：`\n` 会按 `os.linesep` 翻译（Windows 上是 `\r\n`）。

`newline` 参数改这个行为：

| 值 | 读 | 写 |
| --- | --- | --- |
| `None`（默认） | 三种换行都转 `\n` | `\n` → `os.linesep` |
| `""` | 不翻译，原样返回 | 不翻译 |
| `"\n"` | 只认 `\n` | 不翻译 |
| `"\r\n"` / `"\r"` | 只认指定换行 | 翻译成指定换行 |

**CSV 必须 `newline=""`**：否则 Windows 上 `csv.writer` 写出的 `\r\n` 会被再翻译一次，变成空行。

```python
with open("t.csv", "w", newline="", encoding="utf-8") as f:
    csv.writer(f).writerows(rows)
```

### 8.2 buffering：什么时候真正落盘

- 默认 `buffering=-1`：文本/二进制都用系统默认缓冲（通常 8 KB）。
- 二进制可以 `buffering=0`（无缓冲）；文本不行，`buffering=1` 表示行缓冲（只对文本有意义）。
- `f.flush()` 把用户态缓冲交给操作系统；`os.fsync(f.fileno())` 才尽量刷到磁盘。
- `with` 退出时会 `close()`，顺带 flush；进程被 `kill -9` 时缓冲区里的内容会丢。
- 看日志实时输出：`print(..., flush=True)`，或启动加 `python -u`。

### 8.3 encoding：默认值靠不住

- 不写 `encoding` 时用「平台默认编码」：macOS/Linux 通常是 UTF-8，Windows 中文版是 GBK。同一份代码换机器就乱码。
- 永远显式 `encoding="utf-8"`；读别人给的文件先确认编码。
- `errors=` 决定解码失败怎么办：`strict`（默认，抛 `UnicodeDecodeError`）、`ignore`（丢字符）、`replace`（换 `�`）、`backslashreplace`（转义）、`surrogateescape`（保留原始字节，适合 Unix 文件名）。
- 带 BOM 的 UTF-8 用 `encoding="utf-8-sig"` 读写；普通 `utf-8` 读出来第一个字符会是 `\ufeff`。
- `str.encode()` / `bytes.decode()` 是内存里的转换，和文件编码是两件事；`sys.getdefaultencoding()` 固定是 `utf-8`，别拿它当文件编码。

### 8.4 seek / tell

- 二进制模式：`seek(n)` 就是字节偏移，`tell()` 返回字节位置。
- 文本模式：`tell()` 返回的是不透明「cookie」，只能 `seek(上次的 tell 值)` 或 `seek(0)`；随便 `seek(3)` 可能落到半个字符上。
- `truncate()` 从当前位置截断；`w` 模式已经清空，别混用。

### 8.5 原子写：别让半个文件落地

```python
import os, tempfile

fd, tmp = tempfile.mkstemp(dir=".", suffix=".tmp")
with os.fdopen(fd, "w", encoding="utf-8") as f:
    f.write(data)
    f.flush()
    os.fsync(f.fileno())
os.replace(tmp, "target.txt")      # 同分区内原子替换
```

直接 `open("target.txt", "w")` 写到一半断电，目标文件就是残缺的；先写临时文件再 `os.replace` 是通用做法。

## 九、常见坑

1. 不写 `encoding=` → Windows 上默认 GBK，中文乱码。
2. 忘记 `with`，异常时文件句柄不释放，久了 `Too many open files`。
3. `readlines()` 读大文件会吃满内存。
4. 路径用 `/` 拼接在 Windows 会出问题，用 `pathlib`。
5. 写 JSON 时 `ensure_ascii=False` 才保留中文。
6. CSV 忘了 `newline=""`，Windows 上多出空行。
7. `__exit__` 返回 `True` 会吞掉异常，调试时异常「消失」先查这里。
8. 文本模式随便 `seek(n)`，可能 `UnicodeDecodeError` 或读到半个字符。
9. `errors="ignore"` 会让坏字节静默消失，数据对不上时很难查。
