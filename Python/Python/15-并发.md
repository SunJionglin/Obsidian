# 15 并发

> 对应分P：P43–P50

## 一、这一篇要掌握什么

- 线程 / 进程 / 协程各解决什么问题，什么时候用哪个
- GIL 的存在与影响
- `threading` 起线程、加锁，以及 Lock / RLock / Event / Condition / Semaphore / Queue 全家桶
- `multiprocessing` 起进程、进程池
- `asyncio` 的任务创建、取消、超时、TaskGroup
- `gevent` / `greenlet` 协程的写法（课程用 gevent）

## 二、先分清三者

| 方式 | 单位 | 切换代价 | 适合 | 限制 |
| --- | --- | --- | --- | --- |
| 多线程 | 线程 | 小 | IO 密集（网络、文件） | GIL：同一时刻只有一个线程跑字节码 |
| 多进程 | 进程 | 大 | CPU 密集（计算） | 进程间数据要序列化传递 |
| 协程 | 用户态任务 | 最小 | 超高并发 IO | 要全程非阻塞，遇到阻塞调用就退化成串行 |

一句话：**IO 密集用线程/协程，CPU 密集用进程。**

## 三、线程

```python
import threading, time

def work(n):
    time.sleep(0.5)
    print("done", n)

ts = [threading.Thread(target=work, args=(i,)) for i in range(3)]
for t in ts: t.start()
for t in ts: t.join()        # 等全部结束
```

加锁（共享变量自增）：

```python
lock = threading.Lock()
count = 0
def inc():
    global count
    with lock:               # 等价 lock.acquire() / release()
        count += 1
```

### 3.1 同步原语全家桶

| 原语 | 一句话 | 典型场景 | 坑 |
| --- | --- | --- | --- |
| `Lock` | 互斥锁，acquire / release | 保护共享变量 | 不可重入，同一线程连 acquire 两次会死锁 |
| `RLock` | 可重入锁，记持有次数 | 递归函数、同类方法互调 | 必须 release 同样次数 |
| `Event` | 一个布尔旗标，set / clear / wait | 通知「初始化完成」、线程起跑线 | `wait()` 不带 timeout 会一直等 |
| `Condition` | 在锁上等条件，wait / notify | 生产者-消费者、状态变化 | `wait` 会释放锁，醒来要重新拿 |
| `Semaphore` | 计数信号量，限制并发数 | 限制同时访问资源（连接池） | 用 `BoundedSemaphore` 防 release 过多 |
| `Barrier` | N 个线程到齐才继续 | 分阶段并行计算 | 数量写错就永远等 |
| `Queue` | 线程安全队列 | 线程间传数据 | `get` 后要 `task_done()`，否则 `join()` 卡住 |

```python
# RLock：同一线程可以重复拿
rlock = threading.RLock()
def outer():
    with rlock:
        inner()
def inner():
    with rlock:          # 换成 Lock 在这里会死锁
        pass
```

```python
# Event：主线程说「开始」，工作线程才起跑
ready = threading.Event()
def worker():
    ready.wait()         # 阻塞到 set
    print("go")
t = threading.Thread(target=worker); t.start()
ready.set()
```

```python
# Queue：生产者-消费者，用 None 当结束哨兵
import queue, threading

q = queue.Queue(maxsize=10)
def producer():
    for i in range(5):
        q.put(i)
    q.put(None)          # 几个消费者就放几个 None

def consumer():
    while True:
        item = q.get()
        try:
            if item is None:
                break
            print("处理", item)
        finally:
            q.task_done()
```

```python
# Semaphore：最多 3 个线程同时进
sem = threading.Semaphore(3)
def task():
    with sem:
        time.sleep(0.5)
```

**死锁**：两个线程以相反顺序拿两把锁，各等对方释放。三种解法：

1. 全局固定加锁顺序（所有代码都先 A 后 B）；
2. 用 `lock.acquire(timeout=1)`，拿不到就释放已拿的、重试；
3. 尽量只用一个锁，或把共享状态收进一个 `Queue` 由单线程处理。

```python
# 反例：线程 1 先 A 后 B，线程 2 先 B 后 A
with lock_a:
    with lock_b: ...
```

`concurrent.futures.ThreadPoolExecutor` 比手写线程池省事：

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

with ThreadPoolExecutor(max_workers=4) as ex:
    futs = [ex.submit(work, i) for i in range(8)]
    for f in as_completed(futs):
        print(f.result())      # 谁先完成先拿谁
```

## 四、GIL

- CPython 有全局解释器锁，**同一时刻只有一个线程在执行 Python 字节码**。
- 所以多线程做计算不会变快，但做 IO（等网络、等磁盘）时能切换，仍有收益。
- 绕过方式：多进程、`numpy` 这类 C 扩展内部释放 GIL。
- 3.13 有实验性的 free-threaded 构建（`python3.13t`），可以不带 GIL；**默认安装仍是带 GIL 的**，别把它当默认行为。

## 五、进程

```python
from multiprocessing import Process, Pool

def work(n): return n * n

if __name__ == "__main__":        # 必须这一行，否则子进程会重复导入
    ps = [Process(target=work, args=(i,)) for i in range(4)]
    for p in ps: p.start()
    for p in ps: p.join()

    with Pool(4) as pool:
        print(pool.map(work, range(10)))   # 并行 map
```

进程池的 `map` 直接拿结果；进程函数必须是**模块级函数**（能 pickle）。

## 六、协程

```python
# asyncio 版（现代写法）
import asyncio

async def fetch(i):
    await asyncio.sleep(0.5)
    return i

async def main():
    rs = await asyncio.gather(*[fetch(i) for i in range(3)])
    print(rs)

asyncio.run(main())
```

课程里的 gevent 版：

```python
import gevent
from gevent import monkey
monkey.patch_all()          # 把阻塞库换成协作版

def task(i):
    gevent.sleep(0.5)
    print(i)

gevent.joinall([gevent.spawn(task, i) for i in range(3)])
```

协程的本质是「一个线程内轮流执行」，靠 `yield`/`await` 主动让出。

### 6.1 asyncio 的任务管理：创建、取消、超时

`asyncio.gather` 只是「一起等」，真正要控制生命周期得用 `Task`：

```python
import asyncio

async def fetch(i, delay):
    await asyncio.sleep(delay)
    return i

async def main():
    t = asyncio.create_task(fetch(1, 0.2))   # 立刻排进事件循环
    print(await t)                           # 1

    # 超时：超时后内部任务被取消，抛 TimeoutError
    try:
        await asyncio.wait_for(fetch(2, 5), timeout=1)
    except TimeoutError:
        print("超时")

    # 3.11+ 的写法，能包住一段代码而不是单个协程
    try:
        async with asyncio.timeout(1):
            await fetch(3, 5)
    except TimeoutError:
        print("超时")

asyncio.run(main())
```

**取消是协作式的**：`task.cancel()` 只在协程**下一次 `await`** 时抛 `CancelledError`，同步代码不会被打断。

```python
async def worker():
    try:
        while True:
            await asyncio.sleep(1)
    except asyncio.CancelledError:
        print("清理资源")
        raise                 # 别吞掉，吞了外层以为正常结束
    finally:
        print("finally 一定跑")

async def main():
    t = asyncio.create_task(worker())
    await asyncio.sleep(0.1)
    t.cancel()
    try:
        await t
    except asyncio.CancelledError:
        print("已取消")
```

`CancelledError` 在 3.8+ 继承 `BaseException`，所以 `except Exception` 抓不到——这是故意的，防止业务代码误吞取消。

**TaskGroup（3.11+）**：结构化并发，任一任务失败就取消同组其它任务，最后抛 `ExceptionGroup`：

```python
async def main():
    async with asyncio.TaskGroup() as tg:
        t1 = tg.create_task(fetch(1, 0.1))
        t2 = tg.create_task(fetch(2, 0.2))
    print(t1.result(), t2.result())   # 出了 with 才保证都完成
```

**限制并发**：爬虫别一次 `gather` 一万个，用 `Semaphore` 卡住并发数：

```python
async def crawl(urls):
    sem = asyncio.Semaphore(10)

    async def one(url):
        async with sem:
            return await fetch(url, 0.1)

    return await asyncio.gather(*(one(u) for u in urls))
```

**别在协程里做阻塞操作**：`time.sleep`、`requests.get`、大文件读都会卡住整个事件循环。要么换异步库（`aiohttp`/`httpx`），要么丢进线程：

```python
data = await asyncio.to_thread(requests.get, url, timeout=10)
```

## 七、常见坑

1. 多进程脚本忘了 `if __name__ == "__main__":` → 递归创建进程，直接卡死。
2. 多线程里 `print` 混杂输出，加锁或统一由主线程打印。
3. `gevent.monkey.patch_all()` 必须在**最前面**调用，之后 import 的库才被替换。
4. 协程里调用 `time.sleep` 会阻塞整个事件循环，用 `asyncio.sleep`。
5. 线程里抛的异常不会自动传到主线程，要自己收集。
6. `gather` 默认遇到第一个异常就向上抛，但其它任务还在跑；要收齐所有结果用 `return_exceptions=True`。
7. `create_task` 的返回值没人引用，任务可能被 GC 回收（事件循环只持弱引用）；长期任务要存进集合。
8. 在 Jupyter 里 `asyncio.run()` 会报 “event loop is already running”，因为循环已经在跑，直接 `await` 即可。
