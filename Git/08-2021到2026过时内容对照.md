# 08 2021 → 2026 时效核对

> [!info] 这张表收什么、不收什么
> 只收两类：**照抄会真的卡住**，和**命令还能用但官方推荐换写法**。课程没讲的新东西单列在第四节，那是缺口，不算过时。
> 核对日期 2026-10-30，本机 Git 2.39.2；官方最新 2.56.0（2026-09-28，见 [git-scm.com](https://git-scm.com/)）。

## 一、照抄会卡住的

| # | 场景 | 课程写法 | 现在 | 原因 |
| --- | --- | --- | --- | --- |
| 1 | 分支名 | `git checkout master`、`git push origin master` | `main` | GitHub 2020-10 起新仓库默认 `main`；本机 `init.defaultBranch=main`，`git init` 出来也是 main。**先 `git branch` 看一眼真实名字**，仓库里叫哪个就用哪个 |
| 2 | 推代码认证 | HTTPS 输账号密码 | Personal Access Token 或 SSH | GitHub 2021-08-13 起停止接受密码，照抄会 403。Gitee 多数场景还行，但在收紧 |
| 3 | 本地远程分叉后 | `git pull` 自动合并 | `fatal: Need to specify how to reconcile divergent branches` | 2.27 起先给提示，后来收紧成直接失败，2.39 实测为 fatal。配 `pull.rebase` 或 `pull.ff` 解决 |

> 就这三条。剩下的都不是「照抄会炸」，而是「有更好的写法」或者「课里压根没讲」。

## 二、命令没坏，官方推荐换写法

| # | 旧写法 | 新写法 | 从哪版开始 | 说明 |
| --- | --- | --- | --- | --- |
| 4 | `git checkout 分支` / `git checkout -b` | `git switch 分支` / `git switch -c` | 2.23 | checkout 没废弃，两者等价，新写法语义更清楚 |
| 5 | `git checkout -- 文件` | `git restore 文件` | 2.23 | 取消暂存用 `git restore --staged` |
| 6 | 合并输出 `'recursive' strategy` | `'ort' strategy` | 2.34 | **只是输出文字变了**，行为等价，别以为报错 |

## 三、不是过时，是环境不一样

| #   | 课程里                                     | 你的 Mac 上                          |
| --- | --------------------------------------- | --------------------------------- |
| 7   | `~/.bashrc` 写别名                         | zsh 是默认，写 `~/.zshrc`              |
| 8   | IDEA 旧 UI：`VCS → Git`、`File → Settings` | 2023.1 起新 UI：顶部 `Git` 菜单、`⌘,` 开设置 |
| 9   | Git Bash                                | 系统终端 / iTerm，命令一个字不用改             |

## 四、课程没讲，现在算常识（补充，不是过时）

| # | 主题 | 说明 |
| --- | --- | --- |
| 10 | Pull Request / Code Review | 现在协作的默认形态，不直接推主干 |
| 11 | 主干保护 + CI | 平台侧禁止直推，PR 自动跑测试 |
| 12 | 分支模型选型 | Git Flow 与 trunk-based 都成立，中小团队偏后者 |
| 13 | 标签与发布 | `git tag -a v1.0.0 -m "..."`，配合平台 Release |
| 14 | `git stash` / `git worktree` | 处理「改到一半要切走」和多任务并行 |
| 15 | `git rebase -i` | 整理自己分支上的琐碎提交 |
| 16 | Git LFS | 大二进制文件别塞进普通仓库 |
| 17 | Conventional Commits | `feat:` / `fix:` / `docs:` 这类前缀，团队约定 |
| 18 | `--force-with-lease` | 比 `-f` 安全的强推 |
| 19 | 双因子认证 | GitHub 2023 起对贡献者逐步强制，影响网页登录，不影响 SSH 推代码 |

## 五、核对后确认没变的

放心照课程学，机制一点没改：

- 四个区域的流转：工作区 → 暂存区 → 本地仓库 → 远程仓库
- `add` / `commit` / `status` / `log` / `diff` 的语义
- 分支是指针，HEAD 指向当前分支
- 快进合并与三方合并，冲突标记的三行格式
- `.gitignore` 语法
- `reflog` 能救命
- 「推不上去先拉」这条规则

## 六、三条常见的「假过时」

这几条常被二手文章写成「已经不能用了」，其实可以：

| 说法 | 事实 |
| --- | --- |
| `ssh-keygen -t rsa` 被 GitHub 封了 | **没封**。2021-11-02 之后签发的 RSA 密钥必须用 SHA-2 签名，新版 OpenSSH 默认就是；官方兜底写法仍是 `-t rsa -b 4096`。只是 ed25519 更值得首选 |
| `git add .` 不含删除，得用 `-A` | Git 2.0 起 `git add .` 就把删除也记进去。本机 2.39 实测：删掉文件后 `git add .`，`git status` 直接显示 `D  a.txt` |
| `--set-upstream` 已经废弃 | 没废，`-u` 只是它的简写，两个都能用 |

## 七、自己怎么核对时效

```bash
git --version                    # 先看版本，2.23 以下很多新命令没有
git config --list --show-origin  # 本机有哪些默认值
git help <命令>                  # 报错看不懂就看本地文档，比博客准
```

平台侧的变化看官方：[GitHub Changelog](https://github.blog/changelog/)、[Git 发行说明](https://git-scm.com/docs)。
