# Git 视频笔记 · 生成提示词

> 用途：把一集（或一组）Git 课程视频的转写稿 + 讲义 PDF，整理成**能照着敲、能考前十分钟过一遍**的 Obsidian 笔记。
> 用法：复制下面的「提示词正文」，把 `{{...}}` 换成实际内容，交给模型；输出一个 `.md` 文件，存进 `Git/`。

---

## 0. 这套模板的根据

查了一圈笔记方法，最后是四样东西拼起来用的，各自负责一段：

| 方法 | 它解决什么 | 落到模板的哪一段 |
| --- | --- | --- |
| **康奈尔笔记法**（Cornell，Walter Pauk，1950s） | 记录 → 简化 → 回想 → 反思 → 复习，靠「线索栏问句 + 页脚总结」逼出主动回想 | 「自测题」= 线索栏，答案折叠；「一句话结论 / 背诵卡」= 页脚总结 |
| **卡片盒笔记法**（Zettelkasten） | 一条笔记只讲一件事，靠链接长成网络 | 一篇 = 一个主题；文末「关联」区放 `[[双链]]` |
| **渐进式总结**（BASB / Tiago Forte） | 先原样记，再逐层加粗、提炼、压成一句 | 讲义原文 → 命令速查表 → 一句话结论 → 背诵卡 |
| **MOC 内容地图**（Obsidian 社区实践） | 给一屋子笔记一个入口 | `00-Git学习地图.md` 当索引，每篇都能跳回去 |

康奈尔那套的五个 R 里，真正起作用的是「回想」和「复习」，所以这套模板把**自测题**当正文写，不是当附录。参考：[康奈尔笔记法完整指南](https://fabric.so/zh/learn/cornell-method)、[卡片盒笔记法](https://fabric.so/zh/learn/zettelkasten)、[渐进式总结](https://fabric.so/zh/learn/build-a-second-brain)。

## 1. 提示词正文

### 角色

你是 Git 教学助教 + 技术文档作者。你的目标不是复述视频，而是把一节课压成**能直接上手操作、能自查有没有听懂**的笔记。读者是刚学完 C/C++、准备用 Git 管课程作业和项目的大学生。

### 输入

- 课程：`{{课程名，例如：黑马程序员 · Git 全套教程}}`
- 本节课视频：`{{视频标题 + P 号，例如：P9 分支_常用指令}}`
- 视频时长：`{{时长}}`
- 视频转写（本地 whisper，未校对，可能把 Git 听成 Gate、把「暂存区」听成「战存区」）：`{{转写文本}}`
- 讲义原文（PDF 摘出的对应段落）：`{{讲义文本}}`
- 生成日期与当前 Git 版本：`{{YYYY-MM-DD}}` / `{{git --version}}`
- 相邻笔记：`{{上一篇 / 下一篇的标题}}`

### 输出结构

严格按下面 11 段输出，标题从 `##` 开始（`#` 留给文件名）：

1. **本节定位** —— 对应视频哪几 P、时长、先修是什么、在整个学习链路里占哪一格。
2. **一句话结论** —— 一句话说清这一节最该记住的东西，不许写「本节介绍了……」。
3. **知识地图** —— `mermaid` 流程图或树，把概念之间的关系画出来。
4. **核心概念** —— 讲清「为什么」，不是抄讲义。该用比喻就用（分支 = 便利贴，HEAD = 你站在哪）。
5. **命令速查** —— 表格：命令 / 作用 / 常用参数 / 注意点。命令一律用围栏代码块。
6. **动手实验** —— 从空目录开始的**最小可复现脚本**，带「预期输出」；读者复制粘贴就该跑通。
7. **原理补丁**（可选）—— 视频没讲但值得知道的一层（对象模型、引用、三方合并、reflog 为什么能救命）。
8. **易错点与报错** —— 报错原文 → 原因 → 解法，三条以内，只写真会踩的。
9. **过时对照** —— 见下面的「过时内容处理」。
10. **自测 + 背诵卡** —— 3～5 题，答案用 `<details>` 折叠；背诵卡 5 条以内。
11. **关联** —— 前后篇 `[[双链]]`，外加 1～2 个官方文档链接。

### 写作规则

- **只写有依据的内容**。讲义没有、转写没有，但属于必备背景的，标「补充」；自己的推断标「推断」。
- 转写里的同音错字按上下文纠正（Gate→Git、战存区→暂存区、芬支→分支、远程酷→远程库），不许改原意，也不许把没说的内容编进去。
- **不编时间戳**。转写时间戳不可靠时，只写「视频里这一段」，不写 `mm:ss`。
- 命令必须是**现在还能跑通的**。写完在心里过一遍：这条命令在 2.39+ 上会不会报错？
- 每条命令讲清「什么时候用」，比列十个参数有用。
- 中文为主，术语首次出现给英文（暂存区 / staging area）。
- 不要出现「本视频讲述了」「同学们」这类课堂腔，也不要写课程广告、学员案例。

### 过时内容处理（这套课是 2021 年的，重点）

分三层写，缺一层都算不合格：

1. **就地提示**：在讲到的位置放 Obsidian callout，写清「当年怎么写 → 现在怎么写 → 为什么变」。
   ```md
   > [!warning] 2021 → 2026
   > 课程里写 `git push origin master`；GitHub 2020-10 起新仓库默认分支叫 `main`，现在应写 `git push -u origin main`。
   ```
2. **汇总表**：全课程维护一份 `08-2021到2026过时内容对照.md`，一行一条（旧写法 / 新写法 / 版本或年份 / 影响）。
3. **版本标注**：frontmatter 里写 `git_version` 和 `course_year`，让读者一眼知道这份笔记的时效。

已知需要核对的老内容（按需增减）：`master` 与 `main`、`git checkout` 拆分出 `switch` / `restore`、`ssh-keygen -t rsa` 与 `ed25519`、HTTPS 密码与 PAT、`git pull` 分叉时的行为、merge 策略 `recursive` 与 `ort`、Git Flow 与 trunk-based、证书/双因子、以及课程完全没讲的 PR、Code Review、tag、stash、rebase、LFS。

### 自检清单（写完逐条打勾）

- [ ] 每段命令都能在 `git --version` 对应的版本上跑通，报错原文与真实一致
- [ ] 「动手实验」从空目录开始，复制即可执行
- [ ] 没有一条时间戳是编的
- [ ] 过时内容标了三层，汇总表已更新
- [ ] 自测题答案真的折叠了，且答案不是复述题干
- [ ] 有 `[[双链]]`，能回到 `00-Git学习地图`
- [ ] 没用「首先/其次/综上」这类空转折，没有课堂腔
- [ ] 全文没出现「本视频」三个字

## 2. 变量清单

| 变量 | 说明 |
| --- | --- |
| `{{课程名}}` | 写进 frontmatter 的 `course` |
| `{{视频标题 + P 号}}` | 映射到 B 站分 P，方便回看 |
| `{{时长}}` | `mm:ss`，可多 P 相加 |
| `{{转写文本}}` | 本地 whisper 结果，允许有错字 |
| `{{讲义文本}}` | PDF 里抽出的对应小节 |
| `{{YYYY-MM-DD}}` | 生成日期，写进 frontmatter 的 `created` |
| `{{git --version}}` | 校验命令行为的基准版本 |
| `{{上一篇 / 下一篇}}` | 串起 `[[双链]]` |

## 3. 批量用法

31 集一次性铺开时，按「主题」合并，不按「视频」切：

```
01 版本控制概述  ← P1-P4
02 环境安装与配置 ← P5、P28（IDEA 集成 GitBash 部分）
03 本地仓库与基础命令 ← P6-P8、P14
04 分支与合并冲突 ← P9-P13、P15
05 远程仓库与团队协作 ← P16-P22
06 IDEA 集成 Git ← P23-P27
07 实战流程与几条铁令 ← P28-P31
08 2021→2026 过时内容对照 ← 全课程汇总
09 命令速查表 ← 全课程汇总
```

每篇笔记只标它真正对应的 P 号，不硬凑。
